# 对话工作流

对话不仅是一次问答，也是项目、笔记和产物的入口。每个会话绑定创建时的场景与运行实例，避免后续切换配置导致上下文错位。

## 组织会话

- 为长期主题建立独立会话，避免不相关上下文互相干扰。
- 使用项目聚合同一目标下的会话、任务和产物。
- 新会话会采用“设置 → 常规”中选择的场景；已有会话保持原场景。

## 发送与排队

| 操作 | 结果 |
|---|---|
| `Enter` | 发送；运行中发送追加引导 |
| `Alt+Enter` | 加入后续队列 |
| `//文本` | 发送以 `/` 开头的普通文本 |

## 工作模式

输入框右上角可选择「工作模式」，决定代理这次任务的执行边界：

- **问一问（Ask）**：只回答问题与提供信息，不创建、修改或删除文件，也不
  执行有副作用的操作；
- **做一做（Craft，默认）**：直接执行任务并修改文件；
- **想一想（Plan）**：先输出执行计划（步骤、要改的文件、预期结果），在你
  确认前不修改任何文件。

选择后发送的消息会带上对应行为说明；日常使用保持默认的「做一做」即可。

## 提取记忆

输入 `/memory`（或输入 `/` 后选择「从这段对话提取记忆」），ZiCode 会把
当前对话整理成值得长期记住的事实、偏好与跟进事项，去重后写入记忆。后续
新消息会自动带上「相关记忆」（可在“设置 → 一般 → 记忆”里查看、编辑、删除
或关闭该功能）。

## 在手机上添加照片

点击输入框下方的“添加图片”，手机端会分别提供“拍照”和“从相册选择”。照片压缩期间会
显示“正在处理图片”，发送按钮会暂时停用，直到图片预览出现，避免只发出文字而漏掉尚未
处理完成的照片。触屏设备上的移除按钮始终可见；如果图片无法读取，ZiCode 会显示明确的
错误提示，可以换用尺寸更小的 PNG 或 JPEG 后重试。

## 分享回答

在支持系统分享的手机浏览器或主屏幕应用中，Pi 回答下方会显示“分享回答”。点击后可把
回答发送到系统中的聊天、邮件、备忘录等应用。ZiCode 只分享可见回答，不包含思考过程、
工具调用或会话凭据。关闭系统分享面板不会显示错误；如果浏览器无法打开分享面板，
ZiCode 会改为复制回答，并在按钮上显示“已复制”。

复制、保存到笔记和分享在窄屏或触屏设备上都使用至少 40×40px 的操作区域。

安装到 Android 主屏幕后，ZiCode 还可以作为系统分享的接收目标。网页标题、选中文本、
链接和常见图片会进入当前输入区并保留已有草稿，图片先显示预览，确认前绝不会自动发送。
详细的格式、大小限制和隐私边界见“在手机上使用 ZiCode → 从 Android 系统分享到 ZiCode”。

## 手机端未发送草稿

手机端输入的文字和有界图片附件会按会话在本机加密保存。刷新或系统回收应用后重新打开
同一会话，ZiCode 会恢复文字与图片预览但不会自动发送；发送成功后删除。加密、图片容量、
时效和清理边界见“在手机上使用 ZiCode → 未发送草稿恢复”。

手机断线时点击发送会改为保存加密待发送草稿，不会自动请求模型。连接恢复后，使用输入区
上方的“立即发送”再次确认，或选择“保留为草稿”取消待发送状态。详细规则见“在手机上
使用 ZiCode → 断线时保存待发送内容”。

## 与笔记打通

在笔记中使用“关联对话”建立双向来源，而不是依赖聊天命令复制一段文本。关联后可以：

- 从笔记回到原始会话和消息；
- 把多篇相关笔记组装成上下文包，再交给新对话；
- 查看相似笔记、冲突观点和知识关系；
- 将对话结论持续整理为可发布的知识库。

## 错误恢复

模型请求失败时会显示友好的错误卡片。先阅读原因，再选择“重试请求”或“打开模型设置”。重试会沿用原始文本和图片，不需要重新输入。

> 如果任务仍在运行但界面没有新内容，请先检查任务状态和错误卡片，不要连续重复发送同一请求。
