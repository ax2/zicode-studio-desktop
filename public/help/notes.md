# 本地笔记库

Notes 是内置的本地优先笔记应用。它与对话、设置和帮助使用相同的三栏界面：左侧导航切换应用，中间功能区管理笔记本、标签、搜索和笔记列表，右侧主视图负责编辑与预览。

功能区中的笔记采用树状目录：笔记本是父节点，所属笔记直接显示在笔记本下方。展开或折叠笔记本可控制目录密度，当前笔记会在树中高亮；搜索与标签筛选仍保留原有层级，便于理解每篇笔记的归属。

## 创建笔记本

打开“笔记”，选择“新建笔记本”并输入名称。每个笔记本都是独立 Vault，正文以 Markdown 文件保存，并包含 Astro Content Collection 兼容的目录和配置。即使不运行 ZiCode 或 Astro，也可以用普通文本编辑器阅读笔记。

## 编辑和搜索

选择“新建笔记”后编辑标题、标签和 Markdown 正文。使用“预览”检查渲染结果，使用 `Ctrl+S` 保存。搜索会检查标题、标签、正文和网页来源；保存时会校验文件版本，避免静默覆盖其他位置的修改。

搜索命中时，笔记标题会用高亮标记标出匹配位置；预览模式会在右侧生成目录大纲（h1–h3），点击条目可直接跳转到对应标题，方便阅读长文。

## 整理笔记

导航区提供“多选”开关：进入选择模式后点击笔记行可勾选多篇笔记，然后通过“移动到…”把全部选中笔记一次移入目标笔记本；也可用 ⇄ 按钮单篇移动，或直接把笔记拖到目标笔记本。

## 与对话双向联动

- 在助手回答下方点击笔记图标，会把上一条问题、完整回答、会话来源和标签整理成结构化
  Markdown，并直接打开新笔记；
- 在笔记编辑器点击“带入对话”，会回到 Chat 并插入稳定的 `zicode-note://` 引用以及
  `notes_get` 调用参数。Pi 会读取笔记的最新版本，不需要把可能很长、很快过期的正文复制
  进输入框。

## 附件

在编辑器中选择“添加附件”，可加入 PNG、JPEG、GIF、WebP、PDF、文本、Markdown、CSV 或 JSON 文件。单个附件最大 5 MiB；可执行文件和 SVG 等活动格式会被拒绝。附件保存在当前 Vault 的 `public/attachments/`，正文中插入可由 Astro 直接使用的 Markdown 链接。删除笔记会先把笔记移入回收站（附件目录一并保留）；只有从回收站“彻底删除”后，附件目录才会被移除。

## 采集网页

选择“采集网址”，指定目标笔记本和公开的 HTTP(S) 页面。ZiCode 不发送 Cookie 或 Authorization 请求头，会拒绝本机和私有网络地址，移除脚本等活动内容，并记录原始网址、采集时间和内容摘要。相同正文再次采集时会返回已有笔记。

### 采集预览与模型摘要

点击“预览”后，可以查看提取出的正文长度，并通过“查看完整内容”展开全文，
确认导航、页眉页脚、广告和侧边栏等干扰内容已被移除。若需要摘要，先在「模型服务」选择
当前场景已配置的兼容渠道与模型，再点击「使用所选模型生成摘要」，生成结构化摘要（一句话摘要、
要点与结论），支持复制或收起。摘要只用于预览，保存的笔记仍保留完整原文。
没有模型服务时仍可预览、保存和编辑笔记；不会自动调用默认服务。摘要需授予 Notes 网络权限。渠道与本地免密服务配置见[翻译](translate.md)。

## Pi 工具

在插件已启用且当前场景授权 `pi.tools.register` 后，Pi 可以搜索、读取或新建笔记。工具只能访问 Notes 托管的 Vault，调用会记录不含正文和凭据的安全审计元数据。

## 导入、备份和恢复

功能区的“数据管理”提供以下操作：

- “导入 Markdown”把普通 Markdown 或含 Frontmatter 的文件复制为新笔记；
- “导出可读备份”生成 `.zicode-notes.json`，包含笔记、来源元数据和附件；
- “导出全部笔记本备份”将当前工作区的全部笔记本汇总为一个 JSON 文件；
- “导入全部笔记本备份”依次创建独立的导入笔记本，不覆盖原笔记本；
- “导入备份”先完整校验版本、ID、文件类型、大小和引用关系，再创建独立的导入 Vault；
- “检查并重建 Vault”从 Markdown 全量扫描并重写 `.zicode/index.json`，报告损坏文件和孤立附件目录，但不会自动删除原文件。
- “回收站”列出已删除的笔记，可单条“恢复”或“彻底删除”，也可“清空回收站”一次移除全部条目。

导入和导出会等待当前笔记保存成功；保存失败或保存期间仍有新输入时，操作停止并保留编辑内容。
同一时间只执行一次导入导出。文件选择或读取期间切换工作区，会停止后续导入步骤；已经发出的请求可能在原工作区完成，不会自动转到新的工作区。
导入期间继续编辑时，会保留当前编辑器，可稍后从列表打开导入的笔记。
导出期间内容变化时，需要保存后重新导出。

“导入全部笔记本备份”会先在隐藏目录中准备整批内容，完成后再发布为独立的新笔记本，并恢复备份中的笔记本层级与图标。单本备份独立导入时不连接原父笔记本。
发布失败会回滚本批目录；进程中断后，下次访问工作区会先恢复未完成的导入。恢复失败时会保留恢复记录并提示检查权限和磁盘空间，请勿删除 `.imports` 恢复目录。
同一工作区被其他进程占用时会提示稍后重试。文件锁会在进程退出时释放，无需删除 `.notes.lock` 文件。
已派发请求超时仍可能完成，重试前应刷新列表确认结果。

## 回收站

删除笔记不是即时的：笔记会移入所在笔记本的回收站，列表显示图标、标题、来源笔记本和删除时间。选择“恢复”会把笔记连同附件放回原笔记本；选择“彻底删除”需再次确认，之后无法恢复。“清空回收站”同样需要确认，会移除当前所有回收站条目。回收站按工作区隔离，不会跨项目泄露内容。

回收站条目保留 30 天：超过保留期的条目会在下次打开回收站时自动彻底删除（如需提前清理，可手动“彻底删除”或“清空回收站”）。导出备份包含回收站条目，删除后立即备份仍可完整恢复。

快捷键：`Ctrl+N` 新建笔记，`Ctrl+Shift+T` 打开回收站，`Ctrl+S` 保存当前笔记。
编辑器工具栏提供 Markdown 格式按钮（加粗/斜体/标题/代码/引用/列表/表格/
链接），并支持快捷键 `Ctrl+B` 加粗、`Ctrl+I` 斜体、`Ctrl+Shift+K` 代码块；
选中逗号分隔的 CSV 数据后点「CSV 转表格」（⇶）可一键转为 Markdown 表格。

## 数据位置

桌面版把 Vault 保存在 ZiCode 数据目录的 `plugin-data/com.zicode.notes/vaults/` 下。Markdown 和附件不依赖私有数据库即可读取。Astro 发布命令、跨设备同步和独立客户端仍在后续阶段。

## 可迁移的笔记链接

编辑器的“复制笔记链接”生成带稳定 ID 的 Markdown 链接，适合同一工作区内跨笔记本引用；粘贴到另一篇笔记后可在预览中打开。
普通 Wiki 链接支持 `[[标题]]` 和 `[[标题|显示文字]]`。标题先查找当前笔记本中的唯一候选，再查找已加载列表中的唯一候选；多条同名结果会提示使用 ID 链接。
标题查找会受到当前列表过滤和加载范围影响。ID 链接直接向 Host 请求目标，目标不存在时显示错误。

导入备份时，普通正文中指向本批笔记的标准 ID 链接会改为导入后的笔记本 ID；单本导入也会处理本本内引用。
未包含在备份中的目标、代码区域、引用块以及带查询/片段等扩展格式保持原样。标题 Wiki 链接仍按标题解析，不会自动改写为 ID。

## 反向链接与关联状态

反向链接从已保存的笔记生成，跳过代码围栏、行内代码、缩进代码和引用块。标题 Wiki 链接仅在当前笔记本有唯一候选，或全库索引内有唯一候选时建立关联；同名歧义不自动选取目标。
关联索引最多处理 200 个笔记本、2000 篇笔记。达到范围上限时会显示不完整提示，停止推断标题唯一性，ID 引用仍可关联索引内已知目标。
保存成功会刷新当前笔记的关联；未保存内容不会立即进入索引。切换笔记会清空旧列表，读取失败时显示错误和“重试”，不会保留上一篇笔记的关系。
相似笔记最多展示 100 对结果；扫描采用保守语法规则，复杂 Markdown 和扩展 URI 仍可能不被识别。

### 操作前的编辑保护

筛选、新建、复制、选择笔记本、进入网页采集，以及删除或移动笔记前，会等待当前笔记保存成功；保存失败时保留编辑内容。新建请求期间继续编辑时，新笔记仍保存，但不会替换当前编辑器。删除和移动期间暂时暂停编辑，结束后恢复。批量操作失败的条目保持选中，可修正问题后重试。聊天内容保存为笔记时，也会保留当前尚未保存的编辑。

### 本地草稿恢复

编辑内容会在短暂延迟后写入当前浏览器/桌面配置的加密恢复存储。切换项目后返回，可在“本地笔记恢复”中打开草稿、另存为新笔记、下载 Markdown 或二次确认丢弃。正常保存成功后会清理对应副本；不同窗口的草稿分别保留。

恢复打开保留原笔记版本，保存时仍检查冲突。遇到冲突可直接另存新笔记，无需覆盖原文。副本优先保存在原笔记本；原笔记本缺失时使用当前选择的笔记本或列表中的第一个笔记本。若没有笔记本，先创建一个，也可先下载草稿。

待写入或存储失败时会显示提示。单份恢复记录上限为 8 MiB（包含原笔记和编辑内容），不会截断内容；失败后仍可在当前进程内切回并下载。损坏条目保留，不妨碍其他草稿读取。此功能不是备份或同步：浏览器清理、地址/端口变化、配置切换、立即关闭窗口或进程崩溃仍可能导致恢复不可用。附件仍引用原笔记的资源，另存或下载不会复制附件文件。

### 附件上传与恢复

附件上传固定在开始操作时的工作区和笔记。选择或读取文件后已离开原笔记的请求会取消；已经发出的上传若稍后完成，其链接会保留在原工作区的“本地笔记恢复”中。返回后点击“插入附件链接”，会追加到原笔记当前正文，不替换已有文字。正文已包含该链接时不会再次追加。

上传时可以继续输入，链接追加到最新内容。界面区分上传后仍待保存与笔记保存成功；保存失败时链接留在编辑器和本地草稿中。单个文件限制为 1 字节至 5 MiB，文件读取失败会停止上传。恢复记录只保存链接和文字，不保存附件文件本身；原笔记被永久删除或附件清理后链接可能失效。

### 采集与摘要的当前页面

修改网页地址会清除旧预览和摘要；刷新预览、切换模型或关闭采集表单后，旧摘要响应不再显示。切换工作区会关闭原采集表单并清理其结果和模型选择。摘要始终使用发起请求时明确选择的模型和工作区。

同一工作区在采集进行中不会重复提交。采集前会等待当前笔记保存；保存失败保留原编辑并显示错误。请求发出后修改地址、标题、标签或目标笔记本，或者打开另一篇笔记，不会让旧结果替换当前页面；已保存的采集结果可从列表打开。

离开页面只停止接收过期结果，不承诺取消已发给 Host 的请求；网页仍可能在原工作区保存，模型请求也可能继续执行。表单地址和临时预览尚不提供跨工作区草稿恢复。

### 工作区快捷入口

最近笔记与置顶笔记按场景和工作区分别保存。快捷入口记录包含笔记本和笔记标识，不持久化标题或正文；切换工作区会立即清空旧列表，再解析新工作区的引用。搜索结果过滤不会限制已记录的快捷入口。读取失败会提示刷新重试，原引用保留。

“恢复旧快捷入口”只导入当前工作区所返回笔记列表中可唯一匹配的旧 ID，旧记录不删除；受列表范围限制，恢复结果可能不完整。可在其他工作区分别恢复。快捷入口最多保留最近 8 条和置顶 16 条。管理菜单支持二次确认清空当前工作区的最近或置顶引用，不删除笔记。旧全局记录仍可能通过显式恢复再次导入。

修改以设备本地事务保存，失败时暂留在当前会话并排队重试；刷新或后续修改会再次尝试。其他窗口的修改在刷新或窗口重新获得焦点时读取。该偏好不随 Host 备份导出，也不跨设备同步。

### 回收站操作范围

恢复、永久删除和清空操作固定在开始时的工作区；切换工作区后，旧操作结果不会修改新列表，尚未派发的批量删除也会停止。同一工作区的回收站写操作串行执行。恢复只刷新列表，不主动关闭当前笔记编辑器。

清空采用二次确认，仅逐项处理确认时显示的条目；部分失败时显示错误并刷新剩余项，可再次确认后重试。新版 Host 会核对条目版本和删除时间，拒绝过期请求。确认状态按完整条目区分，列表变化后需重新确认。永久删除也会移除该笔记的附件。

已有的 Host 自动保留期清理仍可能在读取回收站时发生；它不属于当前清空批次。旧 Host 或不携带版本条件的旧客户端不能提供同样的校验保证。离开页面不等于取消已经派发的请求，外部文件编辑也不受应用锁约束。

### 删除日期与保留期

新删除的笔记使用独立记录的删除时间计算 30 天保留期，正文的修改日期不会缩短保留期。无法确认删除日期的历史条目标记为“保留期开始于”，从首次识别起保留 30 天。元数据损坏或不可读取时会显示错误，不会根据正文日期自动清理该条目。

新备份保留明确记录的删除日期，导入已超过保留期的条目仍可能在下次读取回收站时被清理；旧备份和未知删除日期条目从导入起重新保留 30 天。每次删除及导入都会生成新事件标识，新版界面与 Host 联合检查事件标识、正文版本与时间，避免旧列表误操作再次删除的同一篇笔记。旧客户端未发送事件标识时无法区分同一秒内的相同内容再次删除。

### 构建、检查与聊天交接

“构建 Astro 站点”“检查并重建 Vault”和“在聊天中讨论”会先保存当前笔记；保存失败或保存期间仍有新编辑时停止。构建确认期间切换笔记、笔记本或工作区后，需要重新发起。执行期间按钮显示进度并阻止重复启动；构建和检查完成不会关闭当前编辑器。

Astro 构建仅在桌面应用可用，使用当前笔记本 Vault 和已有本地 Bun 构建链，可能下载依赖，结果位于 Vault 的 dist/；它不自动部署网站。没有可用 Bun 时会失败。切换工作区不会取消已经发出的构建，旧结果不会覆盖新工作区界面。

聊天交接等待切换到聊天视图后再填入；延迟等待期间若工作区、实例、会话或笔记编辑上下文变化，就停止填入。选中文字在保存期间发生变化时需重新选择。原聊天输入保留在交接内容之后，内容仍需手动发送。离开 Notes 时如果保存后仍有未保存编辑，会继续留在 Notes。
