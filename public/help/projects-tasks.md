# 项目、任务与自动化

## 项目知识与聊天草稿

在「知识关联」中，对相似笔记点击「使用上下文包」，或对潜在冲突点击「在聊天中比较」，可准备当前项目会话的聊天草稿。
草稿包含笔记本/笔记 ID、标题、引用链接及当前场景和工作区，不事先读取正文，也不自动发送。
请检查草稿后发送；提示要求模型通过 notes_get 读取引用，说明缺失或不可读内容，并在结论中引用笔记。
标题和正文作为分析材料处理，提示不改变模型权限，也不保证工具读取或比较结论一定成功。

准备时校验当前知识快照，拒绝不属于该快照的引用，去除重复引用；比较至少需要两篇不同笔记。
刷新期间禁用按钮，交接期间知识快照、场景、项目路径、工作区或聊天会话变化时停止写入。
聊天输入框准备好后追加内容，保留原文字和附件；没有当前项目聊天会话时提示先打开会话。
长度保护、写入后的草稿恢复限制与 Git 审查草稿一致。成功提示仅表示引用已进入当前输入框。

## 项目终端

进入终端页后先读取已有会话；读取成功前不能新建。列表刷新失败会保留最近看到的会话并提示可能过期，仍可停止其中已知运行中的会话。启动或停止错误与列表读取错误分别显示。

启动超时、断线或响应无法确认时，启动按钮会保持禁用，直到「刷新终端」成功读取列表。支持启动意图的 Host 随后可对原目录重试同一请求；若终端已创建，Host 返回原会话，不再启动第二个 Shell。旧 Host 仍沿用刷新后检查并新建的流程。刷新不取消 Host 上仍在运行的先前请求；待重试意图仅保留在当前终端页生命周期内。

在项目导航选择「项目终端」，确认「新终端启动目录」后点击「新建终端」。交互 Shell 从当前子项目目录启动，默认工作区根目录。
项目文件侧栏每次显示最多 200 个条目，点击「加载更多文件」继续浏览。若目录在翻页期间变化，刷新文件列表后再继续；超过 100000 个扫描条目或包含无法无损显示的文件名时，请使用系统文件管理器。
双击文件会在系统默认应用中打开；侧栏的「在文件管理器中打开」按钮打开当前目录。Host 会按当前工作区重新解析相对路径，目录已移走或指向工作区外时会报错。
Windows 优先使用标准安装位置的 PowerShell 7，其次查找 PATH 中绝对目录下的 `pwsh.exe`，均不可用时回退系统 Windows PowerShell；两者均不加载用户 Profile。macOS/Linux 使用宿主 SHELL，
路径缺失或不可执行时使用 `/bin/sh`；若宿主 SHELL 是 PowerShell 7，则使用无 Profile 参数启动。其他未识别 Shell 不附加假定其支持的 `-i` 参数。终端按宿主账号权限运行，可修改文件、启动进程和访问网络。

- 每个项目最多 2 个活动终端，整个 Host 最多 8 个。点击会话按钮切换终端。
- 支持键盘输入、粘贴、ANSI 输出和窗口尺寸同步；单次输入队列最多 64 KiB，过大的粘贴会拒绝。
- 离开页面不停止 Shell；返回可重新连接。断线后不重发输入，请先检查显示结果再继续操作。
- 点击「停止终端」结束当前终端及其受管理进程；宿主退出时也会回收。Unix 上主动脱离会话的守护进程不属于终端的回收范围。
- 输出仅在 Host 内存保留最近 256 KiB，每次读取最多 32 KiB；最多保留 16 个会话（包括已退出会话）。
  超出缓存时会提示，恢复的末尾片段不保证完整重建全屏程序画面，可请求程序重绘。
- Shell 命令与终端输出不写入应用历史库。Shell 或所运行程序本身可能维护自己的历史文件。
- 此入口仅供桌面端使用，远程端不开放终端读取或控制。终端不会自动打开输出中的链接或写入系统剪贴板。

## 项目命令

所选目录有 `deno.json` 或 `deno.jsonc` 时，会显示固定的 `deno fmt --check`、`deno lint` 和 `deno test` 命令；此类目录也会进入子项目目录发现。配置文件中有效的 `tasks` 字符串、含 `command` 的对象，以及仅有非空 `dependencies` 数组的对象会列出；预览同时显示直接依赖和命令正文，点击后通过 `deno task <名称>` 执行。Deno 会并行运行直接依赖，依赖还可能递归触发其他任务，请运行前检查相关声明。两种文件同时存在时，任务声明以 `deno.json` 为准。只接受 JSONC 的注释与尾随逗号，不接受 JSON5 扩展语法；名称不符合运行器安全字符范围的任务可见但不可运行。命令仅在点击运行后执行，使用项目工具目录或有效 PATH 中的 Deno CLI；应用不会自动安装 Deno。
工作区根目录 Deno 配置中的 `workspace` 路径数组也会加入子项目发现，支持受现有界限保护的 `packages/*`、`packages/**` 等模式。成员需有受支持的项目清单或 Deno 配置；明确写出的成员目录无清单、路径越界、目录链接或超限时会标为发现不完整。这里只发现目录，不推断 Deno 工作区的依赖关系或自动运行任务。

含有效 `pyproject.toml` 且存在普通文件 `uv.lock`、`[tool.uv]` 配置，或被工作区根目录 `[tool.uv.workspace]` 的 `members` 明确列入且未被 `exclude` 排除的目录，会显示固定的 uv 锁定、同步、unittest、pytest 和构建命令。成员目录会识别根目录 `uv.lock`；已有适用锁文件时同步使用 `uv sync --locked`。测试使用 `uv run --no-sync`，请先主动同步环境。uv 使用自己的项目环境，不继承项目工具页另选的 Python venv/Conda；项目工具目录中的 uv 可执行文件仍优先使用。锁定、同步和构建可能下载依赖或写入项目文件，只有你点击对应命令后才执行。

首次成功读取运行列表前不能启动命令。读取失败保留最后已知记录并提示可能过期，恢复成功后才可启动；
仍可停止已知活动运行。命令操作、清单读取和运行列表错误分别显示，不会互相覆盖。
启动超时、断线或回复无法确认时，新启动会被禁用。请点击「刷新任务列表」，成功读取后先查看运行记录再决定是否启动；
自动轮询或操作后的自动对账不会解除这项限制。刷新不取消已经发出的请求，Host 上的启动仍可能稍后完成。
该未确认标记仅保留在当前运行器视图的控制器生命周期内；重新进入仍需先读取列表，但不保存该标记。

运行结果默认跟随最新记录。展开「命令运行历史」并选择一条，可固定查看该记录的详情和 Host 仍保留的输出；
点击「跟随最新运行」恢复自动跟随。清理或保留上限使所选记录消失时会明确提示，不会静默显示另一条。
列表刷新后会继续更新同一运行 ID 的状态；跨 Host 会话保存的记录只有摘要，无法恢复命令全文与输出。
命令页可主动下载当前已读取的运行摘要 JSON，包含项目名、快照接收时间、历史保存状态及最多 40 条运行元数据。文件为明文，不包含命令正文、调用参数或输出；项目名、任务名和目录仍可能包含私有信息，分享前请检查。下载文件是留存记录，不会导入新设备的运行历史，也不代表运行状态已实时更新。

在显示的记录下点击「在聊天中分析运行」，可把该次运行快照加入当前项目聊天草稿，由你检查后发送。
材料包含运行 ID、目录、状态、时间、退出码和可用输出，并标明截断、可能过期或仅有保存摘要。
收到运行列表的前端时间不是进程状态的实时证明；交接期间不会重新读取日志或等待命令结束。
运行中、停止中和结果未知都不能当作最终结果，历史摘要缺失输出也不等于“没有错误日志”。
此动作不自动重跑、停止、安装工具或修改文件；提示是可编辑文字，不改变模型权限。
与其他项目聊天交接相同，它保留原草稿与附件，切换项目或会话时停止写入，最终由用户发送。

选择「命令目录」可运行工作区根目录或子项目中的命令，例如 `frontend/`、`services/api/`、
`src-tauri/`。普通扫描覆盖四层子目录、最多 2048 个目录项，并补充支持的根清单声明目录（详见下方「子项目环境诊断」），合计最多列出 64 个目录；跳过隐藏目录、
依赖和构建输出以及目录链接。扫描不完整时会提示，更深的项目可单独打开为工作区。
这不是 monorepo 依赖图解析；包管理器可按下述规则继承明确声明的祖先工作区，`.venv` 仍按所选目录解析，不继承其他父级设置。
切换目录不停止已有任务，输出和历史仍覆盖整个工作区，并标注每次运行的命令目录。

所选目录存在 pyproject.toml 或 requirements.txt 时，还提供 `python -m unittest discover`、
`python -m pytest`、`python -m build`。列表显示选择的解释器：优先使用当前目录内标准 `.venv`，随后检查 `.conda` 中的 Conda prefix；两者均不存在时才按工具目录和宿主路径选择 Python。
在开发环境页显式选择已有 venv 或 Conda 环境时，该选择优先于自动发现，允许使用项目外的环境。
自动发现的 `.venv` 或 `.conda` 损坏、缺少所需标记或目录指向项目外时会禁用 Python 命令，修复后刷新；
应用不会静默回退，也不会创建环境或安装 pytest/build。Unix 解释器文件可链接到系统 Python。
当前自动选择会从所选命令目录向上到工作区根目录查找 `.venv`、`.conda`；其他 Conda 环境可从用户级来源按需发现，Poetry 环境可通过用户主动执行的项目命令查询。也可显式选择现有 Conda prefix 或符合标准 venv 布局的 Poetry 环境。
环境诊断不验证已安装依赖；运行结果会记录实际解释器路径。

有效的 `pyproject.toml` 若包含 `[tool.poetry]` 或 Poetry 构建后端，还提供固定的
`poetry env info --path`、`poetry env list --full-path`、`poetry check`、`poetry run python -m unittest discover`、`poetry run python -m pytest` 和
`poetry build`。它们明确通过 Poetry CLI 运行，使用 Poetry 自己选择的环境；项目页显式选择的
Python 解释器只用于普通 `python -m` 命令，不覆盖 Poetry 的环境选择。运行器不自动安装 Poetry，
也不自动查询 Poetry 的外部虚拟环境。`poetry env info --path` 查询所选环境路径，`poetry env list --full-path` 列出此项目环境；两者只在用户主动运行时执行。
Poetry 可能加载已安装插件。其他命令可能创建环境、运行项目代码或写入构建产物。
如需将 Poetry 选中的环境用于普通 Python 命令和新终端，先在当前子目录主动运行 `poetry env info --path`，再到「开发环境」点击「使用最近发现的 Poetry 环境」，检查填入的路径并保存。只有同一子目录的最近一次查询成功、当前 Host 会话仍保留完整输出且任务清单未变化时才会填入草稿；失败或配置变化后不会使用更早的路径。重启后任务摘要不含输出，需重新运行查询。保存时 Host 会校验标准 venv 或 Conda prefix 布局。

如需选择另一个 Poetry 环境，在当前子目录的项目命令中主动运行 `poetry env list --full-path`，再到「开发环境」点击「读取最近的 Poetry 环境列表」。仅同一子目录最新成功且完整、任务清单未变化的结果可供选择；失败后不回退旧列表。选择后先填入草稿，保存时再由 Host 校验。Host 重启后需重新运行查询。

同一目录可同时发现 JavaScript、Rust、Go 和 CMake 命令。所选目录存在 Cargo.toml 时提供
`cargo check`、`cargo test`、`cargo build`；存在 go.mod 时提供 `go test ./...`、
`go build ./...`、`go vet ./...`。列表标注来源清单，点击后使用已安装的 Cargo/Go 执行。
这些操作可能执行构建脚本、测试、写入输出或下载依赖。清单存在不表示格式和依赖已验证，
工具的真实错误会显示在输出区。

当前目录存在 `GNUmakefile`、`makefile` 或 `Makefile` 时，命令列表还会提供 `make` 默认目标，按 GNU Make 的文件优先级选择来源。只读取最多 256 KiB 文件以生成任务指纹，不解析或预览规则；文件不可读、越界或过大时仅禁用这项任务，不隐藏其他项目命令。点击运行后才调用项目工具目录或有效 PATH 中的 `make`。Windows 需自行安装可用的 Make。默认目标可能执行构建、测试或其他项目自定义动作，运行前请查看 Makefile。

根目录有 `go.work` 时，常见的 `use ./模块`、`use "./带空格的模块"` 和 `use (...)` 声明会补充发现工作区内的
Go 模块，即使模块深于普通四层扫描。每个有效模块在根目录命令列表中有独立的
`go -C 模块 test ./...`、`build ./...`、`vet ./...`，不会把工作区根目录直接当作一个 Go 模块。
路径必须是工作区内的字面相对目录，且含有效 `go.mod`；带引号的路径仅支持无转义的普通双引号写法。
指向外部、链接目录、含转义或复杂注释的声明不会生成命令，目录扫描会标记不完整。Go 1.20 及以上支持 `-C`。

Java 项目目录存在 `pom.xml` 时提供 `mvn validate`、`mvn test`、`mvn package`；
存在 `build.gradle`、`build.gradle.kts`、`settings.gradle` 或 `settings.gradle.kts` 时提供
`gradle tasks`、`gradle test`、`gradle build`。同类 Groovy/Kotlin 构建文件或设置文件同时存在时先提示冲突。
Windows 优先使用当前目录的 `mvnw.cmd`、`gradlew.bat`，macOS/Linux 优先使用 `mvnw`、`gradlew`；
没有对应 wrapper 才使用项目工具目录或宿主的 Maven/Gradle。发现到损坏、链接或不可执行的 wrapper 时不会改用系统工具。
目录指纹包含根构建文件、设置文件、`gradle.properties`、wrapper 脚本以及存在时的 wrapper properties；
不追踪 wrapper JAR、插件与依赖图。wrapper 和构建脚本可执行项目代码、下载工具与依赖、修改文件，请先查看其内容。
任务名称是固定的；Gradle 项目未定义 `test` 或 `build` 时，工具错误会显示在运行输出中。

当前目录中的 `.sln`、`.slnx`、`.csproj`、`.fsproj`、`.vbproj` 会作为独立 .NET 目标列出。
每个目标都有固定的 `dotnet restore`、`dotnet build`、`dotnet test`，项目文件还提供 `dotnet publish`；
目标路径作为单独参数传给 dotnet，避免多个解决方案或项目文件时选择不明确。单目录最多扫描 2048 个条目、发现 16 个目标，目标清单单文件上限 256 KiB。
任务指纹包含目标文件内容，以及所选目录到工作区根目录之间最近的 `global.json`；不解析导入的 MSBuild 文件、NuGet 配置或依赖图。注册工作区之外的祖先 `global.json` 不读取，修改其他配置后请自行刷新并检查结果。
还原、构建、测试和发布均可能运行项目自定义目标、下载包或写入文件；运行前查看项目清单。
Windows 若将 dotnet 配置为 `.cmd`/`.bat` 包装器，包含空格或批处理元字符的目标名会被拒绝；使用 dotnet EXE 可保留这类文件名。
环境页显示最近 `global.json` 的 `sdk.version` 及其相对工作区的位置；有 .NET 目标或 SDK 清单时，还在所选项目目录执行有超时与输出上限的 `dotnet --version`，单独显示实际解析出的 SDK 或失败状态，不运行构建目标。宿主 dotnet 版本检查仍在项目外运行。界面不模拟 `rollForward`、预发布选择或已安装 SDK 集合，也不把版本数字直接判为符合策略。

存在 `CMakeLists.txt` 时提供 `cmake -S . -B build/zicode-studio`、
`cmake --build build/zicode-studio` 和 `ctest --test-dir build/zicode-studio --output-on-failure`。
请先配置，再构建或测试；需预先安装 CMake 与 CTest，测试命令需要支持 `--test-dir` 的 CTest。
构建输出固定放在项目内 `build/zicode-studio`；该目录或其父级 `build` 是文件、链接或重解析点时拒绝启动，避免写到项目外。
配置会执行项目的 CMake 代码，可能运行外部命令、下载依赖或生成文件；请先查看项目清单。
任务目录指纹包含所选目录的根 `CMakeLists.txt`，不解析它引用的其他 CMake 文件；修改引用文件后仍需自行判断是否重新配置。

项目根目录存在 `CMakePresets.json` 时，还会列出其中的配置、构建和测试预设，分别以
`cmake --preset "名称"`、`cmake --build --preset "名称"`、`ctest --preset "名称"` 执行。
隐藏预设和字面值为 `false` 的条件不会列出；其他条件、继承、包含文件及用户预设由 CMake 在运行时判定。
列表只读取项目根预设，不发现仅定义在包含文件或 `CMakeUserPresets.json` 中的预设。
预设可以指定项目外的输出目录，也可以执行外部命令；运行前请检查项目和用户预设。
任务指纹包含根 `CMakePresets.json` 和存在时的 `CMakeUserPresets.json`，不追踪包含文件；
修改包含文件后应重新检查预设与输出位置。预设任务不受固定命令的 `build/zicode-studio` 目录保护。
Windows 下如果 CMake/CTest 来自 `.cmd` 包装器，只允许字母、数字、`_`、`:`、`-`、`.`、`/` 组成的预设名通过；其他名称需改用 `.exe` 工具或重命名预设，避免批处理解释参数。

在项目页选择「项目命令」，查看所选目录 package.json 的 scripts。包管理器优先取
packageManager 声明，否则使用当前目录的锁文件或有效 pnpm 工作区文件；没有本地依据时检查明确声明当前包的祖先工作区，最终回退 npm。
桌面端点击「运行项目命令」后使用对应的已安装工具执行；应用不预先安装工具或依赖，
也不保证满足声明的版本要求。查看完整脚本后再运行，包管理器可能同时执行 pre/post 钩子。

命令按来源文件分组，可按名称、命令文本、来源文件或工具名称在当前列表内筛选；计数显示筛选结果与总数。点击「置顶」可将常用命令保存在此设备的当前工作区与子项目目录下；置顶来源组及组内命令会排在前面，「只看置顶命令」可快速缩小列表。每个目录最多保存 32 个置顶命令，最多保留 64 个最近保存过的目录范围；清除本机应用存储会移除这些选择。清单暂时缺少的命令不会显示，但保留其置顶 ID，重新出现后仍可使用。筛选和置顶仅改变界面呈现，不修改任务 ID、Host 目录指纹或正在运行的命令。切换工作区或子项目目录会清空筛选，但保留各自的置顶选择。
展开「迁移置顶命令」可下载当前目录的置顶标识 JSON，或选择文件预览来源项目、目录与匹配数量，确认后合并到当前项目目录。未知标识会保留以待重新发现；合并后仍受每目录 32 项上限约束。文件为明文，标识可能包含任务名称，请私有保管。导入不会运行命令，也不会覆盖项目清单。

每工作区（包含所有子目录）最多一个活动命令，宿主总计最多四个。离开项目页或切换项目后命令继续运行，
可返回点击「停止项目命令」清理任务及子进程；桌面宿主退出时也会清理。此处没有交互式输入。
脚本按你的宿主账号权限运行，可以访问开发环境和网络，并非文件系统沙箱。

输出区展示最近一次运行的标准输出、错误输出和退出码，每路仅保留最近 64 KiB。
运行摘要保存在本机，每个项目最多 40 条，合计最多 500 条；按项目目录和工作区 ID 隔离。
保存任务名、目录、工具类别、清单指纹、状态、时间和退出码，重启后仍可查看。
命令正文、调用参数、实际工具路径和输出仅保留在本次宿主会话内，内存保留最近 40 次运行。
没有最终结果的历史显示「任务状态未确认」，可能属于另一宿主会话，不提供停止按钮。
历史存储不可用或不完整时会提示，命令仍可运行；已有缓存可能过时。清单变更会要求刷新。

桌面端「清除命令历史」经确认后清理当前项目的已保存及已完成记录，保留当前宿主活动任务。
清理失败保留记录；另一宿主中的活动任务结束时可能重新写入摘要。项目注销不自动清除此独立历史，
如需移除请先在项目中清理。远程端可查看状态与输出，启动、停止和清理请在桌面端进行。

项目负责聚合目标，任务负责记录执行状态，自动化负责按规则触发重复工作。三者配合可以把一次聊天升级为可持续的工作流。

## 什么时候创建项目

项目总览的任务和自动化数量仅统计明确关联到当前项目的条目；点击数量或导航中的
「项目工作」可查看列表，并点击条目打开对应任务或自动化。任务中心会清除旧搜索与日期筛选，
自动化中心会显示所选流程，并提供「显示全部自动化」返回完整列表。

在「项目工作」中点击「为此项目新建任务」或「为此项目新建自动化」，会打开对应表单并带入
点击时的项目目录。目录仍可编辑，打开表单本身不会创建或执行工作；填写内容、调度与执行模式后
点击创建。新建另一个项目的工作会重新初始化表单，请先完成当前输入。
取消不保存本次修改；任务创建失败会保留输入以便重试，保存进行中不可取消。
手动任务是否立即派发、定时自动化何时执行，仍由表单所选执行模式与调度决定。

归属依据为条目的目标项目路径；任务没有目标路径时，可使用已记录的执行工作区标识。
不会按目录前缀、项目名称或相对路径猜测。未关联条目和已归档任务仍可在全局任务中心查看，
已归档任务不计入项目数量。每类列表先展示 20 项，可在项目页分批展开当前已加载的关联条目；全局中心仍可查看和管理所有项目的工作。
读取失败时数量显示「—」，列表保留同项目上次成功数据并提示；点击项目顶部「刷新」重试。
切换项目会清除原项目数据，不把迟到结果混入新项目。

### 保存任务草稿

任务表单填写标题后可点击「保存草稿」，将说明、目标项目、计划和执行模式保存到当前工作区。
在任务中心「草稿」筛选或关联项目列表中找到任务，点击「编辑」继续填写；可再次保存草稿或「删除草稿」。
草稿不会自动派发或定时执行。点击「启用任务」后，手动任务按所选执行模式进入待运行，
定时任务从启用时计算下一次运行时间；启用保留原任务标识和草稿记录。
保存或启用冲突时输入保留，请刷新后检查最新状态再重试。

草稿需要显式保存；取消、新建其他项目的工作或关闭应用前未保存的文字不会恢复。
已保存草稿随工作区任务文件保留，不能用本轮结果推断自动化规则也支持草稿。


项目总览的「Git 工作区」显示分支、暂存与未暂存改动、冲突和未跟踪条目。
可单独刷新 Git 状态，也可使用项目顶部的刷新。列表仅显示当前项目目录内的改动，
最多展示 200 项；未跟踪目录按一项统计，子模块内部改动不在检查范围。
领先/落后基于本地上游引用，不会自动拉取远程数据。读取失败时会显示恢复提示，
不会误报为“没有改动”。可对列表中支持的单个文件点「暂存文件」，确认后将执行时的
工作树内容加入暂存区，并重新读取 Git 状态。Git 可能运行仓库配置的 clean filter。
有已暂存改动的文件也可点「取消暂存文件」，确认后仅重置该文件的暂存区状态，保留工作树内容；
这会移除该文件全部已暂存改动，包括部分暂存的内容。未跟踪目录的聚合条目、无法无损表示的
文件路径及列表之外的条目不提供相应按钮；如状态已变化，需刷新后重新确认。结果不确定时
先刷新状态，不自动重试。暂不在面板中执行提交、回退或推送。

「查看未暂存差异」比较工作树与暂存区，「查看已暂存差异」比较暂存区与 HEAD。
点击同一比较按钮可重新读取，点击「关闭差异」收起。差异为可选择、复制和键盘滚动的只读
文本，未跟踪文件不包含在内。预览最多 2000 行、256 KiB，完整输出超过 2 MiB 时提示
使用 Git 客户端；截断结果不代表完整改动。切换项目、刷新状态、暂存或取消暂存文件会收起旧差异。

项目总览的「最近提交」按需展开，每页读取 HEAD 历史中影响已注册项目目录的最多 50 次提交，
按 Git 默认日期顺序展示。展开条目可查看完整对象 ID、作者、作者时间与提交说明，支持选择复制。
「刷新提交历史」或项目刷新会重新读取；切换项目会收起。分支尚无提交、此目录没有相关提交和读取失败分别提示。
「更早的提交」与「较新的提交」沿用首次读取的 HEAD 对象 ID，之后的提交需刷新才能看到；刷新返回第一页。
较旧 Host 没有提供分页游标时仍可查看最近历史，使用 Git 客户端查看更早记录。
作者时间按本机时区显示，不是提交入库时间。
仅查看当前 HEAD 可达且符合目录筛选的历史，不覆盖其他分支、reflog 或跨重命名追踪，合并记录遵循 Git 默认历史简化。
最多读取 51 条用于判断是否还有更早记录，显示 50 条；每条作者最多 200 字符、说明最多 16384 字符，截断时明确标注。
Git 输出超过 2 MiB 或读取超时会报错；浅克隆和局部克隆的本地记录可能不完整，缺少对象时不应把失败视为空历史。
不执行签名验证、外部差异驱动、自动 AI 发送或仓库写操作。

展开历史条目后，点击「查看提交改动」读取该提交在项目目录内的差异；同一时间只展开一份。
普通提交与父提交比较，合并提交仅与第一父提交比较，并显示基准对象 ID；真正的根提交与空树比较。
先读取原始提交对象中的父引用，浅克隆边界缺少父对象时提示失败，不会误报为根提交。
重命名按删除和新增展示；二进制内容与子模块改动不展开。预览最多 2000 行、256 KiB，原始对象或差异输出
超过 2 MiB 时拒绝读取；部分显示明确标注截断，不能据此认定改动已完整审查。
关闭条目、关闭差异、刷新历史或切换项目后不接收旧差异结果；错误可用「重试」重新读取。
此功能不执行 checkout、暂存、回退或应用补丁。缺少对象时请先在自己的 Git 客户端处理，再重试。

差异读取成功且有内容后，可点击「在聊天中准备审查」。应用把当前显示的差异、提交 ID、父提交、
父数量和截断标记加入当前项目会话的聊天输入框，保留原草稿文字与附件；请检查后自行发送。
仅携带此预览，不自动读取额外文件、补齐截断内容、创建会话或发送模型请求。审查提示要求指出证据与
不确定性，不执行命令或修改文件；提示是可编辑文字，不是模型工具权限设置。
交接期间更换场景、项目、实例或会话会停止写入，并提示返回项目重试。聊天输入框不可用时也明确报错。
合并草稿按输入框自身长度上限及最多 1048576 个 UTF-16 单元检查，超限保持原文字不变，不静默截断。
成功提示只表示内容已加入当前输入框；跨重启恢复仍取决于现有草稿存储，未证明模型能接收该长度。

提交前也可在「查看已暂存差异」或「查看未暂存差异」读取非空预览后，点击「在聊天中准备审查」。
已暂存内容按暂存区对 HEAD 比较，未暂存内容按工作树对暂存区比较；均不包含未跟踪文件。
草稿携带比较类型、预览接收时间与截断状态。接收时间取自前端时钟，既不是提交时间，也不证明读取期间
仓库未发生变化。文件、暂存区或 HEAD 已变动时，可再次点击相应比较按钮刷新后再交接。
交接只使用屏幕上的预览，不重新读取、自动暂存或将已暂存与未暂存差异混合；历史提交仍携带其对象 ID 与父提交。
读取失败、刷新中或空差异时不提供交接按钮；改变项目、比较方式或读取连接后旧预览立即隐藏。

当工作包含多个会话、多个阶段或多个交付物时创建项目。项目可集中展示关联会话、任务进度、产物和最近活动。

- 在「项目」应用顶部点「管理项目」（或顶栏工作区切换器）可以查看全部
  项目（工作区）并切换；「打开文件夹作为工作区」就是新建项目——选定
  一个文件夹后，它会成为新的项目工作区。
- 「项目上下文」里可以编辑当前项目的说明（项目指令，会自动注入该项目
  的对话）和预算；「知识关联」「项目搜索」「最近活动」分别展示与当前
  项目绑定的内容。
  未保存的上下文会在当前窗口切换最近项目时暂存，切回后仍需点击保存；
  窗口内最多保留 32 个项目作用域。编辑时还会尝试写入本机加密恢复副本；关闭窗口或

  写入未完成时不要关闭窗口。不同窗口的副本独立保留，不会自动覆盖已保存配置。

  无法读取的副本会计数；可识别的损坏副本可在确认后清理。达到上限时，新副本不会写入，页面会提示先清理旧副本。
  可读取的副本还可手动下载为 JSON，保留项目名、采集时间、草稿及其基准版本，便于在清理前审阅和另存。
  下载文件为明文，不包含浏览器内部作用域或副本 ID；请自行保管。下载不会自动把草稿保存到项目配置。
  可在目标项目的「本机项目上下文恢复」中选择 JSON 文件导入。应用会检查文件大小与格式，显示来源项目和目标项目，确认后新增一条加密恢复副本；不会直接覆盖编辑器或项目配置。需要应用内容时再点击「恢复此副本」，检查合并结果后保存。
  导入确认前可查看文件中的项目说明、默认场景与预算；恢复列表中的副本预览也显示这三项，请检查后再恢复。
  即使没有未保存草稿，也可在此下载当前已保存项目上下文的 JSON。导入该文件时，应用会以目标项目确认时已读取的保存版本为比较基准，先新增恢复副本；后续恢复会应用文件中的字段，并对其间发生的冲突要求逐项选择。下载和导入均不直接改写项目配置；文件为明文，请私有保管。
  若确认后切换项目，已开始的导入仍写入确认时的目标项目；返回该项目并刷新列表即可查看结果。
- 删除项目会「进回收站」：工作区切换器的项目菜单里点删除，该项目的
  ZiCode 应用数据（`.zicode` 目录）会整体移入
  `%LOCALAPPDATA%\zicode\trash\`，并从项目列表移除注册；工作区切换器
  底部会出现「回收站」，可一键把项目恢复回原文件夹。你的项目文件
  （源码、文档等）绝不会被删除。全局共享工作区与智能收件箱工作区受
  保护，不能删除。

## 项目工具目录

桌面端在「开发环境」页填写工具所在目录的绝对路径，每行一个，最多 8 个。顺序决定搜索优先级。
保存后，新命令、新建终端及环境诊断会优先使用这些目录，再使用 Host 默认工具。配置只保存在本机，
按项目隔离，不写进仓库、不修改系统 PATH，也不安装工具。只添加其中程序可信的目录；诊断会调用所选工具查询版本。

工具目录列表清空并保存即可移除额外工具目录；Python 环境需单独切回自动模式。保存后刷新命令列表再启动；已有任务和终端保持启动时的环境。
目录被移动或删除后会明确报错，请在此页修复路径或清空保存；仍可停止原有任务和终端。
多窗口冲突保留当前草稿，需要重新加载已保存配置再编辑。保存结果不确定时不会自动重试。

Python 提供「自动选择」和「使用已有 Python 环境」两种模式。自动模式依次使用所选命令目录内的 `.venv`、`.conda`，再按工具目录与宿主路径选择解释器。显式 venv 或 Conda 环境优先于各命令目录的自动发现结果，适用于项目及其子目录命令。

已有标准 venv 的目录包含 `pyvenv.cfg`，Windows 解释器为 `Scripts/python.exe`，macOS/Linux 为 `bin/python`。已有 Conda prefix 包含 `conda-meta/history`，Windows 解释器为 prefix 下的 `python.exe`，macOS/Linux 为 `bin/python`。选择环境目录的绝对路径，不输入解释器文件。不能混用两种标记。保存时校验目录、解释器及路径是否有效，不创建环境或安装包；保存成功后刷新诊断并执行显式选中的解释器查询版本。

「查找本机 Conda 环境」读取 `~/.conda/environments.txt`、`~/.conda/envs`、当前 Host 的 `CONDA_PREFIX` 和 `CONDA_ENVS_PATH`，不运行 Conda 或 Python；仅列出仍具有标准 Conda 目录结构和解释器的环境，并标出来源。点击环境会填入草稿，保存后才会校验并应用。来源均不存在、无法完整读取、没有可用环境或达到来源/条目上限时会分别提示，仍可手动输入绝对路径。登记文件和用户目录各最多检查 256 项；配置目录最多 16 个、合计最多检查 256 项。

新命令和终端优先使用所选环境的路径。venv 设置 `VIRTUAL_ENV`；Conda 设置 `CONDA_PREFIX`，Windows 还按 prefix、Library/mingw-w64/bin、Library/usr/bin、Library/bin、Scripts、bin 的顺序加入现有目录。切换时清除继承的旧 Python/Conda 激活变量，不运行 `conda activate` 或 activate.d，也不加载 `conda env config vars` 保存的变量。依赖激活脚本的环境需在终端自行完成激活。已有进程保持启动时的环境；终端提示只表示启动选择，不跟踪 Shell 后续手动切换。自动模式的新终端使用所选启动目录的 `.venv` 或 `.conda`（`.venv` 优先）；损坏或指向项目外的本地环境会阻止启动，不回退宿主 Python。Shell 内切换目录不会改变启动时选中的环境。Pi 与 Git 面板沿用自身运行配置。当前只自动发现所选目录内的 `.conda`，不枚举其他 Conda/Poetry 环境或验证已安装依赖。

## 开发环境

环境检查完成后可主动下载当前报告的 JSON 快照，用于比较不同电脑上的工具版本与清单要求。文件包含平台、架构、检查时间、工具状态和版本、清单要求及包管理器选择；不包含项目 ID、所选目录名、清单文件名或可执行文件绝对路径。报告为明文，版本声明仍可能包含私有信息，请分享前检查；下载不重新检查环境，也不安装或运行项目工具。
选择此前下载的环境报告 JSON 后，页面会比较当前与导入快照的工具状态、版本和来源，以及清单类别和静态要求的数量差异；还会显示目录范围、内嵌 Pi 或包管理器选择的差异。清单文件名不会导出，因此声明比较不区分同类别中的具体文件；超过 24 项的差异会显示剩余数量。导入文件最多约 1 MiB，只在当前视图读取；切换项目、目录或重新检查后需要重新选择。快照不含项目身份，不能证明两份报告来自同一项目，也不能证明导入机器的当前状态。

Deno CLI 也会随其他开发工具一起诊断，并显示其路径、版本和可用状态；环境清单视图对项目根目录的 `deno.json`、`deno.jsonc` 只检测是否存在，任务列表另行读取配置。
有 Deno 配置的目录会把 Deno CLI 放在项目工具组。`.tool-versions` 或 mise 的 `deno` 单一完整数字版本可与本次探测到的 Deno CLI 精确比较；动态版本及多个候选仍需在终端核对，比较不证明版本管理器的实际选择。

在项目导航选择「开发环境」，检查项目工具目录与启动 ZiCode 时环境中的 Git、Node、Bun、Python、Cargo、rustc、Go、CMake、CTest、Java、Maven、Gradle、Poetry 和 dotnet，并检查 npm、pnpm、Yarn。报告显示工具路径、版本、缺失、失败或超时状态，
以及系统平台、架构和 Pi 锁定版本。Bun 与项目命令运行器使用相同的工具选择规则。
新增工具后可能需要重启 ZiCode 才能更新 PATH；Pi 锁定版本不代表已经验证运行健康。

项目根目录识别 `package.json`、`.nvmrc`、`.node-version`、`Cargo.toml`、`pyproject.toml`、`requirements.txt`、
`go.mod`、`CMakeLists.txt`、`CMakePresets.json`、`CMakeUserPresets.json`、`pom.xml` 与 Gradle 构建/设置文件；当前目录中的 .NET 解决方案和项目文件也会列出。JavaScript 清单展示 engines 和 packageManager 声明。预设清单只显示存在状态，不展示用户预设内容。Java/Maven/Gradle 版本诊断只检查工具目录或宿主工具，不执行项目 wrapper。
对 Node、Bun、npm、pnpm、Yarn，版本要求按 npm semver 规则显示满足、不满足或无法判断。
支持区间、`^`、`~`、通配符和预发布版本规则；packageManager 按精确版本比较。
`.nvmrc` 和 `.node-version` 按所选目录读取第一条非注释版本声明；两者声明不同时显示冲突，不推断哪份生效。数字版本按 semver 比较，`node`、`lts/*` 等动态别名需要在系统终端用版本管理器确认；诊断不会自动切换 Node。
工具缺失、探测失败、无效版本或截断声明不会被判为满足。出现不匹配时，请切换或安装合适版本，
重启 ZiCode 后重新检查。诊断不会自动安装工具或运行项目脚本，并禁用 Corepack 网络下载。
此比较不验证 packageManager 的完整性哈希、完整依赖或项目虚拟环境，也不构成项目可构建的保证。
Rust 读取 `Cargo.toml` 的 `package.rust-version` 最低版本要求，并比较宿主 `rustc`，而非 Cargo 版本。
同一清单内显式继承的 `workspace.package.rust-version` 可解析；父目录继承需要在系统终端确认，
虚拟工作区的默认值不会自动套用到全部成员。`rust-toolchain.toml` 或 `rust-toolchain` 中的完整数字版本
按固定版本比较；stable、beta、nightly、日期/目标平台别名和部分版本需要单独确认。
两个工具链文件同时存在时会显示冲突。

Go 读取 `go.mod` 的 `go` 最低版本和 `toolchain` 推荐工具链，分别显示比较结果。
推荐版本未达到不代表最低版本失败；`toolchain default` 和开发构建无法据此确认。
环境检查在临时目录探测项目工具目录与宿主默认工具，禁止自动安装，不解析项目 rustup 覆盖或切换 Go 工具链。
Python 读取 `pyproject.toml` 的静态 `project.requires-python`，按 PEP 440 比较已经查询版本的所选 Python。
支持范围、排除版本、通配符和 `~=` 兼容声明；空字符串表示没有版本限制。已安装的预发布解释器
参与范围比较，这不保证依赖安装器会选择相同版本。动态声明和仅使用 Poetry 专用语法的声明需另行确认。
诊断与所选目录的命令共享选择规则：工作区显式环境优先，其次所选目录 `.venv`、`.conda`、项目工具目录、宿主 Python。界面显示来源和解释器路径。自动发现的 `.venv` 或 `.conda` 不执行版本查询，状态为“尚未检查版本”，版本要求也不会被宿主版本判为满足；要查询它的版本，请在“Python 环境（venv 或 Conda）”中显式选择此环境目录。损坏或越界的 `.venv`、`.conda` 不回退宿主环境。子项目命令按命令目录选择 `.venv` 或 `.conda`；诊断仅覆盖当前选择的目录。`requirements.txt` 是依赖清单，不能推断 Python 版本范围。
CMake 清单只检测存在，不解析最低 CMake 版本或依赖图；运行器提供固定配置、构建与测试命令，但不强制版本要求。
清单内容读取上限为 256 KiB，越界链接、格式错误及超限会显示提示。

选择「重新检查环境」可刷新。检查不执行项目脚本，也不自动安装或修复工具。

## 任务状态

| 状态 | 含义 | 可用操作 |
|---|---|---|
| 定时 | 按计划重复运行的模板，等待下次触发 | 编辑、暂停定时、删除 |
| 待运行 | 已创建或已批准，等待派发 | 批准并运行、取消 |
| 运行中 | Agent 正在执行 | 暂停、取消 |
| 已暂停 | 保留现场但不继续 | 恢复、取消 |
| 需要输入 | 代理执行中提问，等你回答 | 直接回复、重试 |
| 已失败 | 执行遇到错误 | 查看原因、一键重试并运行 |
| 已完成 | 结果已产出 | 查看产物、再次运行 |

暂停、恢复、取消和重试会作用于真实后台任务，不只是改变界面标签。
定时模板本身不会执行；到期时任务应用会生成一条新的“待运行”实例。

## 回答代理的问题

代理执行过程中需要你确认时，任务会进入「需要输入」状态，并在任务卡片上
直接给出回复框。输入回答后任务自动继续，无需重开会话或重新派发。
「重试」按钮在需要输入的任务上是次级操作，避免误把“重新派发”当成
默认路径。

## 一键重试并运行

失败或阻塞且绑定了目标项目的任务，卡片上直接提供「重试并运行」主按钮：
一次点击完成重试计数、清空失败原因并重新派发给项目代理，不用先回到
“待运行”再点“批准”。达到自动重试上限时仍会先弹确认框。

手机上的任务中心将运行中、需要输入、失败和已完成摘要排列为 2×2；任务操作使用等宽按钮，
历史记录标题具有完整触控区域。项目名、时间或其他长值会自然换行，不会以省略号隐藏关键信息。

## 在任务中心创建与管理任务

任务中心不只是接收后台工作的收件箱，也可以直接创建和管理任务，不需要先经过
对话或收件箱：

- 「新建任务」：填写标题、说明、目标项目，选择触发方式——手动、每隔 N 分钟
  或每天 HH:MM；可选择「执行模式」——自动运行（完全访问，到期直接执行）
  或每次运行前确认（默认权限，先停在任务中心等你批准）——并设置最大重试
  次数。
- 手动任务：创建后出现在任务列表；按审批设置自动运行或等你在任务中心点
  「批准并运行」。
- 定时任务：创建后作为「定时」模板卡片，显示计划（如“每天 09:00”）和下次
  运行时间；到期由任务应用自动生成新任务实例并执行（按审批设置决定是否自动
  运行）。支持编辑（标题/说明/目标项目/触发方式/时间）、暂停定时、删除。
- 编辑任务：一次性任务与定时任务卡片都有「编辑」入口，保存后立即生效，定时
  任务会自动重算下次运行时间。
- 按空间分组：列表顶部「按空间分组」开关把任务按目标项目（工作空间）分组
  展示，组头显示项目路径与任务数；默认空间单独成组。
- 搜索：列表顶部搜索框按标题/说明实时过滤，与状态筛选叠加，任务多时也能
  快速定位。
- 置顶：任意任务卡片都有「置顶」，置顶任务始终排在列表最前，方便固定重要
  事项。
- 继续处理：有绑定子会话的任务显示「继续处理」主按钮，点击直接进入该任务的
  对话接着工作。
- 再次运行：已完成/已取消的一次性任务可「再次运行」，以相同设置创建新任务
  并立即派发；自动化来源任务用「再次运行」重跑对应工作流。
- 运行时长：运行中任务的状态旁显示「已运行 N 分钟」，随时了解后台任务进度。
- 归档：已完成/已取消任务可「归档」——从常规视图隐藏但保留；左侧筛选新增
  「已归档」查看，归档任务可「恢复」回列表。
- 「定时任务」筛选：左侧导航只显示定时模板，方便统一管理。

## 多窗口保存任务

任务列表按工作区保存。多个窗口或后台同时更新时，应用会拒绝覆盖已变化的数据。
遇到“任务已在其他位置更改”提示，请刷新任务列表，检查最新内容后再保存；新建任务失败时表单会保留。
遇到“其他进程正在保存”提示，请稍候刷新重试。若持续出现，请保留现有任务文件并排查未退出的进程，避免直接删除仍在使用的锁。

自动化规则使用独立的修订号与文件锁；详情见下文「自动化规则」。

## 自动化规则

自动化适合周期性整理、固定提示词和重复研究。创建前明确：

1. 触发条件；
2. 使用的场景和模型策略；
3. 预期产物及保存位置；
4. 失败后的通知与重试方式。

在“更多 → 自动化”中填写名称、目标项目和任务说明，选择手动、每小时或每日计划，并设置
单次费用、最大重试次数与「执行模式」。列表顶部的搜索框可按名称或提示词实时过滤，
配合状态筛选快速定位规则。新建表单顶部还有「从模板开始」：内置每日技术简报、周报
汇总、每日学习计划、代码巡检、新闻摘要、每晚记忆沉淀等常用模板，点击即预填名称、
提示词与计划，可在此基础上修改或一键「使用自定义」清空。其中「每晚记忆沉淀」会在
23:30 让代理回顾当天会话与项目记录，合并去重后沉淀记忆文件，与「设置 → 记忆」和
对话中的 `/memory` 提取互补。点击“创建自动化”后，新规则会立即出现在列表中；
手机端表单使用防止系统自动缩放的 16px 输入字号和至少 40px 的触控区域。每个字段都有
持续可见标签，输入内容后仍能辨认字段含义；轻点标签也可聚焦相应控件。
已有工作流卡片可「复制」为同配置的新工作流（标题加“副本”后缀、历史清空、
下次运行时间重算），适合基于现有规则派生变体。

### 自动执行范围

- 选择「自动运行（完全访问）」的工作流：到期后自动把任务派发到目标项目，
  无需在任务中心手动点“批准”。文件写入、删除、脚本与网络操作不会逐项确认，
  请仅用于可信、可恢复的任务。
- 选择「每次运行前确认（默认权限）」的工作流：到期后任务停在“需要批准”
  状态，在任务中心手动批准后才开始执行；涉及工作空间外的文件写入、删除、
  脚本命令或网络访问时，执行前仍会再次向你确认。
- 桌面 Host 运行期间会检查所有已注册工作区保存的规则，不依赖当前页面或选中的工作区。
  规则的目标项目可以不同于规则的存储工作区。多个桌面或后台进程同时运行时，只有一个进程
  持有自动化执行权；需要确认的任务仍会停在任务中心等待批准。
- 桌面端自动化中心会列出已注册工作区的规则、到期与任务状态及文件错误。清单为只读快照，
  到期数量不等于已经执行的数量；局域网浏览器暂不显示此清单。
- 可以在桌面自动化中心主动启动或停止独立后台进程。启动后即使关闭桌面窗口，后台进程仍可
  继续检查计划任务；停止它且关闭所有桌面进程后，计划任务不会继续执行。也可以勾选
  「登录系统后启动后台自动化」，让后台进程从下次登录起自动启动；此设置默认关闭，勾选
  不会立即启动当前会话，当前会话仍用「启动后台进程」控制。
- 派发到目标项目的任务在代理执行结束后会自动标记为已完成并弹出通知
  （含结果摘要）；失败也会通知，并可从任务中心重试。

> 自动化不会绕过场景隔离、插件权限或模型预算限制。

### 保存自动化草稿

自动化表单的“保存自动化草稿”允许先保存未完成的内容，包括空白任务说明。
草稿不会被调度。列表支持刷新、恢复和删除；保存后可在同一工作区继续编辑，关闭应用后内容仍保存在本机。
编辑已有自动化时保存草稿只生成独立副本，原规则继续使用原配置。
恢复草稿后，点击“创建自动化”才生成新的工作流；创建成功不会自动删除草稿。
切换工作区会清空当前表单，未显式保存的编辑不会保留。草稿的目标项目可以与保存它的工作区不同。

正式自动化规则保存会检查读取时的文件修订号，并以文件锁和原子替换保护写入。若其他窗口已修改规则，请保留当前表单内容、刷新列表后再编辑；损坏或超限的规则文件不会被当作空列表覆盖。运行历史在并发冲突时会有限次重试。规则最多 200 条，文件上限 8 MiB。
编辑现有规则只更新表单字段；运行历史、最近执行时间和待审批状态保留文件中的最新值。仅改变启用状态或计划时才重算下次执行时间。
新建表单会为本次创建保留固定 ID；若保存响应丢失，保留表单并再次提交时会先核对该 ID 的已保存内容。内容相同会确认此前已保存，内容不同则要求刷新。

如果提示草稿冲突，先保留需要的输入内容，刷新列表，再恢复最新草稿后合并修改。
损坏或超限的文件不会被当成空列表覆盖。当前最多保存 200 个草稿，总文件上限为 8 MiB。


### 子项目环境诊断

目录发现会补充根 `package.json` 的 `workspaces`（数组或 `packages` 对象）、根 `pnpm-workspace.yaml` 的 `packages`、根 `Cargo.toml` 的 `workspace.members/exclude`，以及根 `pyproject.toml` 的 `[tool.uv.workspace]` `members/exclude`。pnpm 文件存在时优先于 JS workspaces；解析失败时提示不完整，不回退另一份 JS 声明。支持工作区内相对路径（可带 `./` 前缀、末尾 `/`）、`*`、`?`、字符组及整段递归 `**`，例如 `packages/app-*`、`services/**/api`。声明路径与实际遍历最多 32 段深，不受普通四层扫描限制；匹配区分大小写，具体字面路径仍受所在文件系统规则影响。

pnpm `!` 前缀表示排除目录；空文件、根 null、未填写 packages 或 packages 为 null 时按 `**` 发现，空数组或仅排除项不添加声明目录，根目录和普通扫描仍保留。支持 YAML 注释、引号、块列表与行内数组；拒绝重复根键、多文档、根合并键、packages 内的别名、自定义标签或非字符串条目。忽略其他配置值，不展开别名。每份 YAML 最多 16384 个事件，无关嵌套最多 64 层；清单仍限制为 256 KiB。

声明扩展合计最多 2048 次路径步进/目录项，每份清单最多 128 个包含/排除模式，合并结果最多 64 个目录（含根），优先保留声明目录。排除项只限制该份声明扩展，被排除的独立项目仍可能被普通扫描发现；列表不代表精确的包管理器成员身份。目录必须有受支持清单；递归模式途经的中间目录没有清单属于正常情况。

任何无效或不支持的模式都会跳过该份声明并提示发现不完整，普通扫描继续。尚不支持 brace/extglob（如 `{api,web}`、`@(api|web)`）、完整依赖图、Cargo 隐式路径依赖成员或父级继承。链接、工作区外目录、隐藏目录及依赖/构建目录不加入。预算耗尽、缺失的字面目录、字面声明目录没有清单时也会提示不完整。

在「开发环境」选择「环境诊断目录」，可查看发现的子项目清单和 Python 选择来源；报告会标明诊断目录。切换目录立即隐藏上一份报告，过期响应不覆盖当前选择。工具目录与显式 Python 环境仍是整个工作区共享的设置。

目录发现复用命令运行器的普通扫描与声明扩展，忽略隐藏目录、依赖和构建目录及目录链接；触及限制、访问失败或声明无法完整解析时显示提示。使用「刷新项目目录」重新发现目录；用「再次检查环境」更新当前报告。诊断和命令运行器共用当前子项目目录；切换视图、刷新或返回项目时保留本窗口会话中的选择，不改变已有命令或终端。

Host 每次读取都重新校验目录。目录消失、链接或越界时报错；旧 Host 未明确回传所选子目录时，不展示其根目录报告，请更新 Host 或选择根目录。此功能逐目录检查已有清单，不解析整个 monorepo 依赖图或继承自父目录的所有配置，也不启动项目任务。


### 当前子项目上下文

环境页、命令页和终端页顶部显示「当前子项目」。在任一页选择目录后，其他页继续使用同一目录；终端页的选择仅作用于之后新建的终端。选择按场景、工作区和项目路径隔离，保留在当前窗口内，最多记住最近 64 个非根目录选择；关闭窗口后重置为根目录，不写入仓库或跨设备同步。终端仍按自身启动目录工作。

切换目录或刷新清单时立即隐藏旧命令，只有新清单确认目录后才显示。旧 Host 未回传目录时仍可使用根目录；子目录需更新 Host。首次运行状态读取完成前或状态刷新失败时禁止启动，可刷新重试。目录已被删除时保留选择并显示错误，方便明确改选；不会自动切到根目录执行命令。


### 子项目终端启动目录

终端页的「新终端启动目录」共用当前子项目选择，可通过「刷新项目目录」重新发现目录。新建终端前 Host 重新检查该目录仍位于工作区内，拒绝父级跳转、绝对路径、目录链接和 Windows reparse point。切换选择不会向已有 Shell 发送 cd，也不会关闭或移动已有终端。

会话列表与详情显示启动目录，Shell 内自行 cd 后该标记不会更新。旧 Host 未报告目录时显示「此 Host 未报告」，不猜测其当前目录。子目录启动使用独立协议操作，旧 Host 不支持时提示更新或选择根目录；不会自动改为根目录重试。响应超时或确认异常时应先刷新终端列表，已经发出的启动可能已成功。支持该协议的 Host 会按原启动意图返回仍保留的会话；若会话已被淘汰，在近期意图保留窗口内拒绝重复启动。

终端列表、输入、停止及每工作区 2 个/每 Host 8 个活动终端限制仍以原工作区归属管理。新终端继承工作区工具目录和显式 Python 环境；自动模式按启动目录选用 .venv 或 .conda。终端仍仅桌面可操作，本轮没有开放远程交互终端。


### 子项目包管理器来源

命令页与环境页共用选择规则，并显示管理器、配置目录、选择依据及可用的版本声明：

1. 当前包的 `packageManager` 显式声明优先（npm/pnpm/yarn/bun，最多 200 字节）。
2. 否则检查当前目录的 Bun、pnpm、Yarn、npm 锁文件及有效 `pnpm-workspace.yaml`。不同管理器的依据同时存在时报错；同一管理器的多个锁文件可以共存。
3. 没有本地依据时，在已注册工作区以内向上查找，最多 32 层。仅当最近的 JS/pnpm 工作区声明明确包含当前包且未排除时，继承该目录的管理器选择；pnpm 声明优先于 JS workspaces。最近声明不包含当前包时停止继承，回退当前包的默认 npm。
4. 没有可继承的声明时默认 npm。无效/不支持的声明或无法访问的配置不会静默跳过；请修复后刷新，或为当前包显式指定 packageManager。

环境页会使用现有工具版本报告比较继承的 packageManager 版本声明；不自动安装、激活 Corepack 或强制切换工具版本。脚本仍从所选子包目录运行。有效管理器、版本声明、配置目录或来源变化会改变命令指纹，启动前需刷新清单。本轮仅继承包管理器选择，不继承 engines、依赖、环境变量或全部包管理器设置。
