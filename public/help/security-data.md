# 数据、安全与备份

ZiCode 采用本地优先设计：会话、笔记、任务和插件数据保存在应用管理目录中，敏感凭据交给操作系统凭据库保存。

## 凭据如何保存

- Windows 使用 Credential Manager 保存场景和模型渠道的 API Key。
- 普通配置文件只记录非敏感索引，不保存明文密钥。
- 启动模型运行时如需兼容认证文件，只会短暂生成并在加载后删除。
- 帮助文档、项目档案、日志和导出内容都不应包含密钥。

## 场景数据边界

每个场景有独立的模型配置、凭据和运行目录。删除或重命名模型渠道时，关联凭据会同步清理，避免留下无法管理的孤立密钥。

## 手机与远程访问

远程访问默认关闭；关闭时 Host 仅监听本机 `127.0.0.1`。在桌面“设置 → 远程访问”
明确启用并重启后，Host 才会在私有局域网地址启动 HTTPS/WSS。

远程安全基础已经开始生效：非本机连接必须使用配对设备身份，HTTP 数据请求需要设备
令牌，远程设备不能继续签发配对凭据。未配对或链接失效时，页面会阻止进入工作区并
提示从受信任桌面应用重新生成链接。外部 WebSocket 来源还必须与设置中显示的 HTTPS
地址完全匹配。

“在手机上打开”的证书设置二维码和一次性会话二维码都只能由本机回环连接请求。即使
远程手机已经配对并持有有效设备令牌，也不能通过 HTTP 二维码接口签发新的配对凭据。

在桌面端打开“设置 → 远程访问”可以查看已配对设备、配对时间、最近活动和撤销状态。
撤销操作需要二次确认；撤销后令牌立即失效，已有远程连接会在数秒内关闭。连续失败的
配对交换会被临时限流。

首次使用时，在手机打开设置中显示的“手机信任设置”HTTP 地址，下载并安装公共 CA
证书。该端口不提供主应用或数据 API。安装前必须把手机页面显示的 CA 指纹与桌面设置
逐字核对；不同则不要安装。CA 私钥只保存在操作系统凭据库。

ZiCode 手机端是桌面主机的安全远程客户端：Pi、工作区文件和工具执行继续留在主机，
不会因为手机连接而复制到设备。Pi 上游可以通过 Termux 在 Android 本机独立运行，
但当前 ZiCode 不会连接或管理该进程；iOS 目前没有对应的本机 Pi 运行方式。

Android 系统分享目标只接收有界的标题、文本、网页地址和受支持图片。分享内容通过 POST
到达，不写入 URL 或 Cache API。文字在标签页读取后立即删除；图片只进入带随机标识、
十分钟时效和容量上限的一次性 IndexedDB 收件箱，并在交给图片处理链前删除。任何内容都
不会自动发送。

手机端未发送文字与有界图片草稿使用浏览器生成的 AES-GCM 256 位不可导出 `CryptoKey`
分别加密，密钥和密文都保存在同一 Origin 的 IndexedDB 中；草稿按会话隔离，文字最多
32,768 字符，图片最多四张、单张 8 MB、合计 12 MB，只保留最近三个含图片会话，并在七天后
清理。该措施保护静态存储中不直接出现文字或图片明文，但不是端到端加密，也不能防御已经能够在
ZiCode Origin 执行脚本的攻击者。发送成功或清除站点数据都会删除相应草稿。

断线时由用户明确触发的待发送状态只保存一个加密会话标记，不复制提示词；实际内容仍使用
上述草稿密文。标记 24 小时过期，重连只显示确认条，不会自动向模型发送。取消待发送状态
不会删除草稿，成功提交或清除站点数据会同时删除标记。

## 备份建议

| 数据 | 建议 |
|---|---|
| 笔记与项目文件 | 纳入常规文件备份或版本控制 |
| 会话（对话记录） | 设置 → 通用 → “导出会话备份”下载为可读 JSON |
| 应用数据目录 | 退出应用后进行一致性备份 |
| API Key | 在服务提供方安全保存恢复方式，不复制到备份文档 |
| Astro 发布目录 | 可重新构建，不必作为唯一数据源 |

> 恢复到新电脑后，需要重新录入系统凭据；仅恢复普通配置不会恢复 API Key。

会话备份为只读导出，包含全部消息内容与项目路径，不含凭据；备份文件可直接阅读，
用于归档或迁移前的数据留存。

会话备份导入：在“设置 → 通用”选择“导入会话备份”并选取之前导出的 JSON 文件。
导入按条目校验（会话 id 与内容首行一致、路径属于当前工作区、单条不超过 10 MiB、
总量不超过 50 MiB），已存在的会话 id 会跳过而不是覆盖；导入成功后新会话出现在
侧边栏，可用于迁移或恢复。

## 工作区数据快照

应用在启动时会对当前工作区自动快照（同一工作区每天最多一次），也可以在
"设置 → 通用 → 工作区数据备份"手动备份：会话、笔记、产物、任务、自动化与
金融数据会复制到 `~/.zicode/backups/<工作区>/`，每个工作区保留最近 7 份。
备份独立于工作区数据存放，误删或损坏后可以从快照恢复——恢复会用备份覆盖
当前工作区数据，恢复前会自动保存当前状态一份（会出现在备份列表中），因此
操作可逆；恢复完成后请重启应用以加载数据。删除备份需要确认。

笔记删除统一先进回收站（包括整本笔记本删除），回收站保留 30 天；会话与
自动化删除需要确认。核心数据因此有"回收站 + 快照 + 导出"三层保护。
