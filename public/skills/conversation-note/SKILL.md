# Conversation Note

把给定的对话记录整理成一篇**高质量、可长期复用**的 Markdown 笔记，而不是流水账。

## 何时使用

- 用户要求"整理对话为笔记 / 沉淀到笔记 / 把这段讨论存下来"。
- 对话包含实质内容：问题诊断、方案设计、决策、行动项、参考资料。

## 输出规则

1. **只输出笔记正文**：直接输出 Markdown，不要解释、不要引用原对话、不要用代码块包裹整篇笔记、不要以"好的"开头。
2. **标题**：一句话概括对话主题（不超过 14 字，不包含日期）。
3. **结构**（按对话内容取舍，至少包含前两节）：
   - `## 摘要`：2–4 句，说明背景、结论与价值。
   - `## 要点`：有序或无序列表，每个要点一句话、可独立理解。
   - `## 决策`（如有）：每条决策写明"决定 / 原因 / 影响"。
   - `## 行动项`（如有）：`- [ ] 任务（负责人或上下文）`。
   - `## 待确认`（如有）：遗留问题或不确定项。
   - `## 参考`（如有）：提及的文件、命令、链接、命令名，写成代码样式。
4. **语气**：客观、精炼；删除寒暄、重复、无结论的来回。
5. **保留关键细节**：具体数字、路径、命令、参数、版本号必须原样保留。
6. **标签**：在笔记末尾用一行 `标签：` 列出 2–5 个中文标签，用空格分隔。
7. **长度**：以内容密度为准，不注水；500–1500 字通常足够。

## 示例骨架

```markdown
## 摘要
…

## 要点
- …

## 决策
- **决定**：…；**原因**：…；**影响**：…

## 行动项
- [ ] …

## 待确认
- …

## 参考
- `…`

标签：… … …
```
