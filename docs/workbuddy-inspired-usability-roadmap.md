# 参考 WorkBuddy 的可用性改造路线图

调研日期：2026-08-21。来源：腾讯 WorkBuddy 官方帮助文档
（workbuddy.cn/docs/workbuddy/*，页面清单见文末「调研页面」）。

WorkBuddy 是腾讯的全场景 AI 办公工作台：一句话下任务 → 自主规划执行 →
交付可验收结果。其产品形态与我们长期目标（提高 ZiCode Studio 可用性、
任务/自动化/收件箱/笔记各自有使用闭环）高度一致。本文档记录差距对照与
分期改造计划，P0 已开始落地。

## 一、WorkBuddy 核心心智（值得借鉴的部分）

1. **任务 = 对话 + 工作空间 + 模式**：每个任务对应一个对话和一个工作
   空间；工作模式分 Ask（仅问答不改文件）/ Craft（直接执行改文件）/
   Plan（先生成计划，确认后执行）。任务左侧列表按空间分组，卡片显示
   标题/状态/最近更新时间，支持置顶、重命名、归档、分享、继续处理。
2. **右侧结果区**：同一面板承载「产物 / 工作空间文件 / 变更(diff) /
   浏览器预览」，不离开对话即可核对产出；产物可分享/上传云端。
3. **执行过程可视化**：对话区展示阶段说明、结果摘要、可展开中间步骤，
   输入区随时可「停止」。
4. **权限护栏**：默认权限（工作空间内放行、敏感路径/删除/脚本/网络
   二次确认）vs 完全访问；把「审批」从单纯开关升级为可解释的权限模式。
5. **记忆**：每晚从会话提取事实/偏好/人物关系/跟进事项，设置里可查看、
   编辑、删除、一键关闭、从其他 AI 导入。
6. **自动化产品化**：任务模板（新闻推送/周报等）、低频率试运行建议、
   推送到手机/小程序、可追溯日志。
7. **技能/专家分层**：Skill=工具能力（可安装/启用/搜索/卸载），专家=
   角色（人设+方法论+工具链），专家团=多角色协作。
8. **收件箱心智**：Agent 邮箱「收件在界面看，干活在对话里」——邮件/消息
   到达驱动 AI 处理，一键「添加到对话」。
9. **资料库**：MD 管内容、CSV 管数据、HTML 管呈现；AI 修改以「待确认」
   呈现，接受后才写入（可审阅可回退）；轻量发布为在线链接。
10. **数据可恢复**：文件备份在修改已有文件前保存；删除走回收站/安全
    删除；明确「重要操作先备份」的用户建议。

## 二、ZiCode 现状 vs WorkBuddy 差距

| 领域 | ZiCode 现状 | WorkBuddy 差距点 |
| --- | --- | --- |
| 任务中心 | 筛选/摘要卡/新建编辑/审批/重试/暂停/模板卡+运行历史 | 无工作模式（Ask/Craft/Plan）；无置顶；按空间分组（本轮已加）；无「继续处理」统一入口 |
| 对话 | 左侧会话列表、右侧文件面板、实时/历史工具卡片 | 右侧面板无「产物/变更」视图；无「停止执行」按钮的强语义；对话内搜索/历史提问已有部分 |
| 自动化 | 工作流表单+编辑+立即运行+历史+审批 | 模板库只有少量示例；无推送手机；无试运行建议引导 |
| 收件箱 | 飞书/企微消息→任务，新手指引已加 | 缺「收件在界面看、干活在对话里」的一键处理闭环 |
| 记忆 | 无 | 会话记忆提取/管理/导入（本地优先更安全） |
| 权限 | 任务级「需审批」布尔开关 | 升级为「默认/完全访问」权限模式 + 高危操作确认清单 |
| 笔记/资料库 | 笔记本/笔记树、图标、标签、回收站 | 无 MD/CSV/HTML 分层；AI 修改无「待确认」审阅；无发布链接 |
| 技能/专家 | 插件市场 8 个插件、启用/禁用 | 无「技能」与「专家」分层概念；无按角色切换 |
| 备份 | 启动每天一次快照+手动备份 | 快照间隔 24h 覆盖缺口（见 P0-3）；任务/自动化写入无文件级历史 |
| 项目 | 工作区切换、全局默认工作区 | 项目指令/连接器/技能共享上下文层未打通 |

## 三、分期计划

### P0：数据安全与任务中心基础（进行中）

- P0-1 任务中心「按空间分组」视图：列表顶部切换，组头显示工作空间路径与
  任务数，移动端无横向溢出。——已落地并验收（桌面 1440 + 移动 390）。
- P0-2 任务置顶：卡片操作置顶/取消置顶，置顶任务恒在最前；字段向后兼容
  （`pinned?: boolean`）。——已落地并验收。
- P0-3 任务/自动化写入前保留滚动历史快照（`.history/` 最多 7 份）：弥补
  启动备份 24h 间隔的覆盖缺口，坏写入（客户端 bug、QA 误覆盖、崩溃）始终
  有近邻恢复点。——已实现（`extensions/picot-config.ts`），下次 release
  重启生效；单测覆盖。
- P0-4 任务卡片三要素（标题/状态/最近更新时间）：标题与状态已有，「最近
  更新」已有 Updated 行，保留现状。

### P1：对话与结果区（下一批）

- P1-1 对话右侧面板升级为「文件 / 产物 / 文件变更」多视图（参考 WorkBuddy
  结果区）：文件视图复用 `#file-sidebar`；产物视图复用 artifacts 数据；
  变更视图收集本次会话工具写入的文件并支持跳回定位。——已落地并验收
  （2026-08-21，桌面 1440 + 移动 390）。差异 diff 视图与「停止执行」按钮
  仍在 P1-3。
- P1-2 任务卡片「继续处理」统一入口：点击进入该任务对应的子会话（已有
  Open session 按钮，扩展到全部任务：有子会话的进入会话，无的提示编辑）。
- P1-3 对话执行阶段可视化：把实时工具卡片升级为「阶段 + 摘要 + 展开步骤」，
  输入区提供明确「停止」按钮（中止当前执行并回到可继续输入状态）。
- P1-4 权限模式：任务/自动化表单的「需审批」升级为「执行模式」（自动运行
  =完全访问 / 运行前确认=默认权限）选择，附上下文说明。——已落地并验收
  （2026-08-21，桌面 1440 + 移动 390，映射现有 `requireApproval` 无迁移）。
  高危操作清单式确认文案待后续增强。

### P2：产品化与生态（后续）

- P2-1 工作模式（Ask/Craft/Plan）：新建任务时选择，Plan 先出计划再执行；
  任务标题栏显示当前模式。
- P2-2 自动化模板库与手机推送：内置模板（新闻推送/周报/学习计划），
  执行完成推送到手机（PWA 通知链路已有基础）。
- P2-3 记忆：本地会话记忆提取（设置 → 记忆，可编辑/删除/关闭）。
- P2-4 技能/专家分层：插件市场增加「技能」分类与「专家角色」入口。
- P2-5 资料库分层：笔记增加 CSV 数据表与 HTML 呈现绑定；AI 修改以
  「待确认」diff 呈现，接受后写入；已有文章创作/博客/公众号发布链路与
  「轻发布」对齐。
- P2-6 项目共享上下文：项目级指令/技能/连接器注入任务（用户已有
  「项目串起相关内容」诉求）。

## 四、验收口径

- 每项改动：单测 + typecheck + Biome + 全量 `bun run test` 绿；
- 桌面/移动无头 QA（`.qa-shots/` 实况脚本）覆盖交互与横向溢出；
- 涉及数据写入的 QA 必须备份原始数据并在结束时恢复（见 P0-3 教训）；
- 关键功能记录到 `docs/implementation-status.md` 与移动端档案。
