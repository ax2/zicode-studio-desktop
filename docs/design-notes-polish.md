# 笔记应用“一版设计”（第 300 轮交付）

> 状态：设计评审稿。基于第 236–299 轮已落地的笔记功能，给出当前形态
> 评估、设计原则、桌面/移动端规格与下一阶段优先级。对应实现按 P0/P1
> 逐轮排期，P0 已完成并随本轮发布。

## 1. 现状与设计目标

笔记是 ZiCode 的主内容应用，已具备：项目 → 笔记本 → 笔记三级结构、
嵌套笔记本、图标（emoji 选择器 + 文件夹组合）、标签（内置图标 + 快捷
添加）、Markdown 预览、自动保存、选中文字带入对话、网页剪藏、附件、
拖拽/弹层移动、导入导出备份、Astro 发布、回收站（本轮新增）。

设计目标：桌面端把窗口宽度用足（内容列随视口分档）、空状态有明确引导；
移动端保持单列优先、弹层与底部导航不挤占主视图；数据操作全部可逆
（删除进回收站、冲突有版本提示）；所有交互有键盘/触屏等价路径。

## 3. 桌面端规格

- 主列宽度：`--app-content-max-width` 分档（1120→1200→1280→1360px），
  编辑器/空状态/搜索结果与其对齐；表单类面板收窄至 680px。
- 空状态：双栏卡片（左侧图标+标题+说明+操作，右侧“快速开始”三步提示），
  垂直居中于主视口；空回收站同规格。
- 编辑器：工具栏常显图标+文字；标题行图标可点开分组 emoji 选择器；
  预览默认开启；textarea 随窗口拉伸。
- 拖拽：指针自绘（ghost 实时跟随、目标行高亮、松开落库），键盘/触屏
  用 ⇄ 移动弹层兜底。
- 数据操作：删除先进回收站（可恢复），彻底删除需二次确认；保存冲突
  以版本号检测并提示重载。

## 4. 移动端规格

- 单列全宽，顶部避让 64px header，底栏应用导航；弹层（emoji 选择、
  移动目标、命令面板）Esc/遮罩可关。
- 工具栏图标化（40–48px 触控目标），标签行单行 + 可选列表按需展开。
- 空状态叠为单列，操作按钮保持整宽触控高度。
- 附件在移动端以链接/图片形式可打开（本地同源路由）。

## 5. 交互与数据原则

- 可逆优先：回收站 30 天前文案提示“删除后可在回收站恢复”，彻底删除
  才不可逆。
- 自动保存：输入防抖 2.5s + 切换/关闭前保存；保存状态 aria-live 播报。
- 变更日志：created/updated/moved/deleted/restored/purged 全量可审计，
  冲突检测以内容哈希为版本。
- 安全边界：笔记本/回收站均按 workspace 隔离；远程设备不能越权访问。
