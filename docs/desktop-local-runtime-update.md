# 本机已有 Studio 的安全更新

本机入口是 `D:\work\start-zicode-studio.cmd`，程序位于
`D:\work\apps\zicode-studio-desktop`，版本号仍为0.5.3。固定资料库始终是
`D:\work\local-state\zicode-studio-desktop`；更新程序不复制、清空或迁移该目录。
长期数据约定见[固定资料库](desktop-persistent-data.md)。

2026-10-27发现，本自动化环境的构建目录/新复制文件继承Low完整性标签。
直接替换安装目录的EXE后，即使启动命令来自普通用户进程，程序仍可能以Low
运行。实际证据为Studio token=4096、Explorer token=8192、没有已注册托盘图标，
修改托盘语言返回访问拒绝。不能把窗口可见或Rust状态中有Tray对象当作图标存在。

已有安装文件原为Medium（普通用户，非管理员），用户对其有内容修改权限，
但Windows拒绝修改文件完整性标签。因此本次采用以下方式保留原安装属性：

1. 记录现有EXE及新构建EXE的SHA，核对精确路径，正常退出当前Studio。
2. 保留旧EXE字节作为短期恢复文件并验证摘要，保留现有Medium文件身份。
3. 用打开既有文件的写入流原位更新程序内容，完成后截断至正确长度并刷新；
   不以新建/原子替换文件覆盖Medium文件，也不复制源文件的安全属性。
4. 验证新SHA，再在同目录重命名到固定EXE名称。不能覆盖未知现有文件。
5. 实际核对运行token=8192、Shell图标注册、菜单、语言切换、关闭恢复，
   以及原笔记与固定数据目录。全部通过后移除本次短期程序恢复文件。

更新过程中断时可用已保留字节原位恢复原文件；不要通过删除用户数据来恢复启动。
不修改构建缓存、目录或用户资料的ACL/标记，不使用管理员token运行应用。
正式安装包/其他机器不能照搬这台机器的路径或假定同样的文件标签问题。

最终本机验证：705项Windows Rust测试通过、54项明确忽略，实际普通用户进程
有一个Shell托盘图标，三次语言切换、关闭/恢复、最小化重开及退出图标清除通过。
再次普通启动后9227关闭、19包启用、两篇原笔记可读取、26个基线文件SHA一致。
