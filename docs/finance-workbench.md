# 金融工作台设计

ZiCode Studio Desktop 的金融模式不是一套聊天提示词，而是由有来源的金融数据、本地确定性
计算、研究工作流和持久化模拟账户组成的独立工作台。

## 产品边界

金融工作台的目标能力包括：

- 使用用户提供的有来源数据；按需通过 QVeris 发现并调用实时行情、历史行情、基本面、公告、新闻、宏观和另类数据。
- 对候选股票进行可解释的多因子筛选与排序。
- 使用本地确定性引擎运行策略回测，不让模型自行计算收益曲线。
- 管理观察列表、研究笔记、投资假设和事件日历。
- 维护不会连接真实券商的模拟账户，记录委托、成交、现金、持仓和净值。
- 将数据日期、来源、执行 ID、策略参数、费用和风险提示保留在每份结果中。

不在当前产品边界内：

- 连接真实券商或提交真实交易。
- 承诺收益、自动跟单或个性化投资建议。
- 使用未来数据、未复权数据或缺少来源的数据生成看似精确的回测结果。

## 分层架构

```text
Finance Workbench UI
    ├── 市场概览 / 观察列表
    ├── 选股器 / 研究卡片
    ├── 策略实验室 / 回测报告
    └── 模拟账户 / 交易日志
             │
             ▼
Finance Service (内置、确定性)
    ├── 标准行情与基本面数据模型
    ├── 因子计算和选股评分
    ├── 回测、费用、滑点和风险指标
    ├── 模拟成交与组合会计
    └── 数据快照、审计和缓存
             ▲
             │
用户提供的数据 ─── 可选 QVeris Adapter (内置 Pi 扩展)
    Discover → Inspect → Call → Usage audit
             │
             ▼
QVeris Capability API
```

### 为什么不直接嵌入 QVeris MCP

桌面产品内部使用直接 REST Adapter，而不是启动额外的 MCP/Node 子进程：

- Pi 扩展已经是受控工具边界，无需重复一层 MCP 进程管理。
- 只向模型暴露少量稳定工具，避免把大量动态 Schema 注入每一轮上下文。
- 复用 ZiCode 场景隔离的 QVeris 凭据，不把 Key 写进 MCP 配置或命令行。
- 内置客户端默认使用固定 Capability API 地址，不从宿主环境变量读取地址覆盖；自定义目标仅由显式集成配置传入，并限制为 HTTPS 或本机回环 HTTP。
- 可以在本地统一执行费用确认、响应大小、超时、审计和错误脱敏。

对外部 MCP 客户端仍可按 QVeris 官方文档使用 Hosted MCP；这与桌面内置 Adapter
互不冲突。

## QVeris 数据契约

模型网关和能力 API 是两个独立端点：

| 用途 | 地址 | 凭据 |
| --- | --- | --- |
| LLM 模型调用 | `https://aigateway.qveris.ai/v1` | 场景中的 `qveris` API Key |
| 金融能力发现与调用 | `https://qveris.ai/api/v1` | 同一场景中的 `qveris` API Key |

内置扩展遵循官方推荐流程：

1. `qveris_discover` 用能力描述查找数据源，默认使用紧凑 routing 响应。
2. `qveris_inspect` 获取当前参数 Schema、示例、成功率、延迟和计费规则。
3. 在界面中显示预估费用并获得确认。
4. `qveris_call` 使用同一次发现返回的 `tool_id`、`search_id` 和参数 Schema。
5. 保存 `execution_id`、费用字段、数据来源和 as-of 时间；需要时查询 Usage audit。

禁止根据工具名称猜测参数，也不能把另一个提供商的参数复用到当前工具。

## 本地策略引擎

第一版内置三种基线策略：

- Buy and Hold：作为任何主动策略的最低比较基准。
- SMA Crossover：用于趋势跟随基线。
- RSI Mean Reversion：用于均值回归基线。
- Donchian Breakout：使用此前窗口的高低通道作为趋势突破与退出基线。

执行约定：

- 第 N 根 K 线收盘后才能得到信号。
- 最早在第 N+1 根 K 线开盘成交。
- 默认只做多、整股交易，并显式计算手续费和滑点。
- 输出总收益、CAGR、年化波动率、Sharpe、最大回撤、交易次数和胜率。
- 所有回测必须同时说明标的、市场、币种、周期、日期范围、复权方式和数据来源。

后续策略以同一执行接口增加：

- 动量与相对强弱轮动。
- 质量、价值、成长、低波和多因子组合。
- 风险平价、波动率目标和最大回撤控制。
- 事件驱动策略，包括财报、公告和宏观事件。

## 选股器

选股不是让模型直接输出股票名称，而是一个可追踪的流水线：

1. 确定股票池和排除条件。
2. 使用有来源且同一 as-of 日期的行情和基本面数据；可按需通过 QVeris 获取。
3. 本地计算因子并处理缺失值、极值和行业中性化。
4. 按用户选择的因子权重评分。
5. 输出候选列表、每个因子贡献、数据缺口和风险事件。
6. 对候选标的生成研究卡片，保留反方证据和失效条件。

## 模拟交易

模拟账户使用独立账本，不会调用真实券商：

- 每个账户有明确的基础币种、初始现金和账户 ID。
- 模拟市价单按指定行情快照立即成交，状态明确为 `filled` 并关联不可变成交 ID。
- 模拟限价单支持 `pending`、`filled`、`cancelled`、`rejected`，挂单时冻结可用现金
  或持仓，行情达到限价时使用带来源快照成交。
- 成交使用带时间戳的市场快照，并记录数据来源。
- 现金、持仓成本和已实现盈亏从成交账本推导，不能由模型直接修改。
- 多个账户和场景之间使用不透明 ID 隔离。

## 实现状态

已实现：

- QVeris Model Gateway `/v1/models` 显式同步，只导入聊天模型，并保留上下文、
  视觉、推理和价格元数据。
- 场景隔离 QVeris Key 读取和错误脱敏。
- QVeris Discover、Inspect、Call 工具。
- Call 前显式费用确认。
- QVeris Usage audit 与 Credits ledger 的精简读取和工作台展示。
- 有界的场景隔离市场数据快照，保存数据类型、标的、市场、币种、as-of 时间、
  来源和原始负载；QVeris tool/search/execution ID 在实际存在时保存。
- 根据当前 Inspect Schema 显式映射提供商字段的 OHLCV 归一化器，校验时间顺序、
  重复时间戳、数值和高低价关系，并保留复权方式与来源。
- Buy and Hold、SMA Crossover、RSI Mean Reversion、Donchian Breakout 回测。
- 下一根 K 线成交、手续费、滑点和核心绩效指标。
- 使用横截面缩尾 Z 分数的多因子选股、权重贡献和缺失数据覆盖率。
- 场景隔离的多模拟账户账本、即时模拟成交、现金、成本和已实现盈亏推导。
- 使用带来源报价进行组合盯市，计算持仓市值、账户权益、未实现盈亏、过期报价和缺失报价。
- 金融工作台面板中的数据发现、回测、选股和模拟账户入口。
- Finance 场景工具白名单和嵌入式 Pi 加载冒烟测试。

进行中：

- 基本面统一模型，以及在经过人工确认的 Schema 映射模板上提供自动复用。
- 行业中性化、因子历史检验和股票池模板。
- 止损单、移动止损、交易日历和组合级风险限制。
