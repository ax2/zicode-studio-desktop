## 多输入能力的Host边界

当前通用Capability/Worker把input作为JSON传递，schema验证支持object/properties/required/additionalProperties及已有类型、长度、范围、enum/const/数组限制，见input-schema-validation.md。此代码能力不等于冻结首批profile允许任意输入：首批仍严格{text:string}。

regex/diff需要新的版本化输入声明。提供方先提交完整字段、必填性、枚举、字段UTF-8字节预算、合计字节预算、输出结构及操作ID；Studio再固定扩展标识/兼容矩阵并验证真实View→Host→Worker及Pi。禁止把两个输入塞入text后用隐式分隔符解析，或把自定义JSON塞进text当作未经声明的协议。

Host的maxLength按Unicode字符计，不代替字节检查。双方都必须执行序列化48KiB/Worker硬上限及guest字段字节检查。不得把未实现的$ref、oneOf、pattern、format等schema关键字当作安全防护；需要时提交明确扩展与测试向量。

结果接力目前已验证文本URL encode→独立Base64；它不能证明可选择diff.left/diff.right。多字段接力需要Studio提供预览、目标字段显示、兼容检查、取消零提交和确认一次写入的通用映射能力；未交付前在矩阵保留缺口，不要求DevTools私自实现跨插件Host访问。

## 非纯计算能力

- timestamp：显式时间戳、时间格式和固定偏移计算可评审；“当前时刻”、宿主本地时区及DST数据库需分别固定来源/版本，不隐式依赖机器环境。
- cron：保留数字五字段、固定偏移、5年/最多10次预览完整范围；显式起始时刻计算与实际后台调度分开交付。后台调度需要service生命周期/取消/权限。
- random：安全模式必须OS安全随机；种子模式明确非安全且可复现。现有冻结profile没有该操作契约，不能用种子算法替代安全功能。WASI随机源需版本化说明、平台验证与预算。
- 网络、路径、数据库、剪贴板、写入操作：现有一次stdin/stdout guest不能凭permission声明获得Host回调。提出受控Host接口及权限、取消、失败恢复需求，禁止启动独立EXE或绕过授权。
