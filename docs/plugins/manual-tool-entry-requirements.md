# 工具中心：工具级入口的接口需求

2026-10-09，Studio 侧需求记录；2026-10-17 更新。`tool.open.v1` 的 Studio 接收侧预览已生效，但尚无提供方实包完成该合同验收。154 项全量接入范围不变；不要求 DevTools 复制 Studio 代码或依赖其运行环境。

## 已有接口与边界

- Manifest capabilities已有稳定ID、标题、输入schema和可选输出schema；Studio注册表客户端已保留这些数据，无需重复导入DevTools代码。
- `/v2/plugin-capabilities`提供当前场景已启用能力，不依赖`pi.tools.register`。AI工具目录需Pi身份、会话与授权，不能代替手动工具目录。
- `/v2/plugin-capabilities/invoke`由Host校验当前能力、权限及输入，外部执行受原Worker预算和沙箱约束。已接线后台锁拆分；原生取消、工具级幂等和完整桌面新Host运行证据仍待。
- WASI文本计算可由Studio按支持的有限schema生成表单，打开不执行；复杂媒体、资源和系统操作不能被任意JSON编辑器替代。
- 应用入口打开落地页；具体工具入口按稳定能力 ID 加载通用表单。声明 `tool.open.v1` 的自定义 View 可接收该能力 ID 以定位界面，旧包仍落地页，具体合同见[预览规范](tool-open-v1.md)。
- 手动工具级分页与按需详情Host/网关接口及界面已接线，见[目录API](manual-tool-directory.md)。真实HTTP验证205项元数据分页/详情加载、无Pi注册授权、旧revision拒绝和零Worker事件；当前Windows调试程序已完成Studio夹具及DevTools Base64编码/解码基本用户流程，旧超时保留；不计全量接入验收。

## Studio接下来提供

1. 手动目录分页搜索只返回名称、用途、分类、来源、版本、可用状态及稳定复合ID；选择后读取当前schema。可搜索不代表授权执行。
2. 通用表单现覆盖有限文本、字符串/数字/布尔枚举、整数、有限数字和布尔输入；复杂嵌套对象与资源声明仍需专用界面，明确显示不支持原因。执行时Host重新校验，搜索、选择和填写不执行。当前输入支持以 `frontend/src/features/toolCenter/manual-tool-fields.ts` 和定向测试为准；此处修正文档旧状态，不把表单类型覆盖算作提供方算法验收。
3. 收藏、最近成功执行、最近打开应用使用不同ID/语义，沿用Host场景/工作区隔离数据；收藏不是权限。
4. 草稿仅在当前工作区内存保存，标签切换保留，跨工作区/销毁释放。写入、保存和传输使用既有确认授权机制。
5. 原生取消须有请求ID、终态和子进程回收证明；浏览器超时、退出页面或取消HTTP不能冒充停止计算。

## 可选生产者扩展：需双方版本化后实施

- 工具元数据提供任务分类、别名/关键词、简短用途和推荐输入方式，由稳定tool/capability ID关联，可以缺省；包名不是任务分类。
- 自定义View定位工具需独立`tool.open.v1`协商。Studio 可信父页面只发送本插件声明的能力 ID 与请求 ID；响应区分已定位、不支持、不存在；不能自动执行或授予权限。
- 2026-10-17 Studio 接收侧已加入 [`tool.open.v1`](tool-open-v1.md) 预览：当前仅使用已声明 capability ID，主 View 通过注入 SDK 回执定位状态。旧包明确降级到应用首页；真实提供方包与原生界面仍待验，不能把此条当作全工具接入。
- 消息绑定当前channel/view/版本/工作区；reload、陈旧View、越权ID必须拒绝。旧View明确降级到应用落地页，不通过跨源DOM或注入选择器操作。
- 计划/未实现项应有状态和原因，不能伪造可执行能力。Studio继续维护154项矩阵与阻塞清单。

Studio 接收侧预览已实现并通过合成 Host/View 定向验证；这不证明 DevTools 已声明或符合该合同。未修改 DevTools。生产者无需为 Studio 通用文本表单重写算法或合并/拆分包；提供方新包仍需独立收据及真实一致性验收。
