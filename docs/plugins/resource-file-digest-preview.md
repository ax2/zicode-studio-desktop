# 文件摘要资源执行草案

`resource.wasi.file-digest.v1`，版本 `1.0.0-preview.1`，当前为 Windows 开发候选，已通过下述 Host 和 Worker 验证。

该能力使用经逐次确认的 `resource.wasi.input.draft2` 文件快照和 `resource.wasi.output.draft1`，不暴露路径或写权限。一次1–4项，总共最多32 MiB，允许空文件。每项按输入顺序返回 SHA-256、SHA-512、字节数以及可选的预期摘要比较。Host 在接纳成功结果前将返回的 SHA-256 与授权快照的内容版本、文件数、顺序和字节数逐项核对，并重新计算 SHA-512 验证。提供方结果仅允许合同规定的字段。错误消息由Host归一化。

执行策略候选为256 MiB guest内存、80亿 fuel、30秒，受现有重资源池约束（全局最多两项、每插件最多一项），沿用宿主授权失效和显式取消的终止逻辑。Windows 真实 Host 与 Worker 验证了单文件 32 MiB、四文件合计 32 MiB 的双摘要与顺序，结果与 Python hashlib 固定向量一致。原生授权和 Worker 调用均拒绝 32 MiB 加一字节。同插件占用配额时第二次调用返回忙。测试在真实进程启动时控制时序，验证取消和撤销权限都能回收进程、关闭管道、释放配额，且不发布新报告。重新启用工具后旧授权失效，重新共享可继续执行。预算保持原值。

该能力按文件快照计算，一次最多四项。独立版任意大小、更多文件和双摘要后台读取进度仍待接入。SHA256SUMS 的目录校验和生成有各自的文件数限制及读取进度。


成功后 Host 可生成不超过 8 KiB 的 `resource.host.file-digest-report.draft1` JSON 报告。报告包含已授权的安全文件名、文件序号、字节数、两种摘要和预期摘要比较。Studio 记录实际插件包版本、程序版本及由操作系统、架构和构建类型计算的匿名指纹。对于已验明的 Files 0.1.0 模块记录来源工具版本 1.2.0，未来未登记的模块将显示版本未知。路径、账号及设备标识不进入报告。所有输入的授权都必须有效。报告支持本地预览和通过现有接力面板显式确认交给兼容工具，例如内置文本查看。选择工具和确认共享都不会运行接收工具。配额不足时原摘要仍然可用。笔记草稿可使用同一份已验证的 JSON。

Windows 可用「浏览本机文件」从任意本机目录选择一至四项，总计最多 32 MiB，标准多选对话框返回文件名和大小。打开对话框和选中文件只冻结身份，确认共享后才读内容。选择授权绑定原窗口、路由、运行会话和工作空间，HTTP 不能代替原窗口消费；重复文件、网络盘和符号链接或重解析点会拒绝。文件身份改变需要重新选择。

从原生对话框或 Studio 已打开的本地文件执行校验后，符合条件的结果行可通过「发送原文件」交给文件编码检查。初始文件授权和接收授权分别确认。接力只展示文件名和大小，确认时核对文件身份和工作空间，点击运行后重新打开文件并核对身份、长度和原摘要。文件删除或替换会拒绝读取。原文件引用从保留本机身份的入口发起。新版编码检查允许接收不超过 8 MiB 的引用。旧接收工具保持 128 KiB。浏览器文件快照仍可校验和传递报告。原生对话框操作纳入集中桌面验收。

独立 Encoding 0.2.0 的「检测文件编码」声明 `resource.wasi.encoding-inspect.v1`，可直接选择或接力一项非空文件，按完整字节进行检测和严格解码核对，报告至多预览 256 个字符。上限是 8 MiB，超限在 Worker 启动前拒绝。该能力沿用重任务池的总并发限制和每插件单并发，单次预算为 64 MiB guest 内存、640 亿 fuel、15 秒。UTF-8 转换延续 128 KiB 输入及原执行规则。Windows 与独立适配器对照保留了 40 亿和 160 亿 fuel 的旧编码失败记录，640 亿设置下七个恰好 8 MiB 样例与原生报告一致。

## Windows 流式 Worker 验证

开发分支增加内部顺序输入帧 `ZIDF`，用于 `resource.wasi.file-digest-stream.v1`。只接受 `com.zicode.devtools.files` 的 `devtools.files.hash`，先核验 WASM 模块摘要，文件内容逐块送入 Worker。原路径和文件名留在未来接入的本机授权层，Worker 只见资源编号、字节长度和内容。按确认顺序逐项计数，单块最多 64 KiB，允许空文件。截断或尾随字节会使整个调用失败。旧快照运行条件仍按原契约验证。

真实 Windows Worker 和提供方 WASI 验证了超过 96 MiB 的混合批次、64 文件批次、遗漏或额外字节、错误工具身份、模块摘要不符、重复资源编号和 65 文件拒绝。成功结果的 SHA-256、SHA-512、长度和顺序与 Python hashlib 独立计算一致。旧冻结 WASM 和新 WASM 各通过一组旧快照回归。Rust 验证还覆盖跨文件或跨块读取被拒绝、空文件跳转以及旧读取边界。

验证的 Worker SHA-256 为 `e845abd024b084505c4ab3a8b9523c23e76ce2caec7c16647501d15c185ea1b2`，提供方 WASM SHA-256 为 `9b69130fa4b9445c17faee3d1a92ebd263c125d221a8ccd7e81e4d0cab9867ce`。本批使用独立的合成输入程序验证真实 Worker。日志为会话工作区 `outputs/issue28-digest-stream-proof-final.log` 和 `outputs/issue28-digest-stream-studio-tests.log`。

当前用户界面的大文件执行仍待接入。Host 后续从实际确认的文件句柄向管道送入字节，负责支持执行中取消、实时复核权限、读取前后复核文件身份和长度、独立核对两种摘要、报告发布与原文件引用接力。原生选择操作加入该阶段的主会话统一验收。

## Windows 本机流式校验授权

文件校验插件 `files-0.2.0-candidate-01` 明确声明流式版本契约。Windows Host 的本机选择接口准备一个绑定窗口、路由、工作区和会话的批次授权。选择只登记文件名、长度和物理身份，确认后消费授权并逐块读取。数据通过已有资源 Worker 进程提供给独立 WASI，单块最多 64 KiB。宿主另算 SHA-256 和 SHA-512，逐项核对返回值与预期摘要比较。返回报告含安全文件名和版本来源信息，不含本机路径。

真实隔离 Windows Host 和生产 Worker 使用已登记的候选实包，通过了工作区外含空文件及 96 MiB 文件的批次与 64 文件批次。字节数、顺序和摘要与独立值一致，真实读取期间能看到进度，取消和撤权终止工作。错窗口、未确认、重放、重复文件、65 文件及同内容替换均被拒绝。旧 32 MiB 快照入口对同一个大文件的原有限制通过回归。

候选收据的目录索引 SHA-256 为 `f43a2119309fbebe56aa58db427f53f74715a623e6e09042eb80f8751769a71b`。Windows 证据在会话工作区 `outputs/issue28-digest-host-test02.log`。本批已接通原生命令及其后端，工具页入口、报告保存与原文件接力仍需联调。实际原生对话框操作由主会话统一验收。

## 批量文件校验工具页接入

Windows 工具目录仅为明确声明流式契约的 Files 候选启用流式本机选择。沿用「浏览本机文件」「确认文件共享」「执行工具」及执行中的取消入口，最多读取 64 个文件。进度来自 Host 的已读字节数及已完成文件数。旧候选、普通资源输入及已打开文件保持既有路径。

确认后的完整报告进入现有保存和传递流程，Host 保存全部行、比较信息和来源版本。离开工具或重新选择文件会撤销临时报告权限，已确认保存的文件可独立使用。可从报告按需生成不超过 8 MiB 的原文件引用。关联报告被撤销或替换后，引用随之失效。接收工具确认共享和主动执行前，引用不会交出内容。

Windows 真实 Host/Worker 通过工作区外 96 MiB 文件、多项进度与取消、撤权和 64 文件校验，另存 64 项 JSON 后从磁盘读回核对字节和 SHA-256。通过较小原文件的接力确认和实际 UTF-16 LE 转换，亦验证直接读取、错窗口、同字节替换及撤权拒绝。工具页及相关前端自动化 66 项通过。真实原生选取、保存窗口并入主会话统一验收。证据在会话工作区 `outputs/issue28-stream-ui-host.log` 和 `outputs/issue28-stream-ui-vitest.log`。
