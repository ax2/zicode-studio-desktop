# 文件摘要资源执行草案

`resource.wasi.file-digest.v1`，版本 `1.0.0-preview.1`，当前为 Windows 开发候选，已通过下述 Host 和 Worker 验证。

该能力使用经逐次确认的 `resource.wasi.input.draft2` 文件快照和 `resource.wasi.output.draft1`，不暴露路径或写权限。一次1–4项，总共最多32 MiB，允许空文件。每项按输入顺序返回 SHA-256、SHA-512、字节数以及可选的预期摘要比较。Host 在接纳成功结果前将返回的 SHA-256 与授权快照的内容版本、文件数、顺序和字节数逐项核对，并重新计算 SHA-512 验证。提供方结果仅允许合同规定的字段。错误消息由Host归一化。

执行策略候选为256 MiB guest内存、80亿 fuel、30秒，受现有重资源池约束（全局最多两项、每插件最多一项），沿用宿主授权失效和显式取消的终止逻辑。Windows 真实 Host 与 Worker 验证了单文件 32 MiB、四文件合计 32 MiB 的双摘要与顺序，结果与 Python hashlib 固定向量一致。原生授权和 Worker 调用均拒绝 32 MiB 加一字节。同插件占用配额时第二次调用返回忙。测试在真实进程启动时控制时序，验证取消和撤销权限都能回收进程、关闭管道、释放配额，且不发布新报告。重新启用工具后旧授权失效，重新共享可继续执行。预算保持原值。

该能力按文件快照计算，一次最多四项。独立版任意大小、更多文件和双摘要后台读取进度仍待接入。SHA256SUMS 的目录校验和生成有各自的文件数限制及读取进度。


成功后 Host 可生成不超过 8 KiB 的 `resource.host.file-digest-report.draft1` JSON 报告。报告包含已授权的安全文件名、文件序号、字节数、两种摘要和预期摘要比较。Studio 记录实际插件包版本、程序版本及由操作系统、架构和构建类型计算的匿名指纹。对于已验明的 Files 0.1.0 模块记录来源工具版本 1.2.0，未来未登记的模块将显示版本未知。路径、账号及设备标识不进入报告。所有输入的授权都必须有效。报告支持本地预览和通过现有接力面板显式确认交给兼容工具，例如内置文本查看。选择工具和确认共享都不会运行接收工具。配额不足时原摘要仍然可用。笔记草稿可使用同一份已验证的 JSON。

Windows 可用「浏览本机文件」从任意本机目录选择一至四项，总计最多 32 MiB，标准多选对话框返回文件名和大小。打开对话框和选中文件只冻结身份，确认共享后才读内容。选择授权绑定原窗口、路由、运行会话和工作空间，HTTP 不能代替原窗口消费；重复文件、网络盘和符号链接或重解析点会拒绝。文件身份改变需要重新选择。

从原生对话框或 Studio 已打开的本地文件执行校验后，符合条件的结果行可通过「发送原文件」交给文件编码检查。初始文件授权和接收授权分别确认。接力只展示文件名和大小，确认时核对文件身份和工作空间，点击运行后重新打开文件并核对身份、长度和原摘要。文件删除或替换会拒绝读取。原文件引用从保留本机身份的入口发起。新版编码检查允许接收不超过 8 MiB 的引用。旧接收工具保持 128 KiB。浏览器文件快照仍可校验和传递报告。原生对话框操作纳入集中桌面验收。

独立 Encoding 0.2.0 的「检测文件编码」声明 `resource.wasi.encoding-inspect.v1`，可直接选择或接力一项非空文件，按完整字节进行检测和严格解码核对，报告至多预览 256 个字符。上限是 8 MiB，超限在 Worker 启动前拒绝。该能力沿用重任务池的总并发限制和每插件单并发，单次预算为 64 MiB guest 内存、640 亿 fuel、15 秒。UTF-8 转换延续 128 KiB 输入及原执行规则。Windows 与独立适配器对照保留了 40 亿和 160 亿 fuel 的旧编码失败记录，640 亿设置下七个恰好 8 MiB 样例与原生报告一致。
