## 已确认的问题

首个界面切片之前，`plugin-shell.js/getCommandPaletteEntries` 仅把启用插件的 `commands` 放入命令面板。固定文本候选声明五项 capabilities 和 piTools，没有 commands，过去不能从这个入口搜到；现在通过已声明的main View及能力关键词找到打开入口。管理器也已增加元数据多词搜索。

命令面板已支持多词搜索、稳定插件标识、跳过不可用项和选中滚动定位。本轮增加结果数量、十项可用结果翻页、Ctrl/Command+Home/End边界跳转及主题选中提示。命令面板现按可见范围及少量预加载行挂载DOM，保留完整搜索、逻辑位置和总数；固定行高使用设计令牌，长标题省略并提供完整提示。手动滚动不恢复旧选中位置，Enter和收藏仅作用于可见选中项；方向键从当前视口继续。插件管理器使用40项分页保留不同高度的完整权限/管理卡片，支持直接跳页；搜索覆盖整个当前分类，搜索/切换分类重置到第一页。该分页只限制DOM，元数据本身仍在内存；不冒充宿主按需目录。

收藏由宿主持久化：原生Host优先尝试57620起的一组端口，冲突后可使用动态端口。浏览器localStorage与origin绑定，不能据此保证桌面重启恢复。当前源码实现`zicode.tool-access/1`，通过已认证桌面Host请求读写现有metadata数据库的preferences表；按场景/注册工作区隔离，逐项原子写入，保留512个收藏及最多40个最近标识。只保存稳定ID、使用时间及修订，不保存工具输入/名称/凭据/schema；对未知/损坏格式拒绝覆盖，失败显示重试并保持工具可运行。插件不可用时保留ID并提供移除入口，重新安装可恢复。该接口不授予执行权限，也不走Pi模型配置通道。

Pi Broker 目前通过环境变量接收完整工具快照；扩展的 `parsePluginTools` 超过128项或256 KiB会返回空数组，`setupPluginBroker`随后不注册任何工具。这是整体不可用，不能通过简单截断掩盖。宿主目前也没有在编码快照时提供超限诊断。

本机捆绑Pi 0.84.2的 `docs/extensions.md` 明确支持启动后 `registerTool`，以及通过 `setActiveTools` 在工具执行期间追加已注册工具。可以复用这一机制，不改写Pi运行时。模型供应商的原生延迟加载能力由Pi处理，Studio不自行推断供应商支持情况。

## 用户入口

统一工具目录面向操作，而不是要求用户先记住插件名称。目录列出有资格展示的已安装工具，启用状态和权限不足给出原因；点击未启用工具进入明确的启用/授权页面，不自动授权。

- 入口：命令面板、工具目录页、已收藏入口、最近使用和右键“发送到”。同一工具使用稳定标识，名称相同也不合并。
- 搜索：工具标题、别名、关键词、说明、插件名称；多词分别匹配，中文名称和提供方声明的拼音/英文别名可检索。未声明别名时不自行臆造分类或模型标签。
- 分类：用途标签、输入/输出类型、安装来源、启用状态；分类可以组合，不强迫一项工具只能归入一类。
- 排序：名称/关键词匹配优先，收藏和最近使用作为同等相关性的次级排序。明确命中某工具时不能被“热门”挤掉。
- 收藏保存工具ID，不保存完整旧描述；卸载后标记不可用并提供移除，重新安装兼容版本后恢复入口。最近使用只记录成功打开/执行及时间，不记录输入文本、凭据或模型内容。
- 工作台不是工具的复制品；保存布局和已固定工具ID，工具更新后显示版本变化和兼容性影响。
- 全局快捷入口沿用应用统一入口；工具内快捷键在焦点进入工具时生效，不能抢占中文输入法组合键。

首个可交付切片为插件管理器文本搜索、命令面板补齐工具入口和键盘滚动。后续再加入收藏/最近及分类目录，避免把大型重构作为简单入口的前置条件。

## 工具记录与版本

目录ID使用 `(pluginId, capabilityId)`，不能使用显示名称或当前数组位置。包版本、独立工具版本、契约版本、输入schema摘要分别展示；工具版本只能来自提供方声明，未声明时显示“未声明”，不能把包版本冒充工具版本。

目录摘要包含ID、名称、简短说明、分类/关键词、输入输出类型、可用状态、权限说明、来源包版本和工具版本。完整schema按需取得，不把所有schema塞入初次启动或每次搜索响应。

提供方目前契约没有承诺分类/工具版本字段；新增字段必须先发布版本化扩展及双方conformance，再由提供方输出。首轮可以使用现有标题、说明和包身份，不修改已冻结候选。

工具界面打开与执行分开。能力只有API入口而没有专用View时，显示输入表单/文档入口；不能猜测能力ID对应哪个View或自动执行默认输入。现有文本候选可以进入声明的主View，但定位具体操作需要另行约定显式深链参数，不能读取或改写提供方HTML来控制其内部DOM。

## Pi 按需发现

拟议扩展：`zicode.tool-catalog/0.1-draft`，尚未实现。使用现有Pi运行时绑定的Broker令牌，不使用浏览器desktop令牌。宿主仍以当前权限为准。

1. 启动仅传递有界的兼容小快照、目录协议能力和诊断。超限进入目录模式，不能静默变成“没有安装工具”。旧扩展不支持目录模式时返回明确不兼容错误，不随意截取前128项。
2. Broker注册目录搜索/加载工具。搜索只返回当前场景允许给Pi发现的能力摘要；未授予Pi权限的工具不通过此接口泄露完整说明/schema。
3. 加载选择绑定的工具ID；宿主返回该工具的当前签名/权限验证后schema和版本。扩展先 `registerTool`，再在加载工具执行期间以追加方式 `setActiveTools`，保留Pi原有工具及其他扩展激活的工具。
4. 工具调用继续通过宿主实时验证权限、实例/会话/工作区、包完整性和缓存身份。目录加载不是持续授权，不复用过期schema来绕过当前验证。
5. 达到本会话活动工具预算时显示“请结束当前任务或调整工具集”的明确反馈；不得在一次执行过程中偷偷移除其他活动工具。预算同时检查数量和schema字节数。

拟议HTTP接口供实现评审：

| 接口 | 作用 | 权限与限制 |
| --- | --- | --- |
| `POST /v2/plugin-tools/catalog/search` | 返回工具摘要及分页游标 | 当前Broker令牌/实例/会话；只含当前Pi授权；查询、页大小和响应字节均有界 |
| `POST /v2/plugin-tools/catalog/load` | 返回选定工具schema与版本 | 复核同一绑定、当前权限和签名；一次加载数量和字节数有界 |
| 现有 `POST /v2/plugin-tools/invoke` | 执行已选择能力 | 保留当前授权、幂等缓存身份、Worker限制；旧工具名不能跨版本错误执行 |

游标绑定查询、场景/工作区和目录修订，不能由客户端拼接任意offset访问其他目录。插件变更/撤权后旧游标失效并提示刷新；不能将两份目录快照混在一页。搜索和加载支持AbortSignal与超时，失败不改变活动工具集合。

接口命名仍待版本扩展评审，不新增Tauri命令，不要求提供方源码、EXE或共享数据库。操作数据的保存/覆盖/网络发送仍按[结果互通方案](tool-result-interoperability.md)逐项授权。

## 验收门槛

使用合成目录与真实独立插件分别验证；生成工具数量不算“已开发工具”。

| 范围 | 要证明的行为 |
| --- | --- |
| 100/500/1000项目录 | 搜索结果正确，支持重名/多词/中文/无结果；有界DOM，布局清晰，键盘选中项可见 |
| 收藏/最近 | 工作区隔离、重启恢复、卸载标记、重新安装与版本变化；历史不保存输入内容 |
| 当前文本候选 | 五项能力可发现，进入对应已声明入口；不修改冻结包、不自动调用模型 |
| 128/129项及256 KiB边界 | 小快照兼容；超限有明确目录模式/诊断，不能全空或静默截断 |
| Pi真实进程 | 搜索→加载→真实Worker调用；已有Pi工具保持活动，无需重启；不是mock registerTool证明 |
| 更新/撤权/禁用 | 旧目录游标和加载描述失效，旧缓存调用拒绝；跨会话/工作区和伪造ID拒绝 |
| 资源边界 | 大schema、搜索超时、加载失败、取消、重复加载不造成无界缓存或重复工具注册 |
| 持续使用 | 保留成功率/延迟和脱敏失败码，实际桌面截图与操作证据；不记录用户文本或令牌 |

最终性能目标以本机实际测量设定并记录机器/浏览器/目录规模；不在没有基准数据时声称搜索或启动耗时已经达标。
