# 项目文件选择入口

2026-10-11，开发版0.4.2；沿用 resource.local-file.draft1 内部候选，不向提供方发布新的运行时声明。

## 用户流程

资源工具的可信文件选择区域增加“从当前项目选择”。在系统文件选择框选择项目内文件，回到页面核对相对名称、大小及接收工具，点击“确认提供文件”才生成只读快照。随后仍需独立点击“执行工具”。取消、改选接收工具、改用普通文件或已保存文件、销毁界面均撤销尚未使用的确认凭据；确认后取消沿用既有资源撤销机制。

系统选择框取消不读取内容；选择项目之外的文件拒绝。切换项目/工具后，迟到的选择或预览不能重新启用旧输入；已生成但未交付的资源会申请撤销。失败不自动重试确认，丢失响应不意味着没有读过文件。最大32MiB及权限、包、实时身份和文件变更检查仍由Host执行。

## 原生入口

`select_project_resource_file({workspaceId})` 只允许当前注册项目对应的 `native-workspace-*` 窗口、当前Host origin。打开选择框前后复核窗口项目及注册根；返回规范化项目相对名称或null，不返回绝对路径、内容、资源权限或自动执行指令。选择框只设置初始项目位置，选择结果仍须校验，不能把初始目录当作边界。规范化后的文件必须仍在当前项目内；真正读取由后续Host确认接口负责。

文件选择框在后台任务中调用，Windows遵循项目进程隐藏规范。Tauri默认权限集中显式登记该命令。Gateway只在原生选择能力存在时显示此入口；普通浏览器仍可使用原有文件上传及已保存文件入口。
