# 工具目录中的资源工具执行候选（2026-10-10）

## 统一入口

工具中心保持按名称/分类/来源搜索、收藏、最近使用和40项分页；浏览阶段只加载目录元数据。选中一个工具后，Host详情返回声明的 `resourceInputProfile`（未声明为null），只有WASI和 `resource.wasi.input.draft2` 进入资源执行区。提供方无需贡献主视图，也不需要每个工具一个侧栏图标。

资源执行区复用可信本机文件选择、项目已保存文件选择、明确共享确认、按需类型参数表单及生产资源Worker。参数支持范围沿用现有通用表单；无法表达的schema明确阻止运行。不存在当前runtime/session、插件未启用或未授予资源读取权限时显示不可用，不自动授权或启动独立DevTools程序。

确认仅签发当前工具临时读取快照，执行是独立操作。成功后可查看文本/结构化结果，以及按需预览、确认保存或转给其他工具的资源输出。普通纯计算调用不会用于绕过资源授权。目录和主视图共用输入、计算、预览、保存、接力控制器。

## 目录版本绑定

可信 `POST /v2/plugin-resources/prepare` 新增可选 `catalogRevision`。目录入口始终传入按需详情的版本，Host在分配资源前：获取接收方身份证明→从实际runtime派生场景→检查同目录版本的工具详情→再次检查接收方身份。目录变化拒绝，不占用资源记录；身份在后续分块/提交/执行中按原有规则复核。旧可信调用不传此字段时保持原候选语义。字段不赋予插件新的读取权限，也不是已正式发布的resource.v1。

运行前再次检查详情版本，取消在目录复查阶段不会启动Worker；进入执行后的取消通过独立请求，运行控件保持锁定直到响应终结。错误/超时不自动重试，参数保留。成功资源结果展示后每5秒检查授权，失效清除旧结果。目录页切换保留当前执行；关闭工具受现有busy保护，宿主销毁或runtime/session变化取消并清理，不把结果发布给其他项目。

## 模块和构建

`directory-resource-runner.js` 负责可信输入/执行/结果控制，`ResourceToolRunner.tsx` 只桥接React生命周期与最近使用。相同工作区值及回调更新不会重新挂载；实际会话变化重置授权。Host仅增加元数据和可信准备请求检查，没有提供方实现依赖。

React构建将该可信控制器作为 `../plugins/directory-resource-runner.js` 运行时模块引用。其通用表单需要动态加载编译后的tool-center；不应把旧编译产物再次当作构建输入。复用同一target、开发版本和依赖缓存。
