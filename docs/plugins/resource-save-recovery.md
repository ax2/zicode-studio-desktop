# 保存响应不确定后的只读核对

2026-10-11。Studio 可信前端功能，复用 `resource.library.draft1`；不新增提供方协议，不修改 DevTools 包。

## 行为

用户明确确认保存后，如果 commit 响应丢失、超时或无法校验，保存对话框提供“核对已保存文件”。核对由用户主动触发，不能调用 prepare-save 或 commit-save，不写入、覆盖、删除文件，不重新授权给工具。关闭窗口不会撤销已经确认的写入。

核对使用准备时保留的收据快照，在原场景、原项目的文件库中按 saveId 查询。只有唯一完整匹配的记录才能继续：保存 ID、路径、MIME、字节数、内容版本、准备时间及来源插件/能力/资源/包版本均须一致。元数据列表不是内容证明；随后按 receiptVersion 读取原始文件，由 Host 检查当前权限、路径、收据版本与内容摘要，前端再次校验字节数和 SHA-256。

成功仅表示当前观察到原批准快照完整存在，不推断内部交易的执行次数，也不承诺之后文件不会变化。找不到、记录不完整、文件被修改、权限撤销、网络失败均保持“暂时无法核对，保存可能已完成”，不能据此判断未保存或自动重试。用户可再次执行只读核对。

核对进行时阻止重复核对；关闭对话框会中断只读请求。原项目/会话变化后不发起核对，迟到响应不更新其他项目界面。旧 Host 或测试 gateway 未提供文件库时保留原手工核对提示。
