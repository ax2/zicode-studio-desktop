# 已保存项目文件作为插件输入（可信桌面候选）

## 交互及权限

在已有插件主视图的可信“提供文件”区域，选择接收工具，再打开“从项目已保存文件选择”。查询和40项分页只读取项目文件库元数据，选择一项不读取原始字节、不签发授权、不执行工具。界面展示固定相对路径、来源插件/能力、大小及接收插件版本；来源文字只作为本地保存记录，不是签名来源证明。

用户点击“确认提供文件”后，通过已有 desktop-only resource.library.draft1 读取当前注册项目中的固定文件。Host检查当前交付物存储权限、收据版本、长度、原始SHA-256；可信父界面再核对长度和所选收据中的摘要，随后复用原有32MiB/顺序64KiB分块资源上传流程。资源准备、提交与执行均仍校验接收方的实时runtime/session、包版本、能力及resource.read权限。确认只共享临时快照，运行由工具自身独立操作。

项目保存文件保持原样，不下载到中间目录、不新增持久文件或磁盘索引。内存读取/上传受既有32MiB、全局单上传槽和110秒上传预算限制；读取受30秒网关超时限制。该实现通过可信父界面重新上传，并非Host零复制导入接口。

## 生命周期

重新查询/翻页/关闭选择区、改选本机文件、取消提供文件或销毁视图会使旧选择失效；取消/销毁中止待完成的文件库读取。已分配未发布的资源由既有上传finally撤销；晚到响应不能发布给已切换目标。已发布资源在改选/取消/销毁时撤销，独立于持久文件。权限不足或文件/收据变化显示固定失败提示，不自动重试或恢复文件。

收据检查和文件库读取完成后，可信父界面已有的内存快照不会因随后撤销交付物存储权限而被收回；后续接收方授权检查仍有效。此语义与用户从本机选择并确认字节相同，不能冒称整个上传期间持续绑定文件库授权。需要撤权贯穿所有阶段、签名来源链和跨重启来源关联时，应新增正式Host导入/授权协议，而非从客户端传入可信来源声明。

该入口复用现有主视图资源选择机制；没有主视图的目录工具尚无此入口。文件类型/能力兼容性由现有工具契约约束，不等同任意DevTools工具都可消费五类文件。多文件/目录、大图、批处理、持久实例、正式resource.v1及全工具scope仍按逐项矩阵验收。
