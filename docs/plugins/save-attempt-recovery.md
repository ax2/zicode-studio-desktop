# 项目保存记录与中断恢复候选

2026-10-11，`resource.save.recovery.draft1`。Studio 可信桌面内部扩展，非正式 resource.v1；DevTools 无需改动，不向提供方开放文件路径或恢复写入能力。

## 写入顺序与磁盘边界

只有有效资源、当前项目/存储权限和用户明确确认都通过的 commit 才创建保存目录。准备和取消仍不写盘。Host 在写入原始内容之前，先独占新建并刷盘 `.zicode/outputs/<saveId>/.receipt.pending`，最多8192字节，内容为原准备收据。随后写入并校验原始字节，再复核权限、来源链、项目、票据与预算，最后发布 `receipt.json`。

正常成功后删除本次临时收据，只保留原始文件和正式收据；没有第二套内容副本或另建 journal 目录。普通失败清理本次未发布的内容文件，保留小型收据供用户核对；进程突然结束时可能同时留下部分内容和临时收据。恢复读取不删除、修复、重命名或发布这些文件。

失败记录和完整输出共用已有128目录/256MiB配额，每资源最多32MiB；不是保留期限到期后自动删除用户文件的规则。达到预算时拒绝新保存，用户须先检查项目目录。未提供自动清理或重新执行入口。刷盘收据支持进程退出后的重新发现，不承诺所有平台/文件系统的断电目录事务持久性。

## 只读发现 API

`GET /v2/plugin-resources/save-attempts?schemaVersion=1&sceneId=<scene>&workspaceId=<registered workspace>&query=<optional>&offset=0`

仅桌面身份可调用；远程凭据、插件 Broker、未知参数、外部路径覆盖均不能代替桌面访问。要求当前已注册项目及交付物核心插件当前 `storage.plugin` 权限，在扫描前后复核授权世代。无需原资源、保存票据、运行会话、来源插件或浏览器缓存。

响应沿用40项分页、120字符查询、128目录有界扫描；包含 schemaVersion、profile、workspaceId、items、total、offset、pageSize、hasMore、skippedEntries、payloadsRead:false。每行包含原 receipt、receiptVersion、integrity:not_checked 和 publication：

- `observed`：读到了结构有效的正式收据；不代表内容完整或真实交易终态。
- `not_observed`：仅读到结构有效的临时收据；可能仍在执行、失败、中断，或已发生其他变化，不代表“未写入”。

有正式收据但它损坏/不安全时不回退到旧临时收据。元数据读取不读取内容文件，改动长度或缺失内容的记录仍能被发现。非法路径、链接、超额/未知字段、外项目收据拒绝或计入 skippedEntries，原文件不删除。

## 用户入口

交付物页面新增“核对保存记录”，不增加侧栏图标。用户展开、搜索、分页后主动点击“核对已保存文件”，调用现有文件库和 SHA-256 核对。只有完全匹配的正式收据与内容当前可读时显示成功；其他情况一律保持结果不确定，不重放保存。列表区分发布元数据与最近一次内容核对，最近核对成功不保证之后不会变化。

关闭面板中断读请求；项目切换不接收旧结果。权限每5秒重新检查，撤销后清除记录和结果；检查只读元数据，不后台读取文件内容。旧 Host 不支持 API 时显示固定可读提示。
