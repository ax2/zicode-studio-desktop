# 插件执行与结果的修订隔离

2026-10-10，Studio 内部实现；不新增公开 Host profile，不改变提供方协议。

## 范围

普通外部 Worker 的准备/完成校验及结果来源证明使用两项进程内 UUID：

- **插件包世代**：属于当前已发现插件，所有场景共用。
- **场景授权世代**：属于已有 registry 场景/插件状态，只影响该场景下该插件。

修改其他插件或同一插件的其他场景不再使本次调用、捕获结果、保存预览或结果接力来源证明失效。目录修订仍使用全局 `result_epoch`，所以目录分页仍可检测目录和授权变动。

## 失效规则

启用/停用和权限设置为对应场景状态生成新世代，包括重复设置。撤权后重新授权、停用后重新启用也不会恢复旧证明。授权状态变更发生后，即使 registry 持久化失败，内存已变化的目标场景仍被保守失效。

开发包替换、签名包安装和回滚在文件切换前使目标插件包世代失效；失败后的恢复也不复活旧调用。删除后重新发现会分配新世代。重新扫描时，已加载插件的 manifest、来源、目录、签名发布者身份和默认启用/core 身份均不变才保留其原世代；其他插件的包操作不使它失效。读取/验证失败而离开目录的插件不能保留身份。

UUID 随现有已加载插件和场景状态存放，不建立已卸载插件的永久墓碑或后台记录队列。场景世代不写入 registry.json；Host 重启后既有内存调用/结果本来就不存在，不提供跨重启结果恢复。

## 保留的保护

来源可用性、当前权限、manifest/schema、模块摘要、路径及签名完整性仍独立检查。资源调用仍核对完整运行实例、凭据、授权资源版本和预算；实际进程回收和管道结束后才释放配额。保存仍需当前存储权限、预览和显式确认，不能因为来源证明保留就绕过写入同意。

## 验证与边界

验证须覆盖无关插件权限变化、同插件其他场景变化、无变化扫描、目标插件撤权/重授与字节相同的管理重装；真实 HTTP 保存流程和活动资源 Worker 分别验证结果保持与自动失效，不用 injected outcome 代替进程验证。

具体终态见技术博客 `iterations/scoped-plugin-revisions-2026-10-10`。这不是文件系统原子快照；外部文件同长度并发改写、外部改写后还原、打开前替换、签名发布者元数据的外部替换及跨平台仍需单独验收。托管签名升级/回滚挂接失效逻辑，不等于真实签名升级链路已经通过验证。原生 Pi/GUI 运行中撤权、低端性能和 DevTools 完整工具 scope 不由此证明；154 项完整验收计数不变。
