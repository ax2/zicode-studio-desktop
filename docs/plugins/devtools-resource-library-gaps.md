# DevTools 资源工具剩余接口需求（2026-10-10）

依据当前154条公开目录scope、Studio资源候选实现和 saved-output-library-2026-10-10 实际证据评审。下面是待完成/待证明的接口与实包要求，不是永久不兼容结论；没有读取或修改 DevTools 仓库，也不把目录声明当作完整实现证据。提供方继续维护独立程序，通过版本化插件包及fixtures交付。

## 已有基础及边界

2026-10-11增加[项目保存记录只读恢复](save-attempt-recovery.md)：内容写入前刷盘有界临时收据，成功只留原始内容/正式收据；关闭工具或刷新页面后可通过交付物核对，源资源/运行会话不必仍存在。这不是持久实例状态、完整交易终态或跨重启写入幂等，下面各工具的原scope缺口仍须独立完成。

Studio 已实际验证单项用户确认资源输入、WASI资源消费/取消、原始输出登记、跨owner明确确认接力、可信静态预览、无覆盖原始文件保存，以及项目文件库搜索/分页/校验预览/下载。后二者是内部 resource.save.draft1/resource.library.draft1，非正式 resource.v1。复制型Studio夹具不是提供方算法包。

2026-10-14 Studio 追加 [CSV、Markdown、HTML 与 SQLite 固定输出类型](typed-document-output-draft1.md)，可在现有有界 Worker 输出、确认保存和项目文件库中保留对应扩展名；HTML 仅文字预览、下载按附件交付。后续真实 Host→当前 Worker 合成用例证明 HTML/SQLite 均可在用户确认后跨插件传递并由接收插件逐字节读取。算法内容、动态网页渲染、SQL 查询及提供方实包仍需逐工具验收，下表相关缺口没有因类型映射而完成。

需要索引 5–26 的候选包现须在 schemaVersion 2 清单中声明 [resource.output.types.v1 预览版](resource-output-types-profile.md) 与 `output.schema.v1`；未协商的扩展输出在 Host 登记前拒绝。提供方旧包保持字节冻结，不就地改摘要；下一版包应附完整声明和正反例。

当前资源记录上限32条/128MiB、单次输出最多4项/32MiB、Worker全局三个槽且每插件最多两个活动名额/五秒；文件库最多128目录，40项一页。图片预览单边4096、总像素4×1024×1024、编码体积8MiB；源工具图片工作台声明1600万像素，因此不能将小图预览通过提升为其全部图片范围接受。原始资源可在32MiB内保存/下载，但大图预览、100项批量、目录和动态持久记录另需契约。

## 给独立提供方的交付要求

1. 先提交包内能力/版本/完整scope清单和缺口说明，明确纯计算子集与需要新Host扩展的操作；不要把Studio内部候选写成已正式支持的requiredProfile。
2. 多文件/目录提出集合schema：每项稳定ID、受限相对名称、内容版本/身份、字节数、来源、总预算、部分结果和撤销语义；绝对路径和任意目录访问不能作为算法输入接口。Studio负责授权和遍历边界，算法负责计算。
3. 大图/批处理/长任务提出实际载荷与输出范围、逐项进度/取消和部分成功规则；提供真实算法 fixtures 与期望值，不通过提高全局五秒/资源预算掩盖边界问题。
4. HTML/Markdown/SQLite等交付类型提交MIME、固定安全扩展名及只读可信预览规则建议；需要正式版本/协商/Host conformance之后才能使用新类型。用户目标/命名/覆盖策略由Host确认，插件不能直接写路径。
5. 持久记录/配方/提醒提交独立schema、迁移、命名空间、乐观版本/多窗口冲突、备份合并/替换和取消/恢复规则；插件安装/卸载不能静默删除用户批准的数据。
6. 每类包附确定性正反例、限额、错误码、取消/撤权/版本变化/恢复证据和支持OS；Studio再做实际发现→加载→执行→展示/接力/确认保存及完整scope验收。

这些是接口需求与评审建议，尚不是已发布扩展。当前全部154项 integrationStatus/完整工具验收0不变；逐项正式原因以 devtools-all-tools-matrix.json 为准。
