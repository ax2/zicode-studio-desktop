# 归档适配事件的进程传输候选（2026-10-14）

Studio 新增内部 `plugin_archive_transport`：Host 自行持有的命令经既有 Worker 进程树传输运行，将有界标准输出交给[归档事件接收器](zifile-adapter-events-draft1.md)。它不是新的插件运行 profile，也没有将插件清单、页面参数或 ZiFile 独立 EXE 当作可执行命令。签名包中的 native 声明仍在预览、安装前拒绝。

## 当前边界

- 进入进程前核对 `archive-call-<UUIDv4>`、六种操作、请求最多 64 KiB，以及大于零且不超过 15 分钟的 Host 时限。命令的 stdin/stdout 由传输层接管，stderr 不向页面转发。
- 复用 `plugin_worker_process` 的 Windows 暂停创建、Job 归属与回收，以及 Unix 进程组清理；其取消、超时和进程退出规则保持一致。标准输出上限 512 KiB。
- 只有进程成功退出，且完整 JSONL 事件流通过 callId、序号、预算、终态和结束符校验，才向内部调用方交付收据和事件。截断、身份不符、非零退出、预先取消均只返回固定错误码，不交付部分目录。
- 本层**不做**原生进程文件/网络访问隔离，不解析资源引用、不暂存私有输入、不管理密码引用、归档分页游标或写入事务，也不把事件直接推送给插件页面。

## 验证与下一步

Windows 定向测试启动真实子进程回放 Studio 自制的 `list-ok.jsonl`，覆盖完整成功、截断、错误 callId、非法时限、预先取消、非零退出和失败后再次成功。Rust 静态检查覆盖编译与严格 Clippy；测试仅验证传输候选，不证明 ZiFile 算法或其他 OS。ZiFile [108 格矩阵](zifile-integration-matrix.json)接受数仍为 0。

后续需在不依赖 ZiFile 安装目录的前提下，从签名包选择经验证的 OS/架构入口并提供受约束原生执行环境；Host 应用资源版本、读/写授权、短期密码引用与 prepare/commit 状态机，再逐平台运行提供方适配向量。达到这些条件之前，不能对插件开放本内部函数。

2026-10-14 后续增加内部 `plugin_archive_cursor`：完整 `list` 事件通过校验后，传输结果可将提供方 `nextCursor` 换成随机的 Host 句柄。句柄最多存活五分钟、单次消费，绑定插件与包版本、能力、场景、运行/会话、归档资源内容版本、查询及页大小；最多保留128个，撤销资源可清除。提供方令牌只在 Host 内存中保存。当前没有真实 Host 路由调用该转换，也没有从已授权资源提取上述绑定、验证下一页稳定排序或跨进程恢复；这仍不解除 `HOST_ARCHIVE_EVENTS` 和 native runtime 阻塞。

2026-10-14 Host 生命周期补充：游标存储现由每个 `HostState` 持有，可信桌面资源撤销接口在成功撤销资源后立即废止该资源的所有归档游标。真实 HTTP 资源上传、确认、读取、撤销回归已断言游标不能在撤销后取回。该接口仍不提供归档分页路由；权限变更、资源到期或包升级后的游标需要在实际翻页请求上重新授权/核对绑定，不能只靠这次撤销通知。

2026-10-14 插件生命周期补充：Host 成功禁用/启用插件、改变权限或卸载后，立即清除该插件的待用游标；开发插件重装、签名包安装与回滚同样按插件清除。开发插件全量重载、发布者撤销会保守地清除全部游标。内部游标单测核对其他插件不会被定向清理牵连；实际 Host HTTP 测试覆盖重载、禁用、权限撤回与卸载。此清理只防止旧句柄在这些变更后继续使用，**尚无分页路由**，资源到期和每页授权仍需在未来翻页请求上检查；签名包安装/回滚亦未因本次接线获得 ZiFile 实包验收。

2026-10-14 分页边界补充：内部 `seal_list_cursor` 现在先核对完整列表的条目数不超过请求页大小，并验证完整游标绑定，即使提供方本页没有 `nextCursor` 也不能用非法绑定通过。超页时整页拒绝，不颁发 Host 游标。定向 Rust 测试和真实子进程协议回放通过。此检查仍未建立真实 Host 分页路由或证明 ZiFile 提供方的稳定排序；108 格接受数不变。
