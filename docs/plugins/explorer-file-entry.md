# 文件启动与工具授权入口（2026-10-11）

## 已实现

`zicode-studio-desktop.exe --open-file "E:\项目\输入文件.txt"` 使用文件父目录的独立工具会话打开工具中心。支持与 `--isolated-profile <绝对目录>` 合用，禁止与 `--tools-only`、`--open-folder` 或菜单管理操作混用。单文件、绝对 Unicode 本地路径，拒绝目录、链接、Windows reparse/UNC；不存在的文件拒绝启动。路径仅作为数据，不执行 Shell 字符串。

启动只检查文件元数据，不读取内容；不恢复 AI 历史、不备份项目、不启动 Pi。文件路径不放进页面 URL 或插件输入。进程内后续显式 AI 操作沿用 Explorer 目录入口的自动扩展发现禁用策略。

可信 Tauri `get_project_resource_entry` 检查窗口标签、Host origin、当前项目映射和启动文件原始父目录，仅返回相对文件名。换项目不能取得原文件入口。资源工具显示“使用已打开文件：名称”，点击后只申请元数据预览；用户另行“确认提供文件”才建立快照，再独立“执行工具”。取消撤销文件读取权。授权身份、文件替换检查、预算、快照和 Worker 隔离仍由 [本地文件资源协议](local-file-resource-candidate.md) 管理。

## 验证记录

实际 Windows CLI → 原生 WebView → 目录搜索与按需详情 → 真实 Tauri 文件入口 → 预览 → 确认 → WASI → 展示结果通过。中文/空格/`&` 路径、错项目拒绝、确认前零 commit/invoke 和零 AI 请求均独立断言。使用 Studio 自有合成资源插件，不代表 ZiFile 或 DevTools 算法接受；插件读取权限在独立验收配置中预置，未验收用户授予插件权限的界面。

完整日志/截图见技术博客 `iterations/file-entry-2026-10-11/work-log.md`。

## 待完成与限制

- 当前没有注册文件通配符或文件扩展名的 Explorer 菜单；现有三类菜单仍是目录入口。真实 Explorer 安装/点击/移除与现代一级菜单仍待验证。
- 文件入口不会自动选工具，当前目录也未按文件类型过滤。需扩展工具的输入类型声明及资源工具筛选，才能隐藏不合适的操作；不能把任何工具的可见状态当成支持该文件。
- 仅支持现有 WASI 资源快照：单普通文件不超过 32 MiB。目录、多文件、大文件流、密码短期引用、原生插件隔离与写入准备/确认/恢复协议未完成。
- 原始启动名称与路径在进程内保留，文件后来替换时由预览/快照边界验证；未承诺跨进程去重、重启恢复或读取中的系统 IO 取消。
- macOS/Linux、其他文件系统、托盘菜单点击和完整 ZiFile 实包尚未验收。ZiFile 实际接受 0；DevTools 154 工具完整接受 0，完整目标保持。
