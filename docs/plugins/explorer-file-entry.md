# 文件启动与工具授权入口（2026-10-11）

## 多文件交接候选（2026-10-14）

Studio 内部新增 `--open-selection <数量> <文件1> ...`，数量限定 2–4，逐个要求存在的本地普通文件、Unicode 绝对路径、无链接或 reparse，文件须互异且同属一个目录。跨进程交接由首进程重新校验并绑定接收窗口和工具会话；项目取共同父目录。启动不读取内容、不启动 Pi。可信命令 `get_project_resource_entries` 只返回当前窗口、会话、项目下的相对名称。文件资源工具筛选默认启用，但不根据多个不同后缀猜测匹配能力。

2026-10-14 后续：多文件目录请求携带 `selectedFileCount`，Host 在统计来源、分类和分页之前，仅保留声明 `resourceInputMax >= 选中文件数` 的已获准 WASI 文件资源工具。单文件工具不会混在多文件结果里；关闭筛选后仍可浏览全部工具。参数限 2–4，须与 `resourceOnly=true` 同用，不可与单文件 `fileName` 或目录筛选混用。请求只含数量，不含路径或内容；类型声明仍须由用户在共享前核对，容量符合不代表 ZiFile 算法或格式可用。

声明多资源输入的 WASI 工具可选择“使用已打开的文件”，先逐个准备只读元数据，再由用户确认共享，最后独立执行；总计最多 32 MiB。取消、切换入口或准备失败会撤回未提交预览；确认中途失败会撤回已发布资源。该入口是 Studio 自身的参数与授权链路，**尚未注册为 Explorer 多选菜单**，也不代表 ZiFile 创建归档已可用。现有传统文件右键保持单选。多选菜单需 Studio 自有 `IExplorerCommand` 接收 `IShellItemArray`、独立应用身份和实体右键验收，不能直接将静态命令模板扩展为不受控多选。参考 [Microsoft 选择模型](https://learn.microsoft.com/en-us/windows/win32/shell/how-to-employ-the-verb-selection-model)、[静态与动态菜单](https://learn.microsoft.com/en-us/windows/win32/shell/shortcut-choose-method)及[打包桌面应用右键入口](https://learn.microsoft.com/windows/apps/desktop/modernize/integrate-packaged-app-with-file-explorer)。

## 已实现

`zicode-studio-desktop.exe --open-file "E:\项目\输入文件.txt"` 使用文件父目录的独立工具会话打开工具中心。支持与 `--isolated-profile <绝对目录>` 合用，禁止与 `--tools-only`、`--open-folder` 或菜单管理操作混用。单文件、绝对 Unicode 本地路径，拒绝目录、链接、Windows reparse/UNC；不存在的文件拒绝启动。路径仅作为数据，不执行 Shell 字符串。

启动只检查文件元数据，不读取内容；不恢复 AI 历史、不备份项目、不启动 Pi。文件路径不放进页面 URL 或插件输入。进程内后续显式 AI 操作沿用 Explorer 目录入口的自动扩展发现禁用策略。

可信 Tauri `get_project_resource_entry` 检查窗口标签、Host origin、当前项目映射和启动文件原始父目录，仅返回相对文件名。换项目不能取得原文件入口。资源工具显示“使用已打开文件：名称”，点击后只申请元数据预览；用户另行“确认提供文件”才建立快照，再独立“执行工具”。取消撤销文件读取权。授权身份、文件替换检查、预算、快照和 Worker 隔离仍由 [本地文件资源协议](local-file-resource-candidate.md) 管理。

## 可选 Explorer 文件菜单

设置 → 通用 → 桌面集成，经明确确认后注册当前 Windows 用户的四类传统菜单：文件、文件夹、目录背景、盘符。已有三个目录入口的安装显示 3/4，可再次确认添加以补齐文件入口；不会自动升级或注册。

文件入口位于 `HKCU\Software\Classes\*\shell\ZiCodeStudio.OpenFile`，显示“在 Studio 中选择文件工具”，命令为 `"<当前 EXE>" --open-file "%1"`，声明单选。不更改文件关联、不为每个工具增加一个菜单项；目录入口继续处理盘符根目录的尾斜杠。普通文件入口不意味着所有格式或所有工具兼容，内容读取、执行和保存分别走既有授权边界。

安装和移除先核对全部四项的所有者、同名 Studio EXE 的绝对路径、精确参数模板和子项；外来归属或未知项时拒绝操作。同一产品的旧 EXE 路径会显示待修复数，经用户明确确认后才更新。操作不是注册表事务，中途写入失败应重新检查实际状态。独立验收配置仍禁止真实 Shell 注册。四项注册/状态/移除及三项升级使用独立临时测试键验证；真实 Explorer 的部分实体点击与当前用户注册另见项目档案，完整移除仍待验收。

## 文件工具筛选

工具目录新增“仅显示文件资源工具”，与搜索、来源、分类、收藏和最近使用相交过滤。文件启动时，可信桌面入口只检测当前项目文件名称是否存在，默认勾选；普通启动默认不勾选。用户可随时取消以浏览全部工具。切换项目/场景重置筛选并忽略旧检测结果；检测失败或超过五秒会恢复全部目录并提示手动筛选，不阻止使用其他工具。

筛选复用 Host `resourceOnly=true`：仅已启用、声明 `resource.wasi.input.draft2`、获准 `resource.read` 的 WASI 插件工具，不在客户端下载完整目录再过滤。不加载详情、不预览或读取文件、不自动执行、不改变权限；切换筛选重置分页快照。未授权或尚不支持资源协议的工具仍可在全部工具中管理。后续新增[文件输入发现提示](file-input-hints.md)：已打开文件按声明后缀进一步筛选，旧包保持未知可见，卡片明确显示提示来源；尚非 MIME/内容探测或算法保证。

实际 Windows WebView 中，隔离验收目录由全部 17 个工具筛到 1 个自有资源工具，取消/再次筛选请求与显示一致，期间文件预览/确认/执行均为 0；随后发现→加载→单独授权→WASI展示通过。40 项前端回归、类型检查和界面检查通过，桌面1440×900及窄屏390×844截图已检查。见技术博客 `iterations/file-tool-filter-2026-10-11/work-log.md`。筛选不代表格式探测或 ZiFile 算法接受，未验证上百真实提供方工具的性能。
