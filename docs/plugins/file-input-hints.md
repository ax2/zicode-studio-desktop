# 文件输入发现提示 1.0.0-preview.1

本候选仅提供工具发现提示，不发布新的读取权限或执行引擎。DevTools/ZiFile 继续独立构建，Studio 消费版本化插件包，不导入提供方源码或启动独立程序。

## 声明与协商

清单 `schemaVersion: 2`，保留正常 `engines.zicode` 与 `engines.pluginApi`，新增：

```json
{
  "requiredProfiles": { "file.input.hints.v1": "=1.0.0-preview.1" },
  "contributes": {
    "capabilities": [
      {
        "id": "archive.list",
        "inputSchema": { "type": "object", "properties": {} },
        "fileInput": { "extensions": [".zip", ".tar.gz"] }
      }
    ]
  }
}
```

每个能力分别声明。`fileInput` 必须恰好是 `{"extensions":[...]}` 或 `{"anyFile":true}`；不允许空对象/null、未知字段、两种声明混合或 `anyFile:false`。扩展名1–32项，不重复、每项2–32 ASCII字节，以点开头，其余是小写字母/数字/连字符及非空的点分段。允许 `.tar.gz`，不允许 `.TXT`、`.*`、路径或 MIME 模式。

省略 `fileInput` 的旧包不必升级；声明却没有对应 profile、要求不兼容版本或声明非法时，开发安装和签名包预览/验证都会拒绝，不会默默忽略提示或先写入持久信任。旧 Host 不认识 required profile 应拒绝该新包，因此不能把应用版本号仍为0.4.2当成具备此候选协议的证据。

## 目录行为

Host目录查询在 `resourceOnly=true` 时可加 `fileName`，仅普通文件名，最多1024 UTF-8字节，拒绝空/点路径、控制字符、斜杠、反斜杠和冒号。不接受本地绝对路径；查询是提示，用户伪造名字也不产生权限。

- 文件启动后，可信桌面入口返回当前项目相对文件名，UI默认发送资源工具筛选和该名称。文件名不进入页面 URL 或提供方输入；Host元数据查询不读取文件内容。
- 扩展名按 ASCII 大小写不敏感的后缀比较；中文文件名前缀正常支持。`.txt.exe` 不匹配 `.txt`。
- 声明匹配或 `anyFile:true` 的条目返回 `fileInputMatch:"declared"`；未声明的返回 `"unknown"`，仍可见；明确不匹配的被排除。没有名称时为 null，不凭资源协议推断格式兼容。
- 来源/分类/搜索、收藏、最近使用和分页仍由 Host 组合过滤；切换过滤重置分页。取消“仅显示文件资源工具”会同时移除 `fileName` 查询，恢复所有工具，方便管理未授权/不支持资源协议的插件。
- 卡片区分“插件声明匹配此文件名”和“插件未声明文件类型”。它是提供方声明，不是算法成功、文件内容格式或安全性的证明。
- 带 `fileName` 的全部/收藏结果先显示明确声明匹配的工具，再显示未声明类型的旧工具，各组内部沿用搜索相关度和稳定 ID；此排序发生在分页前，避免已声明的归档工具被大量旧工具挤到后页。最近使用仍按实际使用顺序。无 `fileName` 时目录顺序不变。

## 不变的授权边界

资源工具仍必须启用，具有 `resource.read` 且使用现有 WASI 资源输入draft2。真正选择文件、元数据预览、确认读取、独立执行、结果传递与保存沿用各自边界。输入快照仍最多32MiB，调用仍重新核对运行时身份、模块和权限；文件改名或更换工具后不能凭发现匹配跳过这些检查。

MIME/魔数探测、目录、多文件、各工具尺寸限制、压缩包内部格式和写入目标不是此预览范围。不能凭 `.zip` 名称自动开始解压或保存。

## 提供方接口需求

DevTools 的文件/图片能力及 ZiFile 各归档能力应按实际算法支持逐能力填写后缀，无法仅靠后缀确定时省略声明并保留未知；只有真正能接收任意文件的能力使用 `anyFile:true`。算法仍须验证输入并返回有界业务错误。不要修改冻结包；应交付新包版本、清单、摘要和正反例。ZiFile原生运行时仍未支持，填写提示不能绕过运行时门禁。

提供方至少给出大小写/复合后缀、同后缀损坏内容、无后缀、错后缀、撤权/升级/取消的材料。发现提示通过不增加任何源工具的完整接受计数。
