# 插件 Worker 的调用隔离

## 当前实现范围

Pi 的 `/v2/plugin-tools/invoke` 对独立插件使用三个阶段：

1. 在注册表与broker锁内验证运行时身份、目录证明、权限、输入契约和模块摘要，预留调用。
2. 释放两把锁后启动独立Worker，保留原五秒截止、取消标记和进程/管道回收。
3. 重新获取锁，核对身份、目录、权限、契约、注册表epoch和模块摘要，再校验输出、写幂等缓存与审计。

预留上限64，结果缓存沿用256项上限。相同runtime/toolCallId的在途调用拒绝重入；调用对象丢弃后weak预留失效，下一次准备清除失效项。broker和registry保持单一状态，未用复制实例绕开事务。

撤权后重新授权仍会改变epoch，旧结果不得发布或进入缓存。模块摘要读取最多2MiB+1字节，发现超限即拒绝。审计只存输入hash、时间、调用标识和错误码，不存输入/输出内容。Worker仍从原通用EXE运行，未增加应用副本或持久编译缓存。

原生 `/v2/plugin-capabilities/invoke` 已改为调用独立 `plugin_desktop_execution` 模块：后台任务内预检桌面身份和结果来源证明，复用上述prepare/execute/finish阶段，等待外部Worker时释放注册表和broker锁。内置处理器保留原事务路径。结果捕获继续核对原来源证明与当前来源；没有跳过保存权限校验。此路径当前没有新增取消或幂等协议，HTTP断开不是Worker已取消的证据。

对应真实HTTP/冻结通用Worker/Studio自有JS guest专项见档案 `iterations/native-worker-isolation-2026-10-09/`，以receipt及终态日志为准。它不依赖dev57历史摘要索引，不替代DevTools WASI或全部工具验收。

2026-10-09第二轮真实专项通过：慢Worker运行时，目录与另一外部工具在各1秒探针预算内返回（本次合计30ms，不是性能保证）；撤权再授权拒绝旧结果，超时后下一工具恢复，4个Worker均已回收并关闭管道。首轮因正常退出缺少回收观察事件失败，日志保留；修正观察记录后重跑通过。未验证原生取消、新完整桌面、DevTools算法或WASI冷编译。

## 验证要求

- 单元层：在途重入、丢弃预留、完成重放、不同输入冲突、撤权再授权、取消、同版本模块变更。
- 实际HTTP层：固定运行EXE摘要和独立插件包；Worker启动后，目录搜索和独立Host工具须在1秒探针预算内响应；随后取消须获得真实cancel_live/reaped/pipes_closed，再执行下一工具。
- 保留失败记录，测试夹具/摘要清单错误不计为插件计算失败，也不计为运行验收通过。

本轮状态与日志在技术博客项目档案 `iterations/worker-isolation-2026-10-09/`。测试注入结果仅验证事务状态；只有实际专项可证明对应HTTP链路。当前源码Host与旧固定EXE的组合，不等于新的完整桌面版本已运行。

## 继续完成的范围

- 原生View能力路径已接线；新完整桌面运行环境及真实DevTools WASI并发、结果捕获/权限确认/写操作一致性仍需验证。插件命令、结果接力仍需接入这一机制。
- 内置Host写操作保持原同步事务；不能从外部Worker隔离推导所有Host任务并行。
- registry epoch目前是全局的；任何注册表变更均保守拒绝旧结果。若改为插件级epoch，必须保留撤权再授权拒绝测试。
- 撤权后结果会被拒绝，尚未新增撤权立即终止活动Worker的机制。
- 当前实现没有减少模块冷编译；有界编译复用仍需实现，禁止直接接受插件提供的原生编译缓存。
- 整个Pi候选的多操作/权限生命周期、原生桌面截图、其他操作系统及154工具完整验收仍独立进行，不能由本项替代。
