## 一、要解决的问题

插件是交付、权限和升级的单位，工具是用户完成任务的入口。一个插件可提供多个工具；154个工具不等于154个插件，也不应等于154个主导航入口。

当前plugin-shell.js的renderActivities把所有enabled且hasActivity的插件映射为活动栏入口，安装规模直接影响主导航。实际独立测试环境显示21个应用入口（包括合成验收插件），另有系统入口；多个外部插件使用相同插头图标。不能把含测试插件的截图当作日常用户安装量，但它暴露了导航随安装增长的机制。

## 二、推荐的整体结构

采用稳定主导航、应用与工具中心、统一搜索和工作区标签页四层结构。

| 层级 | 承载内容 | 增长规则 |
| --- | --- | --- |
| 主导航 | 对话、项目、任务、笔记、工具、自动化 | 默认6项，不随安装数量增长 |
| 主导航个人固定项 | 用户主动固定的常用应用或工具 | 最多2项，超出时提示替换；收藏不受此限制 |
| 应用与工具中心 | 所有已安装工具及完整应用、分类、收藏、最近 | 目录可增长，按需分页/虚拟列表 |
| 工作区标签页 | 当前打开的工具与应用、草稿和运行状态 | 可关闭；过多时有“已打开”列表 |

设置和帮助固定在导航底部；插件安装、升级、信任和权限管理放进中心的“管理插件”。翻译、金融、证件照、图片等已有应用仍可通过中心、统一搜索或用户固定项打开，不删除功能。

默认不提供“插件安装即自动固定”行为。插件提供的图标用于目录结果和工作页面，不能自行占用主导航。第一次安装完成显示“已添加到工具中心”，可提供“打开”和“固定入口”，不代替用户做选择。

## 三、工具中心内部

1. 顶部常驻搜索框，默认搜索已安装内容；搜索结果以文字名称、用途摘要、分类和可用状态为主。
2. 主视图：收藏、最近、全部；另有工具/完整应用类型筛选。默认有收藏时优先展示收藏，否则展示最近和分类。
3. 分类按任务组织：文本与编码、数据与格式、网络与安全、时间与数字、图片与媒体、文件与文档、代码与项目、诊断与运维。允许多标签，主分类唯一；缺少分类进入“其他”。
4. 插件/发布者作为筛选维度和次要来源标记，不用“ZiDevTools/另一插件”替代用户任务分类。完整应用可有独立“应用”视图，避免金融等复杂应用硬塞进一次性工具分类。
5. 每个条目提供名称、简短用途、来源、收藏按钮、状态；详情页展示输入输出类型、权限、版本和限制。收藏、打开、执行分成不同操作。
6. 常用列表保持稳定顺序；搜索按名称/别名精确命中优先，再匹配标签/描述，最近与收藏仅作为同等匹配下的排序因素，不让“用过一次”淹没精确结果。

例：用户搜索“base64/编码”，直接看到“Base64编码”“Base64解码”，无需先知道提供它们的插件名。YAML转换可显示同一工具的方向选项；不能把包、工具和每个细微操作都平铺成重复卡片。

## 四、日常交互流程

### 已知目标

点击“工具”→输入“JSON格式化”→打开工具→填写或粘贴内容→主动执行。搜索选择只打开工具和聚焦输入，不自动运行；最多两次导航选择到达工具。

### 高频使用

工具条目点收藏→之后从中心收藏区打开。用户确实需要全局快捷入口时，另行“固定到主导航”。收藏、固定入口、已打开标签是三种不同状态，不相互自动转换。

### 连续使用多个工具

从JSON工具打开Base64工具时保留JSON标签和草稿。标签切换不销毁iframe或丢弃输入；关闭有草稿/活动任务的标签才询问。可手动“释放闲置页面”，需先处理草稿，不能悄悄淘汰有修改内容。

尚未获得用户同意，不将工具输入/输出持久化到磁盘。标签状态、工具ID等导航信息可以恢复；包含用户内容的草稿若需跨重启保存，必须有明确设置/确认及本地保存范围。

### 结果接力

结果区点击“作为下一步输入”→复用工具中心搜索，但按实际输出类型筛选兼容接收方→选择字段、填写其他必填项→预览映射→用户确认执行。其他不兼容条目可查看理由；不自动执行下一个工具。文件保存、网络请求和其他写操作维持各自确认与权限流程。

### 快捷搜索

沿用Ctrl/Cmd+Shift+P统一命令面板，按“工具/应用/命令”分组，展示与中心一致的工具目录；不另建一份收藏或最近数据。Ctrl+K现用于会话搜索，保留该习惯；中心搜索在中心内提供明确聚焦提示。Ctrl/Cmd+1..9绑定稳定主导航位置，安装插件不重排快捷键。

## 五、生命周期和错误状态

| 情况 | 用户体验 |
| --- | --- |
| 已安装且可用 | 打开工具；执行前完成该工具所需授权 |
| 当前场景禁用/缺少权限 | 显示具体状态，提供启用/授权入口；不点击即运行 |
| 只未授权AI调用 | 手动工具仍按手动权限可见，不能把AI授权当成手动工具目录准入条件 |
| 未安装 | 默认已安装搜索不混入；用户切换“可安装”后再展示独立安装动作 |
| 插件加载失败/超时 | 当前标签内给出可理解的错误、取消/重试和日志入口，中心与其他工具保持可操作 |
| 插件升级/撤权 | 清理旧目录与授权缓存；执行前复核；活动结果不得沿用失效授权 |
| 收藏项被禁用/卸载 | 保留用户收藏意图，显示“暂不可用”和恢复/移除选项，不能无声消失 |
| 无搜索结果 | 保留查询与筛选，支持清除筛选；不清空原输入或跳到安装页面 |

“最近使用”建议以实际成功执行为准；现有命令面板记录的是命令action完成，需要区分“最近打开应用”和“最近运行工具”。失败或取消不计成功运行。最近记录只存工具ID、时间和必要状态，不存内容。

## 六、插件接入规范的影响

### Studio负责

- 主导航布局、固定入口上限、中心、搜索索引、收藏、最近、标签、导航状态恢复及无障碍。
- 统一工具身份沿用pluginId/capabilityId及必要operationId，不依赖显示名或安装路径。
- 复用已有tool-access持久化接口与场景/工作区隔离；当前recent40/favorites512边界保持，不另建重复数据源。
- 目录仅加载经过校验的元数据。搜索和收藏不创建iframe、不启动Worker；只在打开工具时加载UI，在执行时启动计算。

### 需要版本化定义的扩展（本文件为需求，尚未生效）

- 通用工具元数据：稳定ID、名称/中英文别名、描述、分类/标签、输入输出摘要、对应能力和可选viewId/actionId。
- 将手动可发现工具与Pi注册权限分开，复用共同目录元数据，按caller各自检查可见性与执行权。
- 单独定义“打开指定工具/操作”的版本化导航消息：只定位与聚焦，不执行、不授予权限；绑定当前插件、view与声明的工具ID，拒绝越权或陈旧消息。
- 不通过跨源iframe DOM访问、注入脚本或假定#operation控件来选工具。旧插件没有激活扩展时打开原落地页，明确不支持精确定位，不伪称已经打开具体操作。
- 工具无UI时允许按声明的有限输入契约生成Studio通用表单；复杂自定义UI继续留在插件自身，目录入口统一。

这不要求DevTools合并所有工具为一个包，也不要求每个工具独立一个包。包可独立升级，导航由Studio统一。先完成Studio聚合入口与旧插件兼容，再把新扩展形成协议文档及一致性验证，交给DevTools原会话适配。

## 七、布局与可访问性

- 桌面：稳定主导航、可收起的中心分类列表、主内容区；工具打开后分类列表可收起，避免目前“插件未提供功能区视图”的空白侧栏长期占用空间。
- 窄屏：保留“对话/项目/工具/更多”，分类进入抽屉，搜索常驻；不把几十项塞进底部导航。
- 所有操作有文字名称或可访问名称，状态不只依赖颜色；完整键盘上下选择、打开、返回和清晰焦点；切换后聚焦工具标题/首个合理输入，关闭后回到原触发项。
- 检查1440×900、1280×720、390×844及200%缩放，浅色/深色；不从本轮三张浅色桌面截图推导上述状态已通过。

## 八、方案取舍

| 方案 | 判断 |
| --- | --- |
| 缩小图标、加滚动条 | 无法解决重复图标、快捷键漂移及按插件记忆的问题 |
| 左侧按插件厂商分组 | 减少局部拥挤，但用户仍须先知道工具来自哪个包 |
| 仅提供搜索框 | 熟练用户快，新用户难发现能力、缺少持续工作空间 |
| 稳定主导航+中心+统一搜索+标签 | 推荐；同时满足发现、快速访问和多工具连续工作 |

## 九、实施顺序与验收

1. 主导航不再自动枚举外部插件；新增中心与完整应用目录，保证旧插件仍能找到并打开。迁移前保存旧导航偏好，不丢深链接。
2. 统一目录、分类和已有收藏/最近/命令面板；完成精确工具定位的版本化扩展与旧插件降级体验。
3. 标签草稿、按需加载、闲置页面释放、结果接力，共用目录和权限，不另做一套选择器。
4. 用100/500/1000条真实结构的合成目录压力验证，同时对已交付的真实DevTools包验收；合成规模不能冒充真实工具已接入。

关键验收：安装10/100个插件后主导航默认项数不变；搜索列表不启动Worker；已知工具从中心最多两次导航到达；收藏重启后可用且场景隔离；禁用项状态明确；标签切换不丢草稿；撤权后执行拒绝；慢插件时中心和独立工具可操作。记录实际耗时、内存/活动iframe数量，首次索引与热搜索分开，不编造性能达标。

本轮交付仅为现状审查和设计规格，未实现上述新版UI，未作全量规模/暗色/窄屏/屏幕阅读器验收。持续目标仍为完整插件体系接入所有工具，并记录阻塞理由。
