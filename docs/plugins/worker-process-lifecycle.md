# Worker 进程生命周期（2026-10-11）

这是 Studio 通用 stdio Worker 的生命周期保障，也是未来 ZiFile 原生插件的前置工作。原生插件仍不可安装执行；该机制不是文件、网络或资源访问沙箱。

## 已实现

- Windows：暂停创建 Worker，绑定启用关闭即终止的 Job，再恢复执行。绑定失败则终止并回收暂停的子进程。
- 取消、超时、输出超限和正常结束均终止所属进程树。主进程先结束时立即清理后代，再等待管道 EOF，避免后代继承句柄导致调用卡住。
- Windows 终止后最多等待三秒确认 Job 内活动进程为零；失败返回 `worker_cleanup_failed`。最后的 Job 句柄关闭仍提供终止保障。
- Unix：创建独立进程组并发送 SIGKILL；主动脱离进程组的后代不在其保障范围内。本轮未做 macOS/Linux 运行验收。

## 验证边界

Windows 合成真实子/孙进程覆盖取消、超时、输出超限、父进程结束且管道被继承、父进程成功结束五种场景，随后另一 Worker 可正常执行。能力子域回归 24 项通过，另行显式运行的实际 WASI 专项 2 项通过。不是全量 Rust 套件结果。

实际 WASI 专项使用当前测试程序承载修改后的外层传输，既有 debug EXE 仅作为 WASI 子运行时。没有为本轮修改重建桌面 EXE，也没有进行新桌面 UI 验收。静态检查通过；格式检查仍报告既有及局部格式差异，仅为项目规定的 advisory。

首次正常父进程退出场景曾因等待 EOF 顺序错误失败，修正顺序后通过。实际输出协议专项首次暴露旧测试预期与重装后的权限身份绑定不一致；更新测试以分别检查旧调用拒绝、新调用协议错误、恢复和失败不缓存，未更改产品权限规则。

完整日志、前后存储扫描及失败证据位于技术博客档案 `iterations/worker-process-tree-2026-10-11/`。

## 仍需完成

ZiFile 需要独立签名适配包及版本化资源输入、文件写入授权、结果产物协议；原生运行环境还需访问隔离、平台验证和攻击向量验收。详见 [ZiFile 接口需求与完整清单](zifile-integration-requirements.md)。当前 ZiFile 接受矩阵仍全部为 false。
