# 资源调用恢复记录

2026-10-11，Studio 可信父界面的本地恢复机制；不改变提供方协议或一次性调用的 Host 保证。

## 执行前记录

目录资源工具及跨工具接力在领取 Host-issued 凭据之后、发送 invoke-call 之前，先提交 IndexedDB 事务。
记录只包含版本、场景/项目、原 runtime/session/plugin/capability、调用凭据与 Host ID、显示名称和时间。
不包含输入、输出、资源内容/文件路径、桌面 token、插件 bearer 或模型凭据。
恢复记录不授予权限；所有恢复仍要求桌面鉴权、原 Host 匹配与有效的原 runtime/session。

存储失败或满额时不执行，并请求封存准备凭据。事务提交后才允许 invoke；执行前会再次核对当前视图及取消标记。
数据库 `zicode-resource-calls-v1` / `calls` 最多128条，跨实例的 readwrite 事务串行保证总量与重复检查。
同场景/项目、同 runtime/session/plugin/capability 已有待核对记录时，拒绝创建新执行，不因刷新而绕过限制。
未确认记录不自动淘汰；成功响应经过原有完整验证后移除，移除失败只保留元数据，不把已完成执行改成自动重试。

## 工具中心入口

“核对工具调用记录”只读取当前场景/项目的元数据，不加载工具、不执行、不读取文件。
关闭工具、导航或同 origin 页面刷新后，可以重新找到记录；列表操作不会重建输入或原结果。
“停止并恢复调用”是有状态操作：封存未开始调用，或对活动调用请求取消。
同 Host 的严格 ended/not_started/not_admissible 证明通过后才移除记录；active、错误、无效证明与 Host 更换均保留。
证明返回后若视图已销毁或项目变化，不移除记录。记录移除失败仍保留，不能宣称恢复原结果。

“忘记调用记录”需要明确确认，仅删除本地记录，不发送取消、不确认完成，也不删除资源或保存结果。
提示用户先检查原运行环境。它不能解除仍存活的原控制器内部锁定，也不能作为旧执行结束的证据。

## 保证与限制

- 存储归当前 WebView/浏览器 origin 与配置所有，不是项目文件、备份或跨设备同步；系统清理、用户清除站点数据、切换配置或 origin 都可能使其不可见。
- 本轮验证了同浏览器页面刷新和重新挂载，不声称已验证原生进程崩溃、掉电刷盘或完整安装目录迁移。
- Host 表仍为内存记录。跨 Host 重启不恢复旧执行终态；Host 更换继续拒绝。Host 改端口导致 origin 改变时，旧本地记录不会自动迁移。
- not_admissible 只证明原 Host 下严格凭据不能再开始且无活跃 lease；不证明历史操作未发生。
- 未恢复输入/结果/输出句柄；持久执行收据、跨 Host 终态及正式 resource.v1 仍待实现。
- 提供方 iframe 仍使用旧协议，不具有本次本地恢复机制或一次性保证。
