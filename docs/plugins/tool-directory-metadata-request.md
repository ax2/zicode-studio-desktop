## 当前事实

通用目录使用插件displayName/name分组、capability title/id搜索；现有提供方目录没有统一的能力级跨插件分类与别名。Studio已实现按pluginId来源筛选及完整选定列表计数，不把单页工具当作全目录。当前不根据工具ID私自推断产品类别，也不以Studio内置DevTools专属映射来替代插件协议。

## 建议共同确认的扩展

另行选择扩展版本标识，先补规范/校验/迁移样例/兼容测试，再允许提供方声明支持。建议能力级可选目录元数据：

- 稳定categoryId以及可本地化类别名称；一个主类，必要时少量标签，用于跨插件按任务浏览。命名空间与重复类别合并规则需明确，不能从插件绝对路径取值。
- aliases/keywords：显式声明用户会用的名称，如Base64、编码、decode；每项有长度/数量上限，纯文本，不含HTML、执行命令、文件地址或模型指令。
- shortDescription：说明用途与关键限制，不加载inputSchema、View、WASM或启动Worker/Pi即可读取。
- 多语言采用与既有manifest一致的明确回退规则；旧包缺字段时仍按来源和title/id可发现。分类不得影响稳定capabilityId、权限、执行协议或结果授权。

## Studio接收门槛

未知/无效/超量元数据的处理须固定并可测试；搜索规范化（Unicode NFKC、大小写、空白、多关键词）由Host统一实现，不能仅在当前页浏览器过滤。分类、来源、搜索、收藏和最近组合后先过滤再分页；facet计数口径说明；修订与卸载/禁用需失效旧页。100–1000项夹具覆盖边界、重复名称和少见字符，记录真实目录耗时与Worker事件0；界面检查键盘、深浅主题、窄窗和长名称。

## 提供方后续交付要求

提出可独立构建的候选包、扩展版本声明、完整元数据快照、逐文件摘要、迁移说明；Studio据此校验与验收。旧插件/单独DevTools程序保持可构建和可用。当前此项只是接口需求，尚未要求提供方采用上述字段名，也不宣称分类/别名搜索已经接入。
