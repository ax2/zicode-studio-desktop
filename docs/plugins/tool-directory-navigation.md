# 多工具切换与窄屏布局

工具目录集中搜索、来源/分类筛选、收藏与最近使用；只有打开工具才加载详情。
左侧保留一个工具入口，不按插件能力增加图标。打开的工具最多八个，切换不会重新执行或丢弃输入与结果。

已打开工具栏使用单行横向滚动，完整工具名保留在按钮的可访问名称及 title 中，窄屏长名仅在视觉上截断。
选中工具或调整窗口宽度时，只调整切换栏自身的横向位置，不移动整个表单、不抢焦点。
目录按钮回到切换栏起点；原有关闭确认及未确认执行的关闭保护保持。
键盘可使用 Tab 移动与 Enter 激活原生按钮。资源输入控件的边距计入容器布局，不再因满宽控件加外边距而出现横向滚动条。

## 关闭工具的应用内确认（2026-10-11）

通用工具中心使用浏览器原生`dialog.showModal()`，在应用内容中确认关闭，明确列出工具名称及丢弃输入/结果的影响。
默认焦点为取消；Enter默认取消，Escape及取消均保留内容。Tab/Shift+Tab在确认动作内循环，
浏览器top layer使背景内容不可交互。取消后恢复关闭按钮焦点；确认移除后回到工具目录按钮。
明确确认只关闭指定工具，其他工具的输入和结果保留。运行/取消未确认期间仍禁止关闭；
提交确认时再次检查忙状态与场景/项目身份，切换项目后旧确认失效。

采用独立`ToolCloseConfirmation`组件及现有dialog/按钮样式；局部居中和窄屏留白使用现有间距变量。
首次Windows实测发现全局margin重置和WebView焦点时序，随后发现Tab会离开动作区；
修复布局、下一帧初始焦点及显式键盘循环，原失败记录保留。

验证：103项工具中心回归、类型检查和check通过；jsdom仅模拟dialog打开/关闭，不能证明浏览器模态行为。
实际Windows Tauri WebView2验证真实Base64调用完成，取消后结果及另一诊断工具草稿保留、
运行中关闭按钮禁用、Escape/Tab/Shift+Tab/Enter、显式关闭后重开空白均通过；
最终仅1次主动invoke，没有因打开/取消/关闭确认而增加执行。两个安装包按外部接收摘要核对一致。
桌面1440×900浅色与390×844暗色最终截图已检查，居中、标题/动作可读、窄屏左右留白且无横向溢出。
