# Markdown resource rendering candidate, preview 1

This execution contract preserves the source operation and budgets rather than reducing it to a small inline-text formatter. Current Windows installation and proven scope are recorded separately in [the delivery record](../iterations/2026-10-30-markdown-windows-delivery.md); editable drafts loaded directly from files and custom export destinations remain incomplete. The provider's original frozen contract snapshot remains unchanged.

Exact execution profile: `resource.wasi.markdown.v1 =1.0.0-preview.1`. A schema-2 WASI manifest declares exactly `devtools.markdown.render`, `resource.read`, `output.schema.v1`, `resource.output.types.v1` and `tool.directory.v1`. Runtime input is `resource.wasi.input.draft2` (module snapshot) and output is unchanged `resource.wasi.output.draft1`. Single-input count fields are omitted, not set to one. Input parameters are an empty object; no paths, URLs, commands, parser switches, templates or credentials.

The sole resource contains UTF-8 text, 0–2,097,152 raw bytes. Like the native file reader, content encoding decides acceptance regardless of filename, suffix or transport MIME; the exact Markdown execution profile owns this rule. `resource.input.types.v1` and `resourceInputMimeTypes` are omitted and rejected for this profile rather than advertising a narrower file filter. Strip one leading UTF-8 BOM exactly as the native file reader; preserve all remaining source text. Empty Markdown is allowed. Share the source Rust parser's tables, strikethrough, tasks and footnote options, 200,000-event ceiling, HTML escaping, image-to-alt-text treatment and original link allowlist. Relative, file, data, script, control-character and backslash-obfuscated navigation does not become a link. Ordinary HTTP(S) userinfo follows the existing native allowlist; this candidate does not silently change native link semantics. The operation never fetches an image, link or stylesheet.

Success creates exactly one complete UTF-8 `text/html` resource, at most 16,777,216 bytes, using the existing MIME index25 and legacy output frame. It is the same self-contained CSP HTML as the native export, including original document structure and Unicode. Links allowed by the source exporter remain in the downloadable HTML; merely preparing, sharing, rendering or saving never opens them.

The bounded result has exactly `ok:true`, `inputBytes`, `utf8Bytes` (after optional BOM), `htmlBytes`, `eventCount`, `mimeType:"text/html"`, `sourceUnchanged:true`, and `sourceToolVersion` (semver). Result limit is 2048 bytes. `0 <= utf8Bytes <= inputBytes <= 2 MiB`, difference either0 or3, `0 <= eventCount <= 200000`, `0 < htmlBytes <= 16 MiB`; descriptor length/MIME agree. Failure is `ok:false,error:{code:"MARKDOWN_FAILED",message:<bounded>}`, with no output resources. The Host replaces guest diagnostics with a fixed public message and rejects an error paired with partial output.

Initial explicit execution budget: 256MiB guest memory, 1,000,000,000 fuel and a10-second Worker deadline, to be verified with actual boundary vectors. The module declares the same memory maximum. It joins the existing 1024MiB heavy-call pool, reserving one existing512MiB permit, globally2/per-plugin1. The old compute, resource, image, metadata and regex budgets do not change. Guest imports only granted input size/read, legacy output create/write/finish and bounded WASI stdio; no filesystem or networking authority.

The trusted parent preview must render inert document structure without loading images, executing HTML or following links. Never insert provider HTML directly into the application DOM. Original source text, full generated HTML, and current selection must survive preview errors/cancellation; a changed source requires explicit sharing again. Raw markup and links remain available as non-executing text where the native preview showed them. Complete original HTML is retained for explicit confirmation/save/download; visual previews must not substitute a fragment for it.

Managed saves use existing `resource.save.draft1` with separate confirmation, generated names, no overwrite, exact receipt/digest and existing library authority. The HTML file stays a complete16MiB-or-smaller resource, not a small JSON result. No automatic execution, source read, save, download, external navigation or re-execution is added. Manual tool details alone receive Host-owned `resourceInputMin=1`, `resourceInputMax=1`, and `resourceInputLabels=["Markdown text"]`; these fields remain forbidden in the manifest. The parent offers paste/file switching for this exact negotiated role, without inventing an input MIME declaration.

Acceptance must include independent expected structure, actual native/Worker byte comparison, BOM/empty/2MiB/200000-event boundaries, invalid UTF-8/oversize/complexity failures, real Host permission/identity/cancel/output/save/library checks, rendered Windows source/preview/full HTML export and input retention. A mock/template, declared profile, passing static checks or compiled WASM alone is insufficient. Signing and other platforms do not block proven current-Windows scope.
