# 成功调用缓存与授权变化

2026-10-10，Studio Host 内部规则。冻结提供方包、工具输入输出及权限声明不变。

## 重放条件

同一运行作用域和调用 ID 只能对应原 caller、工作区、场景、插件、能力和输入。成功缓存还绑定：

- 原插件包世代和该场景的授权世代；
- 能力描述摘要，包含输入/输出协议；
- 外部插件运行模块摘要，内置 Host 操作为空。

每次重放先检查当前完整性和权限，再比较输入身份及原授权证明，并继续验证输出。修改无关插件、同插件其他场景或无变化扫描不阻止重放。目标插件权限设置、停用/启用、托管重装/升级/回滚会更换相应世代；撤销后重新授权不能复活旧缓存。

## 拒绝与重复写入

当前无权限仍返回原 `capability_unavailable` 等错误。当前已有权限但原证明不同，返回 `idempotency_authority_changed`：用户需先核对上次效果，再决定是否使用新调用 ID 执行。

宿主保留该缓存记录，拒绝时不会删除记录、启动 Worker、自动重算或把旧结果标成新成功；避免重新授权后悄悄重复可能有写入效果的操作。原有缓存容量和退出生命周期不变，仍会按原容量淘汰；这不是永久执行账本或跨重启 exactly-once 承诺。

同步有 ID 的调用在执行前捕获证明，成功后再次核对再缓存。分离式 Worker 使用启动时的证明，现有完成检查通过后才缓存。没有调用 ID 的执行行为保持。新检查不授予额外写入权限，也不替代保存预览与显式确认。

## 预算与边界

每条缓存仅增加固定摘要和两个 UUID，不复制整份 schema 或模块；模块复核沿用普通 Worker 的 2MiB 读取上限。未增加队列、磁盘缓存、依赖或工具链。

外部文件修改后完整还原会恢复字节摘要；没有记录文件系统历史，也不证明原子快照。当前规则不能保证模块在读取和执行之间没有被外部替换。持久执行账本、跨进程/重启幂等、真实写入事故恢复、全部平台及所有提供方源工具仍需另行验收。

本轮证据见技术博客 `iterations/cache-authority-2026-10-10`，明确区分注入结果的单元验证、真实 Worker 和嵌入 Pi 验证。未执行的环境测试不能计为通过。
