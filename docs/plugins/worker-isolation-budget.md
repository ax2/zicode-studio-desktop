# 插件 Worker 并发隔离（2026-10-14）

Studio 的外部 WASI 工具执行不占用 Host Broker 锁，但准备阶段仍有活动 Worker 名额。现将全局上限 64 与单插件上限 8 同时执行；同一插件占满自己的名额时，其他插件仍可取得余下名额。调用结束或被取消后，弱引用失效并在下次准备时回收。重复调用仍按现有幂等键检查。超额返回 `plugin_call_budget_exceeded`，不启动新的 Worker。

后续复核发现 Pi/Host 活动调用表在进入 Worker 前同样有全局 64 个名额。该层现在从已授权工具目录确定插件 ID，并对跨运行会话的同一插件限制 8 个活动调用；调用完成后释放名额。取消请求的预登记仍按运行实例、会话和调用 ID 定位，不伪造插件身份；执行前后仍核对目录与授权。旧版资源调用把已授权资源所有者的插件 ID 传入同一表。单个插件因此不能在 Host 入口处绕过 Worker 层的隔离。

这解决单个插件占满这两层全部 64 个名额的问题。八个插件仍能合计占满全局名额；资源准入、CPU、内存及全部 Host 请求的公平调度不由此规则统一覆盖。它不代表 ZiFile 原生插件已可安装，也不改变 DevTools 154 项和 ZiFile 108 格的完整接受计数。

资源 WASI 调用另有专用进程池，现设全局 3 个、每插件 2 个活动名额。同一插件原有的双调用能力保留，第三个同插件请求返回现有 `resource_worker_busy`；另一个插件可取得剩余名额。名额覆盖完整阻塞任务生命周期，HTTP 等待者断开时不会提前释放；任务结束或失败后自动释放。该层仍依赖可信桌面入口和后续资源授权核验，不替代真正的文件与网络隔离。

验证记录见技术博客档案 `iterations/plugin-worker-fairness-2026-10-14/work-log.md`。
