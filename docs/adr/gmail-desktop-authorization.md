# Gmail 桌面接入与验收（#116）

Studio 使用桌面 OAuth 客户端，经用户默认浏览器完成 Google 授权。邮件页面只展示当前账号和授权结果，不接收密码、授权码或令牌。以下是实现约定，不代表真实账号已经验证。

## 连接与权限

- Host 先绑定 127.0.0.1 的临时端口，再生成一次性 state 和 PKCE S256 挑战。回调只认本次地址、路径、state 与发起授权的本地账号。用户取消或超时后关闭监听；忽略无关请求，拒绝重复回调。
- 使用 Gmail API 的 gmail.readonly 阅读，gmail.send 发信；本地草稿无需申请 Google 草稿或整箱修改权限。分开表示实际授予的能力。未授予发送权限时保留本地草稿并提示授权，授权成功本身不得触发发送。
- 刷新令牌由 Host 存入按资料和账号隔离的系统凭据库。退出账号后停止同步并清除凭据；令牌失效时提示重新授权，不删除未发草稿。日志不得含授权码、令牌、邮件正文或完整授权回调 URL。

## 收发与恢复

- 收件列表使用分页令牌，正文按需读取；缓存键包含本地账号 ID 和 Gmail message ID。切换账号时丢弃旧请求的迟到结果。优先显示纯文本，HTML 必须经过隔离和清理，不自动请求远程图片。
- 用户确认收件人和正文后才发送。请求开始前记录本地发送尝试；响应明确成功后记录服务端消息 ID。超时或中断而无法确定投递结果时显示“发送结果未知”，保留草稿并提示检查已发送邮件，重启或刷新不能自动重投。

## 发版前分层验收

1. 本地协议夹具：拒绝授权、错配或重放回调、过期令牌、取消后迟到回包、分页、双账号隔离、投递响应丢失。以请求计数证明没有重复发送。
2. Google 测试账号：使用项目登记的桌面 OAuth 客户端，实际授权、分页阅读和重新打开；经明确确认向测试账号自身发送一封，核对投递记录。只记录脱敏结果。
3. 面向外部用户前：确认 OAuth 同意屏幕、隐私说明、发布状态以及 Google 对所申请权限的审核要求。测试用户成功不能代替公开分发资格。未准备好时如实标注，不将阿里邮箱与 Gmail 一并宣称可用。

官方依据：[桌面 OAuth 与本机回调](https://developers.google.com/identity/protocols/oauth2/native-app)；[Gmail API 权限与审核分类](https://developers.google.com/workspace/gmail/api/auth/scopes)。
