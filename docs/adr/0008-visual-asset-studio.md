# ADR 0008 · 视觉资产中心作为 Studio 核心模块

- 状态：架构决策已定，阶段验收待实施
- 日期：2026-11-10
- 范围：ZiCode Studio Desktop，Windows 先交付
- 决策来源：用户要求与《图片资产管理与 AI 创作中心方案》V1.0 草案评审

## 产品与模块边界

**视觉资产中心（Visual Asset Studio）是随 Studio 发布、维护和迁移的第一方核心模块，与浏览器、笔记并列。** 采用可信 React 主视图与 Rust 资产服务，复用现有导航、命令和 Host 身份校验。可在现有内置应用目录登记入口，模块的数据和生命周期由 Studio 负责。工作流模板、模型适配器、可选加工器和引擎导出器可独立扩展。

图库功能离线可用，无需 Pi、账号、GPU 或外部图像工具。Pi 在用户发起时通过受控能力读取有限元数据、创建草案和提交获准任务。保留浏览器优先的启动偏好，视觉资产按需初始化。默认显示一个图库，支持稳定图库 ID，授权绑定当前 Studio 资料与默认工作区；将来可增加图库和工作区，日常界面保持现有的简化导航。

| 边界 | 责任 |
| --- | --- |
| 视觉资产中心 | 原件、修订、标签、来源、角色版本、任务、加工产物、备份和导出 |
| Artifacts | 有界报告、导出摘要、追溯链接。资产移除或离线时能解释链接状态 |
| 工具中心 | 单次加工。用户可显式把兼容的已保存输出导入图库，先校验来源与权限 |
| 浏览器 | 网页访问和浏览器数据。后续可由用户将已选图片或下载结果送入图库，绑定来源、版本和授权。资产模块不读取浏览器 Cookie，不使网页获得文件或媒体权限 |
| Notes / 任务中心 | 笔记保留文稿和轻量引用。资产服务持有持久任务，通用任务中心可展示同一任务的进度与取消入口 |

此决策与 [浏览器引擎边界](0007-browser-engine-boundary.md) 一起使用，也沿用 [应用插件平台](0005-application-plugin-platform.md) 的扩展机制。现有 [Artifacts](../plugins/artifacts.md) 的 1 MiB 单条内容和容量限制适用于报告库。

## 数据、恢复和安全

- 目录由 `app_paths::data_root()/visual-assets` 派生，沿用[固定资料目录与隔离规则](../desktop-persistent-data.md)。Host 持有一个图库目录，每库一个本地 SQLite Catalog。托管原件可放在用户选定的本地卷，缓存有独立额度。源盘离线保留位置和版本。应用升级、重装、缓存清理及测试构建均不决定或替换图库位置。
- Asset 表示逻辑条目，Asset Revision 表示确定内容的版本，Blob 表示库内可去重的字节。保留独立来源、许可、标签与引用关系。引用模式以只读方式访问已授权根目录，打开实际文件时复核路径身份，拒绝重解析点或路径替换跨出授权根。批准的参考图和生成结果保存为不可变托管版本。预览失败、源盘离线和损坏分别标记。
- 托管导入先在目标卷暂存、验真、哈希校验和持久化，再以受控方式发布字节并提交 Catalog。每步有可重放的状态，启动时核对半成品和未提交字节。回收范围以当前引用、历史版本和备份保留期为准；源文件从不由去重流程改写。导出先写暂存区并核对 manifest；覆盖或更新工程前须显示计划并确认。
- 备份按同一个 Catalog 快照固定所需 Blob，复制期间禁止回收该快照引用的字节，完成后核对清单和摘要。默认备份托管原件、引用信息、标签、角色证据、配方和导出清单。外部引用内容需要单独纳入才可离线恢复。快照可离机保存；备份完成须在空目录恢复并打开验证。 [SQLite 在线备份](https://www.sqlite.org/backup.html)
- 先用 SQLite 本地回滚日志和单写入队列验证协议。当前 Cargo 锁定 `libsqlite3-sys 0.30.1`，本机缓存的 bundled 头文件为 SQLite 3.46.0。多连接 WAL 放行前须核对实际构建的 SQLite 版本、WAL reset 修复或回补，并测写入、checkpoint 和恢复。依赖升级单独验收，活动数据库放在本地可靠文件系统。 [SQLite WAL 与修复说明](https://www.sqlite.org/wal.html#the_wal_reset_bug)
- 首版支持静态 PNG、JPEG、WebP。解码、缩略图及批处理走受限可终止 Worker，限制输入字节、像素、内存、输出和时间。先用仓库现有 Rust 图像库验证进程隔离。预览以短期 Host 句柄绑定调用者、图库、修订和规格，重新校验权限并按有界字节传输。页面内容、第三方插件和未授权远程客户端都不能打开本地路径或直接接管预览协议。
- Catalog 提供游标分页、结构化筛选和准确中文搜索。短词用精确标签和有界补充索引，长词评估 FTS5 分词。缩略图、OCR 和语义向量可重建；LanceDB 和 libvips 作为各自阶段经基准验证的候选。 [SQLite FTS5 分词与短词限制](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)

## 开发顺序与验收

| 阶段 | 可交付功能 | 出口证据 |
| --- | --- | --- |
| P0 核心验证 | 可信入口、稳定目录、图库与修订模型、单个受限图片 Worker；托管导入、缩略图、有限列表、恢复原型 | 真实 Windows 运行中导入和打开样图。验证路径、图片上限、重复导入、落盘前后进程中断、备份恢复和浏览器同时使用。百万条元数据只用来证明查询与分页方案 |
| P1 可用图库 | 默认图库，引用和托管批量导入，中文筛选、标签和集合，重复候选，备份恢复、失败重试 | 十万级代表性真实文件、坏图和离线盘。记录硬件、冷热缓存、吞吐、查询尾延迟、内存、磁盘占用及原图摘要；实际重启和空目录恢复 |
| P2 确定性生产 | 从已有帧或图集导入、切片、时长、锚点、Alpha、播放及通用导出；首先实现 Godot | 固定目标版本的黄金工程能导入、播放并重复导出，已有工程引用保持可用。首个闭环采用已有素材，不依赖模型产出。 [Godot 精灵动画](https://docs.godotengine.org/en/stable/tutorials/2d/2d_sprite_animation.html) |
| P3 角色与生成 | 身份、造型、风格和配方独立版本化，批准参考集；先接一个明确授权的生成后端 | 参考图到审核、归档、生成配方与成本对账完整跑通。ComfyUI 按能力接入，远端结果未知先对账，不能确认时停止自动提交。再依据实际用途扩展第二个后端。 [ComfyUI 服务接口](https://docs.comfy.org/development/comfyui-server/comms_routes) |
| P4 小说、检索与引擎扩展 | 带章节与修订证据的人物草案，人工批准，智能标注与语义搜索，Unity 适配 | 文稿增量更新可追溯，人工设定不会被模型覆盖；中文检索、向量召回和 Unity 重导入分别验收 |
| P5 规模与高级生产 | 百万级真实文件全链路、复杂格式、更多动画及导出器 | 用实测结果确认规模。记录原件完整性、性能、故障恢复和导出质量 |

生成、识别和导出任务由资产服务持有，保存操作意图、检查点、尝试、预算及可用的供应商任务 ID。关闭视图不影响已授权任务；退出 Studio 保存本地状态，重新打开后恢复或核对远端。付费、上传参考图、覆盖、删除均需对应操作确认。原图精确恢复以归档和校验为依据；重生成能力单独记录。多视角是待审核设计稿，游戏交付以真实引擎验收为准。

## 与浏览器并行

P0 开始在专用会话中推进资产服务、界面与隔离验证。优先改动视觉资产专属目录。导航注册、命令权限、共享依赖和共享构建产物分批集成，提前核对另一条开发线的未提交改动；同一共享 target 的完整构建串行使用。浏览器无需等待图像索引、模型适配或导出器。

首次集成对比有无图库任务时的 Browser 冷启动、已有标签切换和窄窗口遮罩行为。记录 P95 与资源开销，再按测量冻结门槛。扫描、解码与推理限并发，浏览器交互优先于缩略图预取。构建、原型及故障注入使用隔离资料与专用样本。正式交付需逐阶段验收。
