# 文稿人物模型草案

状态：已接入只读准备、后端确认提交、本机持久尝试记录、查询和取消接口。模型建议采纳与可移机来源归档后端已通过隔离回归；前端确认与审核尚未接线。准备接口不构成网络请求授权，模型结果不直接创建角色版本。

## 输入与准备结果

沿用可信工作区窗口的 `visual_assets_control` 命令及 `novelDrafts` 请求。外层携带当前 `workspaceId`、`libraryId` 和 `sceneId`。Host 复核窗口、工作区、图库及当前 Notes 授权。

- `action: { kind: "modelCatalog" }` 返回当前场景中可用于现有模型工具的模型目录。模型必须由调用方明确选择；不启动 Pi，也不调用模型。
- `action: { kind: "modelPreview", input }` 接受 `characterId`、`facet`、`baseVersion`、已预览章节的完整 `evidence`、`provider` 和 `model`。不接受自定义提示词、任意文件路径、凭证或未保存编辑器文本。

准备时从当前 Notes 重新读取章节，校验工作区、笔记本、章节 ID、标题、修订、行号和原文；再核对角色类别的最新已保存版本。依据已保存的版本读取设定，而不是信任调用方传入的设定文本。没有该类别的版本时，基础版本和基础文本均为空。

结果的 `schemaVersion` 为 1。`prompt` 是后续发送需要展示的完整文本，由固定说明和 JSON 来源数据构成；来源只含角色名、类别、已批准设定、章节标题与所选片段。其他章节内容、工作区路径、笔记本 ID 和凭证不进入提示词。准备结果在提示词外保留证据和范围信息，以便审核、重新核验和后续追溯。

模型解析复用 `model_tools`，继续遵循其协议支持范围和配置限制。`model.endpoint` 显示地址来源，`endpointIdentity` 对完整请求 URL、供应商、模型与认证要求生成 SHA-256。即使地址来源相同，只要 URL 路径变化，目的地摘要也会变化。密钥不参与摘要，也不返回调用方。

`digest` 对除自身以外的完整准备结果生成 SHA-256，包含图库、场景、人物与类别、角色版本、章节证据、模型目的地、完整提示词和预算。同一输入及配置重复准备得到相同结果。此摘要用于识别内容变化，**不是防伪凭证或批准令牌**。

## 预算与后续发送边界

准备接口将完整提示词字符串的 UTF-8 大小限制为 32 KiB，计入来源 JSON 的转义开销。发送使用现有模型工具的取消与响应大小限制，设置输出上限为 2,048 token、请求超时为 120 秒。审核建议最多 4,000 字符，只接受明确完成的文本；截断、拒绝、工具调用或非法响应标记为不可用。费用保持未知，不能把 token 上限表述成货币费用上限。

前端接入时必须展示目的地、完整提示词及预算，并获得对应确认。当前提交接口要求 `confirmed: true`，Host 重新检查窗口、场景授权、章节与角色版本及模型完整目的地址，并重新生成计划核对摘要，不使用前端传入的提示词。固定说明把引用内容声明为资料而非命令，这不构成模型服从性或事实准确性的保证，建议结果仍需人工审核。

## 本机持久尝试

`action: { kind: "modelJob", action }` 支持以下子动作：

- `submit`：携带新的 UUID `id`、准备结果的 `digest`、同一 `input` 和 `confirmed: true`。Host 重新生成计划并核对摘要，复核 Notes 读取及 `network.fetch` 授权，再解析完整模型目的地址。凭证由 Host 读取，不写入任务。相同 ID 和摘要的重复请求只返回原记录；已有未知结果的同一计划拒绝新 ID 再发。
- `status`：按 `id` 读取当前图库、工作区及场景内的记录。`active` 仅描述当前 Studio 进程持有的执行，不能据此断定其他进程已经停止。
- `history`：按 `characterId`、可选 `before` 游标返回最近 10 项，包含 `next` 游标。
- `cancel`：按 `id` 请求取消当前进程持有的执行，返回 `cancelRequested`。取消和超时不能证明远端未执行或未计费；结果保持未知。其他进程持有的请求不由这个接口跨进程取消。
- `adopt`：携带 `selection: { jobId, draftId, text }`，从当前范围内的已完成任务读取原始模型建议，以作者审核后的 `text` 保存草案及来源。首次采纳重新校验当前章节及角色基础版本，不直接批准角色版本。

`status` 与 `history` 的 `archivedDraftId` 从 Catalog 查询，不依赖跨数据库的“已采纳”回执。

请求计划、所选片段、结果及状态存放在本机 `visual-assets-jobs/model-drafts.sqlite`，按图库、工作区和场景隔离。发 HTTP 前用同步 SQLite 事务持久化 `unknown` 记录。收到完整结果后事务提交为 `ready` 或 `rejected`，只保存有界文本、可用的供应商响应 ID、耗时及经一致性检查的用量；不保存完整供应商响应或服务器错误正文。响应丢失、取消或保存失败后保留未知，重启不自动重发。记录和结果都不表示人工批准。

每库用系统文件锁限制一个活动模型请求，当前进程最多八个请求。网络等待期间不持有图库锁。执行由 Host 持有，关闭视图不取消；窗口、工作区或 Notes 授权变化时取消等待。进程退出由操作系统释放文件锁，已落盘的未知状态不会因此变成“可以安全重发”。当前通用接口没有按供应商响应 ID 查询未知结果的协议，也尚未提供人工确认承担重复请求风险后的再次提交操作。

这些记录属于本机待审核任务，不随图库快照移动。采纳后另在 Catalog 中保存草案和来源，包含来源表的快照使用版本 9；没有来源表的既有文稿草案仍使用版本 8。前端确认、查询和审核入口尚未接线，不应把后端回归视为用户流程已经完成。

## 可移机来源归档

草案及完整模型来源在同一 Catalog 事务提交。来源保留准备计划、所选章节证据、固定提示词、模型标识与目的地址来源、原始建议、作者是否修改的标记、时间及可用用量。作者最终文本保存在草案中，由摘要绑定到来源。严格字段解码拒绝额外凭证或任意路径字段；摘要用于一致性检查，不是供应商签名。

同一任务只允许采纳一次。提交后回执丢失时，相同任务及相同审核文本的重试返回已有草案，即使调用方生成了新的草案 ID；不同文本拒绝覆盖。这个恢复路径不需要原本机任务记录或原章节仍然存在。Host 采纳路由仍要求当前 Notes 授权。只有明确批准草案才更新角色；保存、展开历史或恢复任务都不能隐式批准。

`action: { kind: "modelSource", id }` 按草案 ID 返回完整来源，先检查草案及当前工作区归属。来源读取直接使用 Catalog，不依赖模型配置、本机任务数据库或当前 Notes 授权。草案列表和已批准角色版本附带模型来源摘要，完整来源可按草案 ID 追溯。

快照备份及恢复校验来源摘要、原始建议和作者文本绑定、准备摘要、固定模板、引用证据和历史基础设定。版本 1 的提示词模板属于持久数据契约，未来调整必须新增模板版本并保留旧版校验。恢复来源不重发模型请求，也不恢复本机待审核任务。版本 9 和旧版本 8 的恢复、中断及篡改拒绝属于本轮回归范围。

## 回归范围

定向回归使用真实 Notes 和隔离 Catalog，检查选中片段与已保存设定、跨工作区与伪造证据拒绝、章节及角色改稿、同源地址下接口路径变化、场景和图库绑定、无初始类别设定、提示词中的引用命令及编码后的字节上限。回环监听用于确认准备操作没有发出请求，数据库变更计数与草案表检查用于确认准备操作没有写入模型草案或角色版本。真实模型质量与 Studio 前端交互不在这些测试的证明范围内。
