## 预算与执行时机

开始、结束耗空间工作前运行 `pwsh -NoProfile -File scripts/storage-budget.ps1`。
该命令只读，不删除文件、不联网、不构建；退出码 0 表示扫描完整且输出卷余量充足，
1 表示卷余量不足、需要评估，2 表示扫描不完整。缓存规模超过参考值只提示，
输出 `BudgetsAdvisory=true`；不能因固定容量门槛影响开发效率。默认检查本仓库 target、.cache 和 site；
显式 Cargo 目标通过 `-CargoTarget` 传入，仅审计，清理前另行确认归属。

| 对象 | 参考规模 | 超过参考规模后 |
| --- | --- | --- |
| Cargo target | 12 GiB | 记录规模，保留后续开发仍会复用的缓存，不中断构建 |
| .cache 中下载等内容（不含 task-scratch） | 1 GiB | 核对当前锁定资源与过期下载 |
| .cache/task-scratch | 512 MiB | 保留需要引用的证据，清理本轮自有临时文件 |
| site | 128 MiB | 复用固定输出目录，禁止重复文档构建目录 |
| 输出卷可用空间 | 至少 20 GiB | 停止新大构建；预计新增量大于 10 GiB 时至少预留其两倍 |

2026-10-08 按用户最新要求：必要缓存可以保留，不要求固定门槛，不因容量要求影响开发效率。
规模提示用于发现重复目录、过期下载和孤立临时文件，不作为失败或自动删除条件。
脚本统计逻辑大小，ReFS/硬链接可能使它高于实际占用；卷空间变化还受其他进程影响。
扫描跳过链接并报告未知；不能把不完整扫描当成通过。

## 生成物生命周期

1. 文档、规范、目录整理只做对应结构/链接检查，不触发完整应用构建。
2. 同一工作树复用一个 target；为实际交付才执行完整构建。诊断未完成前保留缓存。
3. 每轮临时夹具放在 task-scratch 的独立子目录；写入 owner.json，记录任务、用途、
   创建时间、所有者 PID（仅作线索）及需要保留的证据路径。退出时清理自有无引用文件。
4. 检查日志写入固定工作日志目录；同一源码状态避免重复全量测试。保留失败证据及
   最终通过报告，不能因失败而删除日志。已被文档引用的截图/报告不可按年龄自动删。
5. 已验证、非当前锁定版本的下载及孤立 .part 满 7 天后才可列为候选；确认无下载者。
   当前运行资源和依赖保留，避免下一轮重复下载/安装。缓存过期规则不套用到用户文件。
6. 阶段交付保存完整目录、EXE、摘要和说明；临时 staging 成功交接后清理。
   历史正式发布和技术档案不自动裁剪。插件构建只输出当前候选目录和正式容器，
   旧候选在被替代且无引用时清理；正式已签发包不得覆盖为不同内容。

## 清理流程

列出绝对路径、用途、逻辑大小、恢复方法和引用。校验路径属于本项目、没有链接逃逸，
检查活动构建/下载/应用进程；PID 存在不代表归属一致，需结合启动时间与命令。
清理 Cargo 时确认配置与 CARGO_TARGET_DIR 的最终值，并把正式交付移出 target 后才运行
`cargo clean --manifest-path src-tauri/Cargo.toml`（显式目标需同样传递）。
用原生 PowerShell 的 LiteralPath，禁止跨 shell 拼接删除或通配清空整个盘。
自动审批拒绝后保留拒绝原因，不改用另一工具绕过。

记录删除文件数量/逻辑字节及清理前后卷空间；若无合适候选，就记录无需清理。
本规则与只读审计脚本不代表已实现计划清理服务。

需要逐项查看 `.cache/task-scratch` 时，运行
`pwsh -NoProfile -File scripts/storage-scratch-inventory.ps1 -Top 20`。
该脚本只统计顶层条目的逻辑大小、文件数、链接或读取异常及 `owner.json` 是否存在，
并输出 `ReferencesChecked=false`；它不核对文档和外部归档的引用，也不授权删除。
`UnknownEntries` 非零时先查清链接或读取失败，不能据此推断目录可清理。

## 本地开发与缓存配置（2026-10-09）

日常使用bun run dev；只在需要本地EXE时使用bun run build:local，debug/no-bundle复用target/debug，不复制一整套运行资源到新日期目录。bun run build用于有意打包发布，不自动发布远端，也不自动修改版本号。本地开发继续0.1.0，以Git revision/dirty和验证日期定位变化。

Cargo dev/test使用`debug=1`保留有限调试信息，并复用同一依赖优化profile。`incremental=false`避免日常编辑与重复检查持续积累大体积增量会话；代价是修改Rust后需要重新编译crate，首次采用新profile也会重新生成受影响产物。release配置保持既有值。旧增量目录不由此自动删除，实际节省量与编译耗时仍需后续观测，不把配置意图记作已释放字节。

Cargo官方说明：https://doc.rust-lang.org/cargo/reference/profiles.html 。统一target路径，尊重并记录显式CARGO_TARGET_DIR；避免轮次切换RUSTFLAGS/feature/profile产生多套缓存。

2026-10-09 WASI启动诊断：当前debug EXE对同一文本WASM直接调用2533ms成功；同源码引擎定向测试编译2305ms、guest计算9ms。此前真实工具工作台5220ms超时仍保留，不能用绕过Host的诊断当完整验收。dev针对cranelift-codegen与regalloc2设置opt-level=2，test继承；只优化运行时WASM编译热点依赖，不改变应用debug级别、release、执行预算或沙箱。首次需要重建这两项及依赖它们的本地产物，复用单target，禁止轮次间切换该设置；实际耗时/大小记录于技术博客iterations/wasi-startup-2026-10-09，不预先声称改善或释放空间。

开发、本地构建和Rust检查入口会将相对CARGO_TARGET_DIR统一解析为项目根目录下的绝对路径，避免从不同工作目录启动时重复生成缓存。显式绝对路径保持原位置。不要为每个阶段设置新的路径，也不要为了验证这一规则重新编译依赖。

旧dirty开发运行目录按本轮逐文件SHA索引压缩为最新完整运行基线与独有内容集合，不生成ZIP；最新基线因历史索引引用必须保持不可变。正式已签发版本不套用此规则。开发截图/日志/合同和插件版本仍有独立记录，协议不因应用版本保持不变而跳过兼容性版本。
