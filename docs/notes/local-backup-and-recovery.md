# 笔记的独立备份与恢复

**同步不是备份。** 同步用于让各端接近同一份当前资料，误删、错误修改也可能随之传播。云服务保留期限、服务故障和账号可用性也不能由同步功能保证。请另外保留一个不随同步继续变化的副本，并试着恢复它。

## 日常保留一份可读备份

1. 保存当前笔记。在笔记左侧的「数据管理」中选择「导出全部笔记本备份」。只备份一本时可选择「导出可读备份」。
2. 将下载的 JSON 另存到当前资料目录之外，例如自己的独立备份存储或外接盘；保留多个日期版本，不要让下一次同步覆盖唯一的备份。
3. JSON 包含已保存的笔记正文、标题、标签、来源、笔记本层级、回收站笔记和附件字节。它是明文，可按私人文档放入自己的加密备份存储；不会自动使用云端恢复码加密。
4. 未保存的编辑、Studio 设置、同步队列、模型/云端凭据、笔记本展开状态等不属于这份笔记 JSON。原始目录中无法识别的自建文件也不能仅靠 JSON 保存。

附件必须符合既有格式和 1 字节至 5 MiB 的单件限制；一本笔记本附件合计最多 50 MiB，界面导入的 JSON 文件最多 70 MiB；一本的活动和回收站笔记合计受既有笔记数量上限约束，超限导出会报错，不生成已知无法导入的档案。更大资料可按笔记本分别导出，同时保留下面的完整冷副本，不要通过手工删改 JSON 或附件来绕过限制。

v0.6.7 开发分支补充了完整性检查：如果受管笔记本配置、UUID 命名的笔记/回收站文件无法读取或解析，或者受管附件无法读取、非法、为空，导出会报错；不会把少了笔记或附件的 JSON 当作成功的完整备份。普通说明文件等确非笔记内容仍按原规则过滤；普通笔记列表仍保留容错发现行为。先保留原资料的冷副本，再处理异常文件；不要删除唯一原件来消除报错。

## 在全新资料中试恢复 JSON

1. 使用一个新的、自己控制的隔离资料目录。现有参数是 `zicode-studio-desktop.exe --isolated-profile "D:\Studio-Recovery-Test"`；具体规则见[独立测试资料](../desktop-isolated-profile.md)。不要用这个示例覆盖当前资料，也不要把不可信目录当作安全沙箱。
2. 打开笔记，在「数据管理」选择「导入全部笔记本备份」，选中之前独立保存的 JSON。
3. 导入创建新的笔记本，名称会带 `(Imported)`，不会覆盖原有笔记本。层级和内部笔记引用会映射到新笔记本；已保存笔记的正文、来源和时间保留，新笔记本本身的创建时间反映本次导入。
4. 逐项核对笔记本层级、几篇正文、来源和标签；打开图片/附件，并从回收站恢复一篇带附件的笔记。仅看到列表或数量不代表附件和内容都恢复成功。
5. 原 JSON 保留不变。畸形或损坏的完整导入应报错并保留目标中原有资料，不应留下半套已导入笔记本；不要反复改写唯一备份。

离线 JSON 恢复不需要 WebDAV 密码或云端恢复码，也不会自动开始云同步。恢复后如果要重新接入云端，应另行核对同步库 ID、原恢复码和连接信息，见[云同步设置](cloud-sync-settings.md)。

## 保留完整本地冷副本

导出 JSON 之外，还可以保留完整资料目录的副本：保存编辑后，从托盘完全退出 Studio，再复制资料。不要只复制 EXE、安装目录或某个版本的构建目录，也不要在程序仍写入时直接复制 SQLite/笔记文件冒充完整快照。

固定资料规则见[固定数据目录](../desktop-persistent-data.md)。使用 `profileRoot` 时，需要完整保留它的 `system`、`data` 及其他子目录；默认分开的系统/运行资料，以及过去保留在外部位置的笔记资料，也要一并保存。工作区原位置与注册信息相关，不要只保存索引或手工改数据库来搬动笔记。

先把冷副本恢复到一个新的受控测试资料目录，核对笔记正文、原附件和回收站后再决定日常资料的恢复位置。系统凭据库中的秘密不会因复制资料目录自动迁移到另一台设备；云端恢复码与密码请另外保管。本说明只承诺已验证的笔记恢复范围，不把资料目录复制当作所有应用或账号迁移验收。

「设置」中的工作区快照保留最近若干份，适合撤销本机误操作；它仍在本机，不能代替异盘/异地备份。云端恢复码解决解密问题，不能在云端对象已丢失时凭空恢复正文；只有恢复码也不是备份。

## 本轮验证范围

Windows 自动化使用合成笔记和两种二进制附件，通过真实应用存储与 HTTP 接口，在三个独立 `--isolated-profile` 进程/资料目录中验证原资料、完整冷副本和独立 JSON 恢复。恢复前原路径已下线，合成恢复码文件也已移除；没有用源目录或密钥为恢复兜底。另有损坏笔记本／活动笔记／回收站笔记／附件导出拒绝、非笔记文件过滤、普通列表容错、损坏 JSON 整体回滚和已有目标笔记保留用例。

这些是同一台 Windows 的独立资料验证，不是两个实体设备或真实 WebDAV 服务验收；后者继续由 [#25](https://github.com/ax2/zicode-studio-desktop/issues/25) 跟踪。同步配置/冲突和恢复管理入口继续由 [#24](https://github.com/ax2/zicode-studio-desktop/issues/24) 跟踪。
