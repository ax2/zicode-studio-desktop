# 手动工具目录修订值流式计算

## 目标与修改

手动工具目录的搜索、分页和详情都先计算当前修订值。原实现每次把场景、注册表状态与所有插件清单序列化到一个随工具规模增长的 `Vec<u8>`，再进行 SHA-256。现用固定缓冲区把相同 JSON 字节序列直接写入哈希器，避免一次全量临时分配；修订值语义、失效条件、目录响应及工具调用授权均不变。搜索仍遍历当前注册表，未引入索引缓存，不能据此声称搜索耗时已改善。

## 验证与边界

205 项合成能力夹具直接以旧 `to_vec` 算法计算预期 SHA-256，与新 `manual_revision` 相等；最终代码专项 1/1 通过，其他 696 项过滤。`bun run check:rust:static` 的 Cargo check 与严格 Clippy 通过，整仓 fmt 保留既有漂移提示；`git diff --check` 通过。未运行全量 Rust 套件，未构建新 EXE，也未操作 ZiDevTools 包或隔离 JSON 插件状态。此项只降低修订计算的临时内存需求，不证明真实 100/500/1000 插件的搜索性能或跨平台原生体验。完整 DevTools 工具接受仍为 0/154。

空间扫描前后均完整，因 E 盘低于参考余量退出 1；`target` 从 30,024,956,704 B / 75,700 文件至最终 30,026,213,252 B / 75,709 文件，逻辑增加 1,256,548 B。其他被扫描目录未变；卷空闲由 8,986,329,088 B 变为最终 9,150,967,808 B，受并行活动影响不能归因于本轮。未因容量参考值清理可复用缓存。
