# 2026-09-29 本地模型代理流式回复

## 目标与发现

- Pi 经桌面 Host 的本地模型代理访问可选 QVeris 网关。代理原先在上游响应头到达后调用 `bytes().await` 读取完整回复，再向 Pi 返回；SSE 聊天被整段缓存，首个片段无法及时显示，长回复还增加 Host 内存占用。
- 现有 reqwest 已启用 stream 特性，Axum 响应体支持从字节流创建。

## 修改与决定

- 保留原有回环入口限制、请求角色转换、上游 HTTP 状态及 Content-Type 透传；响应体改用上游字节流直接交给 Axum。
- 代理请求体现在有独立 16 MiB 上限，避免全局默认 2 MiB 阻断较大的代码上下文，同时继续限制 Host 的 JSON 重写内存；请求的 `Accept` 与上游的 `Cache-Control`、`Retry-After` 一并透传。
- 不再为了日志读取上游完整正文，只记录状态和正在流式转发。客户端断开后流对象可随响应体释放；上游读到一半失败时，已发送的状态无法改成 502，错误由响应流传递。
- 等待上游响应头最多 180 秒；超时返回 `504 model_gateway_timeout`。计时只覆盖响应头到达前，不中断已开始的长时间流式回复。请求体超过 16 MiB 时由 Axum 在进入代理处理函数前返回 413。
- 该代理目前仍是特定网关的可选适配路径；本轮不改变目标地址或其他用户自选模型渠道。

## 验证与遗留

- 接续请求上限与头部修改后，`rustfmt --edition 2021 --config skip_children=true --check src-tauri/src/host_server.rs` 与目标差异空白检查通过；未运行 Rust 编译、测试、真实 SSE 请求或三平台桌面验收。
- 接续响应头超时修改后做格式与差异检查；Rust 构建缓存已清空，完整检查会重新占用大量磁盘空间。
- 流式传输的代理缓冲、断线处理与实际首字时间需在真实模型服务上核对。
- 本轮仅更新本地工作树，未发布。
