# 目标插件运行时查询（2026-10-18）

## 发现

手动工具调用的准备阶段与桌面能力调用的令牌边界，仍通过 `registry.list(scene)` 查询一个目标插件。完整列表会给每个签名插件读取签名元数据和保留版本目录；插件达到上百个时，无关包的磁盘状态可能拖慢当前工具。这两个判断只需要目标插件的来源与运行时声明。

## 修改

注册表新增目标插件的内存运行时声明查询。手动准备保持原条件：插件不是内置项，且 `runtime.worker` 或 `runtime.wasi` 是字符串。桌面能力调用的令牌边界改用已有目标插件来源查询，仍对非内置插件与结果捕获要求桌面令牌。查询不到目标插件时两处判断均保持拒绝。没有改签名校验、权限授予、Worker 执行或结果保存语义；目标包自身的检查仍由后续执行路径承担。隔离 JSON 对象插件维持用户指定的禁用状态。
