# 项目工作导航时序

日期：2026-10-01。状态：代码已修改，桌面验收待补。

## 目标与发现

项目页的任务和自动化行通过全局事件打开对应中心并聚焦指定条目。旧任务入口在发起页面激活后固定等待 200 毫秒，再调用 `focusTask`；自动化入口则在等待激活前就调用 `focusWorkflow`。插件壳激活可能异步等待当前页面的退出检查，因此两种时序都不能保证焦点操作发生在目标页面已激活后。

## 修改与决策

- 同目标激活请求共享进行中的激活 Promise；后续调用者可等待同一次切换完成。不同目标激活请求串行执行，较新的请求不会被较慢的旧请求反向覆盖；即使某次激活报错，队列仍可继续处理后续请求。
- 任务和自动化跳转等待激活结束，确认当前页面仍是对应中心，再传入目标 ID。任务 ID 仅接受非空字符串，不再隐式转换其他值。
- 两个中心已有的焦点状态会在列表加载后使用；本轮不变更任务读写、项目权限或其他中心的导航。
