# 从工具中心打开一个文件

在工具中心点击「选择文件或拖到这里」，或将一个普通文件拖到这个按钮。目录显示文件名和大小，并用现有插件声明查找已启用的文件工具。选中接收工具后，文件出现在该工具原有的共享确认区域。「确认提供文件」创建只读快照，「执行工具」才运行插件。

文件大小最多 32 MiB，接收工具仍有各自的格式和大小限制。未声明文件后缀的包会显示“插件未声明文件类型”。工具需要多个文件、尚未启用、授权变化，或同一个工具已有打开的标签时，用户可以回到列表另选接收器。清除选择或离开接收工具会丢弃未确认的交接。已确认的快照可用原有「取消提供文件」撤销。

这是 [#29](https://github.com/ax2/zicode-studio-desktop/issues/29) 中源工具 `file-intake` 的单文件接力。浏览目录时只读取浏览器提供的文件名和大小，不读取文件内容或把绝对路径传给插件。工具代码、功能和权限来自各自独立的现有插件；Studio 负责可信文件入口。独立版还支持拖入多份文件、填写路径及 11 条指定目标路由，这些范围继续由 #29 跟踪。

Windows 主 Studio 窗口改用 WebView2 的 HTML 文件拖放。未被组件接收的文件拖放不会导航应用窗口。浏览器独立窗口和网页视图保持原有拖放行为。

## Windows 验证范围

在隔离 Windows Studio Debug 0.7.4（Host 源码 `235431bc2c949148ed8ab731f03953385e1ef0ce`，EXE SHA-256 `b18ca10e188add94d537c0d26321ab500b68b808c44cab1832506a46f053d641`）上为本次生成的工具中心前端单独装载生产资源。使用仓库既有的 [JSON 文件插件](../../tests/fixtures/devtools-json-file-0.1.0-candidate-91/plugin.json) 0.1.0 candidate 91，冻结目录索引为 `0740629545823a99b9e212126a1bb9c743742648fe5546e783c603ce3f96eab2`。

中文宽窗首装（1360 像素）和中文窄窗重启（420 像素）均通过。工具中心以合成原件查找并选择已启用的 JSON 文件格式化，候选为空时可清除并返回完整目录。文件确认前读取及快照请求均为零，确认后单独点击才执行。生产 Worker 接收 40 字节，输出完整的 53 字节缩进 JSON。输出 SHA-256 为 `0dc52a3a8dffb6aa46d8d0051c57157a623f7d3e69b0933358828a7fd0cbfb75`，两次结果一致，源文件保持。撤销共享禁用执行，离开未确认的接收工具清除候选。工具中心及资源控制器回归 404 项通过，24 项保持原来的跳过状态。

自动化为正常文件输入提供合成文件，并用标准 HTML 拖放事件覆盖渲染器路径。Windows 文件资源管理器的实体拖入仍需在包含本次原生窗口配置的下一次 Windows 候选上合批验收。
