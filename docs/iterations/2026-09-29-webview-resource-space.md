# 2026-09-29 WebView2 资源空间与校验

## 目标与发现

- Windows WebView2 离线安装器约 195 MB，同时存在于下载缓存和 Tauri 资源目录；本机项目因此有两份物理文件。
- 下载脚本原先使用 `readFileSync` 一次性读取整个安装器计算 SHA-256，安装和复用检查均产生与文件大小相当的内存峰值。

## 修改与决策

- SHA-256 改为文件流增量计算，保留锁文件摘要核对及目标暂存后的二次核对。
- 安装时先尝试把已校验的缓存文件硬链接到资源暂存名；文件系统不支持时回退原有的独立复制。目标仍由暂存路径提交，缓存保留供后续构建复用。
- 已验证的现有资源若同时有锁定摘要匹配的缓存，脚本会尝试同卷硬链接去重；`--dedupe-only` 模式只处理这一已安装目标，不下载、不清理其他资源。普通构建仍可直接复用已验证资源。
- 已去重时先比较设备与文件标识；目标已完成摘要校验，同一文件不再重复读取缓存计算第二次哈希。
- 已安装资源校验通过后，普通构建遇到硬链接或替换失败只跳过去重并继续复用该资源；显式去重命令则报告失败，避免误报节省空间。

## 验证与遗留

- `node --check scripts/fetch-webview2.js`、`bun run check` 和目标差异空白检查通过；仓库现有静态检查告警仍在。
- 本机运行 `node scripts/fetch-webview2.js --dedupe-only` 退出 0。缓存和资源各自的 SHA-256 均与锁文件一致；两路径随后显示相同设备/文件标识，链接数均为 2，目标文件可继续使用。检查窗口内 E 盘空闲量净增 15122432 字节；同期其他磁盘写入可能影响净值，不把安装器文件大小等同于实测净增。
- Pi 缓存中另有 0.82.0、0.83.0、0.84.1 旧版归档及 0.83.0 下载残片，合计约 143 MB。对其中一个明确旧文件执行单文件删除时自动审批策略仍返回 `blocked by policy`，本轮停止删除尝试，旧缓存仍在。
