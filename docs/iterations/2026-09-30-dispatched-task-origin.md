# 2026-09-30 派发任务写回归属

状态：源码修改与静态检查完成；真实多工作区运行尚未验收。

## 目标与发现

任务从 Runtime 面板派发时，子代理可在另一个目标项目运行，但任务记录仍属于发起派发的工作区。此前 `public/native/app.js` 的派发后状态、子会话绑定、费用累计和完成结果都调用动态的 `window.__picotConfigCall`。用户在任务运行期间切换工作区后，这些调用会改向当前 Pi 实例，导致原任务未更新，甚至在任务 ID 相同时写错工作区。

## 修改

- 在 `sa-dispatch` 收到任务时复制发起工作区的 Pi 目标，并把任务的读写请求固定到该目标。子实例到任务 ID、执行目标和任务归属目标分别记录。
- 后台子代理的 `session_bound`、费用累计与结束事件使用任务归属目标读写；用户回答待输入任务时优先使用同一归属映射。
- 完成写回成功后才清理实例映射和摘要，并发完成通知。读取不到任务或保存失败时撤销结束事件占位，保留后续恢复机会。
- 同一窗口页面重载前把任务 ID、子实例与归属实例的必要路由标识写入 `sessionStorage`，最多 128 条、仅接受 7 天内结构有效的记录。重载时在 WebSocket 连接前恢复订阅；子实例及源实例的临时会话 ID 升级后刷新映射。映射不含任务内容、令牌或凭据，存储失败不阻塞派发。
- 子实例启动后重新读取归属工作区的任务记录；只有任务仍为待派发/运行状态、目标项目未变且未绑定其他子实例时，才保存新的路由并发送提示词。记录已删除或被其他窗口抢先派发时停止这次提示词。失败回写同样核对当前状态和子实例，避免覆盖已取消、已完成或其他实例的结果。
- 从待处理状态重新派发时清空上一轮的子工作区、实例、会话和开始时间，再记录本轮子实例。这使人工重试不会沿用上一次失败运行的导航目标。

## 边界与风险

映射可跨同一窗口的页面重载恢复，但依赖 `sessionStorage` 可用、原 Pi 实例仍存活及子实例可重新订阅。关闭窗口、应用重启、存储过期或实例已退出时，当前代码只能在当前工作区任务文件中按子实例 ID 尝试恢复；其他工作区的任务可能仍停留在运行中。完整恢复需要 Host 持有跨工作区任务索引及写入能力，和全工作区派发器一同完成。固定目标请求失败时不能静默改写当前工作区。
并发抢先导致派发停止时，子 Pi 实例已经创建但未收到提示词。Host 现有的临时实例回收器每五分钟扫描一次，回收创建超过 15 分钟且处于 Idle、Ready 或 Suspended 的临时实例；无需为此另加未鉴权的停止路由。即时回收仍未实现，但不会因此执行失效或错误项目中的任务。
提示词成功发送后，快照获取或会话 ID 写回失败不再把正在工作的子代理误标为失败；后续 `session_bound` 事件仍可补链。绑定、费用和完成写回核对当前任务的子实例 ID，旧实例事件不能覆盖重试后新实例的记录。
