# Installed frontend resource isolation — 2026-11-06

The daily local debug EXE previously preferred the checkout's `public` directory even after being copied to the installation directory. Source edits and frontend rebuilds could therefore change the daily UI without installing a new program. The daily installation now serves its own verified frontend files from `D:\work\apps\zicode-studio-desktop\public`.

## Implementation

`src-tauri/src/runtime_assets.rs` owns resource resolution, extracted from the large `main.rs` composition root. A debug executable running from its actual Cargo profile directory retains live source assets. A relocated executable uses its Tauri resource directory's `public`, just as release builds do. The comparison canonicalizes both directories and derives the compile-time profile location from Cargo `OUT_DIR`, covering custom targets/target triples. It does not depend on the process working directory. A missing installed `index.html` now fails runtime setup with an explicit missing-interface message instead of selecting the available checkout. The fixed user profile/data selection is untouched.

The production main module was reduced rather than expanded with the new resolver. No frontend source semantics, native commands, permission sets, data schema, product version or runtime budget changed. A stale old test helper was removed when its sole test moved into the new module.
