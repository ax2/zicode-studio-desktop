# 千工具搜索任务隔离与容量边界（2026-10-18）

## 背景与目标

上一轮将工具目录搜索的排序、索引与修订计算移出全局插件注册表锁，但计算仍在 Host 的异步 HTTP 请求线程中。千工具分页实测的合成场景会重复计算目录，多个搜索请求可占用事件处理线程并积累工作。本轮针对 Studio 的 Host 隔离能力，不改变提供方包或用户插件状态。

同时复核 ZiFile 与 DevTools 全量接入矩阵：ZiFile 的目录树与大归档流式输入、受约束原生 Worker、密码引用和写入事务仍需独立 Host 扩展及提供方实包；Studio 现有 `resource.local-directory.draft1` 只共享单层名称与类型。DevTools 的 154 项完整 scope 仍需要正式资源契约和提供方逐工具包。上述缺口不因本轮搜索改动而变更接受数。

## 修改

搜索在注册表锁内取得同一时点的目录输入快照后，把排序、索引、修订、相关性排名及有界响应组装交给阻塞任务池。每个 Host 最多四个同时进行的搜索；无名额时在复制目录前返回 HTTP 429 `catalog_busy`，不创建无界等待队列。名额由实际工作任务持有，即使 HTTP 等待者断开也不会提前释放。搜索完成后再次核对运行会话与 Broker 令牌；若身份变化，拒绝返回旧目录。加载和调用原有的当前修订、权限与完整性复核继续保留。

此边界减少搜索计算阻塞异步请求线程，并限制并行内存快照数；它不代表已测得 UI 延迟改善，也不替代完整的生产负载量测。状态在搜索快照后变化可能使目录短暂过期，加载与调用仍会拒绝失效修订。
