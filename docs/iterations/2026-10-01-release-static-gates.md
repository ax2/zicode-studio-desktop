# Release 打包前静态门槛与运行时检查

日期：2026-10-01。状态：工作流已修改，远端运行待验收。

## 目标与发现

正式 Release 构建已有前端测试与 Rust 检查，但没有执行开发平台已有的五个独立 TypeScript 门槛或 Biome/设计规则。另有四个内嵌运行时下载命令写在一个跨系统步骤中；Windows PowerShell 对前几个原生命令的非零退出码可能继续执行，最后一个成功会掩盖早期失败。Windows 运行时版本探测也没有逐一检查退出码。

## 修改与决策

- 在各平台打包前单独执行前端、外部客户端、金融核心、聊天收件箱核心和平台核心的 TypeScript 检查，以及 `bun run check`。每个步骤独立失败，不依赖 Shell 的多行命令退出行为。
- Pi、Portable Git、WebView2 和 Bun 的下载各占一个步骤，某一步失败就停止当前平台的后续打包。
- Windows 对 Pi、Git、Bash 和 Bun 的版本探测逐一核对退出码；WebView2 仍校验锁定摘要。
- 保留现有测试、Rust 检查与资产核对，且不把静态通过当作真实安装和启动证据。

## 验证与遗留

本地五个类型检查和 `bun run check` 均退出 0；Python YAML 解析与修改文件的 `git diff --check` 也退出 0。静态规则仍报告仓库既有的非阻断提示。本轮未运行测试、构建安装包或触发远端发布。需要下次受控 tag 发布核对每个平台的新增步骤与产物。
