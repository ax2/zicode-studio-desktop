## 交付路径

设置中的“立即同步”只在保存配置和凭据就绪时可用。用户核对已保存的地址、用户名与库 ID 后单独确认；界面仅提交工作区、场景、配置 revision 和确认标志。保存/刷新/生成恢复码和重启都不会启动网络传输。

`notes_sync_task` 原生命令复用受信工作区窗口/Host origin 校验，并核对窗口绑定的工作区。开始时通过现有 Notes 插件与 storage.plugin 授权和工作区关闭门；内部解析已保存配置及专属系统凭据，前端无法覆盖目标、路径或秘密引用。Status/Cancel 仍只接受已绑定的受信窗口，但不要求 Notes 仍启用，以便撤权后取消已有任务。

每个工作区只有一个运行；Status 只含运行 ID、实际状态、冲突数量和限流期限，不含笔记正文、密钥、密码或远端错误正文。Start 从本次 Run 自身在 spawn 前取得回执，快速完成后另一窗口启动新任务也不会把新 runId 误交给旧调用。过期 Cancel 不能取消替换任务。

任务使用现有 HostLifecycle 跟踪，退出时取消并等待释放。核心仍为 `synchronize_saved`：已保存投影、持久加密队列/基线、独立传输租约、条件请求、三方合并、取消和事务写回。网络等待不持编辑锁或配置锁。捕获和写回时内部 guard 核对配置 revision，并将与 Save 共用的 settings.lock 租约持有到本地操作结束；网络期改配置后旧任务不能写回。Notes 权限、关闭状态和 Host 生命周期在操作前复核，不声称能撤回已发出的请求。
