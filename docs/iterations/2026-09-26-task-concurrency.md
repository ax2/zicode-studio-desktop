# 2026-09-26 任务保存并发控制

状态：实现及 Windows 自动化检查完成，跨平台与真实界面验收待推进。

## 发现与设计

- 任务文件实际位于工作区 `.zicode/tasks/tasks.json`；全局中心是界面概念，不代表所有工作区共享同一文件。
- 现有完整列表覆盖会覆盖其他窗口或后台刚保存的变化，并且原地写入可能留下半截 JSON。
- 读取返回内容版本；保存必须提交对应版本。在进程间排他锁内重读、校验、快照并原子替换。
- 冲突、忙碌、无版本或损坏数据均不写入；旧客户端需刷新到新协议，不提供无保护覆盖。
- 所有仓库内写入入口传递其读取版本；后台按需重读重试，前台冲突提示用户刷新。
- 锁的异常遗留采取保守处理，不按时间猜测或自动删除可能仍被占用的锁。

## 实现记录

- 独立 `extensions/task-repository.ts` 负责读取、校验、内容版本、排他锁及同目录临时文件替换。版本为原始文件字节的 SHA-256，格式变化也会触发冲突。
- 输入限制为 8 MiB，任务必须有非空且不重复的 ID。损坏文件、无版本请求和过期版本均拒绝覆盖。
- 写入在锁内重读版本并调用已有快照机制；临时文件先刷盘再替换目标。成功或失败路径清理锁，临时文件清理不掩盖原始异常。
- `picot-config` 保持任务读写命令名，读取及成功写入增加 `revision`，保存必须携带读取版本；新服务拒绝旧客户端的无版本写入。
- 旧任务数据在工作区缺少文件时回读；首次通过校验的保存写入工作区，保留旧文件作为来源，避免迁移与更新互相覆盖。
- 任务中心、创建模块、自动化入队/重试、共享后台任务更新及旧运行时面板均传递读取版本。后台单任务更新最多尝试三次，仅在版本冲突时重读并重新应用修改。
- 旧运行时面板发现保存失败时还原最近读取的列表、显示错误，并停止批准、重试或自动派发；自动化任务保存失败也不再记录成功重试历史。
- 中英文错误提示与帮助文档同步；统一平台检查增加任务存储、扩展命令、旧运行时及共享任务写入测试。
- 大型已有 store 和运行时组件仅修改现有保存调用和必要的失败处理；文件持久化与写入参数逻辑独立为模块，避免继续扩张入口职责。

## 验证设计

- 文件测试覆盖相同读取版本只允许首次提交、无版本拒绝、重复 ID、损坏数据、已占用锁、快照回调失败及旧数据保留。
- 两个真实 Bun 子进程同时持有同一读取版本，等待共同启动信号后争抢保存：断言恰好一个成功，另一个冲突或忙碌，最终文件完整且锁已释放。子进程有退出时限。
- 扩展命令测试覆盖服务协议，任务中心测试覆盖冲突后刷新重试，共享更新测试覆盖有限重试及保留其他任务变化。
- 旧运行时测试覆盖自动派发前保存失败，断言不发出派发事件；新建表单保留输入的既有用例继续运行。

## 限制与后续

- 当前保护针对同一路径、遵循新读写协议的参与者。旧服务、外部编辑器或绕过锁直接写文件的进程不在保护范围；不同路径别名和网络文件系统未验收。
- 自动化规则文件本身尚未采用此协议；任务文件的成功保存不代表工作流配置事务或跨文件事务成功。
- 崩溃可能遗留 `tasks.json.lock`。没有自动超时删除：需先检查锁记录的进程、确认所有相关写入进程已退出并保留任务文件，再处理遗留锁。PID 本身不能证明当前持有者身份。自动恢复仍待设计。
- 临时文件刷盘与原子替换避免正常读者看到半截 JSON；未实现目录刷盘，不承诺断电耐久性。替换成功后若清理失败，客户端可能收到失败，应先刷新确认实际内容。
- 文件大小和 ID 校验可能拒绝已有异常数据，保留原文件供恢复；不自动修复或清空。
- 前台修改冲突会提示刷新，不承诺所有编辑草稿都可恢复；后台重试有上限。锁繁忙不被当作无限重试条件。
- Windows 本地证据不能替代 macOS/Linux 实测。未取得本轮真实 WebView 点击或截图；未构建发布包、推送或触发远程 CI。
