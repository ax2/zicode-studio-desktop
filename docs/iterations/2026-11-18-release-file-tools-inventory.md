# Frozen release draft inventory compatibility

v0.6.5 草稿包含已独立核对的文件工具 ZIP，原库存校验只允许安装包，会拒绝正常的可选分发附件。

将原安装包库存校验提取为共享只读验证器，仅允许 **v0.6.5** 的 **`zicode-studio-v0.6.5-file-tools.zip`**，且 GitHub `digest` 必须精确等于 **`sha256:a06c5e9759bf028eb1b95da8a29ac5cfbeae68487b10f068c0253661e4f87163`**。附件可不提供；安装包数量、架构、所有其他额外资产和重复附件继续严格拒绝。

发布作业先从 `github.workflow_sha` 保存验证器及其现有 draft-reader，再检出冻结应用标签，因此旧标签不需要新增脚本或移动；也可在当前工作流源码上直接运行同一只读验证器来核验已有草稿。既有构建、标签 commit 核对和发布条件保持不变，没有新增发布／构建入口。

验证：43 项定向及既有发布策略测试通过，文件 lint、YAML 解析／冻结标签步骤顺序、差异检查通过；同一 CLI 已只读查询实际 v0.6.5 草稿并验证“1 安装包＋1 精确附件”。没有构建应用、调度 release 工作流、移动标签、公开发行或删除／修改附件。

Refs #86, #98。目标是实际执行工作流的 main；v0.6.6 版本线可复用此基础设施提交，默认仍只允许其安装包。
