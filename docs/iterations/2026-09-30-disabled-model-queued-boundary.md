# 2026-09-30 禁用模型渠道的排队输入边界

## 目标与发现

- 内置 Pi 桥接扩展已在 `input` 事件拦截新输入，并在保存禁用配置后尝试取消当前活动。Pi 的 `steer` / `followUp` 可以在配置变更前已接受、变更后才执行，因此原入口不覆盖排队消息。
- 锁定 Pi 文档说明 `before_agent_start` 在输入进入 Agent 前触发，`turn_start` 对每轮模型响应触发，`before_provider_request` 在发送提供商请求前触发。文档没有承诺在这些钩子中调用 `ctx.abort()` 能同步阻止所有传输，不能只靠静态代码宣称完全封闭。

## 修改

- 在上述三个边界重新读取当前渠道的 `enabled` 状态。已禁用或配置不可读时通知用户并请求取消；同一轮重复检查只显示一次相同提示。允许的渠道清除提示去重状态。
- 继续保留 `input` 的直接 `handled` 拦截和保存配置后的当前活动取消。渠道禁用开关仍不在普通设置页开放。

## 验证与遗留

- `bun run build:extensions` 与 `bun run check` 通过；没有运行测试或真实模型请求。全仓根 TypeScript 配置因缺少锁定 Pi 类型树、旧扩展依赖与既有类型错误无法通过，不能将其用作本改动的类型验收。
- 队列执行与取消的真实时序、已经发出的网络请求以及扩展直接调用模型的路径仍待验证和封闭。当前实现是进一步的防护层，不代表渠道禁用功能完整。
