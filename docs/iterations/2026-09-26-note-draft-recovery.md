# 2026-09-26 笔记本地草稿恢复

状态：实现与静态检查完成，运行验收待补。本轮不新增或运行测试。

## 发现与方案

- `setTarget` 在保存未完成或失败时清空当前笔记；现有保存的作用域检查只能阻止迟到响应，不能恢复编辑内容。
- 在当前设备 WebView/浏览器的独立 IndexedDB 中保存 AES-GCM 加密编辑副本，以 scene/workspace 和窗口随机标识隔离。正式笔记仍由 Host 管理。
- 输入时建立恢复副本，正常保存成功后仅清理本窗口对应副本；不同窗口不互相覆盖。无自动过期或静默裁剪。
- 恢复为待保存编辑，保留原始版本号；另存副本是独立显式操作。原笔记不存在或版本冲突时保留恢复条目。
- 明确展示存储失败、待持久化和设备本地范围；不能承诺关闭瞬间、设备故障或清除浏览器数据后可恢复。

## 实现记录

- `draft-repository.ts`：独立 IndexedDB，非导出 AES-GCM 密钥，记录标识/工作区/修订号作为认证附加数据。事务完成才认为写入结束，按修订号删除，保留不可读条目并返回其他可读草稿。单条上限 8 MiB，不截断、不自动淘汰。
- `draft-recovery.ts`：250 ms 合并输入、串行持久化、内存失败副本、切换前按旧作用域留存、页面隐藏时尝试写入、销毁清理监听。存储失败不影响普通笔记编辑。
- 恢复编辑保留原始版本并暂不启动自动保存定时器；后续编辑/保存仍走现有保存逻辑。另存副本可在版本冲突后直接使用，完成前暂时锁定编辑器；不覆盖其他未保存编辑。
- `NoteDraftRecovery.tsx`：打开、另存、下载、二次确认丢弃、刷新，以及待写入和失败提示。当前未保存笔记的打开/丢弃按钮禁用。
- 工作区变化时清空旧列表和多选状态；相同 target 通知不再清空编辑器。笔记未处于活动插件时也更新 target，避免再次打开时沿用旧作用域。
- 核对 Rust Host 后发现 version 是字符串，前端旧类型为 number；改为兼容 string/number，并只调整既有测试文件的三处回调类型注解，未新增或执行测试。
- 大型 notesStore/NotesApp 仅增加类型、模块和生命周期接线、工作区清理；新增核心逻辑均在独立模块中。

## 验收边界与风险

- 当前设备、同一浏览器 origin/桌面配置内恢复；地址/端口或配置变化、清理浏览器数据后可能无法访问，不构成 Host 备份或跨设备同步。加密密钥保存在同一设备数据库中，不防御同源脚本或完整配置访问者。
- 异步写入尚未完成时，强制退出仍可能丢失最后输入；显示 pending 不等于写入完成。IndexedDB/WebCrypto 不可用、配额或大笔记超限时保留进程内草稿并提示下载。
- 附件 Markdown 保留原资源引用；另存/导出尚不复制附件文件。不存在笔记本时需先创建笔记本或下载草稿。
- 未运行 UI、加密存储、配额、关闭恢复、跨窗口或跨平台测试。未修改 Rust，未提交、推送或发布。
