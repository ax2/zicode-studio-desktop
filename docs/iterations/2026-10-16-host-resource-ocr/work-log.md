# Host image resource to OCR receiver

Date: 2026-10-16

## Goal

Extend the existing explicit image-resource transfer flow so a user can send a generated image to Studio's built-in OCR capability, review its text result, and keep plugin boundaries intact.

## Findings

- The Host already had a cross-platform image metadata receiver, while built-in `com.zicode.ocr/ocr.text` accepted a data URL through its ordinary capability route. That was not a resource grant and could not be selected from the resource transfer directory.
- Studio OCR uses Windows.Media.Ocr. It remains Windows-only and depends on installed language packs; this iteration does not claim OCR parity on macOS/Linux.
- The ordinary OCR operation needs an image data URL; the new resource receiver is a separate capability that accepts only a language choice and reads bytes from the Host resource store after confirmation.

## Changes

- Added `com.zicode.ocr/ocr.resource-text` with a dedicated `resource.host.ocr-input.v1` profile. The Host catalog offers it only for explicit resource searches, on Windows, when OCR is enabled and `resource.read` is granted.
- Added a fixed Host receiver allowlist. It checks the built-in origin, plugin/capability IDs, profile, permission, current access proof, ancestry and resource size before invoking OCR. The plugin iframe never receives a path or image bytes.
- The Host validates MIME/decoder agreement and bounded image dimensions before converting the already-authorized bytes into an in-memory data URL for the existing OCR implementation.
- The Windows PowerShell child now has a 45-second deadline, is terminated on cancellation, drains bounded output pipes, and removes the temporary PNG after success or failure. At most one Host OCR child runs at a time.
- Resource transfer displays OCR result metadata, then publishes the recognized text as a bounded `text/plain` Host resource with the shared image in its provenance. The existing preview offers separately confirmed transfer and save actions; neither runs automatically.
