# 签名安装失败时的新发布者信任回滚（2026-10-17）

## 目标与发现

签名包安装必须在插件重载校验前持久化新发布者信任。前一轮已把写入推迟到清单、冲突和版本门槛之后，但包激活、安装元数据写入、注册表重载失败时仍会遗留本次新增的发布者信任。

## 修改

- 仅对本次安装新增的信任建立失败回滚；原已受信任的发布者不受影响。
- 精确核对 key ID、公钥及撤销状态后移除新信任。若信任状态已变化，保留它并在安装错误中附加回滚失败信息。
- 激活前的备份重命名、激活重命名以及激活后的元数据/注册失败均走此回滚。已有包文件和元数据恢复逻辑继续执行。
- 成功激活后的旧版留存/隔离证据操作失败仍需独立事务设计；此时新包可能已在运行，因此没有撤销发布者信任。

## 验证与边界

在注册表生命周期定向测试中，让 `signed-metadata` 路径成为普通文件，稳定触发激活后的元数据写入失败。安装报错，包目录回滚，签名预览重新显示发布者未受信任；随后正常签名安装、升级、回退、撤销继续通过。定向测试 1/1；Rust 静态检查退出 0，Cargo check 与严格 Clippy 通过，rustfmt 仍提示仓库格式漂移。初次编译发现闭包借用冲突，改为捕获路径副本后通过。

本轮只验证了元数据失败注入，没有模拟备份/激活重命名、重载失败及信任存储再次写入失败。若信任回滚写盘失败，错误会明确暴露，不能声称原子提交已完成。未修改 DevTools、ZiFile、插件协议、UI 或应用版本；无新截图、完整运行副本或 ZIP。正式 DevTools 全工具验收仍为 0/154。
