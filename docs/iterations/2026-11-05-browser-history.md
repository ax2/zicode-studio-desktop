# Windows browsing history — 2026-11-05

## Behavior

The compact browser overflow menu now opens Browsing history. It supports title/URL search, fifty-item pages, opening a visit in a new native tab, deleting one visit, and explicitly confirming a clear of all visits recorded up to the displayed snapshot. The confirmation explains that bookmarks, tabs and site data remain. A visit recorded while that confirmation is open has a later ID and survives the clear. Dynamic titles and URLs are plain text. The dialog hides the native website before it opens; closing or successful navigation restores the surface.

Visits come from the native WebView2 successful top-level NavigationCompleted event, using native Source and DocumentTitle. Chrome has no API to fabricate a visit or choose an owner/data path. Failed/cancelled navigation and about:blank are not recorded. Reloads and successful restored-page loads are visits. The title is the snapshot at completion, not a continuously refreshed title. Same-document SPA/fragment history is not covered by this event and remains a separate enhancement. The [WebView2 event contract](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2?view=webview2-1.0.1901.177) also notes that title changes may occur before or after completion.

Metadata format 3 upgrades to 4, adding a separate visit table and owner/ID index beneath the existing fixed browser data root. Existing bookmarks, preferences, tabs, closed-tab records and cookie profiles are retained. Records are not automatically expired. Per request, the Host returns at most 50 visits and a keyset cursor; literal LIKE searches escape %, _ and !. URLs are limited to HTTP(S), no embedded credentials and 16,384 bytes; titles are bounded to 512 characters; search is bounded to 1,024 UTF-8 bytes.

One bounded FIFO performs native history writes and chrome queries/deletions off the native UI thread. Clear uses an explicit maximum visit ID, and AUTOINCREMENT prevents deleted IDs from being reused. Normal exit waits up to ten seconds for its queued checkpoint. Queue saturation, storage errors and checkpoint timeout remain explicit failures; this is not a guarantee against abrupt process termination, disk failure or arbitrary navigation floods. Full URLs, including their query strings, are normal local history data; no network history-sync service is introduced.
