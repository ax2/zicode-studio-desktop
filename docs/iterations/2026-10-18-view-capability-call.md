## 可信父页状态查询

Studio View 调用响应不确定后，可信父页保存 Host 单次调用句柄和原 Host 实例标识，提供“查询执行状态”“请求停止”控件。取消 ACK/运行态不会解锁；只有有效终态或与原 Host 同实例的对账证明才解除同一 View 同一能力的重复执行锁。一个能力正在执行时，同一 View 的并发调用也被拒绝。终态状态接口不返回业务结果，所以 UI 只说明响应不可用并提示核对实际效果，不自动重试，也不向插件 iframe 暴露句柄。

## 同会话 View 重建恢复

继续核对发现上一实现把状态记录放在单个 View 面板实例里，切换页面销毁面板后无法在重新打开的同一 View 找回已发放句柄。现由 Studio 可信父页按 View、场景和运行目标持有记录：句柄发放后即登记，运行中切走会保持锁定；重新打开 View 可查询或再次请求停止。原 View 迟到成功时，新面板只显示“执行已结束但响应不可用”，不假称恢复了业务结果。原响应尚在路上时，`finished` 状态仍保持锁定，直到它返回或转为结果未知。空记录在 View 销毁时清除，避免大量空 View 留下会话内登记项。

前端四文件定向 53/53、`bun run check` 和中文词条覆盖检查通过；增加旧查询不得解除新面板查询 busy 状态的竞态检查。该行为仍只在合成前端环境核验；新版 Tauri 原生窗口、跨应用重启及正式提供方包待验，完整 ZiDevTools 接受仍为 0/154。用户“暂不启用”隔离 JSON 插件的决定继续保持。

## View 调用的页面卸载提示

对仍锁定的 View 普通能力调用补 `beforeunload` 提示，执行中和响应未知时生效，原响应交付后解除，插件 Host 销毁时移除监听。复用普通工具中心已有的浏览器卸载约定。合成前端定向 53/53 与 `bun run check` 通过；尚未在新版 Tauri 窗口实际触发卸载。

原生托盘路径已单独核对：工作区窗口关闭时若托盘可用则隐藏并保留 WebView；托盘“退出”直接调用 `app.exit(0)`，Exit 事件等待 Host 关闭并停止受管 Pi。托盘退出不保证走 WebView 的 `beforeunload`，所以这轮不宣称它会弹出提示。要防止退出时未确认调用状态丢失，仍需要原生退出路径的调用摘要/确认和跨重启恢复设计。隔离 JSON 插件与 `pi.tools.register` 未改，完整 DevTools 接受 0/154。
