# 受管开发插件内容身份（2026-10-17）

## 目标与发现

显式重载已经按执行代次精确撤销游标、授权和活动任务，但执行代次只比较来源、路径、发布者及解析后的清单。开发插件目录中的文件原位变化而清单不变时，旧代次仍被保留。

## 修改

- 发现受管开发插件时，以确定顺序读取目录和文件，计算包含相对路径、类型、长度及内容的 SHA-256 指纹。沿用每文件 10 MiB、包总量 50 MiB、最多 2048 文件的现有边界；拒绝链接、特殊文件、非 Unicode 路径、检查期间变化的文件，并把失败记为该插件的目录诊断，不阻止其他插件加载。
- 把指纹纳入进程内执行身份比较。同内容重载保留执行代次；内容变化或插件校验失败则轮换或移除该插件，Host 按已有精确变更处理旧游标、授权和活动任务。内置插件与签名插件继续沿用各自现有身份与签名完整性机制。
- 不改变清单、插件包格式、应用版本或 DevTools 工程。

## 验证

- 注册表定向用例 1/1：原样重载代次不变；同清单下修改包内 `asset.txt` 后，该插件代次变化，`core.chat` 保持不变。
- 真实 Host HTTP 插件生命周期用例 1/1：原样重载保留游标和运行任务；同清单下修改受管包内文件后，旧游标失效、所属任务转为 `revoked`，无关插件任务继续 `running`；随后修改清单版本、禁用、撤权和卸载的原有断言仍通过。
- `bun run check:rust:static` 退出 0；Cargo check 与严格 Clippy 通过，rustfmt 仍报 advisory。第一次带 `--exact` 的筛选运行 0 项，不计入通过数，已用正确筛选重跑。
- 前后只读空间扫描完整、未知项 0：`target` 29,419,504,255 → 29,419,827,625 B；task-scratch 均为 852,978,182 B；E 盘可用 45,405,417,472 → 45,563,600,896 B。没有执行清理，卷空间变化不归因于本轮。

## 边界与遗留

这是受管开发插件的进程内重载身份，不是持久化任务协议。正常关闭、重启与用户确认流程仍按现有机制处理。真实 DevTools 正式签名包、原生界面链路与跨平台验收仍待；完整工具接受仍为 0/154。需要继续审视签名包在外部替换时的证明身份比较，以及开发目录被其他进程并发改写时的运行隔离。

后续进展：签名包的已验证证明身份已纳入进程内重载比较，见 [签名插件证明身份与重载](2026-10-17-signed-proof-reload-identity.md)。外部并发改写的事务隔离与真实提供方验收仍待。
