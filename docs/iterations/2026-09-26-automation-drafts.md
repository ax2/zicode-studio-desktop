# 2026-09-26 自动化草稿

状态：实现和静态检查完成；运行与界面验收待补。本轮未新增或运行测试。

## 目标与决策

- 显式保存未完成的自动化配置，支持恢复、继续编辑和删除。
- 草稿保存在工作区 `.zicode/automation/drafts.json`，与调度器读取的工作流文件分离。
- 编辑已有工作流时保存独立草稿副本，不修改原工作流；恢复草稿后创建新工作流，草稿保留到用户显式删除。
- 草稿保留表单字符串，包括暂未填写的数值；不会被调度执行。
- 存储采用修订号检查、跨进程写锁、大小限制和原子替换。冲突不自动覆盖，损坏文件不回退为空列表。
- 切换工作区使旧请求的界面结果失效；进行中的文件操作不宣称已取消。

## 验证边界

- 类型、静态检查和构建不证明重启恢复、多窗口并发、真实 Host 路由或界面操作已经通过验收。
- 需后续补齐上述运行证据及 Windows/macOS/Linux 实机结果。

## 实现记录

- 新增独立扩展存储模块 `extensions/automation-drafts.ts`，限制 200 条、8 MiB，拒绝损坏文档和错误修订号；保存原始表单字符串，不引入可运行工作流字段。
- 抽出 `WorkflowForm.tsx`，增加 `draft-store.ts` 与 `DraftList.tsx`。支持未命名/未完成草稿、显式保存、恢复为新工作流、确认删除、刷新及冲突提示。
- 恢复时携带读取修订号；刷新列表不会自动让旧表单覆盖较新的草稿。冲突后保留表单输入，由用户恢复最新版本并合并。
- 草稿状态按场景与工作目录失效，旧请求不会回填新作用域。工作流表单迟到的保存结果也不回填切换后的列表。
- 工作流表单在同一次保存中写入首次运行时间；编辑时携带已有运行信息，避免原先的两次保存间隙。
- 较大的 `picot-config.ts` 和 `store.ts` 仅增加操作路由、类型与状态接线，草稿逻辑放在独立模块；入口表单抽取后低于 500 行。
- 中英文帮助、翻译字典、平台计划与 MkDocs 导航同步。没有提交、推送、发布或生成安装包。
