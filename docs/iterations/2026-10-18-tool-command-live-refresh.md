# Stage：命令面板目录变化刷新与筛选焦点

日期：2026-10-18。目标：插件目录在命令面板打开期间变化时，不继续展示旧具体工具；保持新增来源、分类控件处于键盘焦点路径内。只改 Studio，不启用用户暂不启用的 JSON 对象插件或更改权限。

## 修改

插件 registry 订阅收到变更时发出窗口级 `zicode:plugin-catalog-changed`。已挂载的 `ToolCommandPicker` 接收事件后清空旧页、重置到目录第一页并让搜索框恢复焦点；原搜索 effect 会取消旧请求并按当前查询、来源、分类和视图重新搜索。命令面板的 Tab 焦点边界纳入可用 `select` 与 `textarea`，避免新增下拉框被忽略。Host 的目录修订、执行权限和工具详情加载规则没有改变。

- 初次 `bun run check` 检出多余的 effect 依赖，已删去该状态；最终 `bun run check` 退出 0，现有 147 条 warning、10 条 info 及生成 JS 的 1 项设计 warning；`bun run typecheck` 退出 0，`bun run build:react` 原位成功。未新增运行目录或重编 Rust。

- 未在真实窗口中安装、启用、禁用或更新插件，故**目录事件触发后的运行时自动刷新仍待验收**；代码接线和静态检查不等于该流程通过。全部 DevTools 154 项、ZiFile 108 项与其他平台的完整接受均未因此改变。
