# Native browser Host wiring — 2026-11-05

The production Rust application now includes the previously verified native engine adapter through `browser/mod.rs`, with `browser_control` registered and granted only through the existing trusted desktop capability. The command checks the trusted workspace label and current Host origin before work, then checks again when its UI-thread operation executes. The webpage itself has no Tauri registration, initialization script, desktop token or native messaging access. The accepted request enum exposes create, present/hide, navigate, native history/reload/stop, close and native URL retrieval; it exposes no arbitrary JavaScript, file path, parent window, profile path or caller-supplied owner selector.

Profile identity is read from the fixed browser metadata store on a blocking worker. Native controls and engine contexts remain on the UI thread. Each owner window has its own engine/control map; a tab belonging to another window cannot be selected through that map. Events target only the owning trusted WebviewWindow. New pages start hidden. Window destruction calls the browser cleanup hook; hiding the Studio window to the tray retains its browser lifetime. This adds only imports/registration and one destruction hook to the large `main.rs`; all feature logic lives in dedicated modules.

Viewports must be finite, positive and within the native owner's logical client size. A surface revision gate rejects stale show/hide requests, including a hide arriving before the first page creation. This is necessary for dialogs, app switches and narrow overlays: the frontend must await native hide acknowledgement before exposing an overlay. Frontend wiring is still pending, so no claim is made that existing overlays already exercise this protection.

Initial compilation failed because the Tauri `Manager` extension trait was missing; the import was corrected and the failure log retained. The isolated probe policy helper remains debug-only and is not called by production control; its narrowly documented dead-code allowance covers the main binary while the separate debug runner still uses it. No production loopback exception was added.

Remaining before delivery: native acceptance of the newly wired command path, owner-window rejection, surface transitions and destruction; runtime inventory/revision reconciliation when trusted chrome reloads; re-entrant teardown behavior; trusted Browser UI, durable default routing and explicit deep-link precedence; source extraction/document revision and Pi handoff. In particular, the prior standalone engine probe does not establish runtime acceptance of this new Host layer. The complete P0 and later P1–P6 remain open. Current installed Studio, user notes, model settings and schedules were not changed.

Validation: final all-target Rust check and strict clippy passed (existing repository fmt drift advisory); all 68 command permissions passed; one surface-order regression passed. Logs: `work/browser-host-rust-final.log`, `work/browser-host-permissions.log`, `work/browser-host-tests.log`. These checks do not constitute native runtime acceptance.
