# 自动化后台生命周期收束（2026-10-01）

## 目标与当前证据

全工作区调度、派发、运行结果、丢失进程和重启恢复已经由五个 Host 后台循环执行；它们仍随桌面 Host 退出。`setup_native_runtime` 同时初始化 Tauri 窗口、Pi 运行时、元数据和 Host，直接再起一个完整桌面进程会造成调度与派发竞争，不能作为无人值守方案。

## 本轮修改

将五个循环放入同一个 Host 生命周期任务。它们仍并发运行，使用原来的工作区注册表、运行时和停止信号；Host 停止时，整组循环作为一个 future 被取消。这为后续用一份跨进程独占租约覆盖整组循环提供了明确边界。本轮没有增加常驻进程、开机启动或改变窗口关闭行为。

## 后续实现顺序与约束

1. 使用用户级系统目录中的 OS 文件锁选出唯一自动化执行者。锁需覆盖整组循环和其派生任务；失去锁或退出时先停止派发，再交接给其他进程。锁文件存在本身不代表持锁，不能用文件年龄判断进程是否仍活着。
2. 将自动化执行所需的元数据、工作区注册表、Pi 启动能力与桌面窗口初始化拆开，让同一打包程序有明确的无窗口运行入口。只有持锁进程可以调度和派发；普通桌面实例仍可显示状态和接受人工审批。
3. 定义用户可见的后台运行开关、关闭窗口与明确退出的语义，并提供状态、失败和恢复入口。不能让看不见的进程静默常驻，也不能把“任务已入队”当作“已执行”。
4. 分别验证 Windows、macOS、Linux 的进程锁、休眠唤醒、开机启动、工作区移动或离线、退出时取消与崩溃后接管。未取得这些证据前，不宣称应用退出后持续运行。

## 验证与遗留

`bun run check:rust:static` 退出 0，包含 Cargo check 和以警告为错误的 Clippy；全仓格式检查仍提示既有漂移。目标文件的格式建议中，`git_stage` 模块顺序及子模块末尾空行属于既有差异，本轮已对新加入的调用排版作局部调整。未运行测试。随后执行 `cargo clean --manifest-path src-tauri/Cargo.toml`，移除 18,936 个再生成的构建文件，Cargo 报告约 3.2 GiB。

跨进程独占租约、无窗口入口和三平台实机验收仍未实现。
