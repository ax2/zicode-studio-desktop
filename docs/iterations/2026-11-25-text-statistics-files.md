# v0.7.9 · 文本统计文件与报告

在工具中心搜索「文本统计」，点击「导入 UTF-8 文本文件…」。每份文件上限 8 KiB，以原文件字节计。UTF-8 BOM 作为编码标记处理，统计以正文为准。正文的 CRLF、组合字符和空白保持，导入可撤销。取消选择或读取失败时，当前草稿保留。

点击「执行工具」后统计 UTF-8 字节数、Unicode 标量数、行数与空白分隔词段。空文件返回四项零值。点击「下载文本统计报告」获取本次完整 TXT，只包含这四项统计。修改输入后需要重新执行。

## Windows 验证

- 使用冻结 Transforms 0.1.1 候选 01 和生产 Windows Worker，沿用同一候选的 804 文件核验及此前 Windows Host／本机 Pi 工具通道 23 项固定能力、十个权限阶段的实测。见[候选验收](2026-11-25-line-tool-files.md)。
- 正常工具中心在 1180px 英文浅色与 420px 中文深色共调用生产 Worker 8 次。每个窗口验证三种有效输入和一次超限拒绝。含 BOM、CRLF、组合字符及表情的合成文本得到 15 个 UTF-8 字节、9 个 Unicode 标量、3 行和 3 个词段；另实测空文件及含 BOM 恰好 8192 字节的文件。六份实际下载逐字节等于同次输出。
- 实测选择取消、撤销、无效 UTF-8、8193 字节导入拒绝、已编辑旧结果失效及原件回读。70 项前端与 4 项矩阵通过，8 项既有跳过。TypeScript 和词条覆盖通过。工具中心资源 SHA256 `ec4f7e4daa8a5dad97350a63e25162558d1de677518efd87f96f2063a81eeb58`。

较大文本及 Windows 原生文件选择窗口与安装版桌面下载体验由 [#28](https://github.com/ax2/zicode-studio-desktop/issues/28) 跟踪。
