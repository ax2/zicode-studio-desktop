# 2026-09-29 Pi 归档下载与校验上限

## 目标与发现

- Pi 下载脚本优先使用 Windows BITS、再使用 curl；缺少 curl 时的 Fetch 后备路径以 `arrayBuffer()` 一次性装入整个响应，没有流式大小限制。
- 归档 SHA-256 校验也用 `readFileSync` 一次读入完整文件；本机当前 Windows Pi 归档约 45 MB，异常响应可能远大于正常归档。

## 修改与决定

- Fetch 后备路径复用项目已有的 HTTPS、十分钟超时、512 MiB 上限和 `.part` 原子提交下载器。
- curl 增加 `--max-filesize`；BITS 与 curl 成功后还要检查临时文件大小再提交。BITS 本身在下载期间仍可能占用超过上限的临时空间，成功提交前会拒绝该文件。
- Pi 归档 SHA-256 改为 64 KiB 块增量读取，保留锁文件摘要比对。缓存不匹配时的重新下载行为保持不变。

## 验证与遗留

- `node --check`、`bun run check` 与目标差异空白检查通过。未运行下载、测试或三平台构建。
- BITS/curl 的代理、重定向与超大响应行为仍需真实网络验证；本轮不把静态检查视为下载成功证据。
- 仅更新本地工作树，未发布。
