# 项目上下文加密恢复（2026-09-28）

## 目标与发现

项目上下文已有按修订号保护的宿主保存，以及最近 32 个项目作用域的窗口内草稿。窗口关闭后，未保存输入仍会丢失。Notes 使用设备配置内的 IndexedDB 加密草稿仓库；项目上下文不能直接写入共享明文偏好，也不能把恢复副本当作已保存的 `.zicode/project.json`。

## 修改

- 新增独立的 IndexedDB 恢复仓库：AES-GCM 加密草稿和基准版本，非导出密钥与密文同存于当前设备配置；索引只保存项目作用域 SHA-256、随机副本 ID 和修订号。每个窗口对每个项目使用独立 ID，避免相互覆盖。
- 输入变更按 250 毫秒合并写入；切换项目时刷新待写入副本。页面显示待写入与存储错误，恢复列表可手动刷新、预览、恢复或丢弃。成功保存会移除当前窗口已提交的恢复副本；保存期间继续编辑的草稿仍保留。
- 恢复前要求已读取宿主修订号。恢复草稿与最新已保存项目上下文按字段合并；冲突继续使用现有逐字段选择界面。恢复不会自动写入项目配置；当前已有未保存草稿时，需要再次确认才能替换。
- 代表性中英文帮助与平台路线图同步。恢复副本不是备份或跨设备同步；旧窗口的副本由用户按需丢弃。
- 接续加入全设备配置最多 128 条副本的原子写入门槛，不静默删除旧草稿。达到上限会保留窗口内编辑并提示清理。无法解密的副本计数展示；索引元数据仍可识别的损坏条目可由用户二次确认后按修订号和项目作用域删除。
- 可读取的副本增加用户主动下载的 JSON 导出，记录项目名、采集时间、草稿与基准版本，排除浏览器内部作用域和副本 ID。导出文件是明文，界面和帮助中提示私有保管；下载不修改项目配置，也不删除恢复副本。
- 接续增加 JSON 导入：限制文件为 1 MiB 并核验格式、版本、来源项目、采集时间及草稿字段；解析后只提取已知字段。界面展示来源与当前目标项目，用户确认后用全新副本 ID 写入目标项目的加密恢复仓库，保留来源元数据。导入不触碰编辑器或已保存配置；后续恢复继续使用现有逐字段合并和冲突选择。
- 导入流程按文件选择和项目切换递增代次：较早文件的迟到解析结果，以及离开目标项目后的迟到写入结果，不再覆盖当前项目的预览、错误或忙碌状态。已经确认的写入仍以确认时的目标项目为准，不会因切换页面转写到新项目。
