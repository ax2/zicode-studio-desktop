# 2026-09-29 工作区快照内容摘要

状态：实现与静态检查完成；真实恢复验收待补。

## 目标与发现

快照目录、应用清单和字节数一致时，同长度文件内容变化仍无法发现。现有备份复制先写入暂存目录，恢复也先暂存来源，因此可以在发布或替换前对私有暂存树计算摘要。

## 修改与决策

- 新快照对已复制的应用目录树计算 SHA-256，目录、文件名、文件长度和文件内容按固定顺序进入摘要；只读取暂存副本，不重新读取正在变化的工作区来源。文件名使用 UTF-8；非 Unicode 文件名使用平台原始编码并加区分标记。
- 恢复有摘要的新快照时，对暂存复制后的树重新计算并比较。不一致时删除暂存，保留当前工作区。旧快照没有该字段，继续使用应用清单和大小检查。
- 备份列表显示有无内容摘要，不把“已保存摘要”误报为当前内容已通过验证。同步中英文帮助。

## 验证与风险

`cargo check --locked --all-targets`、`cargo clippy --locked --all-targets -- -D warnings`、目标文件 Rustfmt、`bun run typecheck`、`bun run check`、翻译覆盖及目标差异空白检查通过。Biome/设计检查仍报告仓库其他位置的既有提示。本轮未运行测试或真实备份恢复。摘要能发现静态快照的内容变化，但不能保证源数据在备份复制期间跨应用一致，也不能消除复制与检查之间的路径替换竞态。平台特有的非 Unicode 文件名摘要不保证跨操作系统迁移可复用；摘要存于同一份元数据中，不能抵御有意同时篡改内容和摘要。
