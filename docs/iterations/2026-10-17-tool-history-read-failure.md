# Stage：工具历史读取失败时保持目录可用（2026-10-17）

## 目标与发现

托盘可请求收藏或最近使用视图。上一阶段已处理 `accessStore` 完全缺席，但存储接口存在而 `read` 失败时，目录仍按托盘请求查询个性化视图；没有历史数据的用户可能只看到空列表。完整应用列表也会用空历史状态过滤应用。

## 修改

Studio 工具目录与完整应用列表在历史读取中、读取失败时使用 `all` 作为有效视图，并禁用暂不可用的收藏和最近使用按钮。保留托盘请求的视图状态；用户点“重试”且读取成功后恢复请求视图。工具目录继续只搜索元数据，不自动加载详情或执行工具。没有修改 Host、插件权限或持久数据。

## 验证

- 增强失败读取组件场景：托盘请求收藏后，具体工具 Host 查询不携带个性化参数，工具仍显示；按钮禁用；重试成功后重新请求工作区收藏视图。
- 增加完整应用列表对应场景：读取失败时仍显示应用，重试成功后恢复收藏视图。
- 定向 Vitest：工具目录 30 项、工具中心 4 项，共 34/34 通过；`bun run typecheck`、`bun run check` 退出码均为 0。后者仍报告既有 144 条 warning、10 条 info 和 1 条设计提示。
- 测试前后只读存储扫描完整、无未知项：`target` 29,399,231,464 B / 74,559 文件，task-scratch 838,287,896 B / 31,062 文件，逻辑量不变。没有 Rust 构建或缓存清理。

## 遗留与验收边界

正常原生窗口不易触发历史读取失败，本轮没有该状态的真实 Windows/macOS/Linux 截图；组件 DOM 验证不能代替桌面视觉验收。DevTools 正式工具包全目录接受仍为 0/154，ZiFile 0/108。Pi 1.3.0 草稿 PR 的跨平台组合检查仍未完成，应用版本维持 0.4.2。
