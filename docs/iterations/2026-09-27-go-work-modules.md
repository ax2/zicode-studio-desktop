# Go 工作区模块发现工作日志（2026-09-27）

## 目标与发现

项目命令目录通常只扫描四层并扩展 JS、pnpm、Cargo 工作区声明；`go.work` 中更深的模块不会自动出现。在只有 `go.work` 的根目录运行 `go test ./...` 也不能等价于遍历各模块。

## 本轮修改

- 保守读取有界的根 `go.work`，识别常见未加引号的单行及分组 `use ./module`。每个路径经过工作区相对目录检查，并要求目标有有效 `go.mod`；仅接受工作区内非链接目录。
- 将有效模块补充到命令目录发现，并为根命令列表生成逐模块的 `go -C module test/build/vet ./...` 固定参数命令。任务指纹包含 `go.work` 与模块 `go.mod` 内容。
- 环境清单显示 `go.work`，中英文帮助解释发现边界及 Go `-C` 的版本要求。

## 偏差和风险

- 解析器只覆盖常见字面路径。带引号、空格、外部路径、复杂注释及其他 Go 文件语法不会被猜测；目录发现标记不完整，用户仍可单独打开模块目录。
- 模块总数、清单大小和目录解析均受限。根目录的逐模块命令只处理已确认的模块；普通 `go.mod` 目录仍沿用已有命令。
- 尚未在 Windows、macOS、Linux 实际运行 Go 工作区命令。

## 验证与发布

`cargo check --locked --all-targets`、`cargo clippy --locked --all-targets -- -D warnings`、Rustfmt 检查、严格文档构建及 Git 差异空白检查均通过。按当前约束未新增或运行测试，也未实际启动 Go 工作区命令或发布安装包。检查完成后清理了可重建的 Cargo 调试构建缓存，见[空间清理记录](2026-09-28-project-space-cleanup.md)。
