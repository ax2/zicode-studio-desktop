# 自动化文件操作退出屏障（2026-10-01）

## 目标与发现

上轮把五个自动化循环放入同一 Host 生命周期任务。进一步检查发现，它们用裸 `tokio::task::spawn_blocking` 运行规则、任务和历史文件操作；外层异步任务被取消时，阻塞闭包仍可能继续，原有 `wait_for_shutdown` 不会等待这些闭包。若立即释放未来的跨进程执行锁，另一个进程可能在旧文件操作仍未结束时接管。

## 修改与决策

- `HostLifecycle::blocking` 在提交阻塞闭包时持有任务跟踪令牌，闭包真正结束才释放。Host 的既有退出屏障因此会等待这些已经启动的自动化文件操作。
- 五个自动化模块中的扫描、任务认领、阻塞状态回写、用量、会话绑定和完成回写改用同一入口。派发循环显式接收生命周期句柄；恢复循环的延迟完成任务持有克隆句柄。
- 不改变任务格式、调度间隔、审批规则或已经启动的 Pi 子进程取消策略。跨进程锁尚未接入，仍不能宣称应用退出后持续运行。

## 验证与遗留

`bun run check:rust:static` 退出 0，包含 Cargo check 和以警告为错误的 Clippy；全仓格式检查仍提示既有漂移。目标生命周期及五个自动化模块的 `rustfmt --check` 通过。未运行测试；必须继续核对 8 秒退出等待上限、长期阻塞文件系统调用、Pi 子进程以及多进程交接时序。

静态检查后执行 `cargo clean --manifest-path src-tauri/Cargo.toml`，移除 18,936 个再生成的构建文件，Cargo 报告约 3.2 GiB。
