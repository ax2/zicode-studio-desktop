# 插件管理列表轻量投影

## 发现与修改

Studio 的 `/v2/plugins` 原先向 WebView 传每个插件的完整 Manifest，包括所有能力的输入/输出 Schema、运行时路径和 Pi 工具定义；浏览工具中心或插件管理时只需要目录元数据。接入上百个插件后，这些与浏览无关的字段会随每次列表刷新重复传输和克隆。

新增可选 `summary=true`。WebView 插件网关使用轻量投影，保留应用目录元数据、View/命令、能力 ID/标题/说明、权限和安装状态；默认完整响应仍可用于既有调用方。能力详情与 Schema 仍由原有按需详情路由读取，投影不授权执行。未修改插件协议或 ZiDevTools 包。

后续将注册表状态计算抽成借用 manifest 的列表项。轻量响应现在直接从借用数据生成 JSON，不再先克隆完整 manifest；默认完整响应仍由同一列表项转换为原 `PluginDescriptor`。真实 Host HTTP 对当前 19 个内置插件测得完整列表 34,056 字节、轻量列表 17,283 字节，权限和启用状态一致。此测量只覆盖内置插件，不外推真实百包分布。

同一真实 Host HTTP 大目录专项额外核对了一个 Studio 自有的 205 能力插件：完整插件列表 81,849 字节、轻量列表 29,681 字节；摘要保留 205 个能力 ID 与权限/启用状态，不带 `inputSchema` 或运行时路径。原专项随后仍通过 40 项分页、搜索和选中详情按需加载。它是单包 205 能力的合成场景，不能代替 205 个独立插件的安装、真实 ZiDevTools 包或原生界面验收。

## 验证边界

Rust 投影专项和真实 Host HTTP 列表专项、前端网关与注册表专项已通过；具体命令、失败重跑和空间记录见技术博客同阶段工作日志。列表浏览仍需在大规模真实提供方包和原生 Studio 界面验证；本轮不提高 154 项完整工具接受数。
