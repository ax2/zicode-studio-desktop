# 模型健康检查错误隐私（2026-09-28）

## 发现

设置页的 QVeris 模型健康检查仍读取非成功响应全文，把前 200 字符拼进错误并持久化到场景模型偏好。通用健康错误只用两条正则遮盖部分 Key 形式，上游任意回显仍可能进入界面和磁盘记录。这与模型目录和金融客户端已经采用的固定错误边界不一致。

## 修改

- 非成功健康响应只保留 HTTP 状态；404 响应在 8 KiB 内仅解析明确的 `error.code=model_not_found`，保留“隐藏不可用模型”行为，不保留服务端正文。
- 成功响应按 2 MiB 上限流式读取；超过上限返回固定错误，不把响应内容加入健康记录。
- 健康错误只允许固定类别进入界面和持久化；读取历史健康偏好时也对旧错误做安全归一，之后写入会保存归一后的内容。

## 验证与限制

`bun run build:extensions`、`bun run check`、新模块定向 Biome 与 TypeScript 检查、现有配置模块定向 lint、离线 MkDocs 严格构建及 `git diff --check` 均通过；全局检查保留现有告警。本轮未运行测试或调用真实模型服务。历史偏好文件中的旧原始错误不会仅因读取而改写；下次保存该文件时会被归一。其他渠道的底层 SDK 异常现在统一显示健康检查失败，详细诊断需要另行设计安全的结构化错误码。

## 接续：成功响应的结构化判断

复核发现成功响应原先在整段 JSON 文本上查找 `"content"` 与 `OK`，元数据或其他字段也可能触发假阳性。现解析有界 JSON，只在 `choices[].message` 的 `role=assistant` 且文本 `content` 非空时记为健康；无效 JSON 或缺少 `choices` 返回固定错误类别，不回显正文。扩展构建、定向 Biome 与 TypeScript 检查、`bun run check`、MkDocs 严格构建及 `git diff --check` 均通过；本轮未运行测试，真实模型响应仍待验收。

## 接续：旧健康错误落盘清理

旧文件原先只在内存读取时脱敏，磁盘原文要等用户下次修改模型设置才消失。现在读取时检测被归一的历史错误，并在短时文件锁下重新读取最新内容、写入随机临时文件、同步落盘后替换原文件；可避免两个窗口同时读写时把旧错误或其他窗口的新设置覆盖回去。普通可见性及健康状态写入也使用同一锁和原子替换。若锁被占用或磁盘写入失败，读取仍返回脱敏结果；同一操作不反复等待，下次配置操作再尝试清理。崩溃留下的锁暂不自动删除，需后续诊断与恢复设计。未运行测试或真实模型调用。
