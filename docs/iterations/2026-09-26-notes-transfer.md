# 2026-09-26 笔记导入导出与编辑保留

状态：实现和静态检查完成；运行与界面验收待补。本轮未新增或运行测试。

## 发现与计划

- 笔记已有 Markdown、单笔记本 JSON 和全工作区 JSON 备份接口，无需另建一种备份格式。
- 导入备份当前直接清空 dirty 和选中笔记；没有等待当前编辑保存成功。文件选择后的请求读取动态工作区，可能改变导入目的地。
- 保存接口在请求完成时直接清空 dirty，会将请求期间继续输入的内容误标为已保存。
- 将保存协调和导入导出拆成独立模块；固定操作作用域，处理迟到响应，导入前确认编辑保存成功，重复传输串行限制。
- 保存期间的新输入继续保持 dirty；导入期间继续编辑时保留编辑器，不自动跳走。

## 验证边界

- 前端编译、静态检查和资源构建不证明真实备份往返、跨窗口、重启恢复及各系统运行已验收。
- 本轮不改变 Host 备份格式；全工作区导入在 Host 中逐笔记本写入，失败可能已有部分导入，需明确保留为后续事务改造项。

## 实现记录

- `editor-save.ts` 串行协调保存请求。后续保存等待前一个写入完成后再读取笔记版本；请求期间新增编辑保留 dirty，继续安排自动保存，不将新输入误标为已保存。
- `note-transfer.ts` 接管 Markdown 导入、单本/全部备份导入导出、下载和复制。导入写入前等待保存成功，残留 dirty 时停止；固定 scene/workspace，选择文件与读取文件后检查作用域。
- 导入写入期间继续输入或选择其他笔记时，返回结果保留当前编辑器；导出期间编辑内容变化时不触发下载，提示保存后重试。
- `operation-scope.ts` 提供失效代次，区分离开后返回同一工作区的旧请求；销毁时禁止迟到结果回填。主列表查询加入请求顺序检查，并用响应到达时的编辑状态决定是否保留选中笔记。
- `NoteTransferActions.tsx` 显示传输中状态并禁用重复入口；`transfer-files.ts` 承担文件选择与下载，补充取消事件，不支持下载时显示失败。
- 大型 `notesStore.ts` 抽出保存与七个传输操作；`NotesApp.tsx` 仅替换数据管理按钮接线。没有新增 CSS、修改 Host 格式、提交或发布。
- 中英文帮助、平台计划及 MkDocs 导航同步。

## 遗留

- 真实 Host 往返、保存失败/并发输入、迟到请求、文件选择取消、跨平台下载和恢复仍需运行验收。
- 已派发的导入可能在原工作区完成；前端失效不等于取消磁盘写入。
- Host 全工作区导入缺少整体事务，错误可能留下部分新笔记本；帮助说明要求重试前检查已有结果，后续需实现回滚或可恢复导入记录。
- 本轮聚焦导入导出与保存协调；普通笔记导航、删除等已有操作仍需独立检查未保存编辑的保护，不能据此宣称全部笔记操作已无丢失风险。
