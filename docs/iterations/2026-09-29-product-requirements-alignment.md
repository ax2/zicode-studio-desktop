# 2026-09-29 产品需求基线对齐

状态：需求文档已更新；本轮未运行测试或进行跨平台实机验收。

## 目标与发现

- 持续目标是本地优先的 Windows、macOS、Linux 开发者个人平台。
- `docs/requirements.md` 仍把 Windows 桌面程序作为产品定位，并要求预置不可删除、固定地址的 QVeris 模型渠道；这些条款与现行用户自选渠道实现及平台定位冲突。
- 当前 Release 矩阵声明 Windows x64 NSIS、macOS Apple Silicon DMG、Linux x64 AppImage/DEB。已有历史 Release 资产不能证明当前未提交工作树的跨平台交付。
- Rust 本地模型代理仍转发到固定 QVeris 网关，已存在使用该本地路径的模型配置；直接删除代理会破坏兼容。金融能力客户端的固定地址属于可选适配，不能等同于核心平台必需的网络依赖。

## 修改与决定

- 将产品定位和交付范围更新为三平台开发者个人平台，同时保留各平台真实验收门槛。
- 明确 Windows 内置 Git/Bash/WebView2 资源、macOS/Linux 依赖系统 Shell/Git/WebView 的差异。
- 将模型渠道要求改为用户显式配置，空配置不隐式创建渠道或联网；QVeris 仅是可选渠道，现有本地代理作为兼容路径保留。
- 将凭据和 Release 验收要求从 Windows 单平台表述扩展到三平台。

## 验证与遗留

- 对照 `README.md`、`.github/workflows/release.yml`、模型渠道工作日志和当前代理代码核对文档表述；仅检查文档差异，未运行测试或构建。
- 本轮未改变代码、既有用户配置、服务端行为或发行资产。
- 本地代理的固定上游地址仍需在保留既有配置兼容性的前提下设计迁移。macOS/Linux 的原生安装、运行、升级和卸载证据仍缺失。
