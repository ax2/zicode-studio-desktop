# 自定义 View 的具体工具定位预览

## 目标与修改

工具中心可按能力 ID 发现并加载具体工具，但过去“打开应用”只到插件首页，无法准确定位复杂 View 中的那项工具。新增可选版本化合同 [`tool.open.v1`](../plugins/tool-open-v1.md)：schemaVersion 2 插件精确声明 `=1.0.0-preview.1`，并具备主 View 和已声明能力。Host 校验结构，轻量列表投影支持标志；工具中心从选中条目传递 capabilityId。Studio 可信父页只向同插件、同场景/工作区的当前主 View channel 发送定位意图。View SDK 的 `navigation.onOpenTool` 回调只负责选择界面，回执须匹配 requestId 与当前帧；无回调、错误或超时给固定提示。旧插件仍打开首页，不通过 DOM 选择器猜测位置，也不自动执行工具或写入。

提供方需求已发送至获授权的 ZiDevTools 原会话：独立新版本包、包外收据、能力 ID 到 UI 映射及正反例；冻结候选不变，独立程序保持可用。

## 后续取消链路审计与模型确认修复

检查普通 View 能力调用后确认：`capabilities.invoke` 在目标变化时只抑制旧结果，不能停止已运行 Worker。工具中心的 `manual.tool.call.v1` 强制依赖普通工具目录修订；专用 View 能力不保证进入该目录，不能直接借用其取消能力。Studio 所需独立 Host 接口及安全、终态约束记于 [View 能力取消缺口](../plugins/view-capability-cancellation-gap.md)，尚未实现，不能声称通用 View 调用可取消。

已修正模型生成取消的两个具体边界：预览准备期间取消，收到一次性 grant 后立即拒绝，不再打开确认框；确认框显示期间取消，可信对话框收到 dismissSignal 后关闭并拒绝 grant。正向提交仍需用户确认。模型与 View Host 定向测试 31/31，`bun run check` 通过（仓库既有 lint 提示保留）。本轮不启用隔离 JSON 插件或调整 `pi.tools.register`，无新的提供方真实工具验收、原生截图或 EXE。
