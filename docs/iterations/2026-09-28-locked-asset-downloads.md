# Windows 锁定资源下载可靠性（2026-09-28）

## 目标与发现

Portable Git 和 WebView2 下载脚本此前以 `https.get` 递归跟随重定向，直接写最终缓存路径，没有总下载时限。连接中断可能使残缺文件留在缓存目录；下次虽然能由 SHA-256 发现并重新下载，但当前构建可能长时间等待。

## 修改

- 两个脚本共用流式下载函数，仅接受 HTTPS 起点和最终响应，设置十分钟总超时与 512 MiB 大小上限。
- 内容先写入目标旁的 `.part` 文件，流完整关闭后才重命名为缓存文件；失败只清理临时文件。
- 原有版本锁定、SHA-256 校验及打包资源安装逻辑保持不变。

## 验证与限制

全局 `bun run check`、三个脚本的 Biome 与 Node 语法检查、离线严格 MkDocs 构建通过。没有发起真实下载、运行测试或生成安装包，因此中断、重定向和 Windows 安装场景仍待实机验收。
