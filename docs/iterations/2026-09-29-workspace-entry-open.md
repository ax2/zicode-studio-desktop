# 2026-09-29 文件侧栏打开工作区条目

## 目标与发现

- 文件侧栏双击文件及「在文件管理器中打开」会先在前端拼接工作区根路径，再调用 `open_in_app`。
- Host 的该操作原先只允许路径恰好等于已登记的工作区根目录。因此子目录和文件均被拒绝，且前端字符串拼接不能可靠处理所有系统根路径。

## 修改与决策

- 控制网关新增按工作区 ID 与相对路径打开的调用；侧栏不再请求根路径或自行拼接绝对路径。
- Host 使用现有工作区路径解析器规范化目标，拒绝父级跳转与指向工作区外的链接。原有直接打开已登记根目录的调用保留。
- 默认应用启动仍需桌面客户端权限；远程客户端的 Host 操作边界不变。传给系统打开器时保留路径末尾合法空白。
- Host 以原始 `Path` 传入系统进程，并复用 Windows 路径前缀转换；不再用有损 UTF-8 字符串承载本机文件系统路径。
- 通用错误显示现对已有翻译键调用 `t()`；工作区未登记、路径不可用和路径越界的 Host 文本补充中文翻译，其他系统错误保留原文。
- 中英文帮助与平台日志同步。

## 验证与遗留

- 静态核对网关、Host 路由、工作区路径校验与系统打开器调用链；Rustfmt、JS 语法、`bun run check`、翻译覆盖及目标差异空白检查通过。
- 未运行测试、Rust 编译或三平台真实文件打开。无法无损表示的文件名仍不由侧栏展示；打开前目标若发生竞态变化，系统打开器可能报错。
- 仅更新本地工作树，未发布。
