# 自动化单执行者工作日志（2026-10-01）

## 目标与证据

多个桌面进程可以同时启动同一组全工作区自动化循环。规则和任务文件虽有稳定 ID 与写锁，重复扫描、子进程派发和结果回写仍不应靠竞争碰巧收敛。上一轮已把五个循环收束到同一生命周期任务，并把阻塞文件操作计入 Host 退出等待屏障。

## 修改与决策

- 在用户级 `~/.zicode/automation-runner.lock` 上申请操作系统独占文件锁。锁文件持久存在，不删除、不依据文件时间推测进程是否存活。只接受普通文件，拒绝符号链接。
- 只有持锁进程启动五个自动化循环；其他桌面进程每五秒重试。应用进程结束时，OS 释放锁，仍存活的其他进程才可能接管。
- 锁句柄保留到进程退出，晚于正常 Host 的退出等待，避免循环刚取消就让另一进程开始扫描。若 Host 在同一进程内异常停止但进程继续存活，锁不会提前交接；这属于待处理的可见状态与恢复边界。
- 现有 Host 契约测试在同一进程中启动多个实例，测试编译路径暂保留原独立扫描行为；本轮没有增加或运行测试，跨进程竞争仍需真实进程验收。
