# 模型健康结果凭据作用域工作日志（2026-10-01）

## 目标与发现

模型渠道的配置文件与系统凭据分别保存。只更换或移除密钥时，渠道修订号不会变化；旧密钥发起的健康检查可能在新密钥写入后返回，并覆盖健康状态。

## 修改与决策

- 模型偏好文件增加每个提供方的随机凭据版本标记，不保存密钥或密钥摘要。旧偏好文件缺少标记时按空版本读取，后续密钥操作会生成新版本。
- 成功更换或移除系统凭据后，在偏好文件锁内轮换版本并清除该提供方的旧健康状态。渠道表单中随配置一起更换凭据和删除渠道时也执行相同操作。
- 健康检查开始时读取版本，结束时在同一把偏好文件锁内比对并写入；版本变化则返回未知状态及刷新提示，不写入旧结果，也不会触发批量检查的自动隐藏。
- 偏好文件锁与系统凭据存储是两个资源；若凭据已写入而版本轮换失败，操作会报错，仍需人工复核。外部程序直接修改凭据不会轮换此版本。

## 验证与遗留

`bun run typecheck`、`bun run check`、`bun run build:extensions` 和 `bun run build:react` 退出 0；仓库检查仍显示既有警告。未运行测试；真实多窗口密钥更换、偏好文件异常及三平台系统凭据行为仍待验收。根扩展 TypeScript 配置仍因缺失 Pi 声明而不能作为完整类型通过证据。
