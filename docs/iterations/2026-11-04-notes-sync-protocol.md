# 笔记云同步：加密传输与合并协议阶段

2026-11-04。延续 WebDAV / 坚果云方案，实现本地可测试的协议层。**尚未在 Studio 设置中启用，不是云同步功能已经交付。** 当前运行的 Studio、固定资料库和温度功能保持上一批已验证版本。本轮没有连接用户云账号、上传现有笔记、调用模型或控制窗口。

## 已实现的范围

- 独立 `src-tauri/src/notes_sync/` 模块，接收显式传入的端点、独立凭据、同步库 UUID、密钥与对象快照；没有启动副作用、自动发现凭据或后台网络请求。主入口仅登记模块，超过 500 行入口的例外限于这两行登记，功能逻辑与测试均独立。
- 使用现有依赖树中 RustCrypto XChaCha20Poly1305 0.10.1，直接依赖和锁文件明确登记；32 字节随机密钥、24 字节随机 nonce、带版本的加密封装。加密认证绑定同步库 UUID 及索引/对象用途。恢复码能还原密钥；这仍不是完整的新设备接入流程。[官方库文档](https://docs.rs/chacha20poly1305/0.10.1/chacha20poly1305/)
- 云端对象名使用密文哈希，索引也加密。下载同时校验密文哈希、认证标签及明文哈希。凭据不放入 URL，错误仅带类型/状态码；拥有的凭据字符串与临时解码密钥在释放时清零，不进入状态序列化。
- 创建专用 `zicode-notes/<vaultUuid>/` 目录，不枚举整个云盘。先上传不可变对象，最后条件写入 `index.zns`。远端变化返回明确结果，调用方重新读取合并，不自动覆盖或重发。无变化不重复提交索引。
- 连接时仅用随机专用探测文件检查创建条件、错误版本拒写、正确版本写入及强 ETag；不兼容则拒绝索引写入。探测文件是唯一可删除的远端路径，不删除用户内容或历史对象。条件请求遵循 [HTTP If-Match / If-None-Match](https://www.rfc-editor.org/rfc/rfc9110.html#name-conditional-requests)；目录创建使用 [WebDAV MKCOL](https://www.rfc-editor.org/rfc/rfc4918.html#section-9.3)。
- 三方合并以最后确认的索引为基线：独立对象编辑合并，同一对象的不同编辑或编辑/删除冲突则返回双方原始内容，整批不提交。每个冲突都必须显式选择，不能遗漏后隐式删除；选择后仍重新检查远端版本。
- 保留删除标记，旧离线副本不能自动复活笔记；没有同步基线的旧副本遇到云端删除标记也会冲突。索引丢失、倒退或缺少已知记录时停止，而非重建覆盖。
- 正式构建只接受 HTTPS；仅测试构建接受数值 loopback HTTP。禁止重定向，避免凭据发往新地址。认证、限流、网络失败、过大或损坏数据分别返回，不在方法内无限重试。
- 当前协议边界：单对象 8 MiB、快照 64 MiB、索引 2 MiB、最多 10,000 个含删除标记的对象；各次读取均有字节上限。不是对全部既有大笔记库的容量承诺。
