# 已保存项目上下文迁移（2026-09-29）

## 目标与发现

恢复副本已有 JSON 下载与导入，但项目没有未保存草稿时没有相应下载入口。把已保存配置直接伪装成旧草稿格式会让草稿与基准相同；现有三方合并因此视为没有修改，导入到另一项目后可能不会应用任何字段。

## 修改

- 增加独立的已保存上下文 JSON 格式，按项目名、采集时间与完整配置导出；须先成功读取带修订号的宿主保存版本。文件为明文，用户主动下载。
- 导入识别该格式并只提取已知字段，继续限制 1 MiB。确认时要求目标项目已读取保存版本，以该版本作为恢复副本基准，以文件配置作为草稿。之后恢复仍使用原有逐字段合并和冲突选择，导入本身不写入编辑器或 `.zicode/project.json`。
- 旧草稿格式的导入行为保持不变；界面区分已保存配置与未保存草稿文件，并在目标版本不可读时禁止确认。
- 文件确认前展开显示项目说明、默认场景和预算；恢复列表的预览也改为三字段，避免只看指令文本就恢复整份配置。

## 验证与限制

TypeScript 类型检查、定向 Biome、i18n 覆盖（缺失 0）、React 构建、`bun run check`、严格 MkDocs 构建及差异空白检查通过；全局检查仍有既有警告。本轮未新增或运行测试。跨设备文件选择、Host 修订号、合并冲突和桌面下载仍需实机验收。此文件只包含项目上下文，不包含代码、任务、笔记或运行历史。

三字段预览接续通过类型检查、定向 Biome、i18n 覆盖（缺失 0）、React 构建、`bun run check`、严格文档构建和差异空白检查。未运行桌面交互或视觉验收；长指令文本及窄视口表现仍需实机确认。
