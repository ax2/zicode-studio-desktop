# 自动工作区备份的相同内容去重（2026-10-18）

## 目标与发现

开发者平台按日自动备份工作区 `.zicode` 应用数据，保留最多七份。到期时即使内容未变，旧实现也会发布一份新的完整副本，增加长期磁盘占用并挤占真正有差异的恢复点。用户主动创建的手动备份和恢复前回滚快照有不同目的，应保留其每次创建行为。

## 修改与决策

自动备份仍先在隐藏暂存目录完成复制和 SHA-256 内容校验。若上一份可恢复备份的应用目录、记录的校验值与新快照一致，再对上一份备份本体重新计算校验；全部一致才移除本次暂存目录并返回未创建。上一份校验失败或目录损坏时会发布新的备份。手动备份及恢复前快照不使用去重；已有七份保留上限和发布后裁剪规则不变。成功跳过时必须成功移除本次暂存目录，不能静默留下完整副本。

此策略阻止**未变化的自动备份**永久占用一个新槽位；复制期间仍需要暂存空间，且不能保证其他进程同时写入源数据时获得跨应用原子快照。没有新增清理历史备份的动作，也没有删除用户已有数据。
