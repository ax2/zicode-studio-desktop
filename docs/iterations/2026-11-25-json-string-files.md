# v0.7.9 · JSON 字符串文件转义与还原

在工具中心选择「JSON 字符串转义」，可导入 8 KiB 内 UTF-8 文本。文件开头的 UTF-8 BOM 用于识别编码，正文换行、引号与反斜线保持原样。手动执行后可下载一个完整的 `.json` 字符串字面量，包含引号。

「JSON 字符串还原」可导入该文件，选择器优先显示 `.json` 和 `.txt`。输入须为一个完整的 JSON 字符串，支持首尾空白。执行成功后可下载还原的 UTF-8 `.txt`，包括空字符串还原出的零字节结果。导入可撤销，取消和读取失败时保留草稿与原件，修改输入后须重新执行。

- 使用冻结 Transforms 0.1.1 候选 01 和生产 Windows Worker，沿用同候选 804 文件核验、实际隔离 Windows Host 和内置 Pi 本机工具通道的 23 项及十个权限阶段实测。见[同包验收](2026-11-25-line-tool-files.md)。
- 正常工具中心 1180px 英文浅色、420px 中文深色共通过 14 次生产 Worker 调用，其中 8 次转换成功，6 次预期拒绝。两种窗口直接用下载的 `.json` 还原。35 字节合成正文经 51 字节 JSON 往返后精确回读，含中文、表情、引号、反斜线、CRLF、制表符、NUL 和尾部空白。JSON SHA256 `3ad7a77b7c674d7c029720b9c7c497f90203d108b02efc5ec9897d7b6f697452`。原文件 BOM 与全部原字节保留。
- 八份下载包括空文本转义及空字符串还原，均逐字节等于该次 Worker 输出。对象、未配对 Unicode 代理项和无效转义均返回错误。另覆盖选择取消、撤销、无效 UTF-8 和旧结果失效。72 项前端、4 项矩阵通过，8 项既有跳过，TypeScript 和词条覆盖通过。生成工具中心资源 SHA256 `d3aac65b258036d6ec443c68f9b13e00bbd462d27ce2cc9c791eea6b1c4975e3`。
