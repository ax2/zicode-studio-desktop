# 2026-09-26 从项目创建任务与自动化

状态：实现与 Windows 自动验证完成，桌面交互和其他操作系统实机验收待补齐。

## 目标与设计

- 项目工作视图提供创建任务、创建自动化入口，进入已有表单并带入点击时的项目目录。
- 打开表单不保存、不派发；目标目录仍可编辑，执行模式和调度沿用中心的现有显式设置。
- 连续发起新建意图时重新初始化表单，防止复用上一个项目的字段；完成或取消后清除该意图。
- 对任务创建失败保留表单，不因服务拒绝而丢失输入；写入前刷新全局任务，避免以初始空列表覆盖已有任务。
- 同步补充事件路由、表单到服务参数和关联列表回读测试。

## 实现记录

- 项目面板仅发送创建意图，独立 `project-work-navigation.js` 先设置接收端状态，再激活中心。
  没有有效绝对项目路径时禁用入口。事件不会执行服务写入。
- 任务/自动化 store 记录带序号的创建意图，表单以序号重新挂载，保留点击时的原始目录。
  完成和取消清除意图；旧保存请求完成时不得清除更新的意图。保存中禁用取消。
- 任务创建移至 `create-task.ts`，同一中心的创建请求串行执行；每次先成功读取最新任务列表。
  读取失败或格式不符合 tasks 数组契约时不写入；写入失败返回 false，表单保留输入。
- 发布到本地 store 时按任务 ID 去重，避免轮询已看到写入结果后再次追加同一任务。
- 保留已有执行模式和调度语义；进入表单不自动提交，创建手动任务后的派发仍按用户选择执行。
- 入口大文件仅增加导入和绑定；主要逻辑、路由和测试独立成模块。

## 验证与限制

- 组件/事件测试覆盖点击项目入口、目录预填、保存参数、保留原有其他项目任务、按项目回读。
- 覆盖读取失败禁止写入、写入失败保留输入和重试成功、连续项目意图重置、用户编辑目标目录、取消自动化不保存。
- 独立写入模块覆盖创建串行化、最新状态读取、请求参数快照、失败后继续处理下一次创建。
- 草稿仍为当前视图内状态，不承诺重启恢复；新建另一项会重新初始化表单，帮助文档已说明。
- 排队仅覆盖同一任务中心的创建操作，不能替代跨进程或其他任务修改的服务端事务。
  当前任务服务仍采用列表写入；完整并发控制待后续推进。
