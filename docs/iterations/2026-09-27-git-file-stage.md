# 项目 Git 单文件暂存工作日志（2026-09-27）

## 目标与发现

项目总览已有只读 Git 状态及两种差异预览，但不能完成最基本的暂存。状态列表最多显示 200 项，未跟踪目录会合并；Git 路径可能无法用 UTF-8 无损表示，因此操作范围必须比展示范围更严格。

## 本轮修改

- Host 状态条目增加 `stageable`。仅将可无损表示、位于项目相对路径内、具有工作树改动的文件标为可暂存；聚合目录不提供操作。
- 新增桌面 Host 的 `workspace_git_stage`，只接受已注册工作区。执行前重新读取状态，核对文件及索引/工作树状态；使用 literal pathspec 暂存该条目，随后返回新状态。远程 Host 路由禁止此写操作。
- 项目总览提供单文件按钮与确认框，明确暂存执行时的工作树内容以及 Git clean filter 可能运行。成功后更新状态、关闭旧差异；结果不确定时提示刷新，不自动重试。
- 更新中英文帮助及开发者平台总览。

## 决策、偏差和风险

- 暂存以点击时的文件内容为准；状态字符校验无法保证文件内容与先前的差异预览相同。确认框和预览失效处理了这一差异。
- 未跟踪目录聚合条目、超过展示上限的文件、特殊路径暂不提供按钮。此轮没有提交、回退、推送或部分暂存。
- Git 的 clean filter 由仓库配置决定；超时后进程是否已经修改索引可能无法从原请求得知，必须重新读取状态。
- 没有通过本轮静态检查推断实际仓库暂存操作已在 Windows、macOS、Linux 上完成验证。

## 验证与发布

本轮仅执行静态检查与构建，未运行测试或实际暂存操作。`bun run typecheck`、`bun run check`、i18n 覆盖检查、React 构建、`cargo check --all-targets`、`cargo clippy --all-targets -- -D warnings` 与严格文档构建均通过。全局 lint 和设计检查仍报告仓库其他位置的既有提示。未发布阶段安装包。
