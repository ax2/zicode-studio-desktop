# 自动化规则遗留锁恢复工作日志（2026-10-01）

## 目标与发现

工作区自动化规则使用独占锁、修订号和原子替换保护并发写入。写入进程异常退出时，原有 `.lock` 文件不会被 `finally` 清理；后续窗口一直收到 `automation_workspace_busy`，即使原持有进程已经不存在。

## 修改与决策

- 新锁记录本机名、进程 ID、随机标识和创建时间。
- 遇到现有锁时，先通过独占恢复目录串行化回收者。只处理创建超过一分钟、结构完整、属于本机且系统明确报告持有进程不存在的锁；旧格式、其他机器、活进程、权限不明和不完整锁继续报忙。
- 回收前再次核对锁文件身份与长度；回收后重新以独占创建取得写锁，仍按预期修订号检查内容。恢复目录遗留时保持报忙，避免多个进程同时回收。
- 不改自动化规则文件格式或现有修订号，恢复后的写入仍由原子替换完成。

## 验证与遗留

`bun run typecheck:platform-core` 与 `bun run check` 通过；未运行测试。待真实多窗口、进程强制退出、Windows/macOS/Linux 文件系统以及共享盘场景验收。旧格式或恢复目录遗留锁需要人工核对后处理；本次没有自动删除这些锁。
