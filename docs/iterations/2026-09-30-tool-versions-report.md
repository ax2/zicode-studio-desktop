# 2026-09-30 `.tool-versions` 环境声明

状态：实现及静态检查完成；跨平台实机验收待补。

## 目标与发现

- 项目环境页已识别多个语言的原生清单及 Node/Rust 工具链文件，但不显示 asdf/mise 常用的 `.tool-versions`。
- 该文件可列出多个候选版本及动态引用；只读文件内容不能证明版本管理器最终选择了哪个工具。

## 修改与决策

- 读取选中目录的 `.tool-versions`；若本地没有文件，则只查找注册工作区内最近的祖先文件，最多上溯 32 层，并显示相对工作区路径。
- 使用已有的 256 KiB 文件读取上限和规范路径边界；损坏、不可读或指向声明目录外的文件保留明确状态。最多展示 64 个工具声明，每项版本文本最多 200 字符，重复工具名或缺少版本视为格式错误。
- 各工具名保留文件中的原文；候选版本和动态引用原样显示。环境页明确说明尚不推断版本管理器实际选择，避免把声明误报为宿主版本匹配。

## 验证、偏差与风险

- `bun run check:rust:static`、`bun run typecheck`、`bun run check`、`bun run build:react` 和 `node scripts/check-i18n-coverage.mjs` 均通过；中文文案缺失 0 项。本轮不新增或运行测试。
- 全仓库 Rust 格式检查仍提示已有格式漂移；本轮新增 Rust 模块与清单模块单独执行 `rustfmt --check` 通过。前端检查保留 123 条 warning、7 条 info 和 1 条设计 warning。
- 静态检查后执行 `cargo clean --manifest-path src-tauri/Cargo.toml`，清理 18936 个可再生构建文件，释放约 3.2 GiB。
- 文件可声明任意工具，本轮仅展示声明，不安装工具、不读取版本管理器状态、不推断多版本回退顺序。
- 尚未在 Windows、macOS、Linux 的真实 asdf/mise 项目中验收。
