# 2026-09-29 内嵌资源切换中断恢复

## 目标与发现

- Pi、Bun 和 Windows PortableGit 已使用暂存目录更新。进程若在旧目录移走后、新目录提交前终止，旧资源会留在目标旁的 `.backup-<UUID>` 目录；原入口不会主动找回，离线开发或构建可能在重新下载前就失败。
- 中断后的暂存目录可能不完整，不能直接当作已安装资源；多个旧目录也不能猜测哪一份应恢复。

## 修改与决定

- 三个入口在判断已安装版本前，扫描各自目标旁的暂存及备份目录。目标缺失且恰有一个普通备份目录时，把它改名恢复到目标，再按原有版本标记与可执行文件规则判断能否复用。
- 目标仍存在时只报告遗留目录，不自动删除；多个候选备份时停止并要求人工核对。暂存目录只告警，不推断其完整性。
- 目录存在检查改用 `lstat`，避免悬空链接被误认为空位置。该流程只恢复脚本自己命名的备份目录，不触及其他资源。

## 验证与遗留

- 三个入口和共享模块的 `node --check`、`bun run check` 及目标差异空白检查通过；未制造中断状态、运行测试或实际替换运行时。
- 中断遗留的大目录不会自动清理；断电、并发构建和 Windows 文件锁仍需真实场景验收。
- 本轮仅更新本地工作树，未发布。
