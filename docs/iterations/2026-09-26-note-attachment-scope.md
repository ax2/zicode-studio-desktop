# 2026-09-26 笔记附件作用域与迟到恢复

状态：实现与静态检查完成，运行验收待补。本轮不新增或运行测试。

## 发现与设计

- 原附件上传在文件选择/编码之后读取动态工作区；返回后把链接追加到当前编辑器，没有验证原笔记身份。
- 请求固定开始时工作区和笔记。选文件、编码结束后再次检查；发出请求前离开原笔记则取消派发。
- 上传期间可继续编辑。返回时仍是原笔记则追加到最新内容；离开原笔记或编辑器锁定时，链接写入原作用域的加密恢复记录，返回后显式插入。
- 恢复附件仅追加链接到原笔记的当前编辑内容；不替换正文，不强制覆盖版本冲突。尚未保存的链接继续由普通草稿保护。
- 工作区切换、请求失败、保存失败与迟到响应分别记录结果，不能把文件上传成功等同于笔记保存成功。

## 实现记录

- `attachment-uploads.ts` 提取上传流程：选择文件与编码后检查原笔记，固定请求参数，单工作区 UI 避免重复发起；同笔记继续输入时追加最新内容。
- 实查 `public/native/app.js` 的 Notes 初始化没有传入 fileToBase64，原默认函数返回空字符串；已改为 FileReader 默认读取与 Base64 编码，空结果/读取失败不派发上传。
- `draft-recovery.ts` 在已捕获的原作用域保留迟到附件链接，使用独立随机记录 ID 和既有加密持久化队列；不会覆盖原笔记的其他草稿。附件恢复只插入链接，不恢复上传时的旧正文；重复点击检测同一链接，多条恢复来源在成功保存后按各自修订号清理。
- 恢复面板标识附件条目，提供插入原笔记、下载和丢弃。隐藏附件条目的另存新笔记操作，因为资源仍属于原笔记。
- 大型 notesStore/NotesApp 只做模块、状态和按钮接线；中英文帮助和导航同步。

## 边界

- 没有修改 Host 的附件格式、资源所属笔记和永久清理规则。恢复正文中的资源仍依赖原笔记附件目录。
- 上传响应丢失、进程在响应到达前退出，可能留下未引用附件；本轮没有实现 Host 侧幂等上传或未引用附件回收。
- 加密存储失败时原作用域的恢复记录保留在当前进程内；待写入/失败提示沿用草稿恢复能力。关闭进程后的可恢复性没有运行证据。
- 未新增或运行测试；未做文件选择器、真实上传、并发、跨平台或视觉验收。无 Rust 修改、提交、推送或发布。
