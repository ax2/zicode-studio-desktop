# 2026-09-30 自动化项目切换隔离

状态：代码实现、静态检查与前端构建通过；实际界面和三平台验收待补。

## 目标与发现

自动化草稿在目标场景或工作目录切换时会失效并重新加载，但工作流列表仍保留上一个作用域的内容，待创建请求也可能保留旧项目路径。异步工作流读取仅使用请求序号；切换时若没有立刻发起新读取，旧响应仍可能回填界面。
配置网关默认发往当前目标实例，工作流存储位于该实例的工作区；调度器因此只检查当前工作区。目标项目字段决定派发地点，不会让规则在所有工作区后台轮询。

## 修改与决策

- 目标作用域变化时，递增工作流读取序号，立即清空工作流列表、焦点和待创建请求，再读取新作用域工作流。
- 草稿存储沿用已有 epoch 失效机制，表单因 epoch 变化重新挂载。相同作用域重复通知不触发清空或重新读取。
- 手动运行、调度、任务重试、历史记录与删除操作在每次异步读取后核对目标作用域；切换后不再向新项目写入旧项目结果，迟到响应不回填工作流列表。
- 调度器运行时切换项目会立即为新项目调度一轮；若旧项目轮询尚未结束，先刷新新项目列表，并在旧轮询结束后补跑一次，避免到期任务只能等待下一次定时轮询。
- 自动化页和中英文帮助明确当前工作区轮询范围；全工作区调度列为后续架构工作，不把当前实现称为全局后台调度。
- 自动化的多步配置请求固定到开始时的 Pi 目标。任务写入已提交后，即使用户切换工作区，也尽力向原目标补写运行历史，界面只接收当前作用域的响应；旧实例已关闭或请求失败时，仍需回到原项目核对任务中心。未提交的操作在切换后停止后续步骤。
- 草稿列表与草稿写入也固定到请求开始时的 Pi 目标；未取得目标实例时直接报错，避免配置网关在等待期间改用当前窗口实例。项目路径建议的两次读取同样固定目标，并在切换后丢弃旧结果。
