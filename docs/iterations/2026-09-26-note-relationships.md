状态：实现与静态检查完成；运行验收待补。本轮未新增或运行测试。

## 发现与计划

- Host 标题索引只存一个值，同名标题覆盖后产生不确定的关联；代码示例也被当作引用。
- 提取共用保守扫描器，供备份引用迁移与关联索引使用。标题采用当前笔记本唯一候选优先，其次唯一全局候选；歧义不生成边。
- 明确知识索引的范围上限。范围不完整时不推断标题唯一性，返回不完整标志；显式 ID 仍可关联索引内已知目标。
- 前端关联加载独立管理作用域与请求顺序；开始读取时清空旧列表，失败显示错误，不再保留上一篇笔记的关系。
- 编译与静态结果不能证明真实 UI、跨工作区及数据往返已验收。

## 实现记录

- `references.rs` 统一保守正文扫描。导入迁移使用原始字节范围改写资源 ID；知识索引用同一结构化结果建立 Wiki/ID 边。
- `knowledge.rs` 从大型 Vault 文件抽出关系计算。标题索引保留所有候选，优先当前笔记本唯一匹配，再使用全局唯一匹配；重复候选不创建不确定关系。
- 知识索引最多处理 200 本、2000 篇；笔记数达到上限、物理目录截断或笔记本超限时返回 `incomplete`，不推断标题唯一性。已有 API 增加兼容字段，未改变持久数据格式。
- 相似结果计算期间最多暂存 200 对并保留最佳 100 对；冲突找到前 100 对即停止，避免先建立完整候选集合再截断。
- `note-relationships.ts` 接管加载、作用域与顺序检查；选择变化的订阅统一清空/刷新关系，销毁时解除订阅。失败清空旧结果，提供重试；同一来源笔记的重复引用合并展示。
- `NoteRelationshipStatus.tsx` 显示加载、失败、未保存编辑与索引不完整状态。保存成功后刷新关系，拒绝旧工作区或旧选择的迟到响应。
- 大型 `notesStore.ts` / `NotesApp.tsx` 仅保留类型、订阅生命周期和组件接线。主 Vault 文件抽出关系逻辑；独立模块均低于 500 行。
- 中英文帮助、平台计划和 MkDocs 导航已同步。

## 遗留边界

- 未运行真实索引、UI、跨工作区、并发及跨平台测试；静态检查不证明行为验收通过。
