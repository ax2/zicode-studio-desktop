## 发现与目标

- `scripts/release.sh` 原先用两次 `git diff --quiet` 检查工作树，只覆盖已跟踪文件的工作区与暂存区修改。
- 当前项目有未跟踪的源码、模块及文档。若已跟踪文件已提交但这些文件仍未加入 Git，旧门槛会继续创建 tag；CI 检出该 tag 时将缺少本机构建使用的文件。

## 修改与决策

- 发版前及测试、类型和静态门槛执行后都使用 `git status --porcelain=v1 --untracked-files=all`，同时覆盖已跟踪修改、暂存内容和未跟踪文件；Git 忽略的可再生构建目录仍不计入。
- 将命令输出先赋值，在 `set -e` 下若 Git 状态读取失败会停止脚本；不打印文件名或可能包含敏感路径的状态内容。
- 不运行发版脚本，不执行脚本内的测试、版本修改、提交、tag 或推送。
