# Notes cloud configuration and independent credentials · 2026-11-18

Scope: [#24](https://github.com/ax2/zicode-studio-desktop/issues/24), v0.6.6. Base `fc78333171a61302b62f7d2ec5bc10a9d12c533d` from `integration/v0.6.6`. Coordinated with the #23 owner: this increment supplies its missing local configuration prerequisite and does not duplicate or start the transfer queue.

## Delivered vertical path

Settings → Notes cloud sync → current-workspace Tauri command → bounded local configuration and dedicated system credential store → actual local readiness status. The command requires the trusted desktop Host origin and the window's current workspace binding. Its permission is declared in the default command set.

- Endpoint/username/vault ID and revisioned credential references live below the fixed system root's `notes-sync` directory. Personal configuration retains its workspace-hash directory; named profiles have separate domain-separated name/workspace configuration directories, with no personal/name fallback. Metadata contains no password or recovery code. Separate credential entries use the service `ZiCode Studio Notes Sync` and derive accounts from profile root, explicit test name, workspace, secret revision and kind. They never enter the model credential service/index or Pi environment.
- HTTPS WebDAV input follows the existing transport's address requirements; UUID and size/format checks precede credential writes. New recovery codes reuse `SyncKey`, are generated only on explicit request and are not stored until Save. Stored secrets are not returned to the UI.
- An independent lock and expected-revision check prevent a stale form from overwriting newer settings. Credentials are staged in fresh accounts before the current configuration is atomically replaced. Old configuration versions and credential references remain available; a failed save removes only its new candidate accounts. Blank credentials preserve old references only when all connection details match.
- Readiness distinguishes unconfigured, missing credentials, disabled credentials in ordinary isolation, unavailable system storage, and locally configured. Unreadable configuration is not reset or called unconfigured; unavailable storage is not called missing credentials. Form changes show an unsaved indicator, and successful save or workspace refresh clears secret inputs.
- `syncAvailable` remains false. No networking, note/vault reads, note writes, upload, model call, scheduler, actual sync/cancel operation or cloud login validation is implemented or implied. These settings cannot produce real paused/network/rate-limit/auth-expired task states yet.
