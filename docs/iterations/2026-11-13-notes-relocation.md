# 笔记移动后的持久引用定位（2026-11-13，Issue #22）

## 行为与数据约束

- `NoteDocument` 和 Markdown frontmatter 增加可选 `previousNotebookIds`。新笔记缺省为空，保存、继续移动、回收站恢复保留来源；不改写用户正文，不根据同一 UUID 猜测另一笔记本中的副本。
- 只读 Host GET 使用 `resolve_note`：当前精确位置优先；不存在时仅接受同一工作区中明确记录该旧位置的唯一笔记。目录不完整、损坏、重复来源或超出遍历预算均拒绝推断。保存、删除和移动仍使用严格物理位置及版本检查。
- 最近/置顶入口可在 Host 已成功、客户端未写回时根据来源恢复并持久化；保留顺序、去重，写入失败留待刷新重试。同 ID 的导入副本保持独立。
- 反向链接使用同一个 Host 定位器，不使用有数量上限的界面列表推断身份。备份导入先将包内旧引用映射到导入目标，然后清空副本的历史来源，避免抢占原笔记链接。
- 无来源记录的历史移动不会被自动猜测恢复；旧版本造成的失效记录保留并提示。没有把这类旧故障隐藏或计为已修复。
