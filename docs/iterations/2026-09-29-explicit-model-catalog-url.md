# 2026-09-29 模型目录地址显式配置

状态：本地代码与静态构建检查完成；真实网络和跨平台启动未验收。

## 目标与发现

- ZiCode Studio Desktop 作为个人开发者平台，模型目录同步不能因为调用方遗漏地址而落到公司专用网关。
- 设置页加载只读取本地渠道与模型配置；目录刷新和模型健康检查均由用户按钮触发。同步分发器先确认场景中存在 `qveris` 渠道，并读取该渠道的 `baseUrl`。
- 目录请求函数本身仍把公司网关写作默认 `baseUrl`。这使未来新增调用方可能绕过“显式配置渠道”的约束。

## 修改与决定

- `fetchQVerisModelCatalog` 现在要求调用方传入 `baseUrl`，先校验地址再构造请求；移除内置的公司网关默认值。
- 现有唯一生产调用点继续传入当前场景 `models.json` 中经校验的地址。既有渠道配置与手动刷新入口没有迁移。
- 既有单元测试调用改为传入示例地址；本轮未新增或运行测试。

## 验证与遗留

- `bun run check` 通过，保留仓库当前的 119 条 lint warning、7 条 info 和 1 条设计检查 warning。
- `bun run build:extensions` 通过；目标两个文件的 `biome format` 检查通过。
- 未运行真实 WebView、网络请求或 Windows/macOS/Linux 启动，因此不能据此认定全应用离线或跨平台就绪。
- Rust Host 仍有指向特定网关的本地代理路由，金融适配也保留专用服务默认地址；需要分别评估现有用户配置和兼容性，再推进为通用或显式配置入口。
- 本轮没有界面变化或新截图，也没有发布产物。
