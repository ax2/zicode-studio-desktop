# 聊天收件箱核心类型门槛工作日志（2026-10-01）

## 目标与发现

根扩展配置仍因内嵌 Pi 发布包缺少类型声明及其他源码错误而失败。公开包仓库可查到与当前 Pi 0.84.2 对应的 `pi-coding-agent` 和 `pi-tui` 声明包，但两次 Bun 开发依赖安装均长期停在依赖解析，未写入项目清单；本轮未引入半完成依赖。聊天收件箱的大部分逻辑不直接依赖 Pi UI SDK，可以独立检查。

## 修改与决策

- 新建 `tsconfig.chat-inbox-core.json`，严格检查配置、类型、日志、运行时、远程操作、启动选择、消息渲染及飞书/企微连接，共 18 个源码文件。
- 排除需要 Pi SDK 声明的扩展入口与 TUI 对话框；不以空白声明伪装该部分已被类型检查。
- `typecheck:chat-inbox-core` 纳入 PR 与三平台平台检查入口；锁定 Pi 的运行时打包规则不变。

## 验证与遗留

`bun run typecheck:chat-inbox-core`、`bun run check` 和 `bun run build:extensions` 均退出 0；工作流 YAML 与平台检查脚本已静态解析。仓库静态检查仍有既有警告。本轮未运行测试。完整扩展类型检查、Pi 实际加载、飞书/企微真实连接和三平台运行仍待验收。
