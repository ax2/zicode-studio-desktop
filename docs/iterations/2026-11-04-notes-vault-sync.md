## 完成的后端范围

- `NotesVault::capture_sync` 从真实磁盘读取保存后的正文、笔记本元数据、回收站及附件；原 ID、Markdown 全文和空白保持。未知元数据字段、损坏文件、缺失删除时间记录、读取失败及路径不安全时停止，不把它们解释为删除。孤立附件也保留，不默默丢弃。
- 云端记录按笔记、笔记本、附件分开。笔记本的本地派生更新时间、计数与工作区 ID，以及本地删除确认令牌不参与云端内容比较，避免同一笔记本的不同笔记修改互相冲突。它们仍计入本地磁盘版本校验，保护保存期间的新修改。
- `apply_sync` 先确认本地版本，再准备并验证完整目标；准备后再次核对，移动原目录后再次核对，提交前验证原始备份与实际目标。现有工作区存储锁与稳定 ID 继续有效。
- 独立恢复事务：先将新内容及清单落盘，在同一笔记库内移动现有目录，再替换四处受管理内容（笔记本元数据、正文目录、回收站、附件目录）。自定义文件、配置和可能存在的构建目录不复制到云端，也不被同步替换丢弃。
- 普通中断在未提交时恢复旧状态，已提交时保留新状态；意外外部修改不被覆盖，无法安全恢复时保留当前内容和原始备份并返回明确错误。没有声称能修复任意磁盘损坏或完成真实断电测试。
- 远端永久移除整个笔记本时，将完整本地原目录保存到 `.sync-archives`，包括本地自定义文件。没有恢复管理界面，不能宣称用户已经能通过界面找回这个副本。
- 已完成或回滚的事务先整体移出活动日志，再清理临时数据；清理中断不会变成下一次启动的半截活动事务。未写完所有权记录、尚未触碰当前笔记的准备数据隔离保留。临时清理失败会明确返回一致性已完成、清理待处理的结果。
- 文件读写、移动与清理使用限定在笔记库内的目录能力，并拒绝符号链接。Windows 的真实目录联接分别指向库外和库内非管理数据，两种都被拒绝，源内容保持。
- 修复了既有 Windows 存储锁冲突错误分类：使用 `fs2::lock_contended_error` 的平台错误判断，正确返回“笔记库正在使用”，不再笼统显示存储不可用。真实独立子进程验证了互斥，不只检查错误字符串。

新实现位于 `src-tauri/src/notes_vault/sync/`，每个文件按投影、记录、存储和事务拆分。既有超过 500 行的 `notes_vault.rs` 只登记模块并接线启动恢复，未往入口塞入同步逻辑；网络协议、模型、插件和界面没有混入笔记库。
