## 发现与设计

- Host 已识别 `zicode-note://笔记本ID/笔记ID`，预览点击却只按标题查找；导入后笔记本 ID 变化，正文引用未迁移。
- 在批量暂存阶段重写指向本批已知笔记的显式 ID 引用，提交前完成；单本导入同样可迁移本本内引用。
- 代码块与行内代码保留，未知目标、外部链接和非标准资源路径不猜测重写；本轮不宣称完整 CommonMark 语法支持。
- 前端独立链接模块解析 ID 与标题链接；标题优先当前笔记本的唯一匹配，否则仅使用当前加载列表的唯一匹配，同名歧义提示而非随意跳转。
- 原始 `[[标题]]` 保持文本，不自动转换为 ID；跨笔记本同名引用仍需用户明确目标。

## 实现记录

- `import_references.rs` 在暂存目录内重写已知资源对；同时处理活动笔记和回收站笔记，重写后恢复回收站修改时间。错误仍交给整批导入事务回滚。
- 引用格式为 `zicode-note://UUID/UUID`。仅迁移备份中实际存在的目标；未包含的外部笔记 ID 保留。
- 保留顶层反引号/波浪线围栏、缩进代码和行内代码；引用块整行保守跳过。带查询、片段、百分号路径或额外路径的 URI 不迁移。
- 前端 `note-links.ts` 支持显式 ID、标题和 `[[标题|显示文字]]`。显式 ID 直接请求 Host，不依赖搜索结果中是否出现该笔记；存在性由 Host 返回结果确定。
- `NoteReferenceButton.tsx` 生成可粘贴的 Markdown ID 链接。失败显示错误，成功后才显示“已复制”。
- 标题查找优先当前笔记本的唯一候选，其次为已加载列表的唯一候选；同名候选不取第一条。标题候选仍受当前列表过滤和加载上限影响，因此稳定链接应使用 ID。
- 笔记切换等待保存成功，并用请求代次、作用域和编辑指纹拒绝迟到覆盖；等待期间继续输入时保留编辑内容。
- `NotesApp.tsx` 抽出链接解析，保留旧导出名称；`notesStore.ts` 仅增加选择请求保护。未新增用例或运行测试。
