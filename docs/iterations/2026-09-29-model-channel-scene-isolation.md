# 2026-09-29 模型渠道场景隔离接续

状态：本地实现与静态检查完成；多场景真实运行待验收。

## 发现

- 渠道编辑在关闭 Bearer 鉴权时会沿用旧渠道对象中的 `apiKey` 引用。用户选择免鉴权后，配置仍可能携带旧引用。
- 前端保存密钥和渠道时，先异步调用操作系统凭据库，再向当前配置网关发送命令。若等待期间切换场景，动态目标可能已变成新场景。
- 设置页的旧场景读取结果可能迟到并覆盖新场景的渠道、模型或高级 JSON 编辑内容。

## 修改与决定

- 免鉴权渠道保存时删除模型配置中的 `apiKey` 引用，不接受新输入的密钥；关闭鉴权的表单会清空当前未保存的密钥输入。已在系统凭据库中的密钥不会自动删除，可由用户在 API Key 列表中单独删除。
- 凭据库调用使用操作开始时固定的场景 ID。保存与删除在异步步骤后核对当前场景，避免后续配置命令误发到新场景。
- 切换场景时清空旧渠道、模型、配置编辑内容与凭据表单；每次切换递增场景代次，旧场景的渠道、模型、健康检查和高级编辑读取结果不再写回新场景，快速 A→B→A 也不能让首个 A 的迟到结果覆盖新读取。批量模型可见性更新在每次请求前后检查场景与代次，不跨场景继续执行。
- 通用发现流程保留上轮的渠道修订号检查及非敏感快照；切换场景后不展示旧发现结果。
- 场景检查接入现有大型设置 store 的各异步入口，未另建状态层；新增逻辑只处理场景代次与迟到结果，不扩展应用根入口。后续若继续增加设置动作，应抽取统一的场景操作控制器。

## 接续：固定配置命令目标与部分完成提示

- 核对 `ConfigGateway.call` 后确认：它在调用时读取当前目标。原先在凭据库步骤后切换场景会让第二步被主动中止，留下只有系统凭据完成的状态。
- 网关调用现允许传入固定目标。密钥与渠道保存、删除在开始时捕获目标；通过凭据库步骤后仍尝试对原场景完成扩展配置命令，旧结果不回写新场景界面。
- 若系统凭据已更新或删除，但配置命令失败或超时，界面明确提示核对原场景。超时的远端完成状态不能由前端断言，因此不会自动删除或重写原凭据。
- 固定目标可能在场景切换后已停止运行；此时配置命令仍可能失败。它降低场景切换造成的部分完成窗口，并不构成跨进程事务。
- 应用模式下若操作开始时没有可用配置会话，先提示错误，不写入或删除系统凭据，避免凭据步骤之后才发现网关目标缺失。
- `bun run typecheck`、`bun run build:react`、`bun run check`、目标文件 Biome lint 与差异空白检查再次通过；没有运行测试或真实凭据库操作。
