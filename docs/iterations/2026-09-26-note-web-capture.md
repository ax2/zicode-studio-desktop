# 2026-09-26 网页采集与摘要作用域

状态：实现与静态检查完成，运行验收待补。本轮不新增或运行测试。

## 发现与方案

- 摘要只检查 scene，不检查 workspace、模型变更或请求顺序；旧请求 finally 会清除新请求的忙碌状态。
- 预览保存在组件中，但 URL 修改和工作区切换不会使旧响应失效。网页采集返回后会修改当前笔记本并调用选择，可能覆盖已经变化的视图。
- 提取采集与摘要动作，固定工作区与请求身份。修改 URL、预览或模型时清理旧摘要；同一工作区阻止重复采集提交，已经发出的请求不承诺取消。
- 表单提取为独立组件；返回数据前检查组件生命周期与表单修订，采集成功仅在原编辑上下文未变化时打开结果，否则保留当前页面并提示从列表打开。

## 实现记录

- `web-capture.ts`：摘要、预览与采集分别维护请求序列，使用开始时的 operation scope。摘要结果同时核对模型；clear/dismiss/model change 会令旧结果失效。
- 网页 URL 统一解析为 HTTP(S)，拒绝含用户名或密码的 URL。采集开始即设置 busy，等待保存成功后派发，不因快速重复提交产生第二个请求。
- 采集成功后只在表单修订与编辑上下文仍匹配时同步打开返回的完整笔记；其他情况保留当前编辑器和表单，只刷新列表并提示。
- `CaptureForm.tsx` 提取原表单；使用生命周期和输入修订检查预览、错误与复制状态。TagEditor 作为组件依赖传入，无反向导入大文件。复制不可用/失败显示错误。
- 切换工作区重置 capture 模式、busy 与 summaryModel；同工作区重复 target 通知仍不清空内容。
- 预览过期时返回 null；既有测试的一处属性断言改成可选访问以适配类型，未增加或运行测试。
- notesStore/NotesApp 大文件仅保留类型、模块、组件与重置接线。

## 保留边界

- 请求过期不等于 Host/提供方取消；已派发的采集可能仍写入原工作区，摘要仍可能产生服务端成本。未新增取消协议。
- 采集输入和临时预览尚未持久化，工作区切换会关闭表单。Host 的网页解析、重复 URL 识别和网络访问限制沿用既有实现。
