# 置顶命令跨设备迁移（2026-09-29）

## 目标与发现

项目命令按工作区与子项目目录置顶，数据仅在当前设备的应用 Web 存储中；复制项目 `.zicode` 目录不会带走这些个人偏好。现有任务标识稳定，暂时缺失的命令标识会保留，后续重新发现时恢复置顶。

## 修改

- 为当前项目目录加入用户主动下载的 JSON：只写来源项目名、相对目录和最多 32 个命令标识，不写工作区内部 ID、命令正文、环境变量或输出。
- 导入限制为 256 KiB，核验格式、版本、数量及标识长度；预览来源、目标和当前清单匹配数。确认后与目标目录已有置顶合并，仍受 32 项上限约束；导入不启动命令。
- 写入前严格核验已有置顶文档；若损坏、超限或无法读取，明确失败并保留原数据，不把它当空文档覆盖。普通置顶切换也遵守同一写入保护。
- 命令清单为空时仍显示迁移入口，以便先导入标识，再等待命令重新出现。文件选择的迟到解析结果按代次丢弃。

## 验证与限制

TypeScript 类型检查、定向 Biome、i18n 覆盖（缺失 0）、React 构建、`bun run check`、严格 MkDocs 构建及差异空白检查通过；全局检查仍有既有警告。本轮未新增或运行测试，也未进行桌面文件选择或跨设备实机验收。文件是明文，标识可能包含任务名称；仅迁移置顶偏好，不迁移任务定义、运行历史或工具链配置。
