# Stage：开发插件暂存清单一致性与失败清理

日期：2026-10-17。Studio 要接收大量独立 DevTools 工具，开发插件目录可能包含上百文件。安装期间若复制后的清单无效，暂存目录应随失败退出；若清单仍保留相同 ID 和版本、但能力或权限等字段发生变化，也应拒绝这次安装。

## 修改

`PluginRegistry::install_developer` 复制目录后检查完整解析清单与复制前一致。暂存清单校验失败或字段不一致时，删除本次唯一命名的暂存目录并返回错误，不进入原有插件替换流程。目录复制失败仍沿用原有清理路径。此改动没有扩大插件权限、放宽清单校验、修改提供方候选或引入第二份运行目录。

- `bun run check:rust:static` 退出 0，`cargo check`、严格 Clippy 通过；仓库整体格式检查仍提示既有 drift。未运行完整 Rust 测试集，也未主动调用 `build:local`。检查时发现 `target/debug/zicode-studio-desktop.exe` 已在 14:57:25 被其他活动改写为 124,970,496 B、SHA-256 `C0EA9CF737565B5AF2A08B49AB236897BDAF19D3C177E28F08AFE3F98FAB0BC4`；来源未确认，不能据此声称该 EXE 含本次改动或已完成原生安装验收。上一轮原生 Inspect 复验属于当时另一哈希的 EXE。
