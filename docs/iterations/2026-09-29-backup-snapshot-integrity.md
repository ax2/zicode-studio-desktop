# 2026-09-29 工作区快照完整性

状态：实现与静态检查完成；真实备份验收未完成。

## 目标与发现

- 备份复制目录时会跳过目录枚举错误，遇到符号链接等非普通条目也会静默跳过，因此可能产生内容不全却显示成功的快照。
- 快照原先直接写入最终目录，复制中断会留下半成品；元数据发布与数据复制缺少统一的可见性边界。
- 创建完成后的保留期清理若读取失败，原先会向界面报告创建失败，即使完整快照已经写成。

## 修改与决策

- 目录枚举与不支持的文件类型现在明确报错；文件复制使用实际复制的字节数计量。顶层应用目录也拒绝符号链接或非目录条目，避免备份意外越出工作区或静默遗漏。
- 新快照先写入同一备份目录下的 `.partial-<id>`，完成数据和元数据后再重命名到最终 ID。列表过滤临时目录、非法 ID 及不属于当前工作区的元数据。
- 删除与恢复只接纳真实备份目录；恢复前也拒绝应用目录中的链接或其他非目录条目，避免沿备份目录链接读取其他位置。
- 工作区和快照 ID 限制为 ASCII 字母、数字、`-`、`_`；工作区备份目录若已是符号链接或其他非目录条目则拒绝，阻止 `..` 等路径越界。当前工作区注册表产生 UUID；历史非标准 ID 需要迁移后才能操作备份。
- 正常错误会尝试移除临时目录。进程异常退出可能留下隐藏的 `.partial-` 目录，不会显示为可恢复快照；后续需要安全的遗留清理策略。
- 最终快照发布后裁剪失败仅记录日志，不把已成功创建的数据操作报告为失败。

## 验证与遗留

- `cargo check --locked`、`cargo clippy --locked -- -D warnings`、本轮 Rust 文件 rustfmt 检查及差异空白检查通过。本轮不新增或运行测试。
- 尚未在真实桌面应用中验证大文件复制失败、权限异常、强制退出及 Windows/macOS/Linux 文件系统差异。此改动只保证快照列表的发布边界，不保证正在运行的其他写入者在复制期间不修改源数据，也未实现跨目录的断电耐久保证。
