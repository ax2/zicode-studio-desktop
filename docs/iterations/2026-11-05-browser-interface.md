# Browser interface integration — 2026-11-05

Browser now has a trusted built-in application entry and primary activity navigation. The interface includes closable tabs, address entry, native back/forward/reload/stop, new tabs, persistence and startup-preference selection. Its application registration hides an empty sidebar. The startup preference is persisted, but the default startup router does not consume it yet; browser-first startup is NOT accepted. No model starts from this interface.

The new UI uses existing design tokens and primitives, Chinese/English translations, native commands and fixed browser metadata. It does not embed an iframe. Native status returns existing owner-window tab IDs/URLs and the surface revision so reloaded chrome can reconcile controls instead of creating duplicates or sending obsolete visibility revisions. Tabs are restored lazily. Button actions are serialized; title/loading saves are coalesced. Leaving the application waits for initialization and native hide acknowledgement through canDeactivate. Resize and visible-dialog/sidebar observations request native hide or updated bounds; actual native overlay behavior still needs runtime acceptance. A blocked saved URL can be replaced with a fresh public address without permanently stranding the tab.

Rendered QA used existing Playwright and a separate headless Edge process at an ephemeral owned local HTTP port (Browser plugin not available). It loaded the real UI module and CSS with a mocked native command boundary. At 1200x760 and 420x760 it created tabs, submitted an address, closed a tab, checked no horizontal overflow and requested hide on deactivation. No page script errors occurred. Screenshots and exact page identity are in outputs/browser-ui-{1200,420}.png and browser-ui-rendered.json. These screenshots intentionally contain no real webpage surface: they prove chrome behavior, NOT embedded WebView/Studio integration, actual network navigation or native permission enforcement. The test browser/server exited normally.

Forty existing shell/navigation regressions passed. Real Rust registry loading initially exposed an invalid v2 manifest declaration; the UI-only browser now uses the same v1 contract as other built-in views. The registry's fixed count was updated from 19 to 20 with an explicit browser presence/default-enabled assertion, then passed. The initial late CSS import was fixed to precede stylesheet rules. Final frontend check, design check and strict all-target Rust checks passed; existing warnings and Rust formatting advisory remain. Translation coverage: 3767 keys, zero missing. Original failures remain in logs. This batch only adds minimal imports, registration and one registry entry to existing large roots; feature logic is in public/native/browser and src-tauri/src/browser.
