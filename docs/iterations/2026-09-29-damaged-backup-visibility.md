# 2026-09-29 损坏备份可见性

## 目标与发现

- 工作区备份列表原先静默跳过 `backup.json` 缺失、无法解析或 ID/工作区归属不符的目录；用户可能看到“没有备份”，却无法从界面发现或清理残留快照。
- 自动保留期和每日备份判断复用同一列表；损坏目录需要可见，但不能被当作有效备份或被自动删除。

## 修改与决策

- 对名称合法的普通备份目录，元数据不可用时返回仅用于列表的损坏条目；时间取目录修改时间，恢复按钮禁用，删除仍需用户确认。有效元数据中的 `damaged` 字段不作为事实来源。
- 保留期裁剪和每日备份的最近一次判断跳过损坏条目。列表显示有效快照与损坏目录，状态文案不把损坏目录称为可用备份。
- 后续核对恢复入口后，进一步把未知格式、新版缺少摘要及摘要格式无效的快照排除在保留期与每日备份判断外。设置页也不将它们计入最近 7 份可用备份，并禁用摘要格式无效的恢复按钮；这些目录仍可见且只由用户显式删除。这里只判断元数据，内容损坏仍在实际恢复时检查。
- 接续发现可解析元数据仍可能含无效时间或空白、重复、未知应用目录清单。现在列表将这类目录降为带目录修改时间的损坏条目，直接恢复也拒绝异常结构；自动备份和保留期不计入这些条目。前端同时检查协议返回的可选字段类型及应用清单，避免异常响应冒充可用备份。
- 列表排序改按解析后的实际时间，避免合法但带时区偏移的时间文本按字面顺序排错，影响最近快照与保留期选择。
- 列表也检查元数据声明的已知应用目录是否为普通目录，且没有多出或缺少目录；与恢复入口一样拒绝链接和不匹配的应用子目录。目录内容的大小与摘要仍在恢复时复核，列表不为此读取所有文件。
- Rust 恢复入口继续独立读取和校验元数据；即使直接调用，也不能恢复损坏目录。
- 设置页现在校验列表每条记录的工作区与必要字段；创建和恢复命令必须返回与请求一致的备份 ID、工作区及结果结构，才显示成功。异常响应不会伪装成空列表或恢复成功。
- 创建或恢复的响应无法确认时，界面提示先刷新备份列表或检查工作区数据，再决定是否重试，避免把可能已经完成的操作简单报成“失败”。
