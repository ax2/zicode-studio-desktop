# 扩展目录离线入口（2026-09-28）

## 发现

打开设置的“扩展”页会立即请求固定的社区目录服务。目录约 5000 多项，分页并行请求；没有网络时页面只留下加载失败，已安装包也无法在该页查看。这使扩展管理依赖特定在线服务。

## 修改

- 进入扩展页只调用本机 Host 的已配置包列表，显示包来源并提供卸载操作；本机列表不可用时显示固定提示，避免误报为空列表。
- 社区目录保持可用，但只有点击“浏览在线目录”才发起网络请求；首次进入显示明确的离线状态，失败后可重试。
- 保留目录筛选、排序、安装及刷新本机已安装状态的现有行为。

## 验证与限制

`bun run build:react`、`bun run check`、`bun run typecheck`、i18n 覆盖检查、MkDocs 严格构建及 `git diff --check` 通过；未运行测试或实机离线验收。社区目录仍指向固定服务；本机包列表依赖 Host 可用，目前没有本地持久缓存。卸载沿用现有包控制接口，跨平台实际操作仍需验收。

## 接续：手动来源安装

内置 Pi 的包文档明确支持 `npm:`、`git:`、HTTP(S)/SSH Git URL 与本机路径；宿主 `install_pi_package` 会将来源作为单个参数传给内置 Pi。扩展页新增手动来源表单，可用本机绝对路径离线安装，也可显式安装 npm/Git 来源。输入只接受这些已记录的来源形式，安装失败显示固定提示，成功后重新读取本机列表；页面说明扩展会以当前用户权限运行代码。相对路径的解析基准不直观，暂不在表单中接受。实际安装与跨平台路径验收仍待完成。

## 接续：本机文件选择

复核现有 Tauri 配置与已锁定的 dialog 插件源码：桌面能力含 `dialog:default`，`plugin:dialog|open` 支持单选目录或文件，桌面端返回序列化的绝对路径。扩展页现提供“选择包文件夹”和“选择扩展文件”，只填入手动来源，安装仍需明确点击。取消选择不改动表单；插件不可用时不显示选择按钮。Windows、macOS 和 Linux 原生选择器的实际界面与 Pi 安装仍待验收。
