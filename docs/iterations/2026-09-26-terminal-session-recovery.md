## 发现与设计

- 初次列表读取失败仍可新建终端；启动失败后的刷新错误会覆盖原操作错误。
- mounted 布尔值不能区分同组件中的多轮 API/项目生命周期；列表回复还可能覆盖已收到的实时会话状态。
- 提取按 API/工作区隔离的状态控制器。首次列表成功和状态可信前禁止新建，停止已知会话不依赖列表读取成功。
- 操作错误和读取错误分别保留。超时、断线或启动响应未确认时标记结果不明确，自动刷新不会清除此状态，需要显式刷新后再决定是否新建。
- 不自动重发写操作，不声称显式刷新能取消仍在 Host 执行的请求，也不宣称实现了幂等创建。

## 工作日志

- terminal-sessions.ts 提取列表、创建、停止、选择和流状态更新；use-terminal-sessions.ts 用 useSyncExternalStore 接入 React。生命周期 epoch 和请求序号拒绝旧回复，清理后重新激活也不会接收上一轮结果。
- terminal-list.ts 校验会话 ID 唯一性、工作区、状态、输出游标与终端尺寸，兼容旧 Host 缺少启动目录。请求期间收到的流状态按会话版本保留，不被该列表回复覆盖。
- 首次读取或刷新失败禁止新建，保留最近已知列表；仍允许停止已知运行中的会话。启动/停止错误不被自动刷新错误覆盖，手动刷新会清理操作错误。
- 启动超时、控制连接断开、启动目录或响应无法确认时设置 creationUncertain。自动刷新不清除，只有显式刷新成功后才恢复新建按钮。不自动重发创建/停止请求。
- ProjectTerminalPanel 保留渲染与终端流连接，独立展示读取、操作、结果未确认状态。现有大文件 public/i18n.js 仅增加四组词条；业务逻辑均位于独立模块。
