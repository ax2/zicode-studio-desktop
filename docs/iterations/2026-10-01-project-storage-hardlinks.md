# 项目存储硬链接提示工作日志（2026-10-01）

## 目标与发现

项目存储页按文件逻辑长度汇总常见生成目录；同一内容若有多个硬链接，会在不同路径重复计入。此前本机的 WebView2 下载缓存与打包资源就是同一文件的两个硬链接。用户按目录数字估算清理收益时，可能高估可释放空间。

## 修改与决策

- Host 在原有有界只读扫描中累计链接数大于 1 的普通文件路径数及其逻辑字节数。Windows 通过已依赖的 `windows-sys` 和文件句柄读取链接数；macOS/Linux 使用 Unix `nlink`。无法读取链接数的文件不会被猜测为可回收数据。
- 前端在扫描结果中显示多硬链接文件的观察值，并继续明确：逻辑大小不等于可回收空间。多个链接也可能都在同一目录内，因此提示只说“可能释放更少”，不计算虚假的可回收总量。
- 新字段对旧 Host 保持可选；若新 Host 返回字段，前端校验两者同时存在、为安全非负整数且不超过对应总量。
- 扫描仍不删除文件，不跟随符号链接或 Windows 重解析点，保留时间、深度与条目上限。

## 验证与遗留

第一次 Rust 静态检查发现当前 Rust 1.88 的 Windows `MetadataExt::number_of_links()` 仍是不稳定 API；改为 Windows API 后，`bun run check:rust:static` 退出 0。全仓格式检查仍有既有漂移，目标 Rust 文件 `rustfmt --check` 通过。`bun run typecheck`、`bun run check`、`bun run build:react` 和目标前端文件 Biome 格式检查退出 0；仓库检查仍显示既有警告。未运行测试；三平台文件系统、扫描性能、扫描期间文件变化和真实项目界面仍待验收。
