# 项目存储占用只读检查（2026-10-01）

状态：本地代码与 React 产物已接入，静态检查通过；实机验收待补。

## 目标与发现

- 开发者项目中的依赖、编译目标和缓存会占据空间，但仅凭目录名不能认定文件可删。此前本地清理请求中，WebView2 缓存与打包资源还是硬链接：目录逻辑大小不等于可回收的物理空间。
- 项目页原无空间占用视图。用户需要先看到具体目录、扫描完整性和文件数量，再自行判断其用途。

## 修改与决策

- 桌面 Host 新增按已注册 workspace ID 读取的只读命令，不接受任意客户端路径；在阻塞线程扫描固定的常见生成目录候选。移动/远程端不展示入口。
- 每次扫描共用 5 秒检查预算，单目录最多枚举 100000 项，最多深入 64 层。符号链接和 Windows 重解析点不继续遍历；读取错误、跳过项或达到上限时标为不完整。
- 项目页新增“项目存储”视图，显示文件逻辑大小、文件数、扫描状态和跳过数；支持手动重扫。无候选目录时明确显示空状态。页面不提供删除操作，也不把逻辑大小解释为可回收空间。
- 前端校验 Host 返回的日期、大小、计数、状态和唯一目录名；失败时保留上次结果并显示错误，不以损坏响应渲染清单。

## 接续：子项目扫描范围

- 原实现只扫描工作区根目录，和项目页已有的子项目选择不一致。现复用项目目录选择器，存储视图与环境、命令、新终端共用当前窗口选中的目录。
- Host 使用项目命令已有的 `directories::resolve` 校验相对目录，拒绝越界、链接或无效目录；结果回传所扫描的相对目录。前端只接受与当前选择相同的响应，切换目录时卸载旧结果，避免把根目录占用误标为子项目占用。
- 旧 Host 若尚不接受目录参数或不回传目录，显示扫描错误；不会将无范围信息的旧结果当作当前目录结果。
- 接续静态检查：`bun run typecheck`、`bun run check`、词条覆盖、`bun run build:react`、修改组件的 Biome 格式检查、新 Rust 模块的 rustfmt 检查和 `bun run check:rust:static` 均退出 0。全仓库 rustfmt 仍仅报告 advisory 格式漂移；未运行测试或真实页面。
- 接续 Rust 冷编译后再次执行 `cargo clean --manifest-path src-tauri/Cargo.toml`，工具报告移除约 3.2 GiB 构建文件；缓存下载包仍未处理。

## 接续：阻塞扫描与并发边界

- 5 秒条目预算不能中断卡住的单次文件系统调用。桌面命令现对调用方设 8 秒等待上限；到时返回超时错误，后台阻塞任务仍可能继续，不伪称已取消扫描。
- 同一 Host 同时只准一个存储扫描进入阻塞线程；许可由工作线程持有，超时后仍不释放。其他窗口此时得到“仍有扫描运行”，不会不断堆积扫描任务。
- 前端把扫描占用、超时及所选目录失效分别转成可操作的提示，并保留该目录上次有效结果。真实故障网络卷与多窗口时序尚待实机验收。
- 接续验证：`bun run typecheck`、`bun run check`、中文词条覆盖、`bun run build:react` 与新组件格式检查退出 0；`bun run check:rust:static` 的 Cargo check 和 Clippy 通过，全仓库 rustfmt 仅保留既有 advisory 漂移。未运行测试或真实网络卷场景。
- 冷编译后执行 `cargo clean --manifest-path src-tauri/Cargo.toml`，工具报告移除 18936 个构建文件、约 3.2 GiB；下载缓存未动。

## 接续：排序与人工核对入口

- 存储列表改按已观察到的逻辑大小降序显示，部分扫描仍只代表下限；相同大小按目录名排序。页面明确标注排序口径，不计算“可释放空间”。
- 桌面端可从结果打开生成目录。前端先校验返回目录名仅含安全的相对路径片段，打开时拼接当前子项目目录；Host 再按已注册工作区验证目标。链接和非目录候选不提供打开按钮，失败只显示固定提示。随后另设目录专用 Host 操作，见下方接续记录。
- 仅提供人工查看入口，不新增删除功能。远程和移动端仍不展示存储视图。
- `bun run typecheck`、`bun run check`、`node scripts/check-i18n-coverage.mjs` 和 `bun run build:react` 通过；保留原有 123 条 lint warning、7 条 info 和 1 条设计提示。初次检查发现新词条与现有“打开目录”重复，移除后复查通过。本轮不新增或运行测试，真实桌面文件管理器行为待验收。

## 接续：打开目录时重新验证

- 原先复用的 `open_in_app` 同时允许文件和目录；若扫描后的候选目录在点击前变为文件，“打开目录”可能转而打开该文件。
- 存储页改用独立的 `open_workspace_directory` Host 操作。阻塞任务中按已注册工作区重新解析相对路径，要求当前目标是普通目录，拒绝符号链接及 Windows 重解析点，再调用系统默认文件管理器；客户端不能指定自定义命令或应用。
- 文件系统在最后检查与系统打开之间仍可能变化，无法仅靠路径检查实现无竞态保证。真实三平台文件管理器行为待验收；页面仍不执行删除。
- `bun run check:rust:static` 的 Cargo check 与 Clippy 通过，仓库原有格式漂移仍为 advisory；`bun run check`、`bun run typecheck`、两个公共 JS 文件的语法与格式检查通过。本轮未新增或运行测试。
- 静态检查后执行 `cargo clean --manifest-path src-tauri/Cargo.toml`，移除本轮约 3.2 GiB 可再生 Rust 构建文件。

## 接续：清理前核对提示

- 用户实际清理开发项目时，需要区分 Rust 构建输出、JavaScript 已安装依赖、Python 环境、缓存和可能用于部署的产物。逻辑大小和目录名均不足以证明物理可回收空间或可以安全删除。
- 存储列表在完成或部分完成的扫描项下显示按目录类型区分的核对建议：确认构建已结束且可重新构建、核对包管理器与锁文件、确认 Python 环境可重建，或检查缓存及部署资源的具体用途。链接、不可读和非目录候选不展示用途推断。
- 仍只提供打开目录的人工核对入口；不新增删除按钮或自动清理。硬链接提示与部分扫描下限继续保留。
