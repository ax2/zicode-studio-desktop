# 项目上下文窗口内草稿（2026-09-28）

## 目标与发现

项目上下文已有文件修订号和保存冲突保护，但切换到另一个项目时，未保存的 `contextDraft` 直接清空。Notes 使用设备本地加密草稿仓库；项目上下文尚无可复用的持久化协议，直接写入共享的明文偏好存储会混淆多窗口草稿和已保存的项目配置。

## 修改

- 在项目工作区 store 内按场景、工作区 ID 和目录保存最近 32 个窗口内草稿；切回项目时恢复，且不把草稿当作已保存配置。
- 编辑时更新对应项目草稿；成功保存后只清除已提交的草稿版本，保存期间继续输入的内容仍留在该项目草稿中。
- 项目目标比较改用同一完整作用域，目录改变时重新读取项目资料，迟到响应继续由目标序号保护。
- 页面明确提示草稿仅在当前窗口的最近项目间暂存；项目说明输入限制为宿主接受的 50,000 字符。

## 验证与限制

React 构建、TypeScript 类型检查、`bun run check`、定向 Biome 检查、i18n 覆盖、MkDocs 严格构建和 `git diff --check` 均通过。全局检查保留现有告警。本轮未运行测试。窗口关闭或应用重启后草稿不会恢复；安全的持久化需要独立的加密存储和多窗口冲突语义。超过 32 个作用域时，最久未访问的窗口内草稿会被淘汰；跨平台实机切换仍待验收。
