# 自动化审批反馈作用域工作日志（2026-10-01）

## 目标与发现

自动化待审批任务会捕获发起时的 Pi 目标，但 `approvePendingTask` 返回后直接读取当前工作区；旧项目的异步失败也会向已切换的新项目弹出错误。工作流读取原先主要靠 `syncTarget` 递增请求序号；若目标变化早于同步通知，迟到结果仍存在短暂回填窗口。

## 修改与决策

- 工作流读取同时记录目标作用域；两次异步读取及完成阶段都核对它。若目标已切换而同步通知尚未到达，读取结束时主动执行作用域同步，清空旧列表并启动新项目读取。
- 工作流存储独立记录自身的活动作用域；即使草稿组件先更新了自己的 epoch，工作流同步仍能识别项目变化并清空旧数据。
- 待审批任务映射记录加载时的作用域。用户触发审批时先核对映射归属；审批请求仍固定发往原目标，返回后只有作用域与草稿 epoch 均未变化才刷新界面或显示错误。
- 作用域身份补入工作区 ID 和运行实例 ID。同一场景与目录在工作区重新绑定或实例重启后，旧草稿/工作流请求也不能回填新目标；会话切换仍可沿用同工作区的自动化数据。
- 已提交的审批可能在原项目完成；切换项目后不向新项目展示其结果。用户可回到原项目核对任务状态。

## 验证与遗留

`bun run typecheck`、`bun run check` 和 `bun run build:react` 均退出 0；静态规则仍报告仓库已有的警告。本轮没有运行测试。多窗口竞态、原目标离线与 Windows/macOS/Linux 实际切换仍待验收。
