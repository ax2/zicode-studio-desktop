# 自动化登录项归属保护（2026-10-01）

## 目标与发现

用户可选的后台自动化登录启动使用固定名称。此前启用会覆盖同名条目，关闭会按名称删除条目；如果用户或其他程序已修改该条目，即使不再指向 ZiCode worker，也可能被覆盖或删除。启动状态的旧判断还会把任意包含 worker 参数的文本视为本应用条目。

## 修改与决策

- 写入前检查同名条目：存在但执行命令不符合本应用 worker 格式时返回冲突，保留原条目。关闭开关仅移除已识别的本应用条目；非本应用条目保持原样并报告开关关闭。
- Windows 要求 Run 值指向绝对 EXE 路径且以唯一 worker 参数结束；兼容此前无引号的绝对路径写法。Linux 要求桌面项标识、名称、应用类型及唯一 `Exec` 行一致。macOS 要求 LaunchAgent 标识和 worker 参数同时存在。目录项存在检查包括悬空链接，避免直接覆盖未识别的路径。
- 更新后的路径修复仍只作用于已识别且启用的条目。没有创建登录项，也没有运行后台 worker。

## 验证与遗留

`bun run check:rust:static` 通过，包含本机 Windows 的 `cargo check --all-targets` 与以警告为错误的 Clippy；修改模块的 `rustfmt --check` 通过，全仓库格式检查仍报告既有 advisory 漂移。随后 `cargo clean --manifest-path src-tauri/Cargo.toml` 移除 18945 个构建文件、约 3.3 GiB，仓库根目录 `target` 已消失。本轮不新增或运行测试。三平台真实注册表、桌面项、LaunchAgent 与登录启动行为仍待安装版本验收。macOS 的 plist 识别仍是文本特征判断；未来如支持外部编辑，应使用完整 plist 解析并记录明确所有权标记。
