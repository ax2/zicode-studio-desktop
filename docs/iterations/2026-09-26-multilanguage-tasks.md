# 2026-09-26 Rust 与 Go 项目命令

状态：实现与 Windows 定向验证完成。接续版本要求诊断，扩展项目命令覆盖面；整体平台目标继续推进。

## 设计

- 保留 package.json 脚本，同时识别根目录 Cargo.toml、go.mod。
- Rust 提供 cargo check/test/build；Go 提供 go test ./...、go build ./...、go vet ./...。
- 每项提供独立稳定 ID、来源清单、工具和真实命令预览；混合项目不能因同名脚本而串任务。
- 参数由 Host 固定，不接受客户端任意命令；启动仍重新核对清单指纹。
- 仅点击运行后执行；这些工具可能执行构建脚本、测试、写入文件或下载依赖。
- 保持一项目一个活动任务、四个全局任务及进程树清理，不自动运行仓库本身的构建任务。

## 实现

- Catalog 读取根目录三类清单，统一应用真实路径范围、常规文件和单文件 256 KiB 限制。
  Cargo/Go 以清单存在发现固定命令，不声称已解析或验证完整工程配置。
- ID 使用 `@package/`、`@cargo/`、`@go/` 命名空间；保留旧 JavaScript 脚本名调用兼容，
  兼容分支只接受原有合法脚本名，不能与以 `@` 开头的新 ID 混淆。
- 任务参数只在 Host 内构造，不序列化给客户端；前端只能回传任务 ID 和预览指纹。
- 指纹增加版本标记和各清单长度边界，防止清单拆分、增加或删除造成相同连接字节序列。
- UI 标明命令来源和工具，运行历史显示实际 invocation；相同的命令内容不重复展示。
- 除新增独立测试模块外，复用现有运行器的并发、输出限额、停止和退出清理，不另起后台生命周期。

## 验证与边界

- 新增四项默认 Rust 用例：混合项目与参数、清单变更与删除、目录/大小拒绝、命名空间脚本真实执行。
- 增加前端用例验证 Cargo ID 回传与真实调用展示；定向项目/网关测试 70 项通过。
- 工具链专项用例使用临时 Cargo/Go 无外部依赖工程，默认忽略以避免普通 CI 隐含要求 Go 已安装；本机单独执行。
- 仍只发现根目录清单；Python、嵌套项目、交互输入及 macOS/Linux 实机验收待后续推进。
- 任一清单超限或不可安全读取会阻止当前目录发现，当前不做部分成功列表。
- 尚无本轮视觉截图；命令实际执行仍可访问宿主文件和网络，不是沙箱。
