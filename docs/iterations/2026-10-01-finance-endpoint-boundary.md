# 金融数据凭据目标边界工作日志（2026-10-01）

## 目标与发现

可选金融数据客户端原先默认读取进程继承的 `QVERIS_CAPABILITY_BASE_URL`。场景凭据随客户端请求发送，因此宿主环境变量能够在应用未显式选择目标的情况下改写凭据的网络去向。

## 修改与决策

- 默认客户端只使用代码中的固定 QVeris Capability API 地址，不再读取宿主环境变量作为地址覆盖。
- 构造函数显式传入 `baseUrl` 的能力保留，供明确配置的集成或本地模拟使用；默认金融场景没有该参数。
- 显式地址在客户端创建时解析：远端只接受 HTTPS，本机 `localhost`、`127.0.0.1` 和 `[::1]` 可用 HTTP；URL 用户名、密码、查询参数和片段均拒绝，避免 Bearer 凭据进入明文远端或含混请求目标。
- 同步调整已有的环境变量用例预期，使其检查默认目标不会被继承变量改写。未新增或运行测试。

## 验证与遗留

`bun run check`、扩展构建、改动文件的 Biome 格式与 lint、客户端文件的独立 TypeScript 检查及 `git diff --check` 通过。额外尝试的根 `tsconfig.json` 类型检查因现有缺失模块声明和其他扩展类型问题失败，不能据此宣称整个扩展目录类型检查通过。没有运行测试或真实网络请求。显式自定义端点的授权和产品级配置仍需单独设计，不应由隐式进程环境决定。
显式地址协议与 URL 结构约束加入后，再次执行客户端独立类型检查、静态规则、扩展构建及格式检查，均通过；新增地址分支仍待真实集成验收。
