# 2026-09-26 笔记批量恢复事务

状态：实现与静态检查完成，运行验收待补。上一阶段已有代码与静态证据，本轮继续处理 Host 部分导入问题。

## 设计

- 整批笔记先在工作区隐藏目录生成；无效后续笔记本不会提前发布前半批。
- 工作区操作持有跨进程文件锁，进程退出后由操作系统释放；恢复期间不允许其他 Host 读写同一工作区。
- 暂存目录记录本批生成的新 ID；发布时只移动本批目录，失败则回收已发布目录。
- 通过持久提交标记区分完成与中断。下次访问工作区先恢复未完成事务；恢复失败保留记录并阻止继续操作，不能假装空库或已清理。
- 保留笔记本图标，并将整批备份中的父子关系映射到新 ID。拒绝重复源 ID、缺失父节点和循环层级。
- 不宣称已证明断电耐久性或跨平台运行结果；本轮不新增、运行测试，只进行类型/静态/编译检查与资源构建。

## 实现记录

- 新增 `notes_vault/import_content.rs` 与 `import_transaction.rs`；原大型模块抽出导入逻辑，仅保留目录快照、锁生命周期和入口模块声明。
- `fs2 = 0.4.3` 为当前 Rust 1.88 工具链提供跨平台文件锁。Host 的工作区 scoped 视图在请求期间持锁，固定本次存储目录；持锁后先恢复旧事务，再迁移/访问现有笔记。
- 整批内容先写入 `.imports/<事务 UUID>/data`。记录本批新 ID 和目录归属标记后逐个发布，最后写入持久提交标记。
- 错误或进程中断后，仅回收归属标记匹配的本批目录；清理前校验暂存目录解析后的父路径。损坏日志、符号链接、越界/冲突路径和失败清理保留为恢复错误，不静默删除不明内容。
- 提交标记已发布时，即使后续清理失败也保持成功语义，下次访问完成清理，避免已提交却返回普通失败后重复导入。
- 全批次检查笔记本数量、重复源 ID、缺失父节点和环；恢复父子 ID 映射与图标。单本导入保留独立根笔记本语义。
- 附件增加重复引用检查；回收站文件保留备份删除时间，不因导入重置保留期限。
- 前端独立 `import-errors.ts` 提供占用、层级无效、恢复失败等中英文提示；`host_server.rs` 仅将新的 busy 错误映射为 HTTP 409。

## 实际边界

- 本轮未新增或运行测试，也未启动真实导入、故障注入或跨平台进程；编译只包含既有测试目标，不执行用例。
- 工作区文件锁约束遵守该协议的 Host；外部编辑器及旧版本 Host 不参与锁协调。网络文件系统锁与重命名语义尚无实机证据。
- 恢复路径为进程中断设计；断电、文件系统损坏及恶意并发改写不宣称已验证。Unix 同步目录；Windows 没有等同的目录 fsync 保证。
- 已完成导入与 HTTP 响应之间仍可能断线，调用者重试前需刷新列表；本轮未提供基于客户端请求 ID 的幂等恢复。
