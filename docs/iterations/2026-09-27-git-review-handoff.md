# 2026-09-27 提交差异与聊天草稿交接

状态：实现与静态检查完成，运行验收待进行。上一轮提交差异已完成代码与静态检查，本轮接续 AI 协作流程。

## 目标与设计

- 对已显示且非空的提交差异提供显式「在聊天中准备审查」动作，把提交 ID、父提交、合并/根提交信息与截断标记一并加入草稿。
- 只携带用户已读取的差异，不自动补读文件或发送消息。提示要求审查引用材料、不执行命令或修改文件；最终内容由用户在聊天输入框确认。
- 激活聊天前后固定场景、工作区、实例、会话及 target 对象身份；切换后停止交接，保留原聊天草稿文字和附件。
- 处理重复点击、聊天激活失败、输入框延迟、既有草稿长度限制与错误通知；不把未写入草稿报告为成功。

## 工作日志

- 已检查 Notes 交接与项目入口；现有普通 prefillComposer 不等待项目身份确认，新增独立受作用域约束的草稿交接辅助模块。
- git-review.ts 重新校验差异快照并构造 JSON 引用材料，携带 workspace/commit/parent/parentCount/truncated/patch；提示要求基于证据、限定已有预览并不执行命令或改动文件。
- PrepareGitReviewButton 使用 ref 和按钮禁用防止连续点击；成功读取的非空差异才显示动作。错误和成功通知由独立 createGitReviewAction 处理，store 与大型项目入口只接线。
- chat-draft-handoff.js 固定 target 对象与场景/工作区/实例/会话四元组，等待聊天激活，最多 40 次、每次 50ms 等待可编辑且仍连接的输入框；在写入前再次确认身份。
- 原草稿逐字符保留，不 trim、不覆盖，引用材料追加到尾部；原附件不修改。发送 input 事件并触发现有 draft sync，聚焦并选中追加部分，未调用发送动作。
- 输入框长度上限与 1 Mi UTF-16 单元保护同时生效，超限在写入前失败；draft sync 同步抛错时明确提示内容已插入，避免用户误认为可无条件重试。
- app.js 仅增加导入和回调接线，i18n.js 仅补充词条；中英文帮助、平台说明与导航已同步。
