# 2026-09-29 文件页响应完整性

## 目标与发现

- Host 的分页及旧版完整列表响应都包含 `entries`。前端此前将缺失的 `entries` 默认为空数组，可能把协议异常显示成“空目录”。
- 后续页只检查偏移递增；偏移与实际返回条目数不符时也可能继续追加不一致页面。

## 修改与决策

- 首次读取必须收到数组；若继续分页，下一偏移必须等于首批条目数并带有目录快照。
- 后续页的下一偏移必须等于请求偏移加实际返回条目数；异常时保留已读条目并显示加载错误。
- 旧 Host 只返回完整 `entries` 数组的响应继续可用。Host 的 200 项页大小、100000 扫描上限和目录快照规则未改。

## 验证与遗留

- `bun run typecheck`、`bun run check`、`bun run build:react` 通过；检查保留仓库现有告警。生成的文件浏览 bundle 已同步。
- 未运行测试或真实桌面界面验收。超过 100000 项的目录仍需系统文件管理器；慢速文件系统分页性能仍待跨平台验证。
- 仅更新本地工作树，未发布。
