# 2026-09-29 备份列表工作区隔离

状态：实现与静态检查完成；真实项目切换验收未完成。

## 目标与发现

- 设置页复用一个备份 Store，但列表、加载状态和操作反馈没有记录所属工作区。旧项目的异步读取可能在切到新项目后回写列表。
- 设置页切换项目时只重载配置，没有主动清空和刷新通用页的备份列表。
- 删除、恢复的确认弹窗可能在项目切换后才返回，操作需要核对原列表项的工作区。

## 修改与决策

- Store 记录当前工作区及请求序号；切换时清空旧列表、反馈和进行中标记，忽略过期读取与操作反馈。
- 列表只接纳匹配当前工作区的返回项。通用页可见时切换项目会重新读取备份。
- 创建、删除、恢复在同一工作区互斥。确认后的删除或恢复将列表项工作区传给 Store，目标变化时停止调用。
- 已发出的旧项目原生操作不会因为 UI 切换而取消；其完成结果不写进新项目界面。Host 的工作区归属校验仍是数据边界。

## 验证与遗留

- `bun run typecheck`、`bun run check`、`bun run build:react` 和改动文件的 Git 差异空白检查通过。Biome 对仓库其他现存代码报告非阻断警告；设计检查报告一个现存内联样式警告。本轮不新增或运行测试。
- 尚未在真实桌面应用中用两个项目和慢速备份操作检查切换、确认、恢复结果；跨 Windows、macOS、Linux 的真实备份恢复仍待验收。
