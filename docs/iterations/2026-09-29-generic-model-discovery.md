# 2026-09-29 通用 OpenAI 兼容模型发现

状态：本地实现与静态检查完成；真实服务与跨平台验收待补。

## 目标与实现

- 针对用户显式配置的 OpenAI Chat Completions / Responses 兼容渠道，增加手动“发现模型”入口。其他协议保留手填 ID，不假设其目录接口兼容 `/models`。
- 扩展进程从当前场景配置读取渠道 URL；需要鉴权时通过锁定 Pi 运行时的 `getApiKeyForProvider` 读取当前密钥，不把密钥传给 WebView。目录请求只回传候选 ID，限制 20 秒、2 MB 和 300 项；错误不包含上游响应正文。
- 发现后打开原有编辑表单，合并已有 ID 与新候选，用户检查并保存前不写 `models.json`。空目录、无效数据或请求失败不改变已有配置。
- 渠道配置通过 SHA-256 修订号关联发现与保存。请求返回时和最终保存时均核对修订号；发现响应还带回本次读取的非敏感渠道快照，避免设置列表过期时用旧 URL、协议或模型列表覆盖新配置。若期间修改或删除渠道，则拒绝使用旧结果。
- OpenAI 兼容渠道允许先保存空模型列表。保存现有模型 ID 时继承其原有元数据字段，避免编辑表单仅包含 ID 而抹去上下文和能力参数。
- 中英文帮助说明目录可能包含非聊天模型，需要用户审阅；没有自动调用外部目录。

## 偏差、风险与遗留

- 通用 `/models` 响应只可靠提供 ID，不能推断模态、推理能力、窗口与价格。用户可在高级模型配置中补充，界面保存保留已有元数据。
- 新增渠道若尚未有运行时凭据，需先保存并设置 Key，再执行发现；免鉴权本地渠道可直接发现。
- 修订号检查只覆盖读取到写入前的已观察状态，不是跨进程原子事务；极短的并发写入窗口仍需后续配置文件事务化处理。
- 真实 Ollama、LM Studio、远端 OpenAI 兼容服务，以及 Windows/macOS/Linux 场景切换和凭据生命周期尚未实机验收。
- 本轮不改专用 QVeris 刷新及 Rust 本地代理。没有发布产物或阶段截图。
