# 签名插件替换后的任务终止（2026-10-17）

## 目标和修改

Studio 成功安装新插件包、回退签名版本或重新安装开发包时，原版本活动任务不应留在任务中心。Host 现在复用插件禁用/卸载的任务撤销逻辑，在注册表变更成功后按插件 ID 跨场景置 `revoked`。签名安装失败不触碰任务状态。存储更新失败只记录有界错误；这仍是发布生命周期 profile 前必须解决的可靠性缺口。

## 验证证据

- 使用接收端临时测试密钥签名的 `first/second/tampered.zicode-plugin`，隔离 Host 专项 1/1 通过：旧版本任务运行中 → 篡改包拒绝且状态不变 → 成功升级置 `revoked` → 新版本任务运行中 → 成功回退置 `revoked`。
- `bun run check:rust:static` 退出 0，Cargo check 和严格 Clippy 通过；rustfmt 仍报既有 advisory。
- 前后只读存储扫描完整、未知项 0。`target` 29,418,858,111 → 29,419,049,087 B；task-scratch 均为 852,978,182 B；E 盘可用 48,413,036,544 → 48,374,095,872 B。没有执行清理，卷余量变化不归因于本次测试。

## 边界和遗留

签名容器是接收端测试包，不是 Zi DevTools 正式签发交付。当前只验证 Host/Store 元数据，尚无真实提供方任务或 View 生命周期。批量重载、发布者撤销、工作区关闭和 Host 关闭的任务协调，以及状态存储失败后的强一致性仍未完成；`plugin.task.lifecycle.v1` 未发布。DevTools 154 项完整接受仍为 0，ZiFile 全功能未验收。
