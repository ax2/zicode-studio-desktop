# 项目 Git 单文件取消暂存工作日志（2026-09-27）

## 目标与发现

上一阶段已有单文件暂存，调整索引仍需外部 Git 客户端。Git 有首次提交的仓库和未提交过的仓库对 `restore --staged` 的处理不同，取消暂存必须保留工作树内容。

## 本轮修改

- 状态条目增加 `unstageable`，仅对安全、无损的路径与明确的索引改动开放操作；冲突项和未跟踪项不作为普通取消暂存处理。
- 新增桌面 Host 的 `workspace_git_unstage`。它只接受已注册工作区，在执行前重新读取并匹配状态。已有 HEAD 时用 `git restore --staged` 恢复该文件索引；尚无首次提交时用 `git rm -f --cached` 移除索引条目，均不删除工作树内容。暂存重命名时同时恢复原路径。
- 界面加入确认、操作中状态、错误提示及结果刷新。暂存与取消暂存共用互斥操作状态，完成或结果不确定后关闭旧差异预览。远程 Host 路由禁止此写操作。
- 更新中英文帮助和开发者平台总览。

## 决策、偏差和风险

- 取消暂存针对整个文件的索引改动，包含用户之前部分暂存的内容；确认框和帮助明确提示。
- 状态字符校验不等于内容快照。Git 索引或工作树可能在检查后变化；结果不确定时要求重新读取，不自动重试。
- 聚合目录、特殊路径、冲突项及展示上限外的文件不提供此按钮。此轮不实现提交、回退工作树或推送。
