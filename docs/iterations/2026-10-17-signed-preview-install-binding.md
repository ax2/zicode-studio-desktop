# 签名预览与安装内容绑定（2026-10-17）

## 发现

插件管理界面先通过 Tauri 文件选择器验签、预览发布者指纹与权限，再向用户确认。确认后，另一个安装命令重新读取同一路径并验签，但原先只接收 `packagePath` 与 `trustPublisher`。如果确认期间同一路径被另一个有效签名包替换，Host 可能对用户没有预览的新发布者建立信任并安装。签名本身有效并不能证明用户确认的对象未变化。

## 修改

- 预览返回 `manifestSha256`：对已验签的原始 `package.json` 字节计算 SHA-256；该清单含发布者、公钥、签名与全部文件摘要。
- Plugin Manager 把此摘要原样交给安装命令。Host 安装时重新验证所选路径，核对清单摘要后才进入注册表安装和新发布者信任写入。摘要不一致时提示重新选择。
- 现有 Host 内部直接安装方法保留供现有专项夹具使用；桌面 Tauri 命令走必须提交摘要的路径。签名容器协议没有变化，也未修改 DevTools 或 ZiFile。

- Plugin Manager 定向前端 10/10、TypeScript 类型检查、`bun run build:react` 与 `bun run check` 退出 0。`bun run check:rust:static` 退出 0，Cargo check 与严格 Clippy 通过；全仓库 rustfmt 仍报告既有格式漂移。
