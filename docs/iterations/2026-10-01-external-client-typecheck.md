# 外部数据客户端静态类型门槛工作日志（2026-10-01）

## 目标与发现

现有 `bun run typecheck` 只覆盖 React 前端。仓库根 `tsconfig.json` 试图检查全部扩展，但内嵌 Pi 包当前缺少其指向的类型声明，且其他扩展仍有独立类型错误，因此不能把根配置当作当前可用的扩展门槛。外部模型目录与金融能力客户端会处理网络数据及凭据，需要稳定的源码类型检查。

## 修改与决策

- 新建严格的 `tsconfig.external-clients.json`，只覆盖金融能力客户端、QVeris 模型目录客户端和通用 OpenAI 兼容模型目录客户端；不借用缺失的 Pi 类型声明。
- 通用模型目录解析把已校验的模型 ID 明确标成字符串，消除严格模式下的 `any` 推断。
- `bun run typecheck:external-clients` 进入 PR 测试工作流和三平台验证入口；它是静态类型检查，不执行网络请求或测试用例。

## 验证与遗留

执行新类型检查、原有前端类型检查、仓库静态规则、扩展构建与格式检查；没有运行测试。根扩展配置仍不能整体通过，真实 CI、网络服务和三平台运行仍待验收。
