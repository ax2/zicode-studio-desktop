# 系统信息验证收口与时钟回拨修复

本轮按 #33 已交付的 Windows 范围收口，保留原 Milestone v0.6.5。新发现的低影响时钟回拨缺陷由 #89 跟踪，修复实际排入 v0.6.6；不改已经冻结的 v0.6.5 安装包或 r65。

## 已有真实证据

复核[2026-11-04 的交付记录](2026-11-04-system-information.md)及其原始收据：实际 WebView2 在 1280/900/769/768/360 五种宽度、六主题、中英文通过；内存显示“内存”，CPU/温度/频率图、内存环图、磁盘容量条及 GHz/GiB 单位正常。温度实读 48.375、47.000、48.750°C，停止后状态 idle、读数 null、采集器 0；调用者完整性 8192。原生托盘鼠标未单独验证的记录保留。

Windows 采集、传感器解析、管道身份校验、读取器和托盘实现仍沿用已验路径；后续差异主要为平台条件编译。此处复用历史证据，不声称本轮重新打开过 Studio 或温度监控。

## 本轮必要补充

- 11 项定向前端检查通过：单位和无读数、显式授权/取消、托盘事件路由及晚到监听释放、采样有界性和时钟回拨恢复。
- 40,000 条、间隔 2.5 秒的合成序列验证历史始终限制在最近 60 秒/64 条，缺失温度保留断线。它相当于 27.8 小时的采样数量，不是真实硬件长测。
- 生产 `SensorReader.cs` 原文编译为普通权限隐藏测试进程，仅加载临时空传感器库，无硬件或驱动调用；实际验证管道断开和自有父进程退出时均关闭库、正常退出。夹具不会启动 Studio 或管理员监控。测试脚本为 `scripts/verify-system-sensor-lifecycle.ps1`。
- 前两次 D 盘夹具未连接；独立诊断确认旧 .NET 拒绝该位置的程序集加载（0x80131515）。保留失败，仅使用本任务 C 盘本地 scratch 后通过，没有放宽生产身份/库哈希校验或加载策略。必要时向脚本显式传入本地 `-ScratchRoot`；使用新的 `-Receipt` 保留旧结果。
- 前端类型、仓库检查及设置页资源生成通过；只保留本次设置页生成产物，不生成原生应用。

## 修复版本与边界

时间回拨超过 10 秒时开始新时间线；轻微乱序和重复仍忽略。原始停更红例保留，修复和设置页产物进入 v0.6.6，不计入已经冻结的 v0.6.5。

本轮没有桌面操作、真实提权、硬件长测、其他实体机测试、模型调用或用户资料写入。原生鼠标与更多硬件的历史未验证范围如实保留，不据此追加例行验收活动。后续确有实际问题时按编号版本 Issue 推进；目前明确计划跟进的是 #89。
