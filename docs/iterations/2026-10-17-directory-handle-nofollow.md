# 目录资源句柄打开加固（2026-10-17）

## 目标与发现

Studio 的单层目录元数据入口供未来目录工具共用。此前对每级相对目录先读
元数据并拒绝链接/Windows 重解析点，再用 `open_dir` 打开；两步之间若条目
被替换，打开操作仍可能跟随新链接。此前静态链接回归不覆盖该替换窗口。

## 修改

- 复用锁文件已有的 `cap-fs-ext 3.4.5`，每级改用 `open_dir_nofollow`。
- Windows 在打开后的目录句柄上再次核对 `FILE_ATTRIBUTE_REPARSE_POINT`。
  预检查仍保留，用于稳定路径的明确拒绝；实际安全边界绑定到打开句柄。
- 增加确定性替换用例：先检查普通目录，再将同名条目换成目录链接，
  验证最终打开步骤拒绝。原单层快照、一次性 grant 与链接拒绝用例保持。

## 验证与边界

- `bun run check:rust:static` 通过 Cargo check 和严格 Clippy；整仓格式检查
  仍报告既有漂移。
- `local_directory::tests` 4/4 通过，新增替换用例在本机 Windows 成功创建
  链接并执行拒绝断言，没有因权限跳过。
- 这是 Host 源码与 Windows 单元回归证据；还需真实界面/HTTP/Worker 复验，
  macOS/Linux 实际文件系统以及更复杂的并发替换、junction 类型待验证。
- 目录资源仍只公开单层名称与类型，不读取文件内容或向插件暴露绝对路径。
  DevTools 完整接受 0/154，ZiFile 0/108。没有新签名提供方包、发布版本或 ZIP。
