# 归档插件事件重复 JSON 键拒绝（2026-10-18）

## 目标与修改

ZiFile 原生适配仍未开放，但 Studio 已有内部归档事件接收器。此前它直接将每一行解析为 `serde_json::Value`；同一对象中的重复 JSON 键会在解析时被覆盖，随后字段集合检查无法察觉。对于将来承载归档操作、结果和错误的跨进程协议，这会让两种对同一行的解释不一致。

本轮新增通用严格 JSON 解码器 `plugin_json_decode.rs`，递归读取对象、数组和数值；顶层、嵌套层和 Unicode 转义后同名的对象键均拒绝，且要求一行只有一个完整 JSON 值。归档事件接收入口先严格解析，再沿用现有字段白名单、身份、序号、预算、终态和完整流校验。重复键统一返回稳定 `invalid_json`，当前调用的解码器进入失败态，不向上层释放已接收的局部结果。其他插件协议尚未改用此解码器。

配套的提供方命令行校验器此前也用 `JSON.parse`，同样会覆盖重复键。本轮新增有界 JSON 键扫描并在 `verify-zifile-adapter-events.mjs` 中使用；先由原生 `JSON.parse` 检查语法，再递归扫描原始文本，按解码后的键名判重。它不执行 ZiFile，只让提供方交付前的验证规则与 Host 一致。
