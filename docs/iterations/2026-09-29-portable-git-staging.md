# 2026-09-29 PortableGit 更新暂存

## 目标与发现

- Windows PortableGit 更新原先先删除已安装的 Git/Bash 资源，再运行自解压归档；解压失败或中断会留下不可用目录。
- Bun 已有暂存切换逻辑；两种资源需要相同的旧版本回退语义。

## 修改与决定

- 提取通用的同卷资源目录暂存切换函数。Bun 与 PortableGit 都先在目标旁准备完整目录、写入版本标记，然后切换；提交失败尝试恢复旧目录。
- PortableGit 在暂存目录解压，要求 `cmd/git.exe` 和 `bin/bash.exe` 均为非空普通文件才切换。现有安装的复用判断采用相同的文件检查。
- 解压失败只清理暂存目录，不删除原有 Git/Bash。旧资源清理失败会报告保留路径。非 Windows 构建清除 Windows 专属资源的既有行为保持原样。

## 验证与遗留

- `node --check` 检查两个入口与共享模块，`bun run check` 和目标差异空白检查通过；未运行自解压归档、测试或 Windows 安装包构建。
- 目录切换不具备断电原子性；中断遗留的暂存或备份目录需人工核对，三平台真实交付仍待验收。
- 本轮只更新本地工作树，未发布。
