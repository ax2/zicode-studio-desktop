# 项目上下文字段合并（2026-09-28）

## 发现与目标

多窗口保存冲突后，界面会保留整份旧草稿。用户刷新已保存版本并直接重试时，旧草稿中未改过的字段也会覆盖另一窗口的新值。项目说明、默认场景和预算需要分别判断来源，避免无关字段互相覆盖。

## 修改

- 草稿记录创建时的配置和修订号，并随窗口内项目切换保留。刷新读取到新修订号时，逐字段进行三方合并：本窗口未改的字段采用最新已保存值；仅本窗口改动的字段保留草稿。
- 同一字段在两个窗口都被改动且值不同时，保留草稿显示供比较，并阻止保存。用户需逐项选择“使用已保存的值”或“保留我的修改”；选择后再保存仍由宿主修订号校验。
- 预算按输入文本归一后比较，避免宿主数值与表单字符串的类型差异制造假冲突。保存期间继续输入时，草稿基线随成功保存结果更新。

## 验证与限制

React 与 CSS 构建、TypeScript 类型检查、`bun run check`、定向 Biome 检查、i18n 覆盖、MkDocs 严格构建和 `git diff --check` 均通过；全局检查保留现有告警。本轮未运行测试。此合并只覆盖项目上下文的三个字段；另一窗口可能在用户作出选择后再次保存，最终写入仍可能返回修订冲突，需要再刷新。跨窗口实机交互与辅助技术验收仍待完成。
