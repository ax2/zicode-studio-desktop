# Actual Studio browser integration acceptance — 2026-11-05

Scope: actual Windows Studio browser entry/navigation, application switching and metadata restart restoration. Complete P0, browser-first default and Pi handoff remain unfinished.

`bun run build:local` completed successfully into the existing target/debug executable. The app was launched twice with the same fresh owned `--isolated-profile` and `--tools-only`; no user profile, credentials, installed application, native mouse/keyboard interaction or model calls were used. The QA-only debugger listened on loopback port9231. The build/profile/process identities and exact start times are in the session launch receipts. Both processes and the debugger are now confirmed closed through normal application exit.

Real UI event dispatch opened native tabs through browser_control and navigated to https://example.com/ and https://example.org/. Host-reported native URLs matched both destinations. A native reload produced NavigationFinished success and the native title events persisted Example Domain. A file:///D:/private navigation was rejected without reading a file. Switching Browser -> Notes -> Browser kept the native tabs; the surface revision advanced through the hide/show requests. This proves command/routing behavior, not independently measured native controller visibility or pixel occlusion.

The first process saved five synthetic tabs (three blank QA tabs and two public example pages). After normal exit, the second real Studio process opened the same profile. Saved tab IDs, URL/title/order, active tab and profile UUID matched exactly. Before opening Browser there were zero native pages; opening Browser rendered all five tabs and lazily created only the prior active page. The explicit tools-only deep link still opened Tools on startup. This does not prove browser-first normal startup; its router is still pending.

The separate native browser environment does not expose its page targets through the Studio chrome's debugger endpoint. Consequently, actual integrated body/selection extraction and physical visibility remain unaccepted. Earlier primitive-runner evidence cannot substitute for this integrated path. The next implementation should add a bounded, owner/document-bound content capture used by the product, not an unrestricted eval/debug endpoint. Pi context sharing, overlay/narrow/focus/close-to-tray behavior and re-entrant native teardown remain pending.

Failures retained: direct localhost debugger discovery initially received a proxy-related 503; verified loopback WebSocket discovery with NoProxy succeeded. The first harness raced queued tab creation/navigation and looked for native targets on the chrome endpoint; its failed report is retained and is not counted as navigation success. The corrected harness awaited actual native tab counts/URLs before proceeding. Initial exit identity comparison rejected matching times because PowerShell deserialized ISO timestamps as DateTime; path/hash/exact UTC ticks were verified before normal exit. No identity check was bypassed and no process was killed.

Evidence in the session outputs: browser-studio-launch.json, browser-studio-resume.json, browser-studio-native-qa-first-failure.json, browser-studio-native-qa.json, browser-studio-before-exit.json, browser-studio-restore.json, browser-studio-closure.json and browser-studio-native-acceptance.json. The chrome screenshot does not capture raw native child surfaces and is not evidence of webpage pixels. No source edits were needed in this runtime-only batch, so prior relevant checks were not needlessly repeated. No current user data integrity claim is inferred from these synthetic-profile checks; the current user profile was untouched.
