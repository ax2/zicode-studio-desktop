# 2026-09-30 禁用模型渠道的设置直连请求

## 发现

- `check_model_health` 会创建独立模型会话或直接请求 QVeris 聊天接口；`test_provider_channel`、`discover_provider_models` 和 `sync_qveris_models` 会主动访问模型或目录端点。这些设置操作不经过 Pi 聊天输入事件和桥接扩展的轮次守卫。
- 禁用渠道的密钥仍由凭据 Broker 保存，供以后重新启用。因此仅隐藏模型目录不能阻止上述直连请求。

## 修改

- 上述主动请求在开始前检查 `models.json` 当前渠道是否为 `enabled: false`，禁用时返回明确错误。健康检查在发出模型请求的最后一步复核，目录发现和连接检查在异步取密钥后、发出请求前复核，降低配置切换窗口。
- 设置页的错误文案增加中文映射。只对显式禁用渠道阻断；未设置 `enabled` 的旧渠道维持原行为。

## 验证与遗留

- `bun run build:extensions`、`bun run check` 和改动文件空白检查通过；没有运行测试或真实外部请求。
- 配置在最后一次检查之后改变，已经发出的网络请求无法由此撤回。用户安装的独立扩展及内置 Pi 之外的调用不受该检查覆盖；普通设置页仍不开放完整禁用开关。
