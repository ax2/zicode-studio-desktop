# 2026-10-26 Windows 时间戳双向转换

当前固定配置 `D:\work\local-state\zicode-studio-desktop` 已安装启用独立 Timestamp 0.1.0 候选01。在Studio工具页搜索“时间戳”，选择“时间戳转日期时间”或“日期时间转时间戳”，明确填写输入值和IANA时区，例如 `Asia/Shanghai`、`UTC`、`America/New_York`，点击执行。

共享原生时间戳双向转换核心；明确指定离线IANA时区。整数绝对值大于100亿按毫秒向零除1000，其余按秒；保留原单位规则。支持无偏移本地日期、RFC3339和工具带数值偏移的显示格式，显式偏移优先；历史秒级偏移完整保留，夏令时重复/不存在的本地时间拒绝猜测。值与时区各128 UTF-8字节，请求和结果48KiB。

示例：`0` 与 `Asia/Shanghai` 得到 `1970-01-01 08:00:00 +08:00`。把该显示结果填入反向工具，即使选择 `UTC` 也会得到 `0`，因为显式偏移优先。`1900-01-01 00:09:21 +00:09:21` 得到 `-2208988800`，历史秒级偏移没有截断成分钟。

## 实现和独立包

新增 `zi-timestamp-core`，原生包装层仍传系统Local，WASI适配器传用户明确指定的离线IANA时区。真实修复为原工具显示的“日期 空格 数值偏移”无法反向读取，以及历史亚分钟偏移显示丢失秒。保留原秒/毫秒阈值、负毫秒向零整除、RFC3339优先和原可表示范围；不把最初极端值应当失败的错误测试假设写成已修复崩溃。

Chrono不能直接解析自身秒级偏移格式，因此共享核心仅接受有界的HH:MM或HH:MM:SS数值偏移，严格拒绝超范围和宽度错误；不猜测夏令时重复/不存在时间。纽约重复的01:30可明确填写 `2026-11-01T01:30:00-04:00` 或 `-05:00`，相差一小时。

新增 `zi-timestamp-wasi` 使用公开compute stdin/stdout协议，严格信封、未知/重复属性拒绝；无文件、网络、宿主时钟、系统设置、模型或任务创建操作。包内无原生EXE、兄弟仓库源码、共享用户数据库或HTTP代办。8文件，WASM1150656字节，冻结候选和安装副本逐文件与外部SHA收据一致；unsigned本地交付，不发布。可选Pi注册未授权或调用，不把声明当模型验收。

构建命令为 `cargo build -p zi-timestamp-wasi --release` 和 `cargo build -p zi-timestamp-wasi --target wasm32-wasip1 --profile plugin`。`python scripts/package_timestamp_plugin.py --verify-only`只读核验当前候选；新构建须选未使用的 `--candidate-name timestamp-0.1.0-candidate-NN`，不得覆盖冻结候选01。原生源工具版本更新1.0.3，插件0.1.0，Studio应用0.5.3不变。
