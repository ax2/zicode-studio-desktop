# 2026-09-29 自定义渠道模型详情

状态：源码实现与静态检查完成；真实服务及跨平台桌面行为待验收。

## 目标与发现

- 需求要求模型 ID、名称、上下文窗口、最大输出及价格元数据。此前自定义渠道表单只编辑模型 ID；已有元数据保存时会保留，但新渠道只能到完整 `models.json` 高级编辑器输入价格。
- 渠道复制和模型目录发现均需保留已有模型的其他兼容性与分层价格字段，不能用表单字段覆盖整个模型对象。

## 修改与决定

- 表单增加按模型 ID 键控的“模型详情 JSON”，支持 `name`、`contextWindow`、`maxTokens` 与 `cost` 的 `input`、`output`、`cacheRead`、`cacheWrite`。价格单位为每百万 Token 美元。
- 前端校验 JSON、ID 对应关系、正整数窗口与输出、输入及输出单价同时存在、非负有限价格；扩展端再次校验价格上限并归一化。渠道保存合并新价格与已有价格对象，保留现有 `tiers` 等扩展字段。
- 未在详情 JSON 中填写的旧字段仍由保存端保留；删除旧字段可在完整高级配置中进行。目录发现仅返回 ID，保存时后端仍按 ID 保留已有元数据。
- 未使用模型目录推断价格；用户须自行核对提供商计费。无自动网络请求。

## 验证与遗留

- `bun run typecheck`、`bun run build:extensions`、`bun run build:react`、`bun run check` 和翻译覆盖检查通过。全仓检查仍报告 119 条已有警告、7 条提示及 1 条设计警告；本轮新增的对象原型 lint 提示已修正。
- 未新增或运行测试；未连接真实模型服务。新增 `channelModelDetails.ts` 承担表单数据的 JSON 解析与校验，避免继续把这部分逻辑塞入已超 500 行的配置 store。
- 表单未覆盖推理能力、输入类型、兼容参数、分层价格编辑；完整高级 JSON 仍是这些字段的入口。
