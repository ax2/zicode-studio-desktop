# 开发插件安装锁范围与暂存生命周期（2026-10-17）

## 目标与发现

开发插件只读预览已在注册表锁外完成，但安装仍持锁读取源包、复制至暂存、复核内容以及删除旧版本备份。包允许 2,048 文件、50 MiB，这些步骤会拖慢其他插件操作。

## 修改

Host 的两个开发插件安装入口先短暂读取注册表根路径，再于锁外准备插件：校验源清单和完整内容摘要、复制到唯一暂存目录、校验暂存清单及摘要。预览安装仍检查用户核对的摘要。准备失败由暂存对象清理本次目录，不触及已安装插件。注册表锁内保留最终版本切换、重载和状态变更；旧包备份在释放锁后删除。复制遍历与摘要遍历统一拒绝 Windows 重解析点，不再仅识别普通符号链接。常规安装也复核复制前后的目录内容。

## 验证

`cargo test --bin zicode-studio-desktop developer` 的 11 项相关测试通过，包括准备后拒绝替换内置插件时清理暂存、已有安装升级/卸载、Host 安装/重载。首次严格 Clippy 发现两个旧注册表便捷安装方法只供测试使用；限制为测试编译后，`bun run check:rust:static` 退出 0。新增模块单文件 rustfmt 已整理，全库格式漂移仍为既有 advisory。

随后将 Host 生命周期专项改为实际调用“预览摘要 → 安装”入口并重跑 1/1 通过；最终 Rust 静态检查再次退出 0。

锁外复制与锁外备份删除可由 Host 调用范围核对；最终注册表重载仍持锁，尚无多插件并发延迟基线。复用现有缓存构建 `target/debug/zicode-studio-desktop.exe`，125,063,168 B，SHA-256 `4BECCF0F674CBDBBD9B80957B5E320294357EF4314BD0417C6671B94F8E2BD1B`；隔离 `--tools-only` 进程 PID 56404 存活检查通过，按路径与命令行核对后停止。此烟测不等于原生安装/执行验收。本轮未改 UI、未做新截图或跨平台实机验收。
