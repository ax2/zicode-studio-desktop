# Stage：资源接收工具目录双向分页

日期：2026-10-17。目标是让资源输出在接入上百个插件能力时仍能从后续页返回，并知道当前所在范围。此前可信转交弹窗只有“下一页”，翻页后只能重新搜索才能回到前面的候选。

## 修改

- `plugin-resource-transfer.js` 为有多页的接收目录加入“上一页 / 显示范围与总数 / 下一页”。使用 Host 固定 40 项页大小与已有目录 revision；个性化收藏/最近仍沿用 accessRevision。新搜索或筛选继续从第一页开始，过期请求沿用 AbortSignal 取消。
- 只有一页时隐藏整条翻页栏，避免两项接收工具下出现无用的禁用按钮。首轮真实截图发现仅设置 HTML `hidden` 被 `.ui-toolbar` 的 display 样式覆盖，改用现有 `.hidden` 类后再构建复验。
- 工具执行期间禁用双向翻页；恢复执行控件时按当前页重新设置按钮，不改变显式共享、运行和保存的边界。

## 边界和遗留

多页往返由 41 项模拟目录验证，真实提供方尚无可用于原生接收目录的 41 个兼容资源工具，因此**多页原生交互与百项实际性能仍待验收**。本次原生截图在会话内目视检查，但没有另存可复查的截图文件。macOS/Linux、签名包、DevTools 154 项完整工具及 ZiFile 108 格验收仍未完成。Studio 只修改通用接收 UI，未修改提供方。

隔离进程在核对可执行路径和启动参数后停止。无敏感文件输入，未改插件启用状态或权限，没有删除构建缓存。
