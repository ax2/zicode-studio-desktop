# ZiDevTools 插件协议与磁盘规则

## 目标与决定

用户要求先优化本项目开发规则，控制磁盘增长；以插件规范打通两个独立程序，并将
提供方改造交给 zi-devtools 开发会话。此要求替代之前建议的跨仓库共享 Rust crate：
共享核心只存在于 ZiDevTools 内部的双构建产物之间，Studio 不依赖其源码。

已更新 AGENTS、磁盘预算说明及只读检查脚本。定义 1.0.0-rc.1 插件契约与便携快照，
明确既有 WASI 同步执行能力、五项首批工具、签名容器、错误和字节边界、UI/Pi 权限、
交付清单及后续资源/服务/系统接口路线。

## 源码核对

- plugin_registry.rs：签名后台要求 runtime.wasi，Manifest schemaVersion 1。
- plugin_worker.rs：WASI Preview 1，2 MiB 模块、64 MiB 内存、10M fuel、1 MiB stdout。
- plugin_capabilities.rs：外层 5 秒进程预算；退出后才排空 stdout。
- plugin-view-host.js：现有 window.zicode SDK，消息上限 64K 字符。
- plugin_package.rs / package-plugin.js：Ed25519 清单签名、50 MiB/2048 文件边界。

发现标准 WASI 正常 exit(0) 与外层管道排空两项需接收方验证/修复的问题，明确列入契约。
本轮不改 Rust，不生成应用构建，不宣称插件已接通。
