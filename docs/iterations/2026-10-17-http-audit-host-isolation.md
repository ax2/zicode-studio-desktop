# HTTP 审计初始化故障与 Host 隔离

## 目标与发现

插件失败不能影响 Studio 主界面或其他工具。此前 `service.http.get.v1` 的审计日志初始化失败会直接终止整个 Host 启动；例如当前日志被目录占用、超过上限，或坏尾行的备份路径无法替换。这会同时切断静态界面、插件目录和不依赖 HTTP GET 的服务。

## 修改

Host 现在把 HTTP 审计 Writer 作为可用或不可用的服务局部状态。初始化失败只记录错误类别并禁用该 HTTP 服务；不在日志中输出用户路径或审计内容。HTTP 准备阶段仍需先写入审计；不可用时返回 HTTP 503 `http_service_audit_unavailable`，移除刚建立的临时授权，不进行 DNS 或网络请求。主界面和其他插件路由继续启动。修复审计路径后需重启 Host 才会重新初始化服务；不自动丢弃或覆写故障文件。

## 验证与遗留

真实 Host 路由测试预置“日志路径为目录”的故障，验证主页、插件列表可用，已启用并授权的插件调用 HTTP prepare 得到稳定 503，且无残留 grant，1/1 通过；正常 HTTP 审计、取消及故障路径的现有 Host 专项复验 1/1 通过。`bun run check:rust:static` 通过 Cargo check 与严格 Clippy，仓库级既有 fmt 漂移仅为提示；本次 HTTP 模块与新增测试的单文件 rustfmt 检查通过。磁盘扫描数据及两次失败测试的精确遗留见技术博客同阶段工作日志。
