# Git 审查草稿的上下文归属

日期：2026-10-02。状态：实现与本机前端回归完成，原生界面待验收。

## 目标与发现

项目中的 Git 预览可以交接到当前会话输入框，由用户检查后发送。
原有交接层核对会话身份，但 Git action 仅核对 workspaceId，没有向交接层
提供源场景与目录的持续有效性检查。与运行分析、知识上下文的保护范围不一致。

## 修改

- Git action 从项目 store 读取完整 target，捕获场景、工作区、目录组成的 scope。
- 明确指定不同场景的草稿在激活会话前被拒绝。
- 交接草稿携带捕获的场景与 isCurrent；源场景、工作区或目录变化时，既有交接层拒绝写入。
- 合并调用方原有 isCurrent，保留上层预览有效性约束。
- 使用既有通知与交接路径；仅追加到输入框，不调用模型或提交消息。

## 验证

`git-review.test.ts` 使用真实 createChatDraftHandoff 与 jsdom 输入框，覆盖正常追加与
恢复状态同步、激活期间场景/目录/工作区/关闭项目四种变化、调用方有效性、不同场景。
保留原输入内容，失败不调用草稿同步；七项用例通过。

- 项目前端目录：16 个文件、128 项用例通过。
- 前端 TypeScript 检查、代码与设计检查通过。
- React 分发资源已重新生成。
- 代码检查仍报告 128 条 warning、7 条 info；终端生成资源仍有一条既有设计 advisory。

本轮没有 Rust 编辑、Rust 编译或安装包构建。检查针对前端上下文交接，不证明真实
WebView、模型推理、其他操作系统或整个开发者平台已验收。Git diff 仍是之前读取的
