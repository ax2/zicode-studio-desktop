# 平台验证证据归属工作日志（2026-10-01）

## 目标与发现

跨系统验证报告已有本机 Git revision、dirty 状态及逐项日志，但缺少 GitHub Actions 的仓库、运行编号、事件和触发 SHA。仅凭下载后的 JSON 无法直接核对报告属于哪次 CI 运行，也无法判定触发 SHA 与实际检出源码是否一致。

## 修改与决策

- 报告格式升为第 2 版。仅在 GitHub Actions 中写入非敏感的仓库、运行编号、尝试次数、事件、ref 和触发 SHA。
- 只有这些字段齐全、触发 SHA 与 `git rev-parse HEAD` 一致、且 `git status` 显示干净工作区时，CI 来源校验才通过；来源校验失败会使整个报告失败。
- 本地运行仍标记 Git revision 和 dirty 状态，不要求干净工作区；未提交代码的报告仍不能代表该 revision 的干净提交。

## 验证与遗留

进行了脚本语法与静态规则检查；没有运行包含测试的 `check:platform`，也没有取得三平台真实 CI 运行证据。真实 runner 上的报告字段与安装、启动、升级仍待后续验收。
