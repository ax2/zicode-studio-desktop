# 工作流页面改为 Host 调度状态观察者（2026-10-02）

状态：工作流 store 已修改，前端定向验证完成；真实多窗口和三平台运行待验收。

## 发现与实现

Host 已在取得用户级 OS 执行锁后运行到期工作流调度、执行结果回写及失败恢复。此前 `createAutomationStore.tick()` 仍在页面定时器里对同一批规则入队、重试任务和写入历史；页面不参与 Host 的执行锁，稳定任务 ID 与文件修订号只能降低竞争，不能建立单一职责。

现将工作流页面的 `tick()` 收束为 `load()`，保留原有不重叠轮询、工作区切换和停止定时器逻辑。移除仅由页面自动轮询调用的结果回写、失败重试及终态时间辅助函数。手动运行和审批仍走现有显式操作入口；手动入队后记录运行历史仍保留。`startScheduler()` 名称暂时保留以兼容原生壳调用，其实际作用已变为状态刷新。

本轮仅收束工作流页面；任务中心和 Agent Inbox 的其他定时器、通知及派发职责仍需独立检查，不能据此称所有页面都只读。

## 验证
