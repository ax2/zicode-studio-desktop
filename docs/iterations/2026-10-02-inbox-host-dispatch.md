# Agent Inbox 自动派发交给 Host（2026-10-02）

状态：Inbox 轮询路径已收束；任务中心定时模板的 Host 入队能力待补。

## 调查与修改

`host_server/automation_dispatch.rs` 已扫描已登记项目任务文件中所有 `pending`、`automation.autoDispatch == true` 且尚未绑定子进程的任务，并在持有用户级执行锁的 Host 生命周期内派发。Agent Inbox 的 `_poll()` 此前也会把这些任务写为 running 并发出 `sa-dispatch`，使页面与 Host 竞争执行权。

现移除 Inbox 轮询中的自动抢占和派发，轮询继续读取任务版本、更新列表并刷新界面。用户主动审批、批量审批、重试和再次运行仍保留现有先保存再派发的行为。该修改覆盖 Inbox 自动轮询，不覆盖其他显式操作的并发正确性。

任务中心 `store.tick()` 仍会为任务文件中的 interval/daily 模板生成运行实例；当前 Host 的 `automation_schedule.rs` 只扫描工作流文件，没有完整替代该模板生成路径。因此本轮保留任务中心模板调度，下一步须先补 Host 的模板入队、稳定实例 ID 和崩溃恢复，再收束其页面定时器。不能把窗口关闭后的工作流调度能力等同于全部定时任务已经可用。

## 验证

Inbox 25 个既有用例更新两条职责断言：自动任务与审批任务经过重复读取后仍为 pending，页面不写入也不发出派发事件；主动审批任务遇到版本冲突时显示错误、恢复 pending 并不派发。结合原生派发及任务存储，三个文件、35 个用例通过。未修改 Rust，未产生编译缓存或安装包。真实 Host 自动派发、多窗口竞争与三平台运行仍待验收。
