# 2026-09-29 工作区备份恢复与保留顺序

状态：实现与静态检查完成；真实恢复验收待补。

## 目标与发现

- 恢复会先创建当前状态的回退快照。若已有 7 份备份，创建过程立即裁剪最旧备份；用户选择恢复最旧的一份时，来源会在复制前被删掉。
- 原裁剪按目录名排序，同一秒创建的目录带随机后缀，不能可靠表示创建顺序。
- 不含可恢复应用目录的备份原先也会先创建回退快照，然后才报告无法恢复。

## 修改与决策

- 恢复先检查来源是否含可恢复的应用目录。回退快照创建时暂缓裁剪，复制完成后按元数据时间裁剪，并保留用户选择的来源及新建的回退快照。
- 裁剪删除成功后才计入已清理数量；裁剪读取失败只写日志，不把已经完成的数据恢复报告成失败。
- 普通手动和启动备份仍按原上限立即裁剪。恢复失败时暂缓裁剪产生的回退快照会保留，供人工排查和回退。

## 验证与遗留

- `cargo check --locked`、`cargo clippy --locked -- -D warnings`、本轮 Rust 文件的 rustfmt 检查及差异空白检查通过；仓库全量 rustfmt 检查仍报告其他现存文件差异。本轮不新增或运行测试。
- 尚未用真实工作区覆盖“7 份备份后恢复最旧一份”、复制中途失败及跨系统恢复。恢复过程仍逐个替换应用目录，不是整组原子事务；回退快照需要用户主动恢复。
