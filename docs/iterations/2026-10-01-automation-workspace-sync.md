# 自动化执行者项目注册表同步（2026-10-01）

## 目标与发现

用户可以同时运行多个桌面进程。持有自动化执行锁的进程在启动时取得项目注册表快照；另一个进程随后新增或删除项目，只会更新自己的 Host 内存表和共享 SQLite，执行者的自动化扫描不会看到新项目，已删除项目也可能留在其内存表中。

## 修改与决策

- 持锁进程先从共享元数据数据库只读读取已注册项目，成功后才启动规则、派发、运行和恢复循环。读取失败时每五秒重试，避免用过期快照启动执行。
- 运行期间每十五秒重新读取注册表。存在的项目目录规范化后一次性替换共享根目录表；其他 Host 数据服务与插件 Broker 使用同一张表，因此也能识别其他桌面进程新增的项目。
- 数据库不可读时保留上次成功的注册表并记录警告；缺失或无法访问的项目目录不会放入新快照。项目打开或移除与同步同时发生时，下一轮会按共享数据库收敛。
- 后台读取使用 SQLite 只读连接，不在轮询中创建数据库或运行迁移。Host 契约测试仍使用其注入的隔离目录，不读取真实用户注册表。

## 验证与遗留

`bun run check:rust:static` 退出 0，包含 Cargo check 和以警告为错误的 Clippy；仓库级格式检查仍报告已有格式漂移。改动的三个 Rust 文件经目标 `rustfmt --check` 检查通过。未运行测试或真实双进程验收。跨进程项目变更最多需约十五秒进入执行者视野；关闭所有桌面进程后持续执行、通知及三平台实机行为仍待实现。
