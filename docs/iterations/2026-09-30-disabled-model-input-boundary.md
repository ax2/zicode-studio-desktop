# 2026-09-30 禁用渠道的新输入边界

## 目标与发现

- 高级 `models.json` 可以保留渠道配置并标记 `enabled: false`，Rust 模型工具已尊重该标记；Pi 自身不认识这个字段，原先的模型目录和新聊天输入仍可使用该渠道。
- 锁定的 Pi 0.84.2 文档说明 `input` 事件在普通输入进入 Agent 前触发，返回 `handled` 会跳过 Agent。公开版本源码显示，扩展模型列表在 `models.json` 之上应用，但取消扩展注册会恢复内置模型；仅改 Pi 注册表不能保证已选模型及后续调用停止。

## 修改

- 配置模型目录现在排除显式 `enabled: false` 的渠道，因此应用模型选择列表不会继续主动提供其模型。
- 内置 Pi 桥接扩展在每次新输入时读取当前场景配置；当前所选渠道已禁用时，显示提示并以 `handled` 阻止该输入进入 Agent。配置读取失败也阻止输入并提示先修复设置，不把未知状态当作可用。
- 不对用户提供完整“禁用”开关，保留高级 JSON 的实验性标记。

## 验证与遗留

- `bun run build:extensions`、通知本地化后的 `bun run check` 与改动文件空白检查通过；静态检查仍报告仓库已有的 119 个 warning、7 个 info 和 1 个设计警告。未运行测试或真实模型调用。
- 禁用前已经排队的输入、进行中的请求、Pi 扩展直接发起的模型调用，以及直接绕过该输入钩子的其他调用尚未封闭；本轮不能宣称渠道已被全面禁用。
- 桌面聊天视图会把此两条扩展通知本地化；其他直接消费 Pi RPC 通知的客户端仍收到英文原文。
