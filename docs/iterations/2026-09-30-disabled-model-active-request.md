# 2026-09-30 禁用渠道时的当前请求

## 目标与发现

- 新输入已能在进入 Agent 前拦截禁用渠道；但用户在模型请求运行中修改高级 JSON 或普通渠道配置时，该请求仍会继续。
- 锁定的 Pi 0.84.2 源码确认：`before_provider_request` 处理器的异常被记录后会继续使用原载荷，不能用抛错作为禁用门槛。`ctx.abort()` 调用当前会话的取消流程；其实现不清空转向和后续消息队列。

## 修改

- 渠道保存或高级 JSON 写入成功并已向设置页回报后，如果当前所选渠道已标为 `enabled: false` 且 Pi 不空闲，内置桥接扩展发出取消请求并显示本地化提示。
- 配置已提交与取消请求的结果分开处理：取消失败不会把已完成的配置写入伪报为失败。

## 验证与遗留

- `bun run build:extensions`、`bun run check` 与改动文件空白检查通过；静态检查仍有仓库现存的 119 个 warning、7 个 info 和 1 个设计警告。未运行测试或真实模型请求。
- 取消是尽力而为，未确认在所有渠道和网络实现中都能即时停止。禁用前排队的消息可能继续处理，扩展直接调用模型也未被统一拦截。因此本轮仍不开放完整的渠道禁用开关。
