# 2026-09-26 可恢复任务草稿

状态：实现及 Windows 自动化检查完成，真实界面与其他桌面平台待验收。

## 目标与设计

- 开发者可将尚未准备执行的任务显式保存到工作区，再从任务中心或关联项目继续编辑。
- 使用已有任务文件及版本校验，草稿具有独立 `draft` 状态；不新增浏览器临时存储，不自动保存未提交文字。
- 草稿保留标题、说明、目标项目、计划和执行模式，但禁用调度和自动派发。用户从编辑表单显式启用后才进入正常任务生命周期。
- 支持保存草稿、筛选、恢复编辑、删除及启用；冲突失败时保留表单内容。
- 本轮实现任务草稿；自动化规则草稿、崩溃前未保存文字和跨工作区迁移仍属后续能力。

## 实现与发现

- 增加「草稿」筛选、卡片状态和「删除草稿」；新建或草稿编辑表单提供「保存草稿」，已有草稿提供「启用任务」。草稿仍须填写标题。
- `draft` 保留计划字段但 `enabled=false`、`nextRunAt=null`、`autoDispatch=false`。启用时使用同一 ID，追加事件并按当前时间计算下次计划。
- 定时模板识别排除草稿；普通批准、重试、重跑及原生派发入口拒绝草稿。旧任务面板自动派发只匹配待运行任务。
- 从大型任务中心提取 `TaskForm.tsx`；从 store 提取纯元数据更新模块 `task-metadata.ts`。已有入口仅接入状态、按钮和保存结果。
- 修正编辑保存失败仍关闭表单的问题：元数据保存返回布尔结果，失败保留输入。当前草稿已被别处启用时，刷新后再按草稿保存会被拒绝，避免把执行中任务改回草稿。
- 首轮测试暴露测试定位器同时命中标题栏和空列表的两个「新建任务」入口，已限定选择入口；功能用例重新运行通过。
- 浏览器通道本轮仍返回 `nodeRepl.fetch request failed`，无法获得真实 WebView 截图和点击证据。遵循 frontend-testing-debugging 技能的失败后不擅自切换浏览器通道规则，继续使用组件、文件与协议验证；视觉验收明确保留。

## 验证范围

- 模拟版本服务：保存、重新创建任务中心后恢复、编辑、冲突保留输入、刷新重试、删除、手动与定时启用。
- 调度边界：即使草稿带有旧的 `enabled=true` 和已到期时间，也不会被调度或「立即运行」执行。
- 旧面板即使读取到草稿的错误自动执行标记也不派发；原生派发草稿不解析工作区、不创建会话、不发送提示词。
- 真实临时工作区文件（含中文路径）：通过实际版本存储保存草稿，销毁首个中心后从磁盘重新读取；外部更新后过期启用失败且文件逐字节不变，刷新启用保留其他任务。
- 上述恢复证明重新读取磁盘数据，不等同于真实桌面进程重启或安装升级验收。旧客户端、外部文件编辑、崩溃遗留锁与自动化规则的边界沿用前轮记录。
