# 任务与自动化页面读取生命周期（2026-10-02）

## 发现

Host 接管调度后，页面应只在自身生命周期内观察已提交状态。任务中心销毁时只停止两个 interval，未取消运行时未就绪重试 timeout，也未使正在读取的旧结果失效。自动化中心虽取消 timeout，但晚到读取失败仍可能重新安排 timeout；工作区切换和成功恢复后也有待执行旧重试。

## 修改

- 任务中心销毁时提升作用域代数，使旧读取回复失效；清除待执行重试、刷新标记和读取句柄，并结束 loading。
- 自动化中心销毁时提升读取序列，使旧回复失效；切换工作区与成功读取均取消待执行重试并重置退避次数。
- 任务中心成功读取同样清除待执行重试。自动化列表的内部重试在每次调用前检查读取序列及当前工作区，避免重试已失效请求。
- 两页重新启动观察时，若旧 tick 尚在收尾，登记一次新刷新，旧 tick 完成后立即衔接；避免仅因重开与旧读取重叠而等到下一分钟。

显式任务写入、审批、手动执行及 Host 调度逻辑不在本轮修改范围。

## 验证与限制

TypeScript、项目静态规则检查和 React 分发资源构建通过；现有 124 个 warning、7 个 info 和终端生成代码的设计 advisory 仍在。本轮未新增或运行测试，窗口销毁后迟到失败与重开交错行为仍需实际运行验证。本地 Rust 编译目录保持清理状态。
