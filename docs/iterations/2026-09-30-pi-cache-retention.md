# Pi 下载缓存保留（2026-09-30）

## 目标与发现

项目 `.cache/pi-binaries/` 同时保存多个旧版 Windows x64 Pi 压缩包。2026-09-30 的本机目录中，0.82.0、0.83.0、0.84.1 三个完整旧包合计约 131 MiB，另有一份 0.83.0 的未完成下载。当前锁定版本为 0.84.2。下载缓存由构建脚本维护，不属于源码或项目数据。

## 修改与边界

- `fetch-pi-binary.js` 在确认目标运行时与当前锁定版本一致，或成功安装当前版本后，清理同一目标架构、距最近修改已满 7 天的旧版完整压缩包及未完成下载残留。新近下载的其他锁定版本暂时保留，降低并发构建争用。
- 只匹配该目标的 `版本-pi-目标.zip` / `.tar.gz` 及对应 `.part` 文件名，保留当前版本完整包、其他目标、目录和符号链接。单个文件无法清理时报告警告，不能把已经成功的安装改报失败。下载脚本不会续传 `.part` 文件。
- 本机原有 `src-tauri/resources/pi/.version` 是旧的纯版本格式。锁定的 0.84.2 包 SHA-256 核对通过、未发现运行中的 Pi 进程后，执行 `bun run fetch:pi` 完成安装并写入新式标记，清理三个旧版完整包共 131.2 MiB；再次执行清理旧 `.part` 文件 11.6 MiB。缓存总计清理约 142.8 MiB。旧版回退若未保留压缩包，需要重新下载。

## 验证与遗留

`node --check scripts/fetch-pi-binary.js`、`bun run check`、该脚本的 `git diff --check` 通过；项目检查报告 123 条警告、7 条提示和一条设计警告，退出码为 0。本轮未运行测试或跨平台打包。7 天门槛不能证明没有进程正在使用较旧的压缩包；不同锁定版本的真实并发构建仍需验收。
