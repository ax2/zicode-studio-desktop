# 2026-09-30 模型配置写入边界

## 目标与发现

- 模型渠道保存、删除、QVeris 目录同步和高级 JSON 写入都修改同一场景的 `models.json`。原先分别读取再写入，两个窗口可能互相覆盖；普通文件写入中断还可能留下不完整 JSON。
- 普通渠道编辑已有版本比对；高级 JSON 未携带读取版本，删除操作先移除系统凭据再请求配置删除，冲突时可能只删除了凭据。
- Pi 的 `before_provider_request` 文档说明可替换请求载荷，但没有可依赖的统一拒绝语义，因此完整渠道禁用仍不能只依靠此钩子实现。

## 修改

- 四个配置写入入口共用 `models.json.lock`。在锁内重新读取并完成版本检查、修改与提交；提交先写同目录临时文件并同步文件，再替换正式文件。
- 高级 JSON 读取现在返回文件内容摘要；保存要求该摘要仍与磁盘内容一致，成功后返回新摘要供继续编辑。缺少摘要或内容已变化时保留编辑草稿并提示刷新。
- 删除渠道请求带渠道版本，先完成配置层的删除，再清理对应场景的系统凭据；切换场景后仍清理原场景凭据，避免只完成一半。旧版直接调用接口而不提供版本的客户端仍可删除，其安全性另需收敛。
- 保存高级 JSON 时也拒绝 `providers: null`，与后续读取对 `providers` 对象的要求一致。锁被另一写入占用时返回可恢复错误，不覆盖文件。

## 验证与遗留

- `bun run build:extensions`、`bun run build:react`、`bun run typecheck`、`bun run check` 与改动文件空白检查通过。`bun run check` 仍报告 119 个已有 warning、7 个 info 和 1 个设计警告。根目录 `tsconfig.json` 的全仓检查仍有既有缺失类型与其他错误，不能作为本轮通过证据。未运行测试，也未进行真实双窗口、进程中断或三平台验收。
- 锁文件在进程异常终止后可能遗留，届时写入会明确报忙；安全的自动恢复策略尚未实现。外部程序不遵守此锁时仍可能竞争写入。
- 配置文件与操作系统凭据仍是两个存储系统，无法在一个文件锁中做跨存储原子提交；部分失败会提示并保留可复核状态。
