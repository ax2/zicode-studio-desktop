# 2026-09-29 项目文件浏览完整性

状态：实现与静态检查完成；桌面验收待补。

## 发现

Host 文件浏览使用 `filter_map` 静默跳过目录迭代、条目类型及路径表示错误，页面可能把不完整目录显示成正常列表或空目录。一次读取没有条目上限。路径序列化无条件把反斜杠改为斜杠，也会改变 Unix 文件名中合法的反斜杠。

## 修改

- 目录枚举、条目读取和无法无损表示的文件名现在明确失败；链接与其他非普通条目沿用现有过滤规则。
- 单次目录扫描最多接受 4096 个条目，超限提示在系统文件管理器中打开；这一上限作用于扫描条目而不只是显示条目，避免大量跳过的条目仍占用 Host 时间。
- 仅 Windows 将相对路径分隔符转换为 `/`，Unix 保留文件名中的反斜杠。
- 前端对新的固定错误文本提供中文翻译；保留现有目录切换时忽略过期回复的逻辑。

## 验证与遗留

`cargo check --locked --all-targets`、`cargo clippy --locked --all-targets -- -D warnings`、目标文件 Rustfmt、`bun run typecheck`、`bun run check`、翻译覆盖、React 构建与目标差异空白检查通过。Biome/设计检查仍报告仓库其他位置的既有提示。本轮未运行测试或真实桌面文件浏览。超过上限的目录目前无法在内置侧栏分页访问，需使用已有的系统文件管理器入口；后续应提供有界分页。三平台非 Unicode 路径、权限错误和大量文件场景待实机验收。
