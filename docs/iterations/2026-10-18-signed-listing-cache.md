# 签名插件列表的加载时元数据缓存（2026-10-18）

## 发现与修改

Studio 的 `/v2/plugins?summary=true` 是插件管理和应用目录的常用入口。此前每次列出插件时，都会在全局注册表锁内为每个签名包读取当前签名元数据并扫描保留版本目录；大量插件或单个慢盘包可能拖慢主界面和其他工具。

现在已验证的签名包在发现/重载时保存发布者 key ID 和可回退版本列表；列表使用内存清单。安装、升级、回退与撤销仍经原有签名/信任验证；升级把旧包及其版本元数据写入保留目录后，再刷新内存版本列表。开发插件和内置插件的对应字段为空。执行目标包时仍独立读取签名元数据并验证包完整性；列表缓存不能授权执行。

外部进程若在 Studio 运行期间修改已安装签名包元数据，列表展示可能在下一次重载前滞后；实际执行会拒绝损坏的包。这是缓存的明确边界，不能把列表字段当作当前文件完整性证明。

`bun run check:rust:static` 最终退出 0：Cargo check、严格 Clippy 通过，整仓 fmt 保留既有 advisory。新专项验证：移除测试注册表中的签名元数据后，列表仍从加载时内存元数据响应，而执行用的完整性快照拒绝该包，1/1 通过。

首次签名升级/回退专项失败：升级后 UI 缓存漏掉刚保留的 `1.2.3`，测试实际为 `[]`。原因是首次缓存刷新早于旧版本目录和元数据写入。将成功路径的刷新移到保留版本写入之后，Rust 静态检查及同一安装/升级/回退/撤销专项重跑 1/1 通过。应用目录真实 HTTP 生命周期 1/1；手动工具目录及 205 能力插件轻量列表 1/1。首次失败未计通过。

这些测试验证列表字段、生命周期和目标完整性拒绝；未在上百个真实签名包或慢磁盘上测量 UI 延迟，也未对本轮源码运行 macOS/Linux CI 或原生窗口。DevTools 154 项与 ZiFile 108 格的完整接受数不变。已有四平台 CI 与发布构建配置，不能代替此轮修改的实际跨平台运行证据。
