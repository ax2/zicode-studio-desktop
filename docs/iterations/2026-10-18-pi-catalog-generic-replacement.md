# Stage：Pi 目录工具超预算更新时移除旧活动入口

日期：2026-10-18。目标是让数百工具的按需加载在会话预算边界上保持可解释：某个已激活的类型化插件工具更新后，新声明无法放入当前工具预算时，Pi 目录返回通用调用模式，旧类型化入口不能继续留在活动工具列表中。

## 发现与修改

`extensions/plugin-catalog.ts` 原先在 `next.size > 128` 或累计工具声明超过 256 KiB 时记录通用调用映射并返回 `mode=generic`。如果被替换的工具此前已类型化注册且处于活动状态，旧注册的 schema/目录修订仍在 `getActiveTools()` 中，模型会同时看见过期的类型化入口和新的通用入口。Host 会在调用时复核当前目录，不能把这种 Host 拒绝误认为旧入口正确。

本轮在通用回退前，仅对该工具已有类型化注册的情况从 Pi 活动列表移除其名称；保留其他原生、扩展和插件工具的活动状态。注册本身未删除，新的通用 `studio_plugin_call` 仍绑定工具 ID、当前修订并由 Host 再验权限和输入。新加载的第 129 个工具没有旧入口，不触碰已有活动列表。

## 验证与边界

定向回归构造 128 项预算内初始快照，再替换其中一个工具，使累计声明越过 256 KiB；明确断言预算两侧的字节关系。更新返回 `mode=generic`、旧入口不在活动列表、其他活动项仍在，通用调用继续请求 Host `/v2/plugin-tools/invoke`。初版测试只增加 7 字节、没有越过预算，按失败信息修正为超过边界的向量后复跑成功；不把初次失败计为通过。

`bun run vitest run extensions/plugin-catalog.test.ts` 8/8、`bun run typecheck:extensions-source`、`bun run check` 均退出 0。未重建或启动嵌入 Pi，真实模型会话中的活动工具列表、跨平台 Pi 运行和提供方实包尚未验收。未修改 DevTools/ZiFile、权限、应用版本或发布目录；完整 DevTools 154 项和 ZiFile 108 格接受数不变。
