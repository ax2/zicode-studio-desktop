# 笔记移动晚期失败回滚（2026-11-13）

关联 Issue #22，保持开发中。本批处理普通 I/O 失败，不把内存回滚当作进程硬中断恢复，也不宣称完整 Notes 或 v0.5.10 升级验收完成。

原移动流程先删除源正文、清理源附件，再写笔记本元数据和变更日志；后两步失败会返回错误，但笔记已移动。现在专属 `move_update` 模块先准备正文、两份元数据和日志的前后字节，按序应用，失败时反向恢复。源正文在删除目标正文之前恢复；源附件直到全部成功才清理。回滚只替换本次预期字节，遇到其他修改或二次失败时保留现有数据和附件副本并明确报错，不盲目覆盖。普通原子写在准备失败时清理自己创建的临时文件。
