# 更新后的后台自动化恢复（2026-10-01）

## 目标与发现

更新失败时已能尝试恢复原先运行的 worker，但成功安装后应用重启会释放进程内更新锁，也会丢失 worker 先前的运行意图。更新中途若桌面进程异常结束，失败恢复回调也可能无法执行。

## 修改与决策

- 更新流程观察到运行中的 worker 后先请求它停止；取得独占安装锁并确认它退出时，在用户级系统目录创建一个零内容、一次性的恢复标记。标记不保存路径、凭据或可执行内容；已停止或用户正在停止的 worker 不会因此被标记。标记在独占锁内创建，避免另一桌面实例在准备阶段提前消费。
- 更新失败时释放独占锁后尝试按标记恢复。若安装成功或桌面异常退出，下一次桌面 Host 初始化成功后在后台尝试恢复。通过 OS 单实例锁观察到 worker 已运行后清除标记；启动失败保留标记供下次启动重试并记录日志。
- 用户从桌面或 CLI 显式停止 worker 时先清除恢复标记。该机制只覆盖更新前正在运行的 worker，不启用默认开机常驻。

## 验证与遗留

`bun run check:rust:static` 退出 0，包含 Cargo check 与以警告为错误的 Clippy；新增 worker 模块目标 `rustfmt --check` 通过。仓库级格式检查仍报告已有漂移。未运行测试、真实更新或三平台安装验收。

检查后执行 `cargo clean --manifest-path src-tauri/Cargo.toml`，Cargo 报告移除 18,939 个构建文件、约 3.2 GiB。

worker 退出后到标记创建之间若桌面进程恰好崩溃，运行意图仍可能丢失；真实竞争验收需覆盖此边界。恢复路径依赖新版本桌面应用至少启动一次；操作系统登录时自动启动以及进程异常退出后的常驻监督仍待设计。更新产物当前仍关闭。
