# 2026-09-29 模型渠道连接检查

状态：源码实现与静态检查完成；未进行真实服务或跨平台桌面验证。

## 目标与发现

- 需求要求每个自定义模型渠道可主动测试连接。当前只有模型健康检查和目录发现，缺少渠道级入口。
- 单纯在配置中增加禁用标记不足以满足“禁用渠道”：Pi 模型注册表和 Rust `model_tools` 均会读取 `models.json`；Rust 当前遍历所有 provider 的模型，忽略禁用标记。禁用需要统一约束模型选择与调用路径，留待独立实现。

## 修改与决定

- 渠道行增加“测试连接”，明确提示有模型时可能发起一次收费的短请求。
- 已配置模型时复用单模型健康检查，更新健康状态；空模型的 OpenAI 兼容和 QVeris 渠道只读取模型目录，不保存目录。Anthropic/Google 渠道需先配置模型 ID。
- 检查前后比较渠道修订号，防止在请求期间修改配置后展示过期成功结果。场景切换时清空检查状态；固定配置会话目标，避免结果写到新场景界面。
- 界面仅显示状态、耗时、目录条数或已归一化的错误，不输出上游错误正文和密钥。

## 验证与遗留

- `bun run typecheck`、`bun run build:extensions`、`bun run build:react`、`bun run bundle-css`、`bun run check`、翻译覆盖检查和按 CRLF 规则执行的差异空白检查通过。全仓检查仍报告 119 条已有警告、7 条提示及 1 条设计警告。
- 未新增或运行测试，也未对真实服务进行连接测试。设置页、配置 store 和扩展配置分派文件均已超过 500 行，本轮只在既有渠道动作与分派处接入；后续增加设置动作前应抽取独立控制模块。
- 已有模型的检查可能计费，非 QVeris 模型调用沿用现有健康检查的运行时超时行为；前端等待上限为 120 秒，不能据此前端超时断言后端请求已停止。
- 连接检查不代表模型响应质量、所有模型可用或完整跨平台验收；禁用渠道仍未实现。
