# 桌面自动化后台进程控制（2026-10-01）

## 目标与发现

无窗口 worker 已可用命令行启动和请求停止，但普通用户无法从自动化中心看见它是否存在，也不能在关闭桌面窗口前主动选择是否继续检查计划任务。worker 是否存在与哪个进程持有自动化执行锁是两个不同状态。

## 修改与决策

- Tauri 增加状态、启动和停止三个桌面命令，仅接受原生工作区窗口调用。状态通过 worker 的 OS 文件锁判断 `stopped`、`running` 或 `stopping`；启动返回短暂的 `starting` 也由界面识别。状态只表示无窗口进程，不声称它当前持有自动化执行锁。
- 用户点击启动后，桌面程序用自身可执行文件和已解析的打包 `public` 目录启动独立进程，标准输入输出关闭；最多等待约两秒观察锁或启动失败。worker 的单实例锁处理多个桌面进程同时启动的竞争。关闭桌面窗口不会主动结束该子进程。
- 停止按钮仅写本地停止请求，由 worker 自行结束 Host 与 Pi。桌面命令复用 Tauri 已安装的日志器，不在同进程再次安装独立日志器。
- 自动化中心新增只在原生桌面显示的状态卡片、主动启动、停止和刷新操作。页面可见期间定期刷新，不向远程页面提供进程控制入口。默认不自动常驻。

## 验证与遗留

前端 `bun run typecheck`、`bun run check`、`bun run build:react` 和 `bun run bundle-css` 退出 0；针对本轮改动的七个前端文件单独执行 Biome lint 无诊断，仓库检查仍报告既有的非阻断警告。`bun run check:rust:static` 退出 0，包含 Cargo check 与以警告为错误的 Clippy；仓库级格式检查仍报告已有格式漂移，新增 Rust 模块的目标 `rustfmt --check` 通过。未运行测试、真实桌面启动/关闭/停止或三平台验收。Linux AppImage 资源挂载、Windows 无控制台子进程及 macOS 安装路径下的持续运行仍需实机验证；开机启动、更新时重启和执行者详情仍待实现。
