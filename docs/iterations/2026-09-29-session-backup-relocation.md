# 2026-09-29 会话备份跨目录恢复

状态：实现与静态检查完成；真实备份、跨设备与跨系统恢复未验收。

## 发现与目标

- 会话备份导出记录了原项目的绝对路径；Host 导入要求会话头中的 `cwd` 等于当前工作区。项目迁移到另一台机器或目录后，全部条目会被跳过。
- 导入逻辑原本把备份提供的会话 ID 拼成文件名，没有限制路径字符；写入前的存在性检查与实际写入之间也存在覆盖窗口。
- 导入的每条内容允许 10 MiB、总计 50 MiB，但 HTTP 路由继承 2 MiB 请求体上限。

## 修改

- 界面检查备份格式、来源目录一致性和文件上限，展示原项目路径，由用户确认把会话导入当前工作区。
- Host 在明确的来源路径与每条元数据、唯一会话头完全一致时，仅将会话头 `cwd` 改为当前已注册工作区的规范路径。消息正文、历史文件引用与原始备份不变。未声明重绑定的 API 请求保留原有同目录校验，并核对元数据路径与会话头相同。
- 会话 ID 仅允许有限长度的 ASCII 字母数字、`-` 和 `_`；目标文件使用独占创建，已有文件跳过，不覆盖。导入路由上限提高至与备份 API 相同的 70 MiB，条目与总内容上限不变。
- 导入结果展示错误条目数量；中英文帮助明确备份可能包含用户输入的敏感信息。
