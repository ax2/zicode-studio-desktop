当前范围：源工具 `markdown` 1.0.1，独立插件0.1.0候选01已经冻结、接收并通过真实 Worker 和一次隔离 Host HTTP 流程。**尚未安装到当前 Windows Studio，尚未完成易读预览或实际界面验收，因此不计新增映射或交付。** 当前安装版仍20包、99能力与7个View，154源工具仍5完整、49部分、100无映射。

原生和 WASI 共同使用提供方同仓纯 Rust 核心，原生窗口和文件读写仍属独立应用。保留2MiB原始输入、单个BOM、空文档、20万事件及16MiB完整HTML输出；UTF-8内容决定文件是否可读，不额外限制后缀或传输MIME。表格、任务列表、删除线、脚注、代码及链接净化沿用原生算法和HTML模板。普通HTTP(S) userinfo沿用原有允许规则，没有宣称全部凭据链接都会被拒绝。

新接口 `resource.wasi.markdown.v1 =1.0.0-preview.1` 明确协商一个资源和一个HTML输出；模块快照input draft2、output draft1、已有HTML MIME index25。原生/算法没有Studio源码或运行依赖。Host为该接口单独设置256MiB、1B fuel和10秒预算，加入已有512MiB单次预留/1024MiB总池；旧接口预算不变。实际WASM内存最大4096页，451861字节，SHA256 `567bbebf92a1c42bf2162f332b541bfbceeab5a98f9d832984d40ca7d2145ad9`。导入仅资源size/read、输出create/write/finish及无预开目录的WASI stdio/environment/random；没有文件路径或网络导入。

提供方原生共享核心6项、适配器2项检查通过；此前原生Markdown3项回归通过。生产Worker33个固定正反场景通过：成功时JSON及完整HTML与独立原生适配器逐字节相同，另外检查已知文档结构和不产生活动script/img。包括2MiB文本、BOM边界、20万事件、会展开为10486640字节HTML的代码块；非法UTF-8/复杂度/大小/身份/选项/摘要/协议降级失败。各次完整冷Worker调用均低于10秒。不是以声明、模板或模拟Worker代替算法实测。

## 剩余交付工作

1. Host只向手工详情注入一个可信Markdown文本角色，支持粘贴/文件切换，不假装声明MIME过滤，也不向其他插件开放额外输入。
2. 完成所有原生允许文档结构的惰性安全预览及完整HTML查看/导出。当前通用HTML文本预览仍128KiB，不能用它代替16MiB接口的完整范围。禁止把提供方HTML直接放进应用DOM、执行脚本、自动加载图片或跟随链接。
3. 当前Windows实际构建、安装、表单、语言切换、窄窗、异常输入保留、确认保存与完整导出验收；沿固定资料库进行当前数据备份/差异核对，保留用户后续编辑，恢复普通无调试启动。
