# 启动恢复失败的安全撤销（2026-11-13）

关联 Project #4 / Issue #31，仍为开发中。开发版本保持0.5.3，本批不是发行包或个人资料升级验收。

## 行为

`restore_startup.rs` 接管启动恢复和失败确认，`main.rs` 仅增加模块与两个调用。只有取得 Worker 维护租约、确认未提交且能安全收敛的请求，才在启动错误窗口出现后提供原生撤销确认。选择保留不改请求；选择撤销后重新取得租约，并在系统请求锁下重新核对同一个请求及提交状态。确认期间请求改变或维护锁失败会拒绝，不启动工作区。

备份模块保留快照、当前资料与取消回执，取消使用同目录原子改名。已提交事务继续补发结果，不提供撤销。检查所有注册根时仅 NotFound 可跳过；非普通目录、重解析点和其他读取错误拒绝撤销。目标必须实际存在。旧根无法判定的事务继续保留现场。

启动错误页改为按具体服务或本地资料错误提示，不再将备份缺失误报成 Pi 安装损坏；重启说明明确需要完全退出后重新打开。
