# 项目终端输出帧边界

日期：2026-10-01。状态：代码已修改，真实终端验收待补。

## 目标与发现

项目终端列表会校验 Host 回传的会话信息，但输出轮询此前只核对会话 ID、工作区和游标未后退。损坏或旧版本 Host 响应可能带来非整数 `nextOffset`、超过 `outputEnd` 的游标、过大的数据帧或与游标跳跃不一致的截断标记；客户端可能先渲染再以错误游标继续读取。

## 修改与边界

- 轮询复用会话列表的运行时契约，校验单帧会话、状态、尺寸与输出边界。
- 在启用输入或渲染前核对下一游标为安全整数、位于当前游标和本次 `outputEnd` 之间；Base64 编码长度和解码字节数不得超过 Host 的 32 KiB 帧限制。
- 解码后核对截断标记与实际游标跳跃一致。空数据帧也按相同规则校验，避免无警告跳过输出。
- 失败沿用现有断开处理：停止输入、停止轮询并显示重连入口；不自动重发可能已到达 Shell 的输入。

## 验证与遗留

`bun run check`、`bun run typecheck`、`bun run build:react` 和修改文件的 `git diff --check` 均退出 0；仓库静态规则仍报告既有非阻断提示。本轮未新增或运行测试。仍需用真实 Windows/macOS/Linux PTY、旧 Host 和断线重连核对响应兼容性与界面行为。
