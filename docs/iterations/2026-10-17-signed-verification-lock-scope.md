# 签名包校验的注册表锁范围与解包摘要（2026-10-17）

## 发现

Studio Host 原先在持有全局插件注册表互斥锁期间执行签名包预览及安装前的 ZIP 遍历、文件 SHA-256 和签名验证。大包或慢盘会延迟其他插件目录与调用相关的注册表访问。`verify_package` 校验完后，解包又重新打开原路径，却只按声明长度读取，没有再次比对已签名的逐文件摘要；包在两步间变化时，安装流程不能仅靠前一次校验保证写入内容。

## 修改

- Host 仅短暂持锁取得稳定的注册表根路径，预览和安装的完整包校验在锁外执行。安装再取得锁，按当前信任库重新判断发布者是否受信任或已撤销，然后执行原有安装事务。
- 解包对每个写入 staging 的文件重新核对声明长度及 SHA-256；任何不匹配使解包失败并清理本次 staging。签名包外层仍受 50 MiB、文件数与路径门禁约束。
- 原注册表直接预览/安装包装仅用于现有测试；生产 Host 走预校验再提交路径。没有改变签名格式、权限、插件协议或应用版本。

## 验证

- `signed_install_refreshes_publisher_trust_after_package_verification`：校验后新增信任可被安装读取，校验后撤销则拒绝安装，1/1。
- `rejects_package_contents_changed_after_verification`：同一包路径被等长不同内容替换，解包返回 `Package file hash mismatch`，没有留下目标目录，1/1。首次测试用非等长内容，既有长度门禁先拒绝，断言失败；修正测试输入后通过，失败事实保留。
- 原签名安装、升级、回退、撤销生命周期专项 1/1。`bun run check:rust:static` 最终退出 0，Cargo check 与严格 Clippy 通过；第一次静态检查发现两个测试专用包装在生产编译中成为 dead code，限定测试用途后重验通过。rustfmt 仍提示仓库格式漂移。
