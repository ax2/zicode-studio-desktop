## 发现并修复的实际故障

新隔离资料中的浏览器曾返回 `0x80070057`，无法创建标签。阶段日志确认失败发生在设置 WebView2 建议下载目录；该目录只是建议文件名的来源，不能成为网页初始化的硬依赖。现在对传入路径作 Win32 简化，通常目录被拒绝时改用浏览器私有暂存目录作为建议来源；私有目录也不可用时保留 WebView2 默认值，不再阻止页面创建。

站点权限、网页 IPC 禁用与下载拦截仍为必须成功的初始化步骤。下载仍由 Host 取消并挂起，只有用户明确保存后才设置实际目标。参见 [Microsoft 的目录属性说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2profile#put_defaultdownloadfolderpath)。本机日志保留了目录拒绝，修复后的真实网页标题和正文已可读取。私有目录回退成功，网页链接下载进入等待保存，点击取消后没有目标文件。

本机完整 debug 预检通过：浏览器与图库切换保持同一文档和未提交输入，422 CSS 像素窄窗口无横向溢出，退出重开恢复图库，应用目录搜索进入，无远程调试接口的普通启动也能通过原生辅助功能入口看到样图。记录：`release-058-preflight-native-acceptance.json`、`release-058-preflight-normal-acceptance.json`（文件名沿用最初任务，内容版本为 0.5.9）。

## 发布闸门

GitHub tag 构建只生成草稿。公开发布之前必须取得 Windows CI 安装包导出的候选，核对源码 SHA、安装包摘要及全部运行资源摘要，再完成普通启动、入口、真实导入、预览、浏览器切换、下载确认、窄窗口与退出重开验收。仅源码检查或 debug 预检不能代替安装包验收。

用户固定资料目录保持 `D:\work\local-state\zicode-studio-desktop`，验收使用独立配置。记录测试前后笔记、产物、会话等文件摘要，并保持用户自己启动的日常实例运行。不自动调用收费模型。

最终 CI 链接、安装包摘要和本机安装包验收结果在公开 Release 说明中补充；在该闸门完成前，本记录不代表可以公开发布。
