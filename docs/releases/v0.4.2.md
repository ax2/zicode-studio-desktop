# ZiCode Studio Desktop v0.4.2

面向个人项目、AI 协作、知识与自动化的跨平台开发者个人平台。仓库现已公开，仍为早期开发版本。

## 本次变化

- 修复 Windows 换行依赖断言、PowerShell 启动路径兼容、macOS 重复嵌入应用信息，以及 Linux 通知依赖兼容；适配新版 Rust 严格检查。v0.4.1 的 Inbox 首次加载检查四平台通过，后续平台门槛失败，保持未发布草稿。
- 修复 Windows 终端退出时光标应答线程提前关闭及互斥锁等待问题；修复 Linux AppImage 启动路径类型。为 Linux 自动检查提供真实桌面通知服务，并让聊天测试等待 React 完成渲染与释放实例。

- 修复 Pi 1.1.0 首次加载 Inbox 依赖时的错误堆栈兼容问题；补充首次加载和错误对象回归验证。v0.4.0 构建被该门槛阻止，未公开发布。

- 说明项目来源：最初参考 Picot 的 Pi 桌面封装架构，没有直接 fork Picot，也未持续跟进；保留历史版权和 MIT 声明。
- 完善项目工作台、Git 状态、终端、环境检查、任务、笔记和自动化能力。
- 引入独立插件契约、安装与完整性检查、目录搜索、分类、收藏、最近使用及按需加载；大量工具通过工具中心访问。
- 支持动态工具调用、权限校验、超时、取消与故障隔离，以及经用户确认的结果保存和传递。
- 工具详情渲染失败时保留执行会话，资源工具保留结果、预览和取消操作。
- 内置 Pi 更新到锁定的 1.1.0；统一开发构建缓存，本地开发不频繁变更版本号。

## 使用与验收边界

- Zi DevTools 全目录目标为 154 项；当前完整工具验收计数仍为 0。候选包基本操作验证不等于所有工具全部接入。
- 逐项进度、未接入理由及所需接口见 [全部工具接入清单](https://github.com/ax2/zicode-studio-desktop/blob/v0.4.2/docs/plugins/devtools-all-tools.md)。
- 资源调用或写入确认后的响应丢失恢复仍有待完成；不要将不确定状态视为执行失败并盲目重试。
- Windows 内置 Pi、PortableGit 和 WebView2 离线安装器；macOS/Linux 使用系统 Git 与 Shell。
- Windows 安装包尚未 Authenticode 签名；macOS 使用 ad-hoc 签名，尚未进行 Developer ID 签名和公证。签名自动更新尚未启用。
- 自动检查和构建结果以本 Release 对应的 Actions 记录为准；其他操作系统完整人工体验、所有提供方算法等价性仍待验收。
- Windows 完整 Rust 检查使用两线程测试设置，与本机验收一致；各用例内部并发、功能断言和超时保持。

Windows 提供 NSIS EXE；macOS 提供两种架构 DMG；Linux 提供 AppImage/DEB。Windows 本地保留完整运行目录与 EXE，不制作应用 ZIP。
